## 排查「生成任务：总题数 2 但只出 1 题」（已定位，未改码）

**根因**：结构化 specs 被降级成自然语言往返，后端正则只能还原**一条** spec。
- 前端 `home_notifier.dart:_buildPrompt`（:52-65）把每行 spec 拼成
  `${grade}年级${subject}${label}${count}道，关于${kp}`，多行用「、」连接。
- 后端 `app/ai/subagents/question/agent.py:parse_specs_from_text`（:99-168）**只返回一条** spec：
  subject/grade/count/qtype/知识点全部取首个正则匹配 → 第 2 行起整行静默丢弃，count 取第一个 `(\d+)道`。
- 于是「总题数 2 一键均分到 2 行」→ 每行 1 道 → 只出 1 道；且题型串味（实测 STEP：
  `正在为《数学》3年级「两位数加减法」出填空题…`，语文行的「填空」串到数学行）。

**实证**（临时测试 `tests/ai/test_tmp_repro_count.py`，跑完已删）：
- 单行 count=2 → DATA 题卡 2 张（后端循环本身没问题）；
- 两行各 1 道 → DATA 题卡 **1 张**。

**连带缺陷（同一条链路）**
1. `parse_specs_from_text` 里 `count = min(count, 5)`（:132/136）是防滥用上限，但结构化规格也被
   砍：总题数 10 均分 1 行 → 只出 5 道。
2. 后端 `AssistantChatReq.focus_interest: str | None`（assistant/router.py:76），前端
   `AssistantChatReq.toJson` 发的是 `List<String>`（assistant_api_client.dart:26/36）→ 开启
   「按兴趣出题」会 422。
3. 「总题数」输入框不点「一键均分」不生效（`parent_task_form_view.dart:_evenSplit` 才把总题数
   写回各行），默认每行 5 道。

**推荐修法**：specs 直传，不再走自然语言往返——`AssistantChatReq` 加 `specs: list[dict] | None`
→ router 塞 `ctx.extra["specs"]` → `QuestionSubAgent.run` 优先用 `ctx.extra["specs"]`，无则回落
`parse_specs_from_text`；自由文本上限 5 与结构化上限分开。

**设计层归因（追问「是不是设计问题」）**
- 是**契约设计**问题，不是出题逻辑问题：`features/tasks/service.py:254 _generate_task_questions_for_specs`
  按 count 展开多行是**对的**，现在仍被「整卷重生成」复用；错的只是流式路径。
- ADR-0024（`docs/decisions/娃娃学习App_ADR.md:348`）把统一入口入参定为「前端发一条 user message
  （含 role/session_id）」，**没给结构化参数留位置**；`model`/`focus_interest` 是事后补丁式塞入。
  「生成任务」页的真实输入是 specs[]，契约装不下 → 前端只能序列化成中文句子。
- `parse_specs_from_text` 的设计容量是「悬浮助手一句话出题」（单 spec、弱识别、上限 5 防滥用、
  识别不到就提示补充），被拿去当结构化规格的解码器，属超容量复用。
- **有损编码 + 静默解码**：encode 丢信息、decode 不报错，丢失无人知晓——这是最该修的纪律问题。
- 一致性隐患：流式按自然语言出、落库按结构化 specs 存 → `Task.specs` 与实际生成口径不一致，
  「整卷重生成」会按另一套规格重跑。
- 旧路径 `/tasks/batch-generate`（纯结构化）已删，等于丢掉了正确实现退回字符串解析。
