## 晚间：修打印预览页 PDF 打开崩溃（PlatformException channel-error）

**现象**：题库页勾选 → 打印预览进页面即崩，控制台 `PlatformException(channel-error, Unable to establish connection on channel.)`，栈停在 pdfx 的 `PdfxApi.openDocumentData`。

**归因（两层，别混为一谈）**：
1. **直接原因是运行形态**：macOS 构建产物/build 时间戳停在 09-15，`build/macos`、`.dart_tool/flutter_build` 都早于今天 01:42 那次 `flutter pub add printing pdfx`；`ios/Pods`、`macos/Podfile` 根本不存在。**加插件后没重新完整构建/重跑 App**（Hot Restart 不补原生注册）时，Dart 侧有新通道、原生侧没有 → pdfx pigeon 的 `BasicMessageChannel.send` 返回 null → 抛 channel-error。**这个问题改代码修不了，必须彻底停止 App 重跑一遍。**
2. **代码缺陷（已修）**：原本把 `PdfDocument.openData()` 这个未完成 Future 直接交给 `PdfControllerPinch`，失败时异常无归属 → Unhandled Exception + 页面停在加载态，既没错误态也没重试口。

**改动**：
- `features/export/presentation/export_preview_page.dart`：自己 await 打开文档，阶段区分 `_PreviewFailure.fetch/render`（文案「导出失败/预览失败」）；顺手补上 PdfDocument 句柄的关闭（pdfx **不会**自动 close，且 dispose 顺序要先 controller 后 document）；接 `onDocumentError` 兜底；打印/分享按钮可用性从「字节到手」改为「预览已就绪」。
- `features/export/providers/export_provider.dart`：新增 `PdfDocumentOpener` typedef + `pdfDocumentOpenerProvider` 接缝。
- 新增用例「字节到手但渲染引擎不可用」，替身直接抛 `PlatformException(channel-error, ...)`。**验证过它会咬人**：退回旧写法 → 该用例红（Expected: null）。

**踩坑**：⚠️ widget 测试里真调 `PdfDocument.openData` 会**永久挂住**（既不完成也不报错）→ 探针和整个 test 进程卡死，只能 kill `flutter_tester`。要测这条失败路径必须走 provider 接缝，别对着平台通道写替身。

**验证**：analyze 零 issue；前端 **183 全绿**。

**现象**：上一轮加了 try/catch 后不再有 Unhandled Exception（控制台没输出，说明确实被接住了），但页面提示 `PlatformException channel error`。

**归因（决定性证据，不再靠猜）**：

## 下午：把「退路」与「宽度」各收一个口（ADR-0045 实现期补充决策）

起因：`/critique` 判出 P1——**退路靠每页自觉**。`AppTopBar.showBack` 默认 false，而 ExportPreviewPage 就因为漏写把人锁死一屏（今天早上补的）。补一行能修，结构是没修。

**新增共享组件**（`lib/shared/widgets/`）
- `AppContentFrame`：`Align` + `ConstrainedBox(maxWidth)` 的唯一出口；`alignment` 仍是调用方参数。**全仓 14 处手抄已全部迁入**，`AdaptiveShell._cappedWidth` 也改用它（→ 定义唯一）。迁移时照抄 alignment，不顺手统一。
- `AppPushedPage`：内容框 + 顶栏 + **退路默认化**——`showBack` 默认 **true**（与裸 AppTopBar 相反）、Esc 默认可返回、`onBack` 同时接管返回按钮与 Esc。
  - Esc 两个坑：`Shortcuts` 必须是焦点节点的**祖先**（键事件只向上冒泡）；必须 `autofocus`（桌面端刚进页焦点树为空 → Esc 是死的）。逐个退化验证过会红。
- `AppTopBar` 默认返回按钮补 `Semantics(button/label: '返回')`（此前只有 Icon，读屏读成「按钮」）。

**落地范围**：ExportPreviewPage（已在上一轮）、PracticeScreen + 订正子页（订正的「返回」是状态机回退不是 pop，走 `onBack`）；AssistantChatPage **不套**整页骨架——双宿主（可 push 也可作页签），套了页签形态会长两个顶栏，只迁它的三处宽度。
**有意保留**：`PracticeScreen(maxWidth: double.infinity)` —— 它回顾阶段的底部行动条是通栏设计，钉 1080 会把它缩窄；这是视觉取舍，标注在代码注释里，留待单独一轮。

**批量迁移的做法**（14 处手抄块结构一模一样）：写一次性脚本按「Align→AppContentFrame」做结构替换 + 子树整体左移 2 + 删一层闭合。三次失败都出在细节上，值得记：
1. `ind = line.index('Align(')` 对 `Widget f() => Align(` / `child: Align(` 都错（前者丢前缀、后者缩进按列号算）→ 前缀要保留、缩进按**行首**算。
2. 多行 head（带 alignment）必须作为**多个 list 元素**写入，塞成含 `\n` 的单个元素会让后续索引全错位。
3. 删除区间因 head 变长而偏移：`del lines[k+len(head) : childline + len(head) - 1]`。
4. 括号配对要先剥行注释与字符串字面量。
脚本用完即弃，**不要把这种兜底脚本留在仓库里**。
