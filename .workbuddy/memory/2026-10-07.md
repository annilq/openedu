## 判分链路分析（学生端答题 → 是否正确）
- **入口**：前端 `practice_screen` 收集 `_answerController.text.trim()` → `POST /tasks/{tid}/answer`（`{question_id, student_answer}`）→ `tasks/service.py:answer` → `Grader.grade`（`domain/grader.py`）。
- **Grader.grade 三分支**：① `qtype=='open'` → 委托 LLM `grade_open`（genkit_provider.py:167，prompt=`题目/学生作答/请批改JSON`，受 `GradeSchema` 约束）；② `multi==True` → `'|'` 连接选项文本做**集合比对**（顺序/重复不计）；③ 其余（choice/fill/calc）→ 归一化字符串**严格相等**：`re.sub(r"\s+","",(text or "").strip().lower())`。
- **数学学科判定**（subjects.py 白名单 数学=[calc,choice,fill,open]）：
  - **填空题 `fill`**：归一化字符串严格相等。**不解析数值、不识别单位、不约分、不做分数/小数等价**。`"12"` vs `"12厘米"`/`"0.5"` vs `"1/2"`/`"2/4"`/`"12。"` 全部判错。
  - **应用题 `open`**（CONTEXT.md：数学应用题与语文阅读理解共用 open 形式；`test_document.py:131` `_q("应用题", qtype="open")` 佐证）→ **LLM 柔性判分**（语义层面，依赖 task.model/教师默认模型，未配模型抛「未配置模型」）。
  - 计算题 `calc`：同填空题，字符串严格相等。
- **结论**：数学客观题（填空/计算）是「去空白小写后逐字精确匹配」，主要误判源=单位/分数小数/约分/过程写法；应用题走 LLM 判分但依赖模型配置。如需数值等价判分须改 `Grader._normalize` 或新增数值解析分支。
- **改造方案已落本地 spec**：`docs/specs/numeric-equivalence-grading.md`（@skill:to-spec 触发；遵循用户既有决定**不建 GitHub issue**，只写本地 `docs/specs/`）。核心：唯一缝 = `Grader.grade` 客观题分支；对「数学+fill/calc」新增 `parse_numeric`/`numeric_equal`（stdlib `fractions`/`decimal`/`re`，不引 sympy/pint），解析失败回退现有严格相等保证零回归；open/multi/非数学/前端全不动。建议决策 ADR=**0071**（规划中，落地时创建）。
