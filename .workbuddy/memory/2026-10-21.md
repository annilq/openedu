## 开工 ticket 12：路由 criteria 文案调优（用户「开工票 12」）

### 先修评测脚本的两处漂移（否则量的是另一件东西）
- `criteria` 是**手抄副本**：脚本里硬编码 `CAPABILITY` 字典，只是注释约定同源 → 改为 `sys.path` 引 backend，直接 `discover_subagent_manifests()` + `_capability_text()`，`INSTRUCTIONS` 从适配器常量导入。用 `backend/.venv/bin/python` 跑。
- **学生端可见集写错成 K=2**：脚本 `STUDENT=["capability","tutor"]`，生产实为 **K=3**（`test_student_sees_tasks_but_write_tool_rejects`：tasks 对学生可见，只有写工具按角色拒绝）。ticket 11 那条「学生『23+45』被 0.956 判 capability」是在错误选项集上测出来的；修正后同用例 0.784。可见集改为 `AgentRuntime.visible_businesses(role)`。
- 脚本新增：`--variants <json>` 批量文案对比（一轮跑完 N 个变体，只替换 description）、`HOLDOUT_CASES` 留出验证集（10 条，写于选型之后只用于裁决）、门控视角（pmax + 是否 ≥0.5）、`compare_results.py`。

### 七轮单变量爬山（34 条计分用例 + 10 条留出，基线 59%）
- 基线：top-1 20/34、**采纳且正确 15**、未采纳落引导 10、高置信错 0、p50 25 ms。
- **三条反直觉教训**（已写进 manifest 注释 + 契约测试）：① criteria 里**禁止排他式否定句**（「不查数据/不出题」→ 35%、高置信错 6 条）；② **禁止堆示例问句**（50%）；③ capability **不要窄化成「只在问助手自身」**（44%——它同时是「都没命中」的落点，ADR-0105）。capability 的「能做什么、不能做什么」对称措辞是有效的，不在禁止之列。
- 最优变体 **D4**（74%，采纳且正确 24/32）：tasks「出题与查数据：…」、capability 原文案去实现细节、tutor「讲题与答疑：讲清某道题怎么做、为什么是这个答案。」（删「解释知识点」）。
- **留出集揭示收益性质**：top-1 未提升（60%→60%），提升全在「正确路由过得了 0.5 门控」（30%→50%）→ 改的是**置信度分布**而非排序能力。这直接把 ticket 13（门控）顶到下一步。

### 熔断条件触发 → ADR-0106（与开工预设的偏离）
- D4 的 tasks 文案删掉了「教师可管理题库 / 组建草稿任务」——用户该知道的真实能力；实测加回去准确率 **74% → 56%**。同一份文本无法同时服务「用户读得懂」与「模型分得开」= ticket 预设的熔断条件。
- 故新增可选 manifest 字段 **`routing_criteria`**：`_capability_text` 用它替换 `description`（`name`/`actions` 照旧，未声明行为不变）；用户可见清单 `capability_catalog` 仍直读 `description`，一条能力都没少。ADR-0097 单一事实源的**有据例外**。
- 契约测试 `tests/ai/test_routing_criteria.py`（17 项）守：双通道分离（清单 = description）、长度 ≤120、无排他否定、无示例问句、各具专属动词、三者两两不同。**不断言逐字文案**。

### 验收

- [ ] 新增 2 条高置信错误（T01 0.833 / T03 0.927 查数据 → tutor；基线里这两条也错，只是未采纳→落引导）。
- [ ] 学生端 S01「23+45 怎么算」仍未翻正（capability 0.56）——所有变体都翻不正，属排序问题。
- 两项未达成均为门控/排序议题 → 转 ticket 13。

## 开工 ticket 13：路由采纳门控（用户「执行票 13」）

### 门控上移（使改动，ADR-0107）
- `LayaDecisionModel` **移除 `threshold` 构造参数**：解析出选项就回传 `DecisionResult(choice, prob)`，低分也如实给——此前「回了但 0.43」被吞成 `None`，与「模型没回」不可区分。
- runtime 新增 `min_adopt_score(business, role)`：业务自述（`manifest.min_adopt_score`，0=未声明）→ 角色覆盖（`set_role_min_adopt_score`）→ `DEFAULT_MIN_ADOPT_SCORE=0.5`。两个原语共用 `self._adopt`。
- 被否掉的候选进 `extra["rejected"]`（primitive/business/score/min_adopt_score）；`routed_by="default"` 里终于能分清「没回」与「回了但低分」。
- `consensus` 作为**可选**策略档位（两原语都跑、一致且各自过门控才采纳）。
- 测试 `tests/ai/test_routing_gating.py` 15 项；laya 那两条阈值用例迁移到 runtime 层（断言点不变）。

### 两个候选都被实测否决（数据说话，不是没做完）
- **候选 A 学生端单独阈值 → 否决**：`--sweep` 把 44 条 pmax 逐档摊开，低分段**不存在可分离区间**；抬到 0.53 在调优集净 **+7**、留出集 **−3**（反向）；学生端正确路由 pmax 反而更低（0.41–0.76），要挡住唯一那条学生有害错（0.702）得 ≥0.75，代价是挡掉 10 条正确。→ 默认 0.5 不动，角色覆盖表**保持空**（空表有注释说明依据）。
- **候选 C 交叉校验 → 不启用**：44 条同时问决策模型与真实 LLM（`deepseek-v4-flash`，走生产 `classify_llm`）＝ 决策模型 29 正确/9 有害错、LLM 42 正确/1 有害错、交叉校验 27 正确/**0** 有害错（留出集 5/10、9/10、4/10）。有害错降到 0，但同样付那次往返时**直接信 LLM 全面更好** → 保留为可选档位、不进默认。

### 顺带修掉的一处真实缺陷
- `RoutingDecision.confidence` 原为 `float = 0.0`：deepseek 44 条里 13 条不填该字段 → 按 0 参与 0.5 门控会误杀 **6 条正确**路由（36→30）。改 `float | None = None`，「未自报」不作比较（改完自报率也上升到 4/44 未填）。

### 验证与产出
- `tests/ai` 406 passed；+ features/assistant + test_assistant 506 passed；隐藏 `.env` 全量 **1058 passed / 2 skipped / 1 failed**（唯一红仍是 `materials test_empty_text_422`）；ruff 全净。
- 产出：ADR-0107 新建 + ADR-0105 补「命中」定义修订；`eval` 新增 `--sweep`（阈值扫描，分集/分角色）与 `--consensus`（同源对照，无 provider 则跳过）两个可复跑入口 + `results-2026-10-21-consensus.json`；ticket 13 → done、INDEX 加 13/14 行。
