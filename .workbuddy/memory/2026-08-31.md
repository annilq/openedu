## 修复：ADR-0015 后端流式链路 6 个测试失败（全绿：119 passed / 1 skipped，ruff clean）

- 根因与修复：
  1. **`Ollama` 构造签名**：`genkit_ollama` 的 `Ollama.__init__` 用 `server_address=`（不是 `base_url`）→ `engine._get_or_build` 改 `Ollama(server_address=...)`；`OpenAI(**openai_params)` 透传 kwargs（api_key/base_url 不变）。

  4. **测试传字符串 id 给 `db.get`**：JSON 返回的 `id` 是字符串，`db.get(ModelConfig, str)` 触发 UUID `.hex` 报错 → 测试里 `uuid.UUID(mid)` 包裹。

  6. **conftest 清理漏 `ModelConfig`**：session 级 `db` fixture 的 delete 列表补 `ModelConfig`，避免跨测试残留。
- 复用经验：① Genkit Python 各插件构造签名需查 `site-packages` 源码（Ollama=server_address，OpenAI=透传）；② FastAPI 动态 `/{id}` 路由务必排在字面兄弟路由（如 `/default`）之后；③ `uuid.UUID` 主键列，凡从 JSON 拿到的 id 字符串都要 `uuid.UUID()` 转回再 `db.get`，否则 `.hex` 炸。

## 修复：登录报「请求失败 (-1)」且服务端无日志
- 现象：登录提示 `-1`，服务端零日志；账号密码用户确认无误。
- 根因（两层）：① 前端 `DioNetworkService._extractError` 在 `response==null`（连接层失败：超时/连接被拒/域名解析/证书）时把 `DioException.type` 与底层 OS 错误整段丢弃，统一成无意义的「请求失败 (-1)」，导致完全无法定位；② 真因是请求根本没到后端（uvicorn 默认会打印每次请求访问日志，看不到日志=请求没进来）。本机 8000 端口确认已有后端在跑且 `/api/v1/health` 正常 → 最可能是 App 跑在真机/平板/模拟器上，`127.0.0.1` 指向设备自身而非 Mac，或 App 用了过时的 `API_BASE`；且后端默认只绑 `127.0.0.1`，平板即便改对地址也连不进。
- 修复：① 前端 `dio_network_service.dart` 新增 `_describeConnectionFailure(e)`，按 `DioExceptionType` 透出真实原因+目标地址（`AppConfig.apiBaseUrl`），`_extractError` 在 `response==null` 时走此分支；`flutter analyze` 零问题。② 后端 `main.py` 加 `openedu.request` 请求访问日志中间件（自带 StreamHandler，不依赖 uvicorn/root 配置），每次请求打印 `METHOD path -> status (ms)`；重启后端后即生效。
- 验证：后端 8012 端口起新代码，`curl /health` 后日志出现 `INFO openedu.request GET /api/v1/health -> 200 (26.4ms)`。
- 给用户的定位步骤：A) `curl http://127.0.0.1:8000/api/v1/health` 确认后端通；B) 若 App 在真机/平板，用 `flutter run --dart-define=API_BASE=http://<Mac局域网IP>:8000` 且后端加 `--host 0.0.0.0`；C) 重启后端后看日志——有登录请求行=到后端（看状态码），无行=网络/地址问题（此时前端会显示具体连接错误）。

## 修复（续）：登录 -1/无日志在 macOS 桌面端的真正根因 = 沙盒缺 network.client
- 用户澄清 App 跑在 **macOS 桌面端**（非模拟器/真机），这推翻了上一轮「127.0.0.1 指向设备自身」的假设——同机回环下 IP 本应正确。
- 真因：`frontend/macos/Runner/DebugProfile.entitlements` 沙盒化（`app-sandbox=true`）却只给了 `network.server`（被动接收，供 Flutter 工具热重载连入），**缺 `com.apple.security.network.client`**。沙盒内 App 被禁止主动向外发起任何连接 → 请求在系统层被掐 → `127.0.0.1:8000` 连不上 → -1、后端零日志。Chrome 是系统级应用不受此沙盒约束 → 能连。这与「Chrome 能、App 不能、同机」的现象完全吻合。
- 修复：两个 macos entitlements 都补 `com.apple.security.network.client`（DebugProfile 加在 network.server 前；Release 原本只有 app-sandbox，加 network.client）。`plutil -lint` 两文件均 OK。
- 关键认知：Flutter macOS 调试构建**默认沙盒化**，官方模板只给 network.server 漏了 network.client，凡 App 需调后端 API 必补。地址 `127.0.0.1` 在 macOS 桌面端是对的，无需改 IP；改完 entitlements 后重新 `flutter run`（重新签名）即生效。
- 注：上一轮给 Android 清单加的 `usesCleartextTraffic=true` 对 macOS 无害且利于后续 Android 联调，保留。
