### 四项决策
1. **删除**：`extract_option_group`(scene_extract.py:85) + `extract_scene_inputs`(:50) + **整个 `scene_extract.py`** + `test_scene_extract.py`。两者是同一套「从自然语言猜图形」机制，只留一个等于留一半猜测逻辑。`default_scene_from_figure` **不删**（是"按 key 取权威几何→纯几何 SceneSpec"的盖章原语），建议改名 `scene_spec_from_figure`（4 处调用+测试），因"兜底"语义已消失。`build_scene_spec_for_question` 去掉 `stem`/`options` 形参，改收 AI 显式给的 `figure_key`。
2. **`scene_options` 为何必要**（回应"场景库已能关联 KP，能否直接用"）：关联**本来就在用**且不需新表——`kp.scenes` 就是关联，场景库的 `associated_knowledge_points` 是扫 `kp.scenes[].kind` **反查**出来的（service.py:729-744），库是派生视图。但库不能被生成消费：①方向反=live binding（ADR-0073 红线）②粒度不对（库给 kind 级**一个** `default_figure_key`，选项需要**一组**）③无校验/盖章/落快照能力。新模块只装**目录投影+校验+盖章**三件事；**若只有一个消费方本可省掉模块**——正因出题(tasks/question subagent)与答疑(tutor)两个消费方共用才独立。另 `scene_fusion.py` 已 309 行，ADR-0058 上限 400，塞不下。
3. **图形内嵌选项**：`options: list[str]` → `list[{text, figure?}]`，`figure={key,caption,points,edges}`。`text` 恒存在（判题+无障碍，前缀保留保判题比对 ADR-0061 §T）；几何内联（渲染只认 points/edges、零图库依赖、离线）；`key` 仅身份溯源；**不带 kind**（与 `SceneOptionItem` 同形状，演示 kind 取题目级 `scene_spec.kind`）；全-or-无挪到校验层（部分有图→全丢弃）。无 DDL 迁移（同 JSON 列），靠 `normalize_options` tolerant read（`str`→包成对象）+ 判题改 `option_texts`。
4. **触发 AI 返结构化数据**：出题侧本就结构化（TaskSpec + output_schema）→ 加 `options[].figure.key` + 注入清单。答疑侧替换 `_interactive_scene_for` 为**结构化微调用** `SceneIntent{figure_key}`（复用 `provider.stream(..., schema=)`+`StructuredDone` 模式）：门控（有 KP 上下文 **或** 轴对称类意图关键词）→ 注入目录 → 模型选 key → 校验盖章 → `data_event(type='interactive_scene')`。⚠️ **门控关键词只决定"要不要问模型"，绝不决定给哪个图形**（与旧图形反猜的本质区别）。未命中/异常→不发射且正文照常。

## ADR-0089 v3（用户两项优化指令）

- 产出：`0089-scene-aware-ai-generation.md` + `0089-spec.md` 均重写为 v3；CONTEXT.md 术语「选项图形」→**图形 (Figure)**、「场景意图判定」「答疑知识点解析」三条同步改。
- 指令1 **`OptionFigure` → `Figure`**（理由：图形不只用于选择题，**只与渲染有关**）。实证支撑：前端早有通用模型 `FigureShape`(`shared/domain/figures.dart:23`，注释即「画廊/画板/编辑器/选项组共用」) → 后端叫 OptionFigure 是与前端的概念错位。落点：`app/domain/figures.py`（纯数据、与前端 `shared/domain/` 对称）；字段 `caption`→**`label`**（对齐图库行 `figure_library.label` 与前端）；`Figure` = **SceneSpec 的几何子集**（`SceneSpec = kind 外壳 + 一个主 Figure`）；前端**零新增类型**（复用 `FigureShape`，忽略 `edges`）。模块随之改名 `figure_stamp.py`（原 `scene_options.py`），不并入 `scene_figures.py`(222 行，那是种子+`figure_geometry`，混进去会让改种子的人碰盖章逻辑)。
- 指令2 **AI 如何识别"该不该带交互图形"** → 定为**三层**：L0 确定性门控(解析出知识点 + 能投影出非空目录) → L1 `SceneIntent{should_show,figure_key,rationale}` 微调用 → L2 后端校验盖章。**模型有建议权无决定权**。粒度分工：**知识点级**由数据答(`kp.scenes`)，**提问级**由模型答。
- ⚠️ **v3 删掉了 v2 的"意图关键词门控"**：关键词仍是猜，且与"后端不再从文本猜"自相矛盾；`kp.scenes` 是教师显式配置、更强且零成本的信号。另加：prompt 必给**反例**；`should_show` 与 `figure_key` 冲突取保守；连续同 key 去重；kind 不由模型输出(首版恒 reflection)。
- 新增护栏类型 `FigureRef{key,label}`：目录条目**不是** `Figure`——类型层面保证顶点进不了 prompt。
