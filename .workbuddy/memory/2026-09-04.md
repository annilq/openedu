- 事实核对：项目 Genkit 只做 4 件事——`ai.generate/generate_stream`+`output_schema`、`@ai.flow`+`ctx.send_chunk`(ADR-0017 SSE 信封)、`genkit_fastapi.handle_genkit_request`(原生端点，前端 genkit client.dart 直连)、`resolve_engine` 多模型解析。多 agent 层（ADR-0021）是纯 Python，与 Genkit 解耦。
- 装的是 genkit 0.10.0（pyproject `>=0.10.0`），PyPI 最新 0.11.0（2026-09-03 发布）。0.10 已具备：`ai.define_agent`(model/system/tools/max_turns/state_schema)、`define_custom_agent`(自写 turn loop)、`define_prompt_agent`；`genkit.agent` 下 Session/SessionStore(InMemory,File)/Snapshot/DetachedTask/AgentInterrupt/AgentClient；`genkit_fastapi.serve_agent`；`_transports/_http.py` 的 `remote_agent`+`HttpAgentTransport`；tools 支持任意 async 函数(`@ai.tool`/`define_tool`/`tool()`)+`Interrupt`/`restart_tool`/`respond_to_interrupt`。
- 缺口（决定不用它做编排）：① 无 supervisor/handoff/路由原语，多 agent 组合只能手写 agent-as-tool 或 asyncio ② 无并发扇出原语（gather/超时/部分失败回退自己写）③ `define_agent` 的 model 定义期绑定，与本项目"每次请求按家长选模型动态解析"(resolve_engine) 冲突，动态只能走 `define_custom_agent` ④ mock 零 key 闭环会被破坏（agent turn loop 强制真实模型，mock 需 `ai.define_model` 造假插件，成本高于现有 `_mock_question/_mock_tutor_text` 分支）⑤ 0.x Beta + Python 侧落后 JS 侧，编排核心绑定风险高。
- 0.11.0 release notes 无任何 multi-agent/supervisor/A2A 内容（只有 generate 不再抛异常、Veo 后台任务、provider 错误统一为 GenkitError、typed model refs、Dev UI 日志）。
- 结论（分层）：编排层继续纯 Python（ADR-0021 方向正确）；只有需要「多轮会话 + 中断恢复 + 长任务」的统一 AI 助手入口，才用 `define_custom_agent` + `serve_agent` 白拿 session/abort/detached/Dev UI trace。安全与配额绝不从路由层下沉进 agent（agent 自主循环会绕过配额）。
- ⚠️ 升级 0.11 的 breaking change：`generate()` 模型已回复后不再抛异常，`resp.output` 可能为 None（schema 不匹配/安全拒绝/超 max turns 分别对应 failed/blocked/aborted）。`app/ai/flows.py` 的 `generate_question`/`grade_open` 依赖 try/except 回退 mock，升级必须改为判断 `output is None` 分支。
