## 密钥止血 + 模型来源单点化（ADR-0038 收尾 / ADR-0039）

承接昨日 401 事故（密文当 API Key 外发）的**用户侧收尾动作**，并按其要求做两处收敛。

### 1. 密钥止血（当日完成并验证）

- `backend/.env` 显式写入随机 `MODEL_APIKEY_SECRET`（48 字节 urlsafe）。此前该值为空 → Fernet 密钥由 `SECRET_KEY` 派生 → `SECRET_KEY` 一漂，全部密文失效。
- **重加密 DB**：`ModelConfig` 唯一那行先用旧密钥 `dev-secret-change-me` 解出明文，与 `backend/.env` 的 `DEEPSEEK_API_KEY` 交叉校验一致（len=35, tail `f474`），再用新密钥重新加密写回。新密文尾号 `YnZfH__J`；旧默认密钥 `changeme` 已解不开新密文。
- 端到端复验（新进程读 `backend/.env`）：`decrypt` 出明文、`resolve_engine` 传出 `api_key` len=35 tail=f474、密文未外泄、`openai_compat/deepseek-v4-flash` 解析成功。
- **`env_file` 改为 CWD 无关**（`app/core/config.py`）：原 `("../.env", ".env")` 是相对路径，在仓库根起服读不到 `backend/.env` → 密钥静默回落默认值，与事故同一失效模式。现按 `__file__` 解析绝对路径，实测在仓库根 / `backend/` / `/tmp` 三种 CWD 下均正确加载。

## 附：查询助手「原始工具调用协议泄露」修复（当日追加，未 commit）

用户报「AI 学习助手查询任务时得到乱码消息」——剪切板实为**模型原始输出**：内部思考链 + 未解析的 `<invoke name="list_parent_tasks">` 伪协议，被当成答案回流给了用户。

### 定位过程（真接口实测定案）

- 通读链路：`assistant/service.py`（`rt.run()` → SSE 帧）→ `agent_core/subagent.py#run_with_tools` → `agent_core/adapters/genkit.py`（`return_tool_requests=True`）。
- 前端排除：`assistant_message_list.dart` 把 THINKING 渲成「思考中…」转圈，`ai_text_fold.dart:49` 对 THINKING **直接忽略**，`stream_reasoning_panel.dart` 只用于出题路径 → 用户看到的原文**必然是 `ASSISTANT_MESSAGE`（最终答案）**，不是思考面板。
- genkit 侧排除「工具没下发」：`genkit_openai/models/model.py:263-264` 确实写 `openai_config['tools']`，`:350-366` 确实解析原生 `tool_calls`；`get_default_openai_model_info` 对未知 openai_compat 模型返回 `Supports(multiturn=True)`（`tools` 未设，非 False），且 `genkit/_ai/_generate.py:1143-1144` 的 TODO 表明**尚未实现按 `supports.tools` 拦截** → tools 是下发的。
- **真接口实测（决定性）**：用 `backend/.venv` 直连 `deepseek-v4-flash` 带工具打一次，返回 **`TOOL_REQUEST name=list_parent_tasks input={'status':'assigned'}`** → 默认模型原生 FC 正常，**不会**触发该路径。
- 结论：泄露来自**另一类把工具调用写成文本/XML 的模型**（本地 Ollama 或中转/网关模型）。对它 `_extract_tool_calls` 取不到 `ToolRequest` → 无 `ToolCall` 事件 → `acc` 被当答案。

### 修复（`backend/agent_core/subagent.py`，ADR-0033 补充已记录）

- 工具型 subagent 某轮无原生 `ToolCall` 但命中 → `ERROR(code="TOOL_UNSUPPORTED")` 硬失败，不再把原始协议当答案（ADR-0033「硬失败不降级」的正确兜底）。
- **思考也缓冲**：`turn_thinking` 累积本轮 `TextDelta`，**轮次结束再决定冲刷**（`:193,219,267,286`）——命中泄露则整段丢弃。旧实现边收边 yield thinking，协议仍会混在 THINKING 帧里流出（前端虽不显示，SSE 流不干净）。
- 反向不变量：无协议标记的普通文本收尾照常作答案，不误伤。

### 验证判据

- `ruff check .` → All checks passed。
- `pytest -q` 全量 → **308 passed, 2 skipped**（较 ADR-0039 时点 +2，即本轮两个防护用例）。
- 新增用例：`test_text_tool_call_protocol_is_not_leaked_as_answer`（断言无 ASSISTANT_MESSAGE、无 THINKING 泄露、码为 TOOL_UNSUPPORTED）、`test_plain_text_answer_without_protocol_marker_passes_through`。

- 该防护是**文本启发式**：若模型把调用写得毫无协议标记（纯自然语言「我去查一下」），仍会当普通回答流出——只是不含内部协议，泄露危害已消除；要根治须靠模型侧支持原生 FC。

## 附二：任务查询「status 必填」真实根因 = genkit 的 OpenAI strict 改写（ADR-0040）

用户报「查任务时模型反复重试 status 并最终把调用写成文本」，并判断「大概是没传任务状态，需把 status 改成非必填，不传就查全部」。

### 结论：用户的直觉方向对，但归因错了

**`status` 源码里本来就是可选**（`list_parent_tasks.py`：`"required": []`，描述写「不传＝全部」；handler `if status is not None and status not in TASK_STATUSES`）。改它**不产生任何 wire 变化**——真正决定必填的是 genkit 发包前的加工。

### 根因链（逐环有证据）

1. `genkit_openai/models/model.py#_get_tools_definition`（第 88-120 行）对**每个**工具无条件执行
   `_ensure_strict_json_schema(parameters, ...)` 并打 `'strict': True`。
2. `openai/lib/_pydantic.py#_ensure_strict_json_schema` 第 55-57 行：
   `json_schema["required"] = [prop for prop in properties.keys()]` —— **全部 property 变必填**，
   另加 `additionalProperties: False`。我们写的 `"required": []` 在 wire 上不存在。
3. **真接口实测**（用 `.venv` 直连 `deepseek-v4-flash`，原样下发 7 个工具 + `query_sop.md`）：
   - 非 strict schema → 模型**不传 status**（`list_parent_tasks args={}`）；
   - 复刻 strict 后的 schema → 模型被逼填 `{"child_id": "", "child_name": "", "status": ""}`。
4. `status=""` 既非 `None` 也不在 `["draft","assigned","done"]` 内 → handler 回灌
   `status 只能是 [...] 之一，收到：''` —— **正是模型引用的那句报错**（它说「status null failed /
   schema says required」不是臆断，是照 wire schema 说的）。
5. 模型因此反复试探（省略→仍必填→空串→还错→null→还错）→ 撞 SOP「不重复调用同一个工具凑结果」
   → **空转并把调用叙述进文本**（上一节已修的泄露路径）。

**同类陷阱**：`list_wrong_questions.limit` / `list_due_reviews.limit`（`integer`，strict 下必填）——
模型只能自己编个数字 → **静默截断结果**（200 道错题只说 20 道），或填 `0` → 撞「limit 必须大于 0」。

排除项：genkit 不校验入参（`_core/_action.py:499-500`，input_schema 为 dict 时 `_input_type=None`）；
工具 schema 确实下发了（`model.py:263-264`）。

### 修复（ADR-0040）

- `_shared.py` 新增 `UNSET_TOKENS` / `NO_FILTER="all"` / `optional_str()` / `optional_int()`；
  **归一收口在 `resolve_children`**（全部定位工具的公用入口）→ 7 个工具一次性受益，不逐工具打补丁。
- `list_parent_tasks.status` 的 `enum` 改为 `["all","draft","assigned","done"]`，描述「不过滤时传 all 或空字符串」。
- `limit` 描述改「0 或空＝不限」；`optional_int` 把 `0`/空 → `None`，负数报错。
- 定位参数描述改为「不指定时传空字符串」，模型不必猜。
- 契约测试 +4（`test_query_tools_contract.py`）：证据锚点（strict 确实把 required 改写为全量）、
  枚举必含 `NO_FILTER`、**行为级**「缺席编码填满 ≡ 不传」、非法值仍报错。
- 文档：新增 `docs/adr/0040-tool-schema-strict-mode-absent-encodings.md`；AGENTS.md 加「工具 schema 硬规则」并更新 ADR 索引至 0040。

### 验证判据

- `ruff check .` → All checks passed；全量 `pytest -q` → **312 passed, 2 skipped**（+4）。
- **守卫自证有效**：临时回退 handler 的归一行后跑契约测试 → 1 failed（`status 只能是 [...] 之一，收到：'all'`），恢复后全绿。
- **真接口复验**：改后 schema 下模型填 `status: "all"`（合法枚举 + 显式不过滤），handler 归一到 None → 不再报错。
- 编译期不变量：`_shared.py` 顶部注释 + ADR 记录了「新工具忘加缺席编码会被测试拦下」。

### 遗留

- 本约定依赖 `openai.lib._pydantic` 这个**私有 API** 的 strict 行为；升级 genkit / openai 时证据锚点测试会先失败。
- `strict: True` 下模型仍无法传未知字段；`tool_choice='none'`（出现 tool 消息后强制文本收尾）未动。
- `"all"` 成为保留词（被归一为缺席），不能当真实学科名/状态值用。

## 附三：草稿任务查询「child_id 不是合法的 uuid：'null'」（ADR-0040 第二例）

用户报「查询草稿任务时提示查询失败：child_id 不是合法的 uuid：'null'」，并提议两个方案：
① 把客户端当前切换的 `child_id` 传过去；② 娃娃登录时直接用登录的 `child_id`。

### 根因：与 status 同一机制，只是缺席值被**文本化**了

模型对「没有目标娃娃」的表达是**字符串** `"null"`（不是 JSON `null`——那样报的是 `'None'`）：

```json
{"child_id": "null", "child_name": "", "status": "draft"}
```

旧 handler `str(child_id).strip()` 对 `"null"` 为真 → 送去 `_as_uuid` → 抛
`child_id 不是合法的 uuid：'null'` → 模型再试一轮。**strict 强制填值**是同一个前提（附二）。

### 两条建议的结论

- **② 已是现状，无需改动**：`extra["child_id"]` 由端点从 JWT 写入
  （`assistant/service.py:85-90`，child → `caller.user.id`，parent → `None`），**客户端传不进来**；
  `resolve_children` 在孩子分支直接 `return [own]`、**忽略入参**。`AssistantChatReq` 里也没有
  `child_id` 字段（MEMORY.md「业务字段不要前端预填」）。
- **① 不做**：故障不是缺上下文，是 strict 强制填值；且多一个客户端可控定位字段=新攻击面。
  若真要「家长在看哪个娃就默认查哪个娃」，正确形态是 `AssistantChatReq.focusChildId`
  → 服务端校验归属后写 `extra["focus_child_id"]` → 工具层仅在家長未显式指定时采用。
  已写进 ADR-0040「明确不做」段，将来要做请单独立 ADR。

### 修复

- `UNSET_TOKENS` 扩到各语言口径的文本化缺席：
  `{"", "all", "any", "*", "none", "null", "nil", "undefined", "unset", "n/a", "na"}`。
- `_as_uuid` 增加 `hint` 参数；`child_id` 的报错追加「按昵称定位请改用 child_name；不指定目标请留空」
  —— **回灌给模型的错误必须带可执行出路**，否则它只能换个猜法重试。
- 契约测试 +18（两条 parametrize，各 9 个缺席值）：`child_id` / `child_name` 的文本化缺席
  必须等价于「不指定」，且草稿仍进 `unassigned_items`；并在
  `test_absent_normalization_does_not_weaken_real_validation` 里补 `child_id="abc"` 仍报错。

### 验证判据

- `ruff check .` → All checks passed；全量 `pytest -q` → **330 passed, 2 skipped**（+18）。
- **守卫自证**：临时把 `"null"` 从 `UNSET_TOKENS` 抽掉 → 测试复现原话
  `child_id 不是合法的 uuid：'null'（按昵称定位请改用 child_name；不指定目标请留空）`；恢复后全绿。
- **真接口复验**（strict wire schema）：问「有哪些草稿任务？」→
  模型传 `{"child_id": "", "child_name": "", "status": "draft"}` —— `""` 与 `draft` 都合法，
  草稿路径通。
- 注意：归一有**两处**（handler 里为算 `explicit_target`、`resolve_children` 里为 7 个工具统一收口），
  幂等、无害；只测其中一处不会暴露问题，验证时要动 `UNSET_TOKENS` 这类真机制。

### 遗留

- 同 ADR-0040：依赖 `openai.lib._pydantic` 私有 API 的 strict 行为，升级时证据锚点测试先失败。
