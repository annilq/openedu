## 助手 4 个 subagent / 路由实态核查（用户问询）

- **`decide` 是三级路由，非文档写的「两级」**：① `match_action`（router.py:43 等值匹配 manifest.actions）② `classify` 的 `_rule_match`(triggers) ③ `_heuristic`(hints)→兜底 priority 最低者。①②两级仅当 `signal.action` 为空/未知时才跑；带动作键的请求直接走①级。
- **`_build_intent_signal`（service.py:403）是承重墙，全仓仅 `chat()` 一处调用（service.py:513）**：产出 `quiz_judge`(pending_quiz) / `quiz_generate`(req.quiz) / `courseware_hint`(courseware+「提示」) / 透传 req.action。这些靠上下文判定、无文本触发词，删它会瘫痪 quiz 闭环与课件提示路由。
- **`guide` 是伪·AI 子代理**：不跑 LLM、不持工具，只产出受控跳转卡（去发布任务/看题库）；其存在唯一理由是 `priority=20` 把写意图「创建任务」从只读 `query`(p12, triggers 含「任务/作业」) 手里抢回。认知上应视为「高优先级导航路由规则」而非 AI 能力。`query`/`question`/`tutor` 三者能力正交（读状态/造内容/做讲解），粒度恰当。
- **`courseware` 上下文实为知识点聚焦**：前端 `AssistantCoursewareContext` 字段仅 coursewareId/knowledgePoint/knowledgePointId/subject/grade/semester（ADR-0086 已删 sectionId）。后端真正消费点仅两处——`courseware is not None`+「提示」→`courseware_hint` 路由（service.py:431）、tutor 拿 subject/grade/knowledge_point 做讲解聚焦（tutor/agent.py:120-130）。`courseware_id` 字段已死（前端不再下发、无任何逻辑依赖，只拼进文案「课件：xxx」）。用户建议改为「知识点上下文」语义更准确，但属跨前后端重构（字段名+动作键 `courseware_hint`→`knowledge_point_hint`+契约测试），需新建 ADR 追认。

## ADR-0089 场景感知 AI 出题/答疑（grill-with-docs + architect 定稿）

- 产出：`docs/adr/0089-scene-aware-ai-generation.md`（决策+类型签名+模块边界+否决候选）+ `docs/adr/0089-spec.md`（8 票 T01–T08 依赖序）；CONTEXT.md 术语扩 5 条（图形几何库/选项图形/结构化图形发射/场景感知出题/答疑知识点解析）。取号 0089（目录最大 0088 且 git 仅有 0088 未跟踪，memory 无预留）。
- **实证（关键，别再推断）**：`extract_option_group`（scene_extract.py:85）把**文字选项**正则匹配 figure_library key → `optionGroup.items`；`SceneInterpreter`（scene_interpreter.dart:65）已渲染成带 A/B/C/D 角标的图形画廊，且明确「零图库依赖」只吃 `points/edges`（同文件 139）。→ **「选项渲染成平面图形」前端早就通了**；坏的是生产路径（靠模型写出标准中文图形词才命中 + 全-or-无 → 命中率极低）。故本 ADR 是**减法**：不新增列、不改渲染契约。
- **纠正一处易错表述**：用户说的「出题先查场景库」≠ 查 `SCENE_LIBRARY` 注册表（那是作者辅助库，ADR-0073 红线：渲染/生成永不回查）。生成语境的「查场景」= 读 `kp.scenes`，入口 `resolve_kp_scene`(scene_fusion.py:42) / `build_scene_spec_for_question`(:257)。
- **figure_library 不删**（用户问过）：角色从「文本匹配目标」收敛为「几何权威源 + 创作 UI 数据源」（ADR-0083 单源不变）。删的是对它的误用方式。
- 核心决策：结构化图形发射 —— prompt 只注入 `key+中文名`（**顶点不进 prompt**，防模型编坐标）→ 模型每选项引用 key → 后端校验 ∈ 允许集并按 key 从图库盖章取几何 → 落 `scene_spec.optionGroup`（既有 JSON 快照列，**零迁移**）。全-or-无沿用。`extract_option_group` 降为存量老题兼容回退（不删）。新增可选 `figureKey`（画廊现拿 caption 当身份键不稳，scene_interpreter.dart:220）。
- grill 定档：①渲染只认 sceneSpec+{points,edges}、不依赖文本抽取 ②问答侧走**开放语义检索命中 KP** ③几何由后端给 key+sceneSpec ④**首版先做 AI 出题闭环**（答疑为 Phase 2/T07）。
- Phase 2 补 ADR-0073 缺口：`resolve_question_kp`（KP 名关键词精确 > 资料片段检索→KP 名）+ 命中且 `scenes` 非空才 emit `interactive_scene`；未命中绝不发射（反臆造）。前端卡槽已就绪、零改动。
- 否决候选记档：结构化 option 对象 `options:[{text,figure?}]`（破坏面过大，几何属渲染关切不该混进内容模型）；纯文字+扩词表（仍是猜）；模型自由输出顶点（必然错）。

### 演示视频（submission_docs/final_demo.mp4）用法裁定

- 实测（ffprobe）：**4:22（261.8s）、954×1006 近正方、h264+aac、30fps、17.5MB**；14 段带配音+烧录字幕的产品演示成片（`narration.md` 是旁白稿，`subs/all.srt` 是字幕，raw/out/voice/subs 分目录）。
- **小红书机制（已核实）**：支持「**1 段视频 + 最多 8 张图片**」混排（App 端；网页端不支持传视频）；时长 1s–15min 建议 10s–5min；**>3 分钟自动开启进度条+倍速(0.5–2.0x)**；建议 1080×1920 竖屏/1920×1080 横屏；⚠️**发布后不能替换原视频**（只能改文字/标签/封面/可见范围）→ 一次做对。
- **裁定：不要整片发**，三不匹配 —— 比例近正方（非竖屏吃亏）、4:22 超 3 分钟（开倍速→完播率崩）、**带包装配音 =「产品在介绍自己」，与人设 A「老师讲自己怎么用」冲突 → 广告感+限流**。
- **正确用法（已写入策略文档 §8）**：混排笔记**封面可指定静态图** → ①封面=新孟菲斯卡片（保点击率+九宫格统一）②第2张=15–45s 视频片段（吃曝光红利）③第3张起=打码截图 ④可抄清单冲收藏。
- 片段对应（时间为 narration **规划稿**，成片实测 4:22 ≠ 规划 5:08，**发布前必须 ffprobe 重新对齐**）：出题=第8段(3:04–3:43,30–40s)、资料库知识点=第4段(1:15–1:43,25s)、问AI老师=第12段(4:45–5:08,20s)、学生作答=9–10段(3:43–4:28,20s)、复习错题本=10–11段(4:06–4:45,30s)。
- 比例处理：**裁 3:4 而非 9:16**（9:16 要砍 40% 横向内容，界面看不清）：`ffmpeg -i final_demo.mp4 -ss 00:03:04 -t 40 -vf "crop=754:1006:100:0,scale=1080:1440" -c:v libx264 -crf 20 -c:a aac -b:a 128k -r 30 out.mp4`
- **更优于剪片**：手机竖屏重录 15–60s + 真人语音、零包装（「随手录的」比「精心包装的」更像真人，也更贴人设 A）。完整 4:22 版 → B 站（方案里 B 站定位就是 10 分钟实操录屏）/知乎嵌。
