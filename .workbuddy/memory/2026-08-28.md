## 排错：点击「添加娃娃」报 404
- 现象：前端家长端进入 HomeScreen 即 `GET /api/v1/children` 返回 404（stale uvicorn 进程未加载 children 路由）。
- 诊断：当前代码 `children` 路由完全正常——用 TestClient 跑通「注册家长→登录→GET/POST children」全链路（200/201）；`UserCreate` 仅要求 username/display_name/password，grade 可选，无 email 必填，与前端 `children_remote_data_source.createChild` 字段一致，POST 不会 422。
- 根因：运行中的 uvicorn（PID 98515/98517，:8000）是旧进程；`app/main.py` 后续改过（`include_router(children.router)`）且未重载。进程重载后线上已返回 401（路由存在、需登录）。
- 处置：顺手消除日志里 `StarletteDeprecationWarning`——`app/core/errors.py` 5 处 `HTTP_422_UNPROCESSABLE_ENTITY` 改为 `HTTP_422_UNPROCESSABLE_CONTENT`（值同为 422，`-W error::DeprecationWarning` 下 import 已干净）；另：`SECRET_KEY` 仅 20 字节触发 `InsecureKeyLengthWarning`，属 dev 噪声（改密钥会使旧 token 失效，未动）。
- 经验：再遇 backend 接口 404，先确认运行进程是否已重载最新代码（curl openapi.json 看 paths），而非代码 bug。

## 产品闭环分析：题库「只写不读」
- 现象：后端支持「逐题加入题库 / 一键加入题库 / 锁定自动入库」(`promote_one`/`promote_all`/`confirm` 自动 promote)，但题目入 `Question` 表后客户端无法再使用。
- 根因（代码事实）：① crud.py 无任何"列出题库"函数；② routes 无 `GET /questions`；③ `batch-generate` 永远只现出模型题，无"从题库选 question_ids 组卷"入口；④ 前端 `lib/features` 无 题库 页面，`parent_task_form_view` 仅 AI 生成一种组卷方式。即 `Question` 表为「写死库」。
- ADR-0004 D2 本意是 `Question` 即题库层「可跨 Task 复用」，读取/复用侧从未落地。
- 闭环方案（待确认）：新增 `GET /questions`（parent 作用域、subject/grade/kp/qtype/keyword 过滤+分页）+ `POST /tasks/from-bank {title,child_id,question_ids[]}`（把 Question 深拷贝为 TaskQuestion 并回填 question_id 实现复用）；前端家长端侧边栏加「题库」入口 + 列表多选 + 「用这些题生成任务」→ 落到现有 draft 审核页，复用 lock/assign/practice 全流程。🔴 数据模型缺口：`Question` 无 `parent_id`，题库当前全局共享（单家庭 MVP 可接受，多租户需补 owner 作用域）。

## 排错：登录报 401（POST /api/v1/auth/login）
- 用户疑「参数格式/协议不对」。实测排除：前端 `auth_remote_data_source.login` 发 JSON `{username,password}`，后端 `login(credentials: LoginRequest)` 正是 Pydantic JSON 体；格式错会 422，401 说明 JSON 已正确解析。
- 401 唯一来源：`auth.py:36` `authenticate()` 返回 None = 用户名查不到 OR 密码 argon2 校验不过（并非「格式问题」）。
- 验证链路：① 真实库 `app.db`（含 testp/testp2，argon2id 哈希）下新账号正确密码 `authenticate`→OK、错误密码→None；② 旧 testp 哈希当前库可解析（排除 pwdlib/argon2-cffi 升级致旧哈希验不过，版本 pwdlib 0.3.1 / argon2-cffi 25.1.0 / bcrypt 5.0.0）；③ 对运行 :8000 注册探针账号后出现在 `backend/app.db` → 运行服务用的就是同一库（DB 没被换走）。
- 结论：backend 登录管线 + 库 + argon2 全部健康；用户 401 = 提交凭证在 app.db 不匹配。隐性陷阱：`User.username` 大小写敏感（`where(User.username==X)`），`TestP`≠`testp`。
- 经验：login 401 ≠ 协议/格式问题，是凭证不匹配；先核对库内用户名是否存在与大小写、再核对密码。

## 排错：题库视图 ChoiceChip 崩「No Material widget found」
- 运行时异常：`ChoiceChip`（及同页 `Checkbox`/`InkWell`）构建抛 `No Material widget found`。
- 根因：`DesktopShell` 的 body 直接是 `Container`，不提供 `Material` 祖先；`HomeScreen` 用 `DesktopShell` 承载各家长视图，无 `Scaffold`/`Card` 包裹。`analyze` 静态检查不报此错（仅运行时断言）。
- 修复：`ParentQuestionBankView.build` 根 `Column` 外包 `Material(type: MaterialType.transparency)`（透明不覆盖底色，同时为 Material 组件提供祖先）。`flutter analyze` 复跑 0 问题。
- 经验：`DesktopShell` 容器内凡用 Material 组件（ChoiceChip/Checkbox/InkWell/TextField 等）的家长视图，需自行保证有 `Material` 祖先；此类错误静态分析查不出，靠运行时。

## 重构：题库视图去 Material，改用 shadcn_ui
- 用户要求去掉题库视图内所有 Material 组件，改用 shadcn_ui。
- 替换映射：`ChoiceChip`→`ShadButton`(active 用默认 primary / 非 active 用 `ShadButton.outline`，`ShadButtonSize.sm`)；`Checkbox`+`InkWell`→`ShadCheckbox`+`GestureDetector`；对话框内 `ListTile`→`GestureDetector` 行；移除根 `Material` 包裹；`import 'package:flutter/material.dart'`→`import 'package:flutter/widgets.dart'`。
- 关键 API 事实（shadcn_ui 0.56.1）：主 `ShadButton({...})` 默认 `variant=primary`，**无 `variant` 具名参数**；变体用 `ShadButton.outline/secondary/ghost/link/destructive`；`variant` 仅 `ShadButton.raw({required variant})` 可用。枚举 `ShadButtonVariant`/`ShadButtonSize` 随 `shadcn_ui` 导出。`ShadCheckbox({required bool value, ValueChanged<bool>? onChanged})`。
- `AppTextField`/`AppPickerField` 已是 `ShadInput` 实现，共享组件无需动。
- `flutter analyze` 0 问题；确认全文件无 ChoiceChip/Checkbox/InkWell/ListTile/Material 残留（grep 仅命中 `ShadCheckbox`）。
