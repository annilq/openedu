## 修复 · 布置任务页 ChoiceChip「No Material widget found」
- 报错：`ChoiceChip` 要求 `Material` 祖先，但 App 入口 `ShadApp`（基于 `WidgetsApp`）整树无 `Material`，故抛断言（报错栈 `ChoiceChip → Padding → Row → SingleChildScrollView`）。
- 根因确认：全仓库 `.dart` 源码 grep 无任何 `ChoiceChip`/`FilterChip`/…，报错来自用户本地未保存/其它版本的编辑；但根因（ShadApp 无 Material）是项目级真实约束。
- **方案B 落地**：新建 `frontend/lib/shared/widgets/app_chip.dart`，提供 `AppChip`（选中=`ShadButton`、未选=`ShadButton.outline`，零 Material）与 `AppChipRow`（横向可滚动多选 chip 行），替代「`SingleChildScrollView` + `Row` + `ChoiceChip`」写法。
- **规范固化**：在 `MEMORY.md`「Flutter / shadcn_ui 约定」新增硬规则——本项目**严禁 Material Chip 家族**（`ChoiceChip`/`FilterChip`/`ActionChip`/`InputChip`），改用 `ShadButton`/`ShadButton.outline` 或 `app_chip.dart`，确保后续生成代码不再触发该错误。`Switch`/`IconButton` 不要求 Material 祖先，可正常使用。
- **修正 · 跟进修模 Switch 报错**：用户又报 `_MaterialSwitch: No Material widget found`，定位到 `parent_task_form_view.dart:250` 的 Material `Switch`（「按兴趣出题」开关）；报错栈 `Switch → Row → Column → Column → Flexible` 与 `_buildInterestSection` 完全吻合。已改用 shadcn `ShadSwitch`（`value`/`onChanged`/`checkedTrackColor: app.primary`），`flutter analyze` 通过。**纠正此前误判**：`Switch` 同样需要 `Material` 祖先（内部 `_MaterialSwitch`），并非只有 Chip 家族会炸；`IconButton` 才不要求 Material 祖先。`MEMORY.md` 规则同步修正，并补充 `Checkbox`/`Radio`/`Slider` 等 Material 控件也须改用 shadcn 对应件（`ShadSwitch`/`ShadCheckbox`/…）。

## grill-with-docs · 年级生命周期 ADR-0005（同日）
