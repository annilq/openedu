## 顺手修掉最后一条红灯：fl_chart 护栏**误报**（提交 `2c7a320`）

起因：收尾时我按旧记忆说「5 个前端守卫旧账」，**实际全量跑只剩 1 条红的**（另 4 条
`file_size`×2 / `no_bare_gesture` / `feature_boundaries` R2 已被中间改造消掉，那 5 条是
`a47c53e` 时的口径）。教训：**基线结论要现跑现认，别照抄旧记忆**。

那条红灯也不是业务代码的错，是**护栏自己的 bug**：
`analytics_charts_test.dart` 的裸用探测写成 `src.contains('BarChart(')`，而适配器自己的
类名 `AppBarChart(` / `AppGroupedBarChart(` / `AppStackedBarChart(` 里都**含有**子串
`BarChart(` → **只用适配器**的 `workbench_analysis.dart` / `workbench_glance.dart` 被常年
判红。grep 全量复核：全仓只有 `shared/widgets/analytics_charts.dart` 一个文件 import
fl_chart，业务侧零裸用。

改法：
- 裸用探测改**词边界锚定** `\b(?:Bar|Pie)Chart\(`（`App*Chart(` 里 `BarChart` 前面是字母
  `p`/`t`，无词边界 → 自然排除）。
- import 探测改**引号不敏感** `import\s+['"]package:fl_chart`（本仓未开
  `prefer_single_quotes`，双引号导入合法，原来只认单引号是个绕过口子）。
- 两个探测器抽成顶层 `flChartImporters` / `bareFlChartUsers` + **4 条自测**（适配器类名
  不误报 / 真裸用必抓 / 适配器自身豁免 / import 引号不敏感）。

**通则**：静态护栏**误报比漏报更坑** —— 漏报只少拦一次，误报会把正经代码钉死在红线上、
逼后来者去改本来正确的代码。凡扫源码的字符串匹配都要词边界锚定。

## 错题本页面崩溃修复（`wrong_questions_screen.dart`）

- **症状**：`LayoutBuilder does not support returning intrinsic dimensions` —— `IntrinsicHeight`
  （行 133）包 `_WrongQuestionCard`，卡片内 `SceneInterpreter`（`sceneSpec` 非空时渲染）含
  `LayoutBuilder`（`reflection_figure_gallery.dart:98` / `reflection_scene.dart:448`），
  `IntrinsicHeight` 向子树取 intrinsic 高度触发其拒绝 speculative 计算 → 抛异常。仅带交互讲解的
  错题会崩。
- **修法**：去掉 `IntrinsicHeight` + `Row(stretch)`，把左侧 4px 学科色条改成 `AppCard.listRow` 的
  `border.left`（4px `subjectColor` + 其余三边 1px `scheme.outline`）。边框随卡片自然撑满行高，
  不再需要 intrinsic 计算，冲突消失、色条语义保留。
- 验证：`flutter analyze` 该文件 `No issues found!`。新教训补进 `MEMORY.md` §2（`IntrinsicHeight` +
  `LayoutBuilder` 子树也崩）。

### ⚠️ 上一节「border.left 修法」本身就是今天新崩溃的根因 —— 更正

上一节把学科色条改成 `AppCard.listRow(border: Border(left: subjectColor 4px, 其余三边 outline 1px))`
**绕开了 IntrinsicHeight，却引入了新的白屏**：`AppCard._convertBorder` 把非均匀 `Border` 转成
`ShadBorder` 塞进 `ShadCard`，而 `ShadCard` 内部 `BoxDecoration` 在**已设 borderRadius**时要求四条边同色，
否则 paint 抛 `A borderRadius can only be given on borders with uniform colors`
（`shadcn_ui-0.56.3/lib/src/components/card.dart:206`）。本仓 card 一律带圆角 → 非均匀边框必崩。
用户今天报的「错题本前端爆粗」就是它。

**最终修法**（已落地 `wrong_questions_screen.dart`，`flutter analyze` 该文件 `No issues found!`）：
- 去掉传给 `AppCard` 的非均匀 `Border`，改回 `AppCard.listRow` 默认均匀 1px 墨黑边；
- 学科色条改为卡片内 `Stack` + `Positioned` 左侧 `Container(width:4, color: subjectColor)`，靠
  `ShadCard` 自身 `clipBehavior: Clip.antiAlias` 把色条左缘裁成圆角。
- 同样**不引入 IntrinsicHeight**（避免之前的 SceneInterpreter `LayoutBuilder` 崩溃），两头都避开。

**通则（补进记忆）**：凡要「圆角 + 单边异色描边/色条」，绝不能走 `Border` 非均匀四边——
任何把它喂给 `BoxDecoration(borderRadius:)`（含 `ShadCard`/`AppCard`）的路径都会抛 uniform-color 断言。
正确做法是：要么用 `Border.all` 同色 + 内部 `Container`/色块叠加，要么用 `CustomPaint`/`ShapeBorder`。
`MEMORY.md` §2 的「`Row(stretch)` 须包 `IntrinsicHeight`」旁应补：「非均匀边框不可用于带圆角的
`BoxDecoration`/`ShadCard`」。
