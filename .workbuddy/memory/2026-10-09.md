## 教师工作台图表 UI（第三轮，agent，未提交）

- **用户定位（关键澄清）**：① **速览层**的「活跃错题」chart **被容器截断**（不是 x 轴标签旋转）；② **分析层「掌握度」**文字被截断、并显示 `instan...`（疑 `Instance of '...'`）。
- **① 容器截断根因（已修）**：上一轮为「高度统一」加的 `equalHeight` 用 **`IntrinsicHeight`** 包 Row —— `AppCard` 底层 `ShadCard` 内部是 `Row → Flexible → Column → Flexible`，被 IntrinsicHeight 钉死高度后内部 `Flexible` 会**压缩**内容 → 图表被裁。
  - **修法**：去掉 `IntrinsicHeight`，只靠 `Row(crossAxisAlignment: stretch)` 等高。栅格外层是 `Column`（竖向无界），Row 高度天然等于**最高子项**，stretch 把矮的那一格**拉伸**到该高度——拉伸不压缩，既等高又不裁图表。
  - ⚠️ **教训（长期）**：本项目 `AppCard` 内**禁用 `IntrinsicHeight` 做等高**，其 ShadCard 的 Flexible 链会被钉死约束压掉内容。等高一律走 `Row(stretch)`。
- **② 掌握度标签截断（已修）**：`AppBarChart._BarRow` 标签列由 `SizedBox(width: 128)`（钉死窄列）改为 `Expanded(flex: 5)`，条列 `Expanded(flex: 6)`。标签宽度随卡片自适应（越宽越宽），长知识点名不再被固定窄列截断。
  - ⚠️ 必须用 `Expanded`(tight) 而非 `Flexible`(loose)：loose 会让列宽随内容长短变化 → 各行条形起点参差、失去对齐；tight 保证各行列宽一致。
- **验证**：`analytics_charts` 590（≤ 基线 592）、`responsive_grid` 83、`workbench_glance` 406（持平基线）；4 文件 `flutter analyze` No issues；`workbench_analysis_test` + `workbench_glance_test` 共 4 项全绿。`file_size_guard` 余项失败仍来自并行会话（courseware/app_theme/adaptive_shell/student_management），非本次。
- **待用户提供**：`instan...` 的**完整文本或截图**。当前掌握度卡取的是 `it.knowledgePoint`（`MasteryGroup` 的 `String` 字段），全仓 grep 无硬编码 `Instance of`、无对象插值（`${item}`/`${it}`/`${g}`），代码路径上不该出现该串；需完整串才能定位是哪一类对象被当文本渲染。

## 修复素材库缩略图 / 预览加载失败（agent）
- **根因（双重）**：① 后端 `asset_service.url` 下发的是**带 `/api/v1` 前缀的相对路径**（`/api/v1/courseware/assets/{id}/file`），前端 `Image.network(asset.url)` 没有 host → 解析失败；② 原图端点要求 `CurrentTeacher`（Bearer 鉴权），`Image.network` 默认**不带 `Authorization` 头** → 即使拼了 host 也会被后端 401/403 拒。两者叠加导致缩略图与点击预览都走 `errorBuilder` 显示「加载失败」。

## 课件模块一等化分析（grill-with-docs，已落地 ADR+票据）
- 用户 4 问（新增入口散落/课件信息无编辑/讲解环节只能删不能加/AI 应作辅助）→ 同一根因：课件不是一等模块，是"知识点行进入→AI 代写"的副作用。用 `@skill:grill-with-docs` + AskUserQuestion 对齐 4 岔路 + 2 核实。
- **落盘**：`docs/adr/0078-courseware-first-class-module.md`（状态 提案；取号前查目录最大号 0077→本 ADR=0078）+ `.scratch/courseware-round-3/` 6 张垂直切片票（01 中心新增入口+空壳 / 02 课件信息编辑 / 03 去 kind 化 / 04 手动添加环节 / 05 AI 补充讲解三项回填 / 06 练习内容块）。
- **4 岔路结论**：① 新增入口 = 课件中心主按钮 + 保留知识点行内快捷；② 新建改**空壳**（`create_courseware(draft:False)` 不调 AI），AI 由「AI 补充讲解」显式触发；③ **去掉 kind 类型**（用户拍板：环节内容都是配置选择的，无需类型化）；④ AI 补充 = 基于知识点+用户教学目标，从服务端拿提问/素材/场景三项数据回填真实 id。
- **2 核实（影响方案）**：① `kind` 非结构驱动——`PresentStage` 已"按填了什么渲染"，kind 只影响列表标签/空态文案，去掉安全；② `practice` 环节在 `PresentStage._buildBody` 根本没调用 `SectionPractice`（演示页不可见，潜在 gap），去 kind 后练习内容需新归宿，归 T06 取舍（内容块 vs 暂不支持）；③ 现状 AI 起草只召回教材文本片段当上下文，`materials`/`scene` 留空（service 注释"LLM 当前不生成"），"三项数据回填"尚未实现，需 T05 后端增强。
- **关键约束**：03 是最大改动面（动后端契约 `CoursewareSection.kind` 可选 + diff 匹配键去 kind + 前后端渲染/编辑），须保旧带 kind 课件兼容；未提交，等用户确认后实施。
