## 根导航栈 `_history.isNotEmpty` 断言修复（非 push 页禁裸 pop）
- **现象**：`NavigatorState.build` 抛 `_history.isNotEmpty`（白屏后重建撞断言）。根因＝根栈最后一条（home）被弹空。
- **审计结论**：全仓导航出口已守纪律（maybePop / 注入回调 / 对话框 `ctx`）。剩两处真·硬 pop 隐患：
  ① `shared/widgets/app_dialog.dart` 的 alert/confirm 按钮闭包捕获**调用方 `context`** 去 `pop()`，
     而非对话框路由自身的 `ctx`——若调用方 context 的就近 Navigator 是根栈，弹错栈。已改为
     `builder: (ctx) => ... Navigator.of(ctx).pop()`（用对话框自己的路由）。
  ② `home_screen.dart:78` PracticeScreen `onDone` 闭包捕获 HomeScreen `context` 做**硬 `pop()`**；
     若练习路由已被其他方式先移除，再 pop 会弹空根栈。改为 `maybePop()`（练习在栈顶则弹它本身，否则 no-op）。
  `model_form_dialog.dart` 的 pop 因在 `showShadDialog` builder 内、context 即对话框路由，安全，未改。
- **守卫**：新增 `test/app_dialog_root_guard_test.dart`（alert/confirm 取消+确认，单路由壳断言占位存活），
  沿用 `review_tab_exit_test` 模式。修后全仓已无「能把根栈弹空」的硬 pop。
- **验证**：`flutter analyze` 两文件 No issues found!；`flutter test app_dialog_root_guard_test + review_tab_exit_test` 5 项全绿。

## Riverpod 构建期改 provider 断言修复（`ParentTaskFormView`）
- **现象**：`Tried to modify a provider while the widget tree was building`，栈顶 `parent_task_form_view.dart:105`
  `_ParentTaskFormViewState.initState` 给 `taskFormPrefillProvider.notifier.state = null`。
- **根因**：Riverpod 禁止在 `initState`/`build` 等生命周期同步改 provider（`_debugCanModifyProviders`）。该清空动作本应延后。
- **修法**：把赋值包进 `Future.microtask(() { if (mounted) ...state = null; })`，与同文件第 108 行
  `modelsNotifierProvider.load()` 的延迟写法一致；`mounted` 守卫防表单恰在本帧卸载后操作已释放的 `ref`。
- **同类排查**：全仓其余 `notifier).state =` 均在按钮回调 / auth 状态回调里（`mastery_board.dart:92` 的 onGenerate、
  `app.dart:57/81/92`），非构建期，安全，未改。
- **验证**：`flutter analyze` 该文件 No issues found!

## 意图路由漏词修复（方案 1 落地）
- **改动** `backend/app/ai/subagents/query/manifest.py`：triggers 在「我的错题」后新增
  `"错了哪些" "做错了哪些" "哪些题错了" "错过的题"` 四个精确短语（带「哪些/错过」）。
  刻意**不加裸「错/做错」**，避免把「这道题我哪里做错了」这类伴学问句从 tutor 抢到 query（守
  `tests/ai/test_query_subagent.py::test_tutor_intent_unaffected` 与 ADR-0024/0030）。
- **回归测试** `tests/ai/test_query_subagent.py` 新增 `test_wrong_question_phrasing_goes_to_query_not_tutor`：
  断言「我错了哪些题 / 我错过的题 / 做错了哪些题」→ query（parent），伴学句仍 → tutor，
  **娃娃端**「我错了哪些题」→ query（查自己错题，ADR-008）。
- **验证**：`pytest tests/ai/test_query_subagent.py` 全 18 项绿；ruff check 改动文件 All passed。
- **根因回顾**：路由是字面子串包含匹配（`agent_core/router.py`），「我错了哪些题」因「错」「了」断开
  「错题」、且「哪些题」≠「有哪些题」而不命中，落 priority −10 的 tutor（无取数工具）→ 上轮那个 bug。
  本修零成本、零延迟、100% 确定，优于引入 laya/LLM 兜底。

## laya 方案评估（https://github.com/NandhaKishorM/laya，LLM 决策引擎）
- **结论**：本机**能运行**但**不适合本项目意图路由**。
- 实证 `pip install --dry-run laya` 在 macOS arm64 + py3.13 解析通过（laya-0.3.5 /
  torch-2.14.0 / transformers-5.17.0 的 macosx_11_0_arm64 wheel 齐全，未编译）；Apple M4 + Metal
  可 `device="mps"`；16GB 内存够；首次需联网拉 ~1–2GB 权重。
- **不适用原因**：① base checkpoint 在 typed-decisions zero-shot 仅 0.362（随机 0.318、多数类 0.461），
  README 的 0.766 是微调在 benchmark 自有训练集上的——开箱近乎随机，须针对 4 类中文意图微调才有用；
  ② 中文 base 弱（MASSIVE 13 语言 0.451）；③ 与「确定性优先」路由哲学冲突；④ 后端常驻 421M 权重
  违背「轻量、模型在客户端可插拔（resolve_engine）」架构。定位应是「未来意图 >10 类规则维护不住时的
  本地软分类兜底」，且只作第三层、不替换规则。
