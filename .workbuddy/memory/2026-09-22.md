## 意图路由漏词修复（方案 1 落地）
- **改动** `backend/app/ai/subagents/query/manifest.py`：triggers 在「我的错题」后新增
  `"错了哪些" "做错了哪些" "哪些题错了" "错过的题"` 四个精确短语（带「哪些/错过」）。
  刻意**不加裸「错/做错」**，避免把「这道题我哪里做错了」这类伴学问句从 tutor 抢到 query（守
  `tests/ai/test_query_subagent.py::test_tutor_intent_unaffected` 与 ADR-0024/0030）。
- **回归测试** `tests/ai/test_query_subagent.py` 新增 `test_wrong_question_phrasing_goes_to_query_not_tutor`：
  断言「我错了哪些题 / 我错过的题 / 做错了哪些题」→ query（parent），伴学句仍 → tutor，
  **娃娃端**「我错了哪些题」→ query（查自己错题，ADR-008）。
- **验证**：`pytest tests/ai/test_query_subagent.py` 全 18 项绿；ruff check 改动文件 All passed。
- **根因回顾**：路由是字面子串包含匹配（`agent_core/router.py`），「我错了哪些题」因「错」「了」断开
  「错题」、且「哪些题」≠「有哪些题」而不命中，落 priority −10 的 tutor（无取数工具）→ 上轮那个 bug。
  本修零成本、零延迟、100% 确定，优于引入 laya/LLM 兜底。

## laya 方案评估（https://github.com/NandhaKishorM/laya，LLM 决策引擎）
- **结论**：本机**能运行**但**不适合本项目意图路由**。
- 实证 `pip install --dry-run laya` 在 macOS arm64 + py3.13 解析通过（laya-0.3.5 /
  torch-2.14.0 / transformers-5.17.0 的 macosx_11_0_arm64 wheel 齐全，未编译）；Apple M4 + Metal
  可 `device="mps"`；16GB 内存够；首次需联网拉 ~1–2GB 权重。
- **不适用原因**：① base checkpoint 在 typed-decisions zero-shot 仅 0.362（随机 0.318、多数类 0.461），
  README 的 0.766 是微调在 benchmark 自有训练集上的——开箱近乎随机，须针对 4 类中文意图微调才有用；
  ② 中文 base 弱（MASSIVE 13 语言 0.451）；③ 与「确定性优先」路由哲学冲突；④ 后端常驻 421M 权重
  违背「轻量、模型在客户端可插拔（resolve_engine）」架构。定位应是「未来意图 >10 类规则维护不住时的
  本地软分类兜底」，且只作第三层、不替换规则。

## ADR-0060 反馈边落地（D1 显式入口 + D4 代表错题仿写）
- **背景**：2026-09-21 盘问结论——闭环六段只有「答错即建错题」通，出题对 Mastery/WrongQuestion 零
  引用（断的反馈边）。本轮实现 ADR-0060 的 D1+D4（用户 Q1=A 显式入口、Q2=B 同类题）。
- **`origin` 字段（版权遗留）** `backend/app/db/models/question.py`：新增 `origin`（默认 `"ai"`），
  常量 `QUESTION_ORIGIN_AI/PARENT`；`app/core/db.py` 启动期迁移补列（sqlite+postgres，存量回填 `"ai"`）。
  仿写只取 `origin=="ai"` 的题，避免把家长教辅录入题再繁衍（ADR-0020）。
