## Q1/Q2 配色字体不协调根因（用户追问）

  1. **primary=近黑 vs accent=靛蓝 分裂**：shadcn `primary` 走 `c.primary #1D1B17`，故开关/单选/勾选选中态、primary 按钮渲染近黑；而 `ring/selection/custom.accent`=靛蓝。交互主色在黑(primary 系)与靛蓝(accent 系)间分裂，眼睛难建立一致规则。

## Border 割裂根因分析（用户追问，仅分析未改）
- 量化：亮模式 `outline #ECECEA` 在白卡(#FFF)/surface(#FBFAFA) 上对比仅 **1.18 / 1.14 :1**；`outlineVariant #F2F2F0` 1.08:1；`surfaceContainerHigh #F4F4F2` 1.06:1——1px 发丝线在这些浅值下**几乎不可见**，spec 承诺的"1px 描边分层"实际没发生，卡片只靠白vs暖白微差悬浮。
- 割裂三因：① 发丝 border 不可见 → 分层系统（本应靠描边）失效；② 同时 accent 色条(章节 3px #5E6AD2)、focus ring、学科色、progress 是**强饱和实边**——全站出现"不可见发丝线 vs 强饱和实边"两套边语言并存，眼睛感知割裂；③ `outlineHover #D1D1CE` 令牌**定义了却从未接入**任何 hover 边框（死令牌），非聚焦 hover 边框无反馈；且 `outline/outlineVariant/surfaceContainerHigh` 三档近同灰角色重叠（border vs 分隔 vs surface），取用含糊导致跨页面边权重不一致。
- 建议（待用户确认再改）：a) `outline` 提到可感知但仍克制的值（亮 ~#E4E3DF / 暗 ~#2F2F2C，约 1.28/1.35:1，仍低于 WCAG 文本线但 hairline 本就不该达标）；b) 把 `outlineHover` 接入 input/button hover 边框或删死令牌；c) 明确三灰分工：`outline`=边框、`outlineVariant`=低强调分隔、`surfaceContainerHigh`=surface 只用，禁止互串。

## 修复：macOS 字体发糙根因（变量字体被当单档静态字体）
- 现象：桌面/macOS 上正文尚可，标题/标签/按钮（w500/w600/w700）发虚、边缘发糙。
- 根因：`assets/fonts/Inter.ttf` 含 `fvar`+`gvar`（真变量字体，覆盖 w400–w700 字重轴），但 `pubspec.yaml` 把它声明为**单档静态字体**（无 `weight`）。字体家族只注册 400 一档 → 所有非 400 字重被 Flutter **合成加粗 (faux-bold)**，GPU 字形模拟在 Retina 上锐利对比下显糙。
- 次要（非糙因，但 off-spec）：`fontFamilyFallback: ['HarmonyOS Sans SC','Noto Sans SC']` 声明了却**未打包**，是空引用；CJK 实际回退到 macOS 系统字体(PingFang)。要真正一致需打包真实字体文件。
- 修复：`pubspec.yaml` 的 Inter 按 w400/500/600/700 各显式 `weight` 声明（同文件多档），`flutter pub get` 重建字体清单后引擎直接取变量轴实例，不再合成加粗。`flutter analyze` 全量 No issues。
- 验证方式：macOS 上 `flutter run -d macos` 看标题/标签是否变锐。

## 输入框文字不居中：根因二次定位（真正修复）
- 上轮"OFFSET=0"只量了 `EditableText` **盒子**中心，盒子居中≠文字居中。**量字形中心**（`RenderEditable.getLocalRectForCaret` 取字形中心）才发现 glyph 仍偏上：compact `AppTextField` GLYPH_inBox=-2.83、child/normal 模式 GLYPH_inBox=-8.67。
- 根因：shadcn 0.56.3 的 `ShadInput` 全源码**无 `textAlignVertical` 参数**，内部 `EditableText` 默认 `top` → 文字钉在编辑盒顶端。`editableTextSize` 只钉盒高、字形仍顶对齐，所以之前"修"了等于没修。
- 真正修法（已实测 6 类输入全部 GLYPH_inBox=0.00）：单行输入加 `strutStyle: AppControl.inputStrut(ctx, style)`（`forceStrutHeight:true` + `height=(controlH-4)/fontSize` 强制行高撑满编辑盒，半行距使字形居中）。多行/带大竖向 padding 的输入本就居中，勿设 strut。
- 改动：`app_theme.dart` 新增 `AppControl.inputStrut`；`AppTextField`/`parent_task_review_screen`（选项+答案）/ `theme_preview` 的裸 `ShadInput` 去掉 `editableTextSize`+`LayoutBuilder`，改加 `strutStyle`。
- 验证：GLYPH_inBox 全 0（compact/pwd/child-normal/裸单行）；`flutter analyze lib/` No issues!；根 smoke 测试通过。全量 `flutter test` 16 通过 / 3 失败——3 个失败是 `children_notifier_test`/`genkit_client_test`/`tutor_notifier_test` 的 **Genkit→assistant 重构遗留 API 签名错误**，与本任务无关、非本次引入。
