## 优化：生成任务回退为「单次调用、单流多 type」流式（GenUI 风格）
- 用户反馈：不应两次调用，参考 GenUI——一次推理包含不同 type 的 stream，全部显示即完整 agent 输出。
- 改动（`app/ai/flows.py`）：删除两阶段与 `_build_reasoning_prompt`；改为**单次 `generate_stream`（无 output_schema）**，
  模型在**同一文本流**里先输出 `<reasoning>…</reasoning>`（逐 token 下发 REASONING），随后输出 JSON 题卡；
  后端边流边解析（`_build_stream_prompt` + `_parse_question_json` + 状态机），JSON 完成即发 CARD。成本减半、推理实时可见。
- 状态机兼容三种模型输出：① 标签推理+JSON；② 无标签直接出 JSON（`{` 之前当推理）；③ ```json 围栏；解析失败优雅回退 mock（仍展示已流式推理）。
- subject/grade/知识点/题型/难度由 spec 回填，JSON 只含可变字段（stem/options/answer/explanation/reasoning），降低出错面。
- 验证：用假引擎跑真实 `generate_questions_stream` 覆盖上述 4 种输入全部正确；ruff 干净；`pytest -k "flow or generate or question or stream"` 31 passed / 2 skipped（smoke 需 key）。
- 前端无需改动：STEP/REASONING/CARD 信封 + 卡片持久「出题思路」块已在上轮就绪，满足「不同 stream 都显示」。
