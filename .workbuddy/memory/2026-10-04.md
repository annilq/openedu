## 交互式图形讲解：设计方向（2026-10-04 傍晚，设计阶段未落地）

- 用户诉求：喂**每道题**生成交互式讲解，支持"设置输入变量 + 播放/暂停/拖拽/倍速"。
- 拍板方向（待 ADR-0061）：**每题一份 SceneSpec（主路径）**，知识点场景作为**可选的概念级继承层**，二者共存；复用发生在渲染器/输入变量机制，不强制共享一份场景。
- SceneSpec 关键字段：`kind`（选绘制器）+ `inputs[]`（用户可设的输入变量：key/label/value/min/max/step/unit，改值重算动画）+ `controls{}`（时间轴播放/暂停/拖拽/倍速，通用）+ `timeline[]` + `narrative`。
- **两个控制面要区分**：输入变量面板（调 v/T 等场景参数，改值重算）+ 时间轴控制（播放进度，所有 kind 共享）。
- 存储：沿用 house 风格 `Question.scene_spec` JSON（可空，不建外键，像 source_refs）；`KnowledgePoint.scenes` 可选 JSON 数组（概念级，题目可继承覆盖 inputs）。
- 生成可靠性：AI 经结构化输出/函数调用产出 SceneSpec + schema 校验，失败降级为纯文本讲解（不破解出题/答疑）；仅"可图形化"的题（含数值/几何）才生成。
- 渲染：`shared/widgets` 落 SceneInterpreter（≥2 调用点才进 shared），按 kind 分派；复用 `app_motion.dart` 的 `ConfettiBurst` 模式（CustomPainter+AnimationController+AnimatedBuilder+reducedMotionOf）。
- 已知缺口：全工程无 flutter_math/LaTeX 公式渲染；题→知识点同名匹配漂移问题（ADR-0055 已点名）须先收敛，否则图形讲解会重复/缺失。
- 编号：0055 已用，下一 ADR 从 **0061** 起（写前复核目录最大号 + git status）。

### 工作流细化（2026-10-04 17:50，用户明确）

- 用户给定明确三阶段工作流，**推翻"AI 自由生成每题场景"**，改为**教师先编、生成时融合**：
  1. **编写（教师）**：上传资料→知识点抽取→在知识点上编写基础交互演示动画（KnowledgePoint.scenes：kind+默认 inputs+controls+solve）→教师调整交互体验。
  2. **生成（AI+融合）**：生成题目时查询对应知识点→抽取本题输入值（v/T/已知条件）→与知识点默认场景**融合**成 Question.scene_spec（含 locked_answer=本题正确答案）。
  3. **使用（学生/用户）**：打开题目场景仍可改演示变量→**执行分析流程**（solve）达成讲解/验证。
- 关键设计变更：① 场景由教师编写而非 AI 凭空生成（更可靠）；② 引入**融合**机制（KP模板 + 题面输入覆盖）；③ 区分**被动播放**（概念体验）与**主动执行分析/求解**（what-if 验证），SceneSpec 需带 solve 派生规格。
- AI 在生成时的角色收窄为「参数提取+绑定」，不是场景发明——可靠性高。
- 数据依赖：KP.scenes 必须先于题目生成存在（编写阶段前置）。
