## 交互式图形讲解：设计方向（2026-10-04 傍晚，设计阶段未落地）

- 用户诉求：喂**每道题**生成交互式讲解，支持"设置输入变量 + 播放/暂停/拖拽/倍速"。
- 拍板方向（待 ADR-0061）：**每题一份 SceneSpec（主路径）**，知识点场景作为**可选的概念级继承层**，二者共存；复用发生在渲染器/输入变量机制，不强制共享一份场景。
- SceneSpec 关键字段：`kind`（选绘制器）+ `inputs[]`（用户可设的输入变量：key/label/value/min/max/step/unit，改值重算动画）+ `controls{}`（时间轴播放/暂停/拖拽/倍速，通用）+ `timeline[]` + `narrative`。
- **两个控制面要区分**：输入变量面板（调 v/T 等场景参数，改值重算）+ 时间轴控制（播放进度，所有 kind 共享）。
- 存储：沿用 house 风格 `Question.scene_spec` JSON（可空，不建外键，像 source_refs）；`KnowledgePoint.scenes` 可选 JSON 数组（概念级，题目可继承覆盖 inputs）。
- 生成可靠性：AI 经结构化输出/函数调用产出 SceneSpec + schema 校验，失败降级为纯文本讲解（不破解出题/答疑）；仅"可图形化"的题（含数值/几何）才生成。
- 渲染：`shared/widgets` 落 SceneInterpreter（≥2 调用点才进 shared），按 kind 分派；复用 `app_motion.dart` 的 `ConfettiBurst` 模式（CustomPainter+AnimationController+AnimatedBuilder+reducedMotionOf）。
- 已知缺口：全工程无 flutter_math/LaTeX 公式渲染；题→知识点同名匹配漂移问题（ADR-0055 已点名）须先收敛，否则图形讲解会重复/缺失。
- 编号：0055 已用，下一 ADR 从 **0061** 起（写前复核目录最大号 + git status）。

### 工作流细化（2026-10-04 17:50，用户明确）

- 用户给定明确三阶段工作流，**推翻"AI 自由生成每题场景"**，改为**教师先编、生成时融合**：
  1. **编写（教师）**：上传资料→知识点抽取→在知识点上编写基础交互演示动画（KnowledgePoint.scenes：kind+默认 inputs+controls+solve）→教师调整交互体验。
  2. **生成（AI+融合）**：生成题目时查询对应知识点→抽取本题输入值（v/T/已知条件）→与知识点默认场景**融合**成 Question.scene_spec（含 locked_answer=本题正确答案）。
  3. **使用（学生/用户）**：打开题目场景仍可改演示变量→**执行分析流程**（solve）达成讲解/验证。
- 关键设计变更：① 场景由教师编写而非 AI 凭空生成（更可靠）；② 引入**融合**机制（KP模板 + 题面输入覆盖）；③ 区分**被动播放**（概念体验）与**主动执行分析/求解**（what-if 验证），SceneSpec 需带 solve 派生规格。
- AI 在生成时的角色收窄为「参数提取+绑定」，不是场景发明——可靠性高。
- 数据依赖：KP.scenes 必须先于题目生成存在（编写阶段前置）。

## 交互式讲解：reflection 原型翻折 bug 修复（21:26）
- 用户反馈：支持轴角度后，点「播放翻折」**没有沿轴对折、而是整图镜像反转**，与上一版不一致。
- 根因：翻折公式须对**单个图形的全部顶点**应用任意直线反射的 2D 投影 `p' = c + u·d + v·cosθ·n`（θ:0→π，u=沿轴分量、v=法向分量、d/n 单位向量）。上一版竖直轴时退化成 `x' = axisX + (x−axisX)·cosθ`（一致）。出错的那版只折单侧或把图形画成两份，导致表现为整图反转。
- 修正：① 折叠全部顶点（单一图形，非左右两份）；② 对称轴由「角度 axisAngle + 中心点 (axisX,axisY)」定义，可旋转任意角度+平移，覆盖竖直/水平/斜轴对比；③ 重合判定程序化（`outputs.isAxisymmetric`）：把所有基础顶点关于当前轴反射，逐点取与任一原顶点最近距离，最大距 < 阈值即判对称，不硬编码。
- 已重做可交互 HTML 原型（house/kite 竖轴对称 + para 非轴对称，验证"轴偏了就不重合"）。ADR-0061 决策 9.1 已同步澄清"折叠全部顶点、保持单一图形"的语义与程序化判定口径，供后续 reflection_painter(Flutter) 落地对齐。
- 🐞 **reflection 原型 UX 修复（21:33）**：切换图形时左侧画板看不到参考图像。根因：翻折填色图形叠在原位，半折叠态或切换时显得图形消失。修复：① 始终绘制一层原始图形虚线参考轮廓（α=0.35, θ=0）始终可见；② 切换图形 `onchange` 重置 `theta=0`（完整显示）。Flutter 落地时 reflection_painter 也应保留"原始参考轮廓 + 实时翻折层"双层结构。
- 🐞 **reflection 原型 canvas 空白根因（22:01）**：改用 canvas 后，宿主在交互时重排 DOM 会清空 canvas 位图，导致切换图形画板空白。改 **SVG 渲染**（`<svg>` + `<path>`/`d` 属性由 JS 更新，真实 DOM 不丢内容），问题消除。⚠️ 教训：在该 widget 宿主里做交互图形**优先用 SVG 而非 canvas**。Flutter 端 CustomPainter 是引擎每次按 state 重绘，无此问题，reflection_painter 仍按双层结构实现。

## 交互式讲解：reflection 翻折语义最终敲定（22:07）
- 用户最终纠正：支持轴角度后，点「播放翻折」应**按对称轴对折**——把图形**一侧沿折痕翻折盖到另一侧**，并据**是否重合**判断是否为轴对称图形；**不是**「旋转整个图像、再比对是否与原图一致」（那是整图镜像反转，非对折）。
- ADR-0061 决策 9.1 第三版改写（推翻上一版「折叠全部顶点、保持单一图形」）：**只翻折一侧、另一侧保持静止**——静止侧顶点不动，折叠侧顶点沿折痕 2D 投影 `u 不变，v'=v·cosθ`（θ:0→π，θ=π/2 塌到轴、θ=π 跨轴落另一侧）；静止侧/折叠侧以青/橙双色叠加，便于看清是否重合；`outputs.isAxisymmetric` 改为「θ=π 后把折叠侧顶点关于当前轴反射，逐点匹配静止侧顶点，最大距<阈值即两侧重合/轴对称」。**这才是纸感对折**，涵盖竖直/水平/斜轴所有对比场景。
- 已重做可交互 HTML 原型（SVG 兼容宿主，但本次用 canvas 实时翻折：house/kite 竖轴 / arrow 横轴为正确重合样例；旋转或平移轴偏离真正对称线即不重合）。切换图形自动设正确轴角（house/kite→90、arrow→0）。下一步：实现 reflection_painter(Flutter) 落 shared/widgets，复用 app_motion 的 AnimationController/reducedMotionOf，按「静止侧+折叠侧双层」结构渲染。

## 交互式讲解：reflection 升级为「面重合」（22:17）
- 用户在上一版（单侧线段翻折）基础上要求：翻折时对称轴一侧图形应**覆盖到另一侧图形**、看**面积是否完全覆盖**，而非仅线段/轮廓重合——即「面重合」。
- 原型实现升级：用**多边形按直线裁剪成两半**（Sutherland–Hodgman 半平面裁剪）得到「静止半」与「折叠半」两个填充区域；静止半保持不动，折叠半沿折痕 `v'=v·cosθ` 翻折覆盖上去；两半以青/橙半透明填充叠加，翻折后直观看橙色面是否完全盖住青色面。
- ADR-0061 决策 9.1 同步：被动播放描述补「面重合（非线段重合）：按对称轴裁剪两半填充区」；`outputs.isAxisymmetric` 判定口径明确为「折叠半面积完全落在静止半内且面积相等（等效顶点反射匹配）」。Flutter 落地时 reflection_painter 须对图形做**半平面裁剪**而非仅描边。

## 交互式讲解：reflection 原型「提前重合」bug 修复（22:25）
- 用户反馈：reflection 原型在「对折进度=1」时就判定重合，但"按理说只有 180° 才重合"。
