## 缺陷：多学科出题静默少题（"数学出了、语文没出"）

- 现象：specs = 数学×1 + 语文×1，落库任务只有 1 道数学题，前端无任何报错。
- 排查（重要方法论）：
  1. 直接查 `app.db`：`task.specs` 有 2 条、`taskquestion` 只有 1 行 → 请求规格是对的，少的是题。
  2. 用 TestClient 跑 `/api/v1/tasks/generate` N 次：后端 11/11 都吐 2 张卡 → **后端生成链路没问题**。
  3. 注意「跑着的后端 ≠ 本地 `.env` 配置」：8000 端口那个进程用的是**另一套库**（自定义 ModelConfig
     `deepseek-v4-pro`），本地 `app.db` 的 `model_config` 是空的。复现要打真实端口，别只信本地库。
- 根因（三处叠加）：
  1. **单题失败被静默吞掉**：出题是逐题串行，某题失败只发一条 `STEP(status="error")`
     （`translate.py` 把 `QuestionFailed` 转的帧）；前端 `QuestionGenFold.apply` 不判 `status`，
     把它当普通进度 STEP 折叠 → 流结束照常落库 → 残缺任务 + 零提示。
  2. `agent.py` 的 `fail_reason` 变量**声明后从未赋值**（重构时丢失），收尾文案还用
     `items[0].subject`，多学科会说出「已生成 2 道数学题」这种错话。
  3. 放大因素：真实模型出 2 题实测 **19–36 秒**，而前端 dio `receiveTimeout` 只有 30 秒。
- 修复：
  - 后端 `agent.py`：接上 `failures` 列表（捕获 STEP status=error）+ `_finish_message()` 三态文案；
    `TOOL_RESULT` 带上 `requested/count/failed/fail_reason`。
  - 前端 `question_gen_fold.dart`：STEP `status=='error'` → 记入 `failures`，不推进 `liveIndex`。
  - 前端 `home_notifier.dart`：`expected`（specs count 之和）→ `TaskGenSuccess.isShort/shortMessage`。
  - 前端 `parent_task_form_view.dart`：少题走 `AppToast.error` + 预览区 `_FailureBanner`。
  - `dio_network_service.dart`：流式端点默认 `receiveTimeout` 10 分钟（SSE 不该受 30 秒短超时约束）。
- 测试：`tests/api/routes/test_tasks_generate.py` 的 4 个用例**此前全崩**（打桩点 `router.build_ai_provider`
  在 ADR-0033 下沉到 service 后已不存在）——这条回归防线长期失效，正是本 bug 漏出的原因。已改打
  `service.build_ai_provider` 并新增部分失败用例；`FakeLLMProvider` 加 `fail_at` 支持。
- 验证：后端 259 passed（剩余 4 failed + 1 error 均为 review/会话隔离的**既有**问题，与本次无关）。

## 草稿审核页「删除 / 编辑 / 换一题」点不动排查

- 结论：后端三个接口**都是通的**，前端接线也对；「点了没反应」主要是前端无反馈 + 超时。
- 验证方式（可复用）：`cd /tmp && backend/.venv/bin/python -m pytest <abs test path>`。
  在 backend 目录里跑会去读 `backend/.env`（含 API key）被沙箱拦下；从 /tmp 跑 dotenv 相对路径
  找不到文件，绕开权限弹窗。建 Task + TaskQuestion 直写库，再用 `tests.utils.user.register_parent`
  拿 token 打 HTTP 即可。
- 实测结果（mock 引擎）：
  - `PUT /tasks/{id}/questions/{tq}` 编辑 → 200，字段正常回写。
  - `DELETE /tasks/{id}/questions/{tq}` → 204；**即使只剩 1 题后端也允许删**（前端却禁用）。
  - `POST /tasks/{id}/questions/{tq}/regenerate` → 无引擎时 500
    `SYS_10006 无可用 LLM 引擎…`；有引擎时是同步一次 LLM 调用。
- 前端「没反应」的三个真因：
  1. `parent_task_review_screen.dart:216` 草稿只剩 1 题时 `onDelete` 传 null → 按钮禁用且零提示。
  2. `regenerateOne` 没走 `ReviewLoading`（只有 `regenerateAll` 切了加载态），期间无 loading、
     按钮也没禁用/防抖 → 连点会并发多次请求，后返回的会用旧快照覆盖（丢更新）。
  3. dio 普通请求 `receiveTimeout=30s`（dio_network_service.dart:22），而单题重生成是同步 LLM 调用，
     常常超过 30 秒 → 超时报「请求超时」，看起来也像没反应。
- 待办（用户确认后再改）：给三个动作加 pending 态 + 按钮禁用/防抖；换一题放宽超时或改流式；
  最后一题删除要么放开要么给明确禁用提示。
