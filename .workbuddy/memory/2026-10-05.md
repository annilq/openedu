## 自查：题目 ↔ 知识点 ↔ 交互场景的关联度（ADR-0061 §M，10:43–10:55）
用户问「4选项选择题会不会为每个选项生成交互讲解」→ **不会，且当前连1个场景都不出**。实测
（非推断）结论：
- ✅ 题目→知识点**已关联**：`Question.{subject,grade,semester,knowledge_point}` 随规格落库。
- ⚠️ 知识点→场景**形同虚设**：205 个知识点里 `scenes` 非空仅 **1** 条，且内容是 JSON 字符串
  `'null'`（非 SQL NULL）→ `fuse_scene_spec` 收到 None 返 None。
- ❌ 题目→场景实例**从未写入**：`Question.scene_spec` 列已建但全库 8 道题非空数=0；
  代码里 `scene_spec=` 只出现在 `tasks/service.py:158`（**读路径**响应字段，不是落库）。
- ❌ 题面数值→inputs**没接**：`scene_fusion.py:106` 调 `fuse_scene_spec(kp.scenes)` **不传
  overrides**；`overrides` 参数**全仓无调用方**（ADR §C 决策 2/3 规划至今未实现）。
- ❌ 选项→场景**结构上不可能**：场景由 `knowledge_point` 单键解析，与 `options` 无关；
  前端 `options` 只喂 `_QuestionOptions`（纯文本），`sceneSpec` 只喂 `SceneInterpreter`。
- **形态定性**：现在是「一个知识点→一份通用模板」，不是「一道题→一份贴合该题的场景」。
  模板配好后也只会出现**一个**场景、用知识点默认轴参数（house/90°），与该题图形选项无关。
- **补齐需要三步**（均未做）：① 出题时抽题面数值→overrides（选择题逐选项抽是难点）；
  ② 落库快照（_gen_for_swap / from-generated 缝，顺带拿快照语义）；③ 选择题逐选项场景
  需要**新 kind**（集合语义 options[]+locked_answer），不是现有 reflection 的参数扩展。
- ⚠️ 数据缺陷：JSON `null` 存进 `scenes` 会让「非空计数」失真（IS NOT NULL 真但内容空）。
  写入侧应统一 `scenes or None`（update_knowledge_point_scenes 已如此，疑为历史数据）。

## 落库快照 + 题面数值抽取（ADR-0061 §N，11:00–11:15）— §M 的第2/1步
- **①题面抽取**（新 `materials/scene_extract.py`，纯函数）：`extract_scene_inputs(stem, options)
  -> overrides`，抽 figure（房子/风筝/箭头/平行四边形，中英词表）+ axisAngle（`45°`/`60度`，
  **正则必须带负号** `[+-]?` 否则 `-30°` 抽成 `30°`→对称轴画到镜像位置）。
  ⚠️ **axisX/axisY 永不从题面抽**（归一化对称轴位置，题面极少精确表述，强行推断=编造），
  只由教师调参面板手摆。抽不到就返回空 dict 留模板默认值——**给与题目无关的图形比不给场景
  更糟（会教错）**。角度只收 0..180（360°是旋转题不是轴对称题）。选择题只取第一个命中图形
  （题面优先于选项）——逐选项配场景要新 kind（集合语义），见 §M 第3步仍未做。
- **②落库快照**：`TaskQuestion` 加 `scene_spec` 列（Question 早有）；草稿期就带，否则确认前
  预览拿不到（Question 要等 promote 才有行）。三处落库缝写：`create_from_generated`（主路径，
  优先前端回传的、否则就地融合）/`_gen_tq_for_spec_item`（经新增 `scene_ctx=(session,parent_id)`）/
  `_gen_for_swap`（**必须重算**，新题 stem/options 不同不能沿用旧快照）；`promote_task_question` 带进题库。
- **③读路径快照优先**：`wrong_question_to_resp` = `q.scene_spec or build_...(...)`（老数据无快照
  回退实时解析，存量题仍能出图）；`question_to_resp` 直发草稿快照。
- **④缓存纪律**：`overrides` 非空时**绕过 cache**——缓存键只含(知识点,学期)，带题面值时同一
  知识点不同题目结果不同会串味。故 `build_scene_spec_for_question` 透传 cache，仅抽不到题面值时生效。
- **⑤根因修复（比§M 判定的更深）**：「文本 null」**不是历史脏数据**，是 **SQLAlchemy `JSON`
  默认把 Python `None` 序列化成字符串 `'null'`** → 清空模板写进去就是文本，`IS NOT NULL` 为真

## 修：点播放抛 AnimationController.forward() called with no default duration（12:34–12:40）

## 修：知识点 UNIQUE 缺 semester → 同一知识点按学期存两份必崩（ADR-0061 §R，16:00–16:10）
用户报`UNIQUE constraint failed: knowledgepoint.parent_id, .subject, .grade, .name`
（确认知识点时崩，500）。**这是我§J 加学期维度时留下的既有 bug**。
- ⚠️ **根因：SQLite 没有 `ALTER TABLE ... ADD CONSTRAINT`**。§J 那次迁移只补了**列**
  （`ADD COLUMN semester`），`ADD COLUMN` 里写的 `UNIQUE(...)` 子句会被**静默忽略** →
  任何在加学期维度**之前**建库的库（含本机 dev 库）唯一约束仍是**旧的 4 列**
  `UNIQUE(parent_id, subject, grade, name)`，**缺 semester**。
  **新建库没事**（`create_all` 按模型建 5 列），**只有老库坏** → 测不出来。
- ⚠️ **后果不是报错而是静默废能力**：同一知识点**无法**按学期各存一份（上/下学期模板）
  —— §J 承诺的核心能力在老库上根本不可用。且旧4列约束**更严**，迁移前不可能有重复行
  → 重建表必然安全（拷行不搬值）。
- **修法**：`_rebuild_kp_unique_with_semester(conn)` —— SQLite 改约束只能**重建表**
  （建新表 → `INSERT..SELECT` 拷 → 删旧 → `ALTER..RENAME` → 重建
  `ix_knowledgepoint_scope` 为 4 列版）。**幂等**：先读 `sqlite_master` 判UNIQUE 里
  有没有 semester，缺才动手；表还没建 / 列都还没有则跳过（偏序迁移纪律）。
- **实测**：迁移后约束 = 5 列、索引 4 列、**205 行守恒**、连跑 3 次幂等；
  HTTP 复现原崩溃路径（上/下/整学年各确认一次同名知识点）**全200**。
- **测试** `tests/core/test_kp_semester_unique_migration.py` 9/9，在临时库上**造出老库
  形状**（4 列约束）跑迁移：老库必撞/迁移后能共存/**同学期同名仍拒**/幂等行数守恒/
  **scenes 列不丢**/表缺失是 noop。
- ⚠️ **测试坑**：迁移函数内部用 `text(...)`，**必须喂 SQLAlchemy 连接**
  （`engine.connect()`），喂裸 `sqlite3.Connection` 会报
  `execute() argument 1 must be str, not TextClause`。
- 验证：ruff app 全过（tests 有 1 个**既存** F401 在 test_subject_qtypes.py，非本次）；
  后端全量 **542 passed**（3 vector 既存顺序污染同前）。
- ⚠️ 教训：**SQLite 迁移里「加列」不等于「加约束」**。凡是要改 UNIQUE，必须重建表；
  且这类问题在「新建库」环境测不出来 —— 回归测试要**手工造老库形状**。
