## AI 架构盘点与「去 subagent 化」分析（只读调研，未改代码）

- 用户指出 `ai_architecture_map.html` 过时，要求分析当前 AI 架构并评估：能否去掉多余 subagent（如 guide）、把 tools 暴露给 main agent、是否应全删 subagent 改 LLM 路由。
- 结论（已向用户给出，待其拍板）：
  - **没有 main agent**。`AgentRuntime.decide`（`agent_core/runtime.py:79`）是零 LLM 的确定性路由器（动作直配 → triggers 子串 → hints → 兜底 tutor），契约测试 `tests/ai/test_intent_routing_contract.py` 钉死。
  - **能力知识四处手抄**：manifest 声明（只给路由器看，LLM 看不到）/ 各 agent 自己的 system prompt / `capability/agent.py` 的固定清单 / 前端空态文案。互不生成，会漂移。
  - **五个 subagent 对应三种执行模型**，不是组织癖：guide+capability 零 LLM 确定性应答；query 是唯一持真工具的（8 个只读工具）；question 走约束解码（`provider.stream(schema=QuestionSchema)`），tutor 包 TutorService 流式+安全闸门，二者都不是 tool 形态。
  - **实测**（`.venv/bin/python` 跑 `QUERY_TOOLS`）：8 个工具 schema 合计 3934 字符 ≈ 2000 token，每轮随请求下发。全量暴露给单 agent 会让每轮（含本可零 LLM 的轮次）都付这份钱。
  - **建议方案 B**：规则路由不变，启用 router.py docstring 预留的「弱意图 LLM 兜底扩展点」作为第三级（配置开关+eval）；capability 清单改为从 manifest 生成。**不建议**全删 subagent：ADR-0033 记载小模型（qwen3:1.7b/ministral-3:3b）流式下编造学生数据，整套硬失败机制为此而存在；儿童产品要求路由确定性。
  - guide 不建议删：删了「创建任务」回落 query(12)（trigger「任务」命中）→ requires_tool_data 未查先答硬失败或「只能查询」，即 ADR-0087 之前的老问题回归。它真正的问题是 triggers 太宽（把「出题+发布」整句当发布），属调词表不是删。
- 另：本轮早些时候诊断了「请为我创建一个任务」返回 guide 固定卡的原因（路由整句拦截 + guide input_schema 全 optional 死配置 + 话术越界），修复选项 A/C 已给用户，未开工。

- 用户贴三框架文档（Genkit multi-agent / Pydantic AI harness subagents / LangChain subagents），认为本项目 subagent 拆得过细，倾向「全部并成一个」或「当前不需要 subagent，对接其他业务时再加」。
- 后台调研代理抓取 5 个官方页面，报告落 `docs/research/subagent-frameworks.md`（含横向对比表 + 逐框架详述 + 反过度拆分专项 + §5 对本项目评估）。三家共识：官方示例一律「1 编排 + 1~3 专家」，无 5+ 示例；上下文隔离是拆分头号动机（Pydantic「永远看不到父对话」/ LangChain「干净窗口」/ Genkit historyLength）；能力感知 = subagent 包装成工具（delegate_to_X / delegate_task / task()）；<10 agent 用提示词枚举。
- **关键实测反差**：本项目 `agent_core/subagent.py:258` `history = list(ctx.history or [])`——subagent 全量共享对话历史，**零上下文隔离**，即拆分没拿到框架列为核心收益的那项，只买到指令分化/路由精度/requires_tool_data 闸门/kind 审计。
- 框架标准对标：不同指令 ✅（question 出题 SOP / tasks 只起草 / tutor 安全锁三套不可互替）；不同模型设置 ❌（统一 resolve_engine）；专家记忆 ❌；上下文隔离 ❌；多领域 ⚪（单业务内多域）。
- **用户「拆得过细」有实据的部分**：students（1 工具）与 capability（0 工具 0 LLM）不构成 agent——前者是工具、后者是路由层固定回复。**但全并成一个会丢真实存在的东西**：tutor 是另一套执行引擎（TutorService 安全闸门+RAG+persona，不经 tool loop），requires_tool_data 硬闸门源于真机编造事故（subagent.py:94），合并后无法对「伴学零工具答题」统一生效。
