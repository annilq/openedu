## flows.py 收敛进 feature/subagent + 重命名 generation.py（2026-09-09 续）
- 用户问能否把 flows.py 功能收敛到 feature/subagent、基于什么原则。结论：放 `app/ai` 共享内核正确（ADR-0027 共享内核 + ADR-003 框架隔离 + ADR-0023 单安全闸门），但文件过度拆分。
- 实际收敛：
  - `git mv app/ai/flows.py → app/ai/generation.py`，只留**跨入口共用**出题脚手架（QuestionOut/QuestionSchema/GradeSchema、prompt 构造、JSON 解析、`_assemble_question` 安全闸门、`generate_question` 共享原语）。
  - `_tutor_generate` + `grade_open` 仅被 `GenkitProvider` 单一消费 → 收编进 `app/domain/genkit_provider.py`（inline 为 `tutor`/`grade_open` 方法体，`_chunk_text` 也移入），彻底删出共享内核。
  - **关键架构修**：出题 SubAgent（`app/ai/subagents/question/agent.py`）原本 `if self.engine: from app.ai import generate_question else: self.provider.generate_question` 双分支直连 `app.ai` 原语，违反 ADR-003（绕过 LLMProvider 抽象）。改为统一只走 `self.provider.generate_question(...)`，删直连分支。
  - `app/features/tasks/router.py` 的 `_gen_question` 落库路径仍直调共享原语（`from app.ai import generate_question`），保留显式 engine + LLM_UNAVAILABLE 语义。
  - `app/ai/__init__.py` 惰性导出 `flows`→`generation`、删 `grade_open` 导出；`app/domain/__init__.py` 与架构文档/glossary 的 `flows.py`/`tutor_stream`/`零 key 闭环` 过期引用同步修正。
- 原则沉淀：**共享原语（多消费者，如 generate_question）留 `app/ai` 内核；单消费者实现（tutor/grade_open）应下沉到 `LLMProvider` 实现（`genkit_provider.py`），不藏进共享层**；subagent 只依赖 `LLMProvider`，不直接 import `app.ai` 引擎原语。
