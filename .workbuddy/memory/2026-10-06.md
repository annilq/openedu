- ⚠️ **macOS `com.apple.security.device.audio-input` 是硬需求**：本项目 `app-sandbox=true`，沙盒下缺该项麦克风被系统直接拒且**不抛错**（两个 entitlements 文件都要补）。
- **`--check` 模式**（只检查不写入、缺则退 1）是给 CI 用的：原生权限缺失是**静默失效**（门禁判 `unsupported` → 麦按钮不渲染 → 界面零异常），只有 --check 能把它变成会失败的检查。
- **Android 插入位置**：`uses-permission` 必须是 `<manifest>` 的**直接子元素**、在 `<application>` 之外（放进 application 不生效）。正则匹配 `<manifest[^>]*>` 开标签行后插入，改完用 `ElementTree` 回验。
- **实测**：`--check` 识别 7 项缺失退 1 → 补齐 → 二次运行 7 项全 `[ok]`、`--check` 退 0。manifest XML 合法、子元素顺序 `uses-permission, application, queries` ✅。

## ⚠️⭐ 更正上一条：insteadOf 对 SwiftPM **无效**；真正解法是 SwiftPM mirror（已实测通过）
- **为什么「配了 gitconfig 还是报同样的错」**：`url.<x>.insteadOf` 是 **git 命令行**的特性，SwiftPM 走 **libgit2**，而 libgit2 **不实现 insteadOf** → 它照旧直连 github。上一轮「`git ls-remote` 0.011s 命中 ⇒ 预期对 SwiftPM 生效」是错误推断：那个验证只证明命令行生效。
- **第二根暗桩（不解决就换汤不换药）**：全局 gitconfig 的 `safe.bareRepository = explicit` 会让 libgit2 拒绝打开 SwiftPM 的**裸**缓存仓库 → `fatal: cannot use bare repository '…' (safe.bareRepository is 'explicit')`，症状与「Couldn't get the list of tags」完全相同，但根因已在本地。已 unset（回到 git 默认 `all`）。
- **解法（本机实测通过）**：SwiftPM 官方 mirror，把远程 URL 映射到本机 bare 仓库
  - 落点三处：全局 `~/.swiftpm/configuration/mirrors.json`；工程级 `macos/Runner.xcworkspace/xcshareddata/swiftpm/configuration/mirrors.json` 与 `macos/Runner.xcodeproj/project.xcworkspace/…/mirrors.json`（两个 workspace 都写，省得猜 xcodebuild 用哪个）。
  - ⚠️ **schema 以 `swift package config set-mirror` 的实际输出为准**：`{"version":1,"object":[{"mirror":…,"original":…}]}`。网上老资料的 `{"object":{"mirrors":[…]}}` 直接崩 `DecodingError.typeMismatch: expected Array<Any> … Path: object`（实测踩到）。别凭记忆写，跑一次官方命令看输出。
  - 实测：清空 `.build` 且只留全局配置，`swift package resolve --disable-sandbox` → `Fetching file:///Users/annilq/.openedu-deps/CwlCatchException.git` → `resolved at 2.2.1`（revision `07b2ba21…`，与官方 tag 一致），约 2s，零网络。

## 语音输入改微信式两态切换（键盘态 ⇄ 语音态，用户点名要的）
- **交互**：默认键盘态（输入框 + 模式切换按钮，图标=**当前**模式「键盘」）→ 点击切成语音态：输入框**整个**换成全宽「按住 说话」，切换图标变麦 → 再点回键盘态，草稿不丢。ADR-0063 §5 已改写（含三端表 + 「为什么不挂一个小麦按钮」三条理由）。
- **为什么是两态而不是「输入框旁挂麦按钮」**：40px 小图标儿童点不准；语音输入真正要的是**能按住的大靶面**；两态后整条输入区都是靶面，转写还能直接显示在这条上。
- **`AppVoiceButton` 加 `expanded` 形态**（172 行）而不是新建组件：两种形态共用同一套受控 listening / 手势 / 配色，新组件只会让「桌面档点按」这类契约被实现两遍、且 `AppVoiceButton` 会变成死代码。
- ⚠️ **触屏档 `AppFocusableAction.onTap` 必须传 null**（`hold ? null : ...`）：否则手指**点一下**就开口，与「长按说话」打架，误触即一段废转写。桌面档才点按即说。
- ⚠️ **文案优先级**：有草稿就显示**草稿**（实时反馈比固定文案有用），否则 listening ? '松开 完成' : '按住 说话'。⚠️ 不能写「松开 发送」——ADR §4 定的是落草稿、用户确认后才发，文案必须说真话。

  1. `tester.pumpWidget` 会**复用同类型同位置的 element** → 上一用例的 `_voiceMode` 漏到下一用例（表现为「切换按钮找不到」）。解法：`ProviderScope(key: UniqueKey(), ...)` 强制重建，两个测试文件的 harness 都改了。

## 诊断：`flutter` 报 `Operation not permitted`（不是权限位，是 TCC）
- **现象**：用户终端 `% flutter` → `bash: /Users/annilq/Documents/fulttersdk/flutter/bin/flutter: Operation not permitted`。
- **排除项（逐条实测）**：文件 `-rwxr-xr-x` 有执行位（缺位是 `Permission denied` 不是 EPERM）；`xattr` **无** `com.apple.quarantine`（只有 `com.apple.provenance`）；卷是普通 apfs 非 noexec；`ls -lO` 无 uchg 锁标志。
- **决定性证据**：**同一个文件，我的 shell 里 `flutter --version` 直接跑通**（Flutter 3.47.6 / Dart 3.13.5），`bin/dart --version` 也通 ⇒ 文件与内核层面都没问题，差异在**会话级权限**。旁证：我这边 `ps` 也是 `operation not permitted`（沙盒拦），但 exec 未拦。
- **根因**：SDK 装在 **`~/Documents/fulttersdk/flutter`**，macOS 用 **TCC 保护 `~/Documents`**；终端（尤其 SSH / 非 GUI 会话，用户提示符 `annilq@192`、hostname `192.168.5.112`）exec 那里的脚本会被内核拒。Flutter 官方因此推荐 `~/development/flutter`。
- **解法二选一（用户选了前者）**：① 系统设置 → 隐私与安全性 → 完全磁盘访问 → 勾终端 App（**GUI 终端有效，SSH 无效**）；② 迁移 SDK 到 `~/development/flutter`（同卷 mv 只改元数据，4.5G 秒级、可逆）。
- **迁移的话要同步改的引用点**：`~/.zshrc:18` 的 `export PATH="/Users/annilq/Documents/fulttersdk/flutter/bin:$PATH"`；`frontend/android/local.properties` 的 `flutter.sdk=`；平台目录的 `FLUTTER_ROOT`（`{macos,ios}/Flutter/Generated.xcconfig` + `flutter_export_environment.sh`，由 `flutter pub get` 重生成，不在 VCS）。
- ⚠️ 已确认：同卷（device id 均为 16777230），磁盘余 27G 足够。

## ⭐ 真机问题「说中文识别成英文」= 没传 localeId（ADR-0063 §6.1）
- **根因**：`PlatformSpeechGateway._startSession` 调 `_speech.listen` 时**没传 `localeId`** → 插件用**系统默认 locale**，而开发/教室机器系统语言常是英语 → 中文被识别成英文。
- ⚠️⚠️ **7.5.0 的两个 API 坑（都会静默失效，lint 只给警告）**：
  1. `listen` 的顶层 `localeId` 参数**已 `@Deprecated('Use SpeechListenOptions.localeId instead')`** → 必须挂在 `SpeechListenOptions(localeId: ...)` 上。旧写法编译得过、运行不生效。
  2. `locales()` 是**异步方法**（`Future<List<LocaleName>>`），**不是 getter**，且必须 `initialize()` 之后才有数据。（`systemLocale()` 同理是 async。）
  3. `SpeechListenOptions` 定义在 **`speech_to_text_platform_interface`** 包（被 export），不在 `speech_to_text` 的 lib 根目录——想看字段别找错文件。
- **选择策略**（`_chineseLocale()`，结果缓存）：`locales()` → 筛 `norm(id).startsWith('zh')` → **简体优先**（`zh_cn`/`zh_hans`）→ 否则第一个 `zh*`（繁体也比英文强）→ 都没有则 null。⚠️ `norm` 必须把 `-` 换成 `_` 再小写，因为平台给 `zh_CN`/`zh-CN`/`zh-Hans-CN` 三种写法。
- ⚠️ **取语言失败绝不能打挂会话**：mocktail 未打桩的 `locales()` 返回 null（`locales.where` 直接 NoSuchMethodError），真机取列表失败同理 → 整段包 try/catch，退回 null + 日志说明装包路径（macOS 系统设置 → 键盘 → 听写；iOS 设置 → 通用 → 键盘 → 听写）。这是「界面一切正常、识别结果全是英文」的静默失效高发处。
- **测试**：`voice_input_gate_test.dart` 新增 6 用例（有 zh_CN 必带 / 简体优先 / `zh-Hans-CN` 归一 / 只繁体不退英文 / 无中文包退 null / 抛异常不打挂）。捕获方式沿用既有 `invocation.namedArguments[#listenOptions] as SpeechListenOptions`。门禁文件 **13 全绿**；全量 **341 通过 / 1 失败**（仍是另一会话 436 行）。
- **未做的增强**：`SpeechListenOptions.contextualPhrases` 可注入数学术语（三分之二/方程/轴对称）压低术语误识，但 Android 会忽略、跨平台不一致，已记进 ADR §6.1 待验证。
- ADR-0063 新增 §6.1。未提交。

## ⭐⭐ 真机问题「能识别中文，但点了发送没反应」= clearDraft 抢在 onSend 前面（ADR-0063 §4.1）
- **根因（两层交界的顺序 bug）**：`AssistantInputBar._send()` 原写法先 `clearDraft()` 再 `widget.onSend()`。`clearDraft()` 把 `draft` 置空 → 触发「draft → 输入框」回写监听 → **把 controller 清空** → 页面 `_AssistantChatPageState._send()` 读到空文本 `if (text.isEmpty) return;` → 静默不发。
- ⚠️ **为什么既有测试全绿照样漏**：`_pump` 的 `onSend` 是 `() {}` 占位。测试 harness 里的 `onSend` **必须照抄页面真实行为**（读 controller → 空则 return → 否则记录并 clear），否则这类 bug 永远测不出来。这次就是靠改 harness 才复现出 `Actual: []`。
- ⚠️ **纯键盘输入踩不到**：draft 本就是空，`copyWith(draft: '')` 不产生变化、监听不触发 → 表现为「用过一次语音之后发送才失灵」。
- **修法三件套**：① `_send()` 顺序改为 `onSend()` → `clearDraft()`；② `VoiceSession.cancel()` 里 `_sub?.cancel()` **就地断开**（不等平台 async cancel 返回），避免迟到的 final 转写在发送后把文本写回输入框；③ 输入框为空时发送按钮置灰（`_canSend` + controller listener），把「点了没反应」变成可见状态。
- **另一处守卫盲区**：`AppPrimaryButton.onPressed` 为 null 即禁用，断言方式用 `tester.widget<AppPrimaryButton>(...).onPressed` 读属性，别去 tap（禁用态 tap 被忽略且不抛错，断言难写）。
- **验证**：`assistant_input_voice_mode_test.dart` +3 用例（发送真的发出去 / 发送后「重说」消失 / 空文本置灰），该文件 9 全绿；语音三文件 28 全绿；全量 **344 通过 / 1 失败**（仍是 `knowledge_point_scene_editor.dart` 436 行）。`assistant_input_bar.dart` 297 行、测试 301 行（均 <400）。
- ADR-0063 新增 §4.1（含顺序示例与「测试 onSend 不能占位」这条易漏点）。未提交。

## ⭐ 轴对称交互讲解：多图形改「图形画廊 + 弹窗演示」（ADR-0061 §V）
