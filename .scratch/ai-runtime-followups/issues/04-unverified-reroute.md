# 04: 无据正文改为换一个业务重来一次（至多一次）

> 标签：`done`（2026-10-21，ADR-0109）
> 来源对话：2026-10-21 用户「按照 4 个提案优化」提案 4
> 关联：ADR-0033（绝不静默降级，本票修订其**兑现方式**）、ADR-0043、ADR-0105、ADR-0107、
> ADR-0081、four-proposals 的 why 追溯（本票当时被判为「撞 ADR-0033」，落地时按该约束重写）

**落地摘要**：`requires_tool_data` 的末闸命中时，改为丢弃正文、排除当前业务再问一次决策模型，
问得出且过门控就换业务重来，问不出则**逐字维持**原 `TOOL_UNSUPPORTED`。
另两闸（正文是调用草稿 / 只有思维链）**不动** —— 那两个是模型能力问题，改了会把「换模型」
这个真问题藏起来。生产拓扑端到端实测：tasks 无据 → 决策模型点名 tutor → 讲解流出。

## Problem Statement

1. ADR-0033 的末闸把两种成因混成了一句提示：
   - **A 类（路由误判）**：「23+45 怎么算」被判给任务学情 → 模型直接作答（答对了）→
     用户拿到「请重试；若反复出现，请改用支持原生工具调用的模型」。
     **重试一万次也是同一条错误，且问题根本不在模型。**
   - **B 类（模型能力）**：小模型产不出原生 FC，直接编造业务数字（`c361dd01` 原型）→
     同一句话，而这句**恰好是对的**。
2. 同一句提示不可能同时正确；对 A 类它给的是一条不可执行的建议。

## Solution

```text
末闸命中 → raise UnverifiedAnswerError(text=acc)      # 正文随异常丢弃，从未进过事件轨
  → 排除当前业务再问决策模型
       判得出且过门控 → 换业务重来（交接帧显式可见）
       判不出 / 不过门控 → 维持 TOOL_UNSUPPORTED 原文
```

三条约束：

1. **只有末闸参与**（正文干净、无协议痕迹）；「正文是调用草稿」与「只有思维链」两闸不动。
2. **至多一次**：候选集排除当前业务；接手业务再无据时 `raise_unverified=False`，直接收原硬失败。
3. **只有自然语言路径开启**：`allow_reroute=True` 只由「业务是路由算出来的」那条路径传入
   （生产聊天路径 `service.py` 的 `decide → run`）。结构化出题自带 `business`（规格即意图），
   改判等于推翻调用方的显式指定。

### 为什么这不是静默降级

- **静默降级** = 放行正文（用户拿到假数据还以为是真的）；
- **重路由** = 换人。正文在抛异常前从未进过事件轨（思考缓冲要到末段才 flush），结构上
  就不可能被转发；交接本身在事件轨上显式可见（`THINKING(extra={"routing": True})`）。

### 落点怎么选

A/B 在该业务内部无从分辨（正文都是干净的自然语言），故让路由在排除当前业务后再判一次：

- A 类：这句话天然是讲解问题 → 排除 tasks 后给 tutor 高分 → 换人，用户拿到解法；
- B 类：「小明最近错题多吗」排除 tasks 后在 {tutor, capability} 上拿不到高分 → 不过门控 →
  维持原文，用户拿到「改用支持原生工具调用的模型」这句**正确的**建议。

只问决策模型（p50 23 ms），不问 LLM 分类（p50 1084 ms）；决策模型不可用 → 不猜，维持硬失败。

## Implementation Decisions

- **抛异常而不是 yield 帧**：调用方结构上不可能误把正文转发下去。
- **`allow_reroute` 做成 `run` 的显式 kwarg**（不是 `ctx.extra`）：`run` 是被多个测试桩覆写的
  公开接口，显式 kwarg 让覆写者必须表态——不接受的桩当场 `TypeError`，而不是静默丢掉一个新
  选项（本次据此补了 6 个桩的签名）。
- 排除一项不改变门控口径：`LayaDecisionModel._top_probability` 取 `probabilities` 的 top 值
  而非 TypeSafe 的 `confidence`，跨 K 可比（ADR-0107 定的口径）。

## 验证

- 新增 `tests/ai/test_unverified_reroute.py`（12 项）：默认仍是硬失败、opt-in 才抛且正文随异常
  带走、换人后无据正文一个字都没外发、候选集排除了刚失败的业务、换不出落点时提示语逐字不变、
  低于门控不换、**至多一次**（provider 只被问 2 次）、结构化路径不换、生产拓扑 tasks → tutor
  端到端、生产拓扑换不出时维持原文。
- `tests/ai/test_tool_loop_bounds.py` 守住另两闸**不受影响**。
- 全量后端 **1078 passed / 2 skipped / 1 环境性红**（与基线一致）。

## 已知局限（未处理，留待另开票）

轨迹里 `routing` 步记录的是**首路由**的业务；重路由后的实际接手者只出现在交接思考帧里
（前端可见，轨迹步不重写）。
