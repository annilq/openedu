# 08: 作业派发对象关系与批量派发

**What to build:** 引入「作业派发对象」关系（任务 + 学生 + 派发时间 + 完成时间，`(task, student)` 唯一，唯一约束写在 `CREATE TABLE` 里）。派发接口从单学生改为「班级列表 + 学生列表」，服务端展开后按学生去重、原子写入。任务状态从「一个学生的状态」变为**作业整体状态**：首次派发后置为已派发；**全部**派发对象都有完成时间时自动转已完成；取消派发 / 取消全部回退待派发。迁移从旧单值学生列幂等回填派发关系。旧单值列保留作过渡态、新代码只读关系、不做双写（contract 删列本轮不做，后续单独立项）。

**Blocked by:** 01: 班级实体与 CRUD 端点（班级作为派发分组来源）

**Status:** done

**Done note (2026-10-07):** `TaskAssignment` 模型（`db/models/task_assignment.py`，唯一约束写 `CREATE TABLE`）；`tasks/service.py` 含 `bulk_assign_task`/`create_task_assignment`/`cancel_assignments`/`mark_assignment_completed` + 整体状态语义（全完成转 done）；`core/db.py` 迁移建 `taskassignment` 表。非派发对象 403 与只完成一半仍 assigned 属 09/14 验收。
