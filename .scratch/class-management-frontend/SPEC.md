# Spec：班级管理前端（容器 + 下钻）与年级语义反转

> 决策依据：[ADR-0086 班级管理前端（容器 + 下钻）](../adr/0086-class-management-frontend.md)。
> 上游后端：[ADR-0068 班级实体与学生管理](../adr/0068-class-entity-and-student-management.md)（已落地）。
> 术语以 `CONTEXT.md` 为准（教师 / 学生账户 / 班级 / 年级 / 学情 / 答疑）。
> 本文件是 GitHub issue 的正文源；落库后以 issue 为准。范围：ADR-0086 全文（含 2026-10-11 年级语义反转）。
> ⚠️ 年级语义已于本轮反转：学生不再持有独立年级字段，年级完全由所属 `Class` 承载。

## Problem Statement

教师现在能在后端管班级、按班级分学生、Excel 导入导出，但**前端没有一处可以"看到并管理班级"的界面**，学生管理也只是一个扁平的全量列表。具体卡点：

1. **班级管理界面不存在。** `features/classes/` 只有 `data/` 和 `providers/`，没有 `presentation/`。`student_management_screen.dart` 里那个班级选择器的空态还写着「请先在侧栏新建班级」，可这个入口根本没有。教师无法在 App 里建班、改名、删班。
2. **学生管理没有"班级"这一级导航。** 现有学生管理是全部学生的扁平视图，班级只是里面的一个分组维度；教师想"进到某个班里面去管这一班的人"做不到，只能回到全量列表再筛选。
3. **年级在两端各说各话、且会失同步。** 原先学生身上有一个可空的 `grade` 字段，班级也有 `grade`；学生加班/改班时要手动把班级年级抄回 `user.grade`，未分班/导入待分班学生则留空。这条"抄写"链路既是冗余，又会在任一处漏写时让学情/答疑读到的年级与真实班级不一致。
4. **年级字段对未分班学生无意义。** 未分班学生既没有班级也没有年级，硬留 `user.grade` 只是多一个永远为空、又必须处处兜底处理的字段。

## Solution

两件事一起做：

**A. 班级管理前端（容器 + 下钻），落地 ADR-0086。** 新增一级导航「班级管理」，进去做班级卡片列表（建/改/删）；点班级卡片下钻到该班的学生管理页（复用既有 `StudentManagementScreen`，用 `classId` 参数化，而不是再造一份学生列表）。原「学生管理」保留为全局扁平视图（含「未分班」）。

**B. 年级语义反转（2026-10-11）。** 删除学生身上的 `grade` 字段，年级的唯一来源变为所属 `Class.grade`。班级名可直接编码年级（如 `1级2班`），展示层无需单独的年级列。任何消费方需要学生年级时，一律经 `user.class_id` 解析到班级后取 `class.grade`（唯一入口 `_student_grade`），未分班返回 0。

## User Stories

1. 作为教师，我想在导航里看到「班级管理」入口，以便进入班级管理界面。
2. 作为教师，我想在班级管理页看到所有班级的卡片（名称 + 年级 + 人数 + 下钻箭头），以便一眼掌握分班全貌。
3. 作为教师，我想新建一个班级（名称 + 年级 1–9），以便开始把学生分组。
4. 作为教师，我想给班级改名或改年级，以便在学期初调整分班。
5. 作为教师，我想删除一个班级，以便清理建错的班；删班时班内学生只转未分班、账号与错题保留。
6. 作为教师，我想在班级列表看到每个班多少人，以便核对分班结果。
7. 作为教师，当还没有任何班级时，我想看到空态引导我去「新建班级」，而不是一片空白。
8. 作为教师，我想点一张班级卡片下钻进去，看到**只属于这个班**的学生列表，以便专注管理这一班。
9. 作为教师，下钻页里我不想看到"全部/各班/未分班"筛选 chip（因为我已经在某个班里了），以便界面简洁。
10. 作为教师，下钻页标题应显示「{班级名} · N 人」，以便我知道当前在哪个班。
11. 作为教师，下钻页里「返回」应回到班级管理列表，而不是回到全量学生管理。
12. 作为教师，在班级下钻页里「添加学生」时，新增学生默认归入本班，以便不用再手动选班级。
13. 作为教师，在班级下钻页里「导入学生」时，导入的学生直接归入本班，以便免去"导入后再分班"。
14. 作为教师，在班级下钻页里我可以搜索本班学生（按姓名/学号），以便几十人里快速定位。
15. 作为教师，在班级下钻页里我可以批量把学生移出本班 / 移入他班，以便学期末调整。
16. 作为教师，在班级下钻页里我可以删除某个学生账号（级联清错题/作答/打卡/答疑），以便清理垃圾数据。
17. 作为教师，我想保留「学生管理」作为全部学生的扁平视图（含未分班分组），以便从全局视角操作。
18. 作为教师，我希望别人无法查看、修改、删除我的班级与学生，以便数据隔离（后端归属校验）。
19. 作为教师，我希望年级信息始终与我给班级设的年级一致，无论学生是否已分班，以便学情/答疑不出错。
20. 作为学生，我希望自己属于哪个班、对应哪个年级由老师分班决定，而不是我或系统单独记一个会过期的年级。
21. 作为开发者，我希望年级只从班级解析、不要有第二份学生年级字段，以便不会出现"两处年级不一致"的 bug。
22. 作为开发者，我希望下钻页复用既有学生管理页而非复制，以便不养出两份学生列表实现。
23. 作为开发者，我希望导航状态只有单一来源（扩展 `sealed TeacherPage`），以便不会出现两个并行的导航状态。
24. 作为开发者，我希望所有新增页面都在不套 Material 的树里真构建一次，以便不出现 `flutter analyze` 查不出的崩溃。

## Implementation Decisions

### 信息架构：班级管理（容器）+ 下钻

- 新增一级导航项「班级管理」（`TeacherPage.classManagement`），与「学生管理」并列，不取代它。
- 「班级管理」页 = 班级卡片列表；点卡片 → 下钻到该班学生管理页（push 整页非浮层，遵循 ADR-0047/0048，禁止裸 `Navigator.pop`）。
- 原「学生管理」保留为「全部学生」扁平视图（含「未分班」）。
- 导航单一源：扩展 `sealed TeacherPage` 增加一个 case（ADR-0059），所有入口只调 `_go(page)`，禁止再开并行状态。

### 班级管理列表页（classes 的 presentation）

- 列表项：名称 + 年级标签（1–9）+ 人数 + 下钻箭头；行内「重命名 / 删除」走页内联浮层（不用 Material `Dialog`，保持无 Material 祖先）。
- 顶部「+ 新建班级」：内联表单（名称 + 年级 1–9 选择器），提交建班。
- 重命名 / 改年级：底部抽屉表单。
- 删除：确认浮层 → 后端仅把班内学生 `class_id` 置空（保留账号与错题），前端提示「N 名学生已转为未分班」。
- 空态：`AppEmptyState`（解释为什么空 + 下一步「新建班级」）。

### 班级下钻页（复用并参数化学生管理）

复用既有 `StudentManagementScreen`，新增构造参数 `classId`（`String?`）做参数化，而非再造列表：

- `classId == null`（原学生管理）：全量 + 未分班；显示班级筛选 chip；标题「学生管理 · N 人」；添加/导入不预填班级。
- `classId != null`（班级下钻）：`GET /students?class_id=`；隐藏筛选 chip；标题「{班级名} · N 人」；返回班级管理；添加/导入默认归属本班（`class_id` 预填）。

班内学生操作：查看名册（搜索走 `GET /students?class_id=&keyword=`，分组客户端做）、批量移班（复用 `POST /students/batch-reassign`）、删除学生（级联清理，后端已就绪）—— 这三项**全用既有端点**，故下钻页（ticket 04）可与后端 class_id 扩展（ticket 05）并行。"单个添加 + 导入直接归入本班" 依赖后端 class_id 扩展，单列 ticket 06（block 04 与 05）。

### 年级语义反转（2026-10-11，已落地）

- **删除学生独立年级字段**：`UserBase` 不再有 `grade`；迁移在 `_add_classes` 中 `DROP COLUMN grade`（旧库向后兼容，极老 SQLite 包在 `try/except` 兜底）；`UserUpdate` / `update_user` / `students/router` 同步移除 `grade` 形参；前端 `UserModel` 及整条仓库链（repository / datasource / notifier / form / picker / detail / home / profile / 测试桩）全部去 `grade`。
- **年级唯一来源 = 所属 `Class.grade`**：班级名可直接编码年级（如 `1级2班`），展示层无需单独的年级列。
- **统一解析入口**：任何消费方需要学生年级时，一律经 `user.class_id` 解析到班级后取 `class.grade`，唯一入口为 `assistant.service._student_grade`；未分班（`class_id` 为空）返回 `0`。`ai/subagents/query/tools/_shared.py` 的 `student_meta` 已不再回传 `grade`（其调用处无 session 可解析班级年级）。
- **不保留 `user.grade` 字段**（采用原被否决的「学生年级=班级」方案）：未分班学生年级解析为 0，不影响既有消费方——它们本就只在已分班/校内场景读取。

### 后端小扩展（必要缺口）

- `POST /students`：请求体已可携带 `class_id`（经共享 `UserCreate`/`UserBase`），缺口是**缺少对 `class_id` 归属当前教师的校验**——须在落库前用 `require_owned` 校验班级归属。
- `POST /students/import`：当前**不接受** `class_id` 参数；需新增可选 `class_id`，导入行直接归入该班（模板仍只「姓名/学号」两列不变），并做归属校验（越权整体失败）。
- 两项扩展均复用既有 `core.guard` 归属校验（分层不变量 9），不内联 `teacher_id` 比较。

### 边界与红线

- 文件规模棘轮：新增列表/表单/确认浮层拆独立 widget 并在 `test/file_size_guard_test.dart` 的 `_baseline` 登记（只许下调）。
- 全站禁 Material 控件；新增控件必须在不套 Material 的树里真构建。
- 导航回落走单一出口，不用裸返回调用（ADR-0059）。
- 复用 `StudentManagementScreen`，不复制学生列表实现。

## Testing Decisions

### 接缝（两条，一进一出 + 一处导航）

1. **前端主接缝（输出侧，ticket 04）**：复用并参数化后的 `StudentManagementScreen`——喂不同的 `classId`（null / 某班 id），断言加载的端点（`GET /students?class_id=`）、是否显示筛选 chip、标题文案、返回落点、班内查看/批量移班/删除。`classId != null` 时断言看不到"全部/各班/未分班" chip、标题含班级名、返回回到列表。这是最高接缝：班级下钻的全部外部行为都能从 `classId` 这一个输入观察。
2. **前端次接缝（ticket 06）**：下钻页「添加学生 / 导入学生」入口——断言提交后 `class_id` 落为本班（依赖 ticket 05 后端），用假仓库 + 后端端点接住保存调用。
2. **前端次接缝（班级管理列表）**：新建 `ClassManagementScreen` —— 断言卡片渲染（名称/年级/人数/下钻箭头）、新建表单提交、重命名、删除后提示「N 名学生已转为未分班」、空态出现。列表行为用假仓库接住保存/删除调用即可，不必驱动真实持久化。
3. **前端导航接缝（单源纪律）**：扩展既有 `teacher_nav_single_source_test.dart`，断言新增 `TeacherPage.classManagement` 后，所有入口只经 `_go(page)`、无并行状态。不新建导航测试文件。
4. **后端接缝**：REST 端点（FastAPI TestClient + 临时 SQLite，夹具沿用 `backend/tests/conftest.py` 与 `tests/utils/user.py`）——`POST /students` 带 `class_id` 后该生 `class_id` 落库且属当前教师；带他人 `class_id` 应 403；`POST /students/import` 带 `class_id` 后导入学生归入本班且 `username` + 初始密码能登录；越权整体失败。

### 什么样的测试算好

- 只断言**外部行为**：端点响应 + 随后的 `GET` 结果；widget 可见结果（卡片数/文案/chip 有无/返回落点）。
- 不测实现细节：不断言内部方法调用、不靠 widget key 数内部结构、不单测私有状态。
- 每条用例必须能被一句产品语言描述（"在班级下钻页添加学生，新建学生就归这个班"），只能用实现语言描述的说明接缝选低了。

### 覆盖的模块

- 导航：`sealed TeacherPage` 扩展 + `teacher_nav_single_source_test`。
- 班级管理列表页：卡片 / 新建 / 重命名 / 删除 / 空态。
- 班级下钻页：参数化 `StudentManagementScreen` + 班内四项操作。
- 后端：`POST /students` 与 `/students/import` 的 `class_id` 归属校验。
- 年级解析：既有 `assistant/service` 测试桩已补 `class_id=None`（解析为 0），年级回归经 `class_id` 解析 `== class.grade`。

### 既有先例（照抄其手法）

- `teacher_nav_single_source_test`：导航单源纪律的回归网，扩展 case 时同步更新。
- `test/file_size_guard_test`：单文件 ≤400 行基线，新增/改动的每个文件都要过行数基线。
- 全仓禁 Material 祖先：新增控件必须在不套 Material 的树里真构建。
- 后端端点测试缝：`tests/api/routes/test_student_import.py` 等学其形状（临时 SQLite + 身份助手）。

### 回归要求

- 前端 `flutter analyze`（认 `No issues found!`）+ `flutter test`（先关代理），0 回归。
- 后端 `ruff check` + `pytest`（沙盒带 `--basetemp` 指向新目录），0 回归。
- 年级回归：加入班级后消费方经 `user.class_id` 解析的年级 `== class.grade`；移出班级后 `class_id` 为空、年级解析为 0、不报错。
- 原「学生管理」扁平视图与未分班分组观感一字不变。

## Out of Scope

- 多班归属（学生可属多个班）。
- 班级间共享题库 / 资料（ADR-0065 §7 维持关闭）。
- 学生自助加班 / 班级码加入。
- 班级排序拖拽（v1 按 `created_at` 排序）。
- 班级封面/头像等扩展档案。
- 年级在展示层单独成列（已由班级名编码 / 班级年级标签承载）。

## Further Notes

- **年级反转是本轮最易漏的回归源**：凡是读 `user.grade` 的旧消费方都必须改走 `class_id` 解析；本 spec 落地时全局 grep 已确认 `app/` 内无 `user.grade` 残留，仅剩 `db.py` 一处说明注释与独立语义字段（`Class/Question/Material/...grade`）不受影响。
- **class_id 扩展的"已做/未做"边界**：`POST /students` 已能透传 `class_id`（共享 schema 自然带上），真正的缺口是**归属校验缺失**与 **import 无 class_id 参数**；ticket 05 只补这两处，不重写建生逻辑。
- **复用优先**：下钻页是参数化既有 `StudentManagementScreen`，不是新列表；新增页面只做"班级管理列表"一个，避免过度实现。
- **与既有 epic 的归属**：本轮是前端班级管理 + 数据模型收口，不并入纯内容填充的 epic；向后端只追加两个小校验，不碰 ADR-0068 已稳定的端点主体。
- **文档归属**：决策在 ADR-0086（含 §2.4 反转），本 spec 只做可执行展开；两者冲突时改 ADR，不在本文件里偷偷改口径。
