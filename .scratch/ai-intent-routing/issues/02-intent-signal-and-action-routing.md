# T02 — 意图信号与动作直配内核

**What to build:** 把路由的输入从「一段文本」升级为**结构化意图信号**（原始文本 + 结构化动作键 + 结构化上下文），
并新增**动作直配**作为第一级路由：动作键与各 SubAgent 清单里声明的 `actions` **等值**匹配，命中即路由。
它排在触发词匹配**之前**，且**不参与优先级排序**——所以不存在「谁的词更长、谁的优先级更高」，也就没有竞争。

配套三条硬边界：
- 动作命中但业务对当前角色**不可见** → 返回显式的「动作不可见」，**不许**沿用「换成第一个可见业务」的静默兜底；
- **未知动作** → 落回自然语言路由，不报错（容错）；
- 出题助手声明拥有「按规格出题」与「换一题」两个动作——这是「哪个业务拥有哪个动作」的唯一声明处，
  不在对话编排里写 `if`。

**Blocked by:** T01
**Status:** ready-for-agent

> 信号类型形状（来自设计底稿，非可运行原型；只列承载决策的部分）：
>
> ```
> IntentSignal:
>   text:    str              # 用户原始输入，结构化请求可为空
>   action:  str | None       # 结构化动作键
>   context: dict | None      # 结构化上下文（课件 / 待判定态）
> ```

## 决策锚点

- 动作直配用**等值**比较而非包含匹配，且位于触发词之前、不参与优先级排序 → 这是「消除竞争」的机制本身，不要为了省事复用触发词的包含匹配逻辑。
- 唯一性由契约测试保证（每个动作恰好一个归属业务），因此**不需要**为动作通道设计排序规则。
- 不可见必须显式：静默回落会把「你不能用这个功能」变成答非所问，不报错、不拦截，最难排查。
- 未知动作回落不报错，是有意取舍；代价是动作名与清单不同步时会**静默失效**，所以契约测试是硬要求而非可选项。
- 纯文本调用（不带动作）的路由结果必须与改动前**逐条一致**——本票不修任何自然语言路由问题（那是 T03）。

## 验收

- [ ] 给定「信号 + 角色」，动作等值命中正确业务，且**不受清单遍历顺序影响**（打乱顺序结果不变）
- [ ] 动作命中而业务对当前角色不可见 → 显式「动作不可见」，**不是**第一个可见业务
- [ ] 未知动作 → 落回自然语言路由，不抛错
- [ ] 每个已声明动作**恰好一个**归属业务：无孤儿（声明了但无请求方）、无悬空（有请求方但未声明）
- [ ] 纯文本调用（不带动作）的路由结果与改动前逐条一致
- [ ] 既有路由用例全绿（教师出题 / 教师查询 / 教师伴学 / 学生越权改判 / 学生查询可见 / 学生不安全输入被拦）
