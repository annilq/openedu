# T04 — 按规格出题走统一路由

**What to build:** 教师（与学生）按规格出题时，请求**经过与对话同一个意图路由**，而不是写死业务。
对话端点接受结构化动作，服务端按动作**合成**那条落库的用户消息，动作经意图信号交给统一路由，
产出与对话路径**同一套事件帧**。教师可用，学生也可用——而且学生这条路上输入安全闸门**真的被调用**。

**Blocked by:** T02
**Status:** ready-for-agent

## 决策锚点

- 落库的用户消息由**服务端按动作合成**，不由前端拼。它同时解决三件事：请求体的非空校验、
  会话名可读（会话名取首条消息截断）、以及历史里能认出哪一条是出的卷。
- 学生可用，且**不做角色门禁**；但动作不可见时要显式报错（T02 已立），
  不静默回落——静默回落会把越权变成答非所问。
- 跨切面能力现在自动生效：输入安全闸门、资料库检索、学科提示、溯源引用、工具信封。
  其中**安全闸门**是修掉一个真实缺口：此前结构化出题那条链路把闸门设为「无」，学生出题不设防。
- 会话照常落（不是临时的），这是历史里能回看「出过什么卷」的前提。

## 验收

- [ ] 带动作的请求经统一路由到出题助手（动作直配命中），对话编排里不再有「有动作就写死业务」的分支
- [ ] 学生发同一动作时，输入安全闸门**被调用**（此前该链路没有）
- [ ] 落库的用户消息由服务端按动作合成；会话名可读、历史里能辨认这是出的卷
- [ ] 事件帧序列与对话路径同一套（运行开始 / 用户消息 / 路由思考 / 工具调用 / 数据 / 完成）
- [ ] 学生打教师专属动作 → 显式报错，**不是**被静默改写成另一个业务的回答
- [ ] 学生出的题有落点（接上错题本/掌握度由 ADR-0082 负责，本票只需不阻断）
- [ ] 契约测试守住：请求体的动作名与清单声明同步（不同步会静默失效）
