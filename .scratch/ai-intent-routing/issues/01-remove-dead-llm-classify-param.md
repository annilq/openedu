# T01 — 删除从未生效的 LLM 意图分类器参数（prefactor）

**What to build:** 让路由的文档形态与代码形态一致。路由模块收下一个「可选的 LLM 意图分类器」参数，
函数体里**从来没有调用过它**；依赖端口声明了它，而两个依赖构造点也**都没有注入**。
删除参数本体、端口声明与运行时透传，让「规则匹配 → 启发式兜底」成为真实的、也是文档所写的形态。

**Blocked by:** 无（可立即开工）
**Status:** ready-for-agent

## 决策锚点

- 本次是**纯清理**，路由行为零变化：没有调用方依赖这个参数，删掉不改变任何一次路由结果。
- 之所以放在最前（prefactor）：T02 要改同一个分类函数与 `decide` 的签名，先清掉一个无用参数，
  T02 的改动面才是干净的，也不会有人误以为「接上它就好了」。
- 真需要弱意图兜底时，重写一个**真的被调用**的扩展点，并把「是否启用」做成显式配置——那是独立议题，不在本票。

## 验收

- [ ] 路由模块的分类函数不再接受该参数；调用它的运行时不再透传
- [ ] 依赖端口不再声明该字段（含其说明文字）
- [ ] 路由模块与端口的 docstring 里「规则 → 启发式 →（可选）LLM 兜底」的三级表述改为两级，不再承诺不存在的兜底
- [ ] 两个依赖构造点无需改动即仍可工作（它们本来就没注入该参数）
- [ ] 既有路由用例全绿；全量后端回归无失败
