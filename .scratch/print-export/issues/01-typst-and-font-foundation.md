# 01 — Typst 排版基建与中文字体

**What to build:** 让后端具备「可靠地编译出含中文的 PDF」这一能力，且中文不能成为豆腐块。

引入 `typst` 依赖与一份中文字体，新增 `EXPORT_FONT_DIR` 配置项（**不在代码里硬编码路径**），
并沿用 ADR-0041 的启动冒烟模式加一条校验：字体不可用时生产环境拒绝启动、开发环境告警。
再建一条最小编译通道（一份三行字的模板），验证两件事在本仓库确实成立——
编译器能经额外的字体目录拿到字形、能把一段 JSON 作为输入喂进模板。
编译失败（尤其字体缺失）必须返回**明确的错误**，不允许静默产出一份全是豆腐块的 PDF。

这一票是后面所有票的地基：字体是整个功能最大的未知，必须在铺任何业务逻辑之前坐实。

**Blocked by:** None — can start immediately

**Status:** done（本地实现，gh 未登录未发 GitHub）

- [ ] 指定中文字体目录后，最小模板编译出的 PDF 里中文字符正常显示——由人打开 PDF 肉眼确认，不是靠断言
- [ ] 字体无关部分的等量验证：同一份模板配拉丁文本能编译通过（用于区分「字体问题」和「编译器问题」）
- [ ] 字体目录缺失时：启动冒烟给出告警（开发环境）/ 报错（生产环境），且编译入口返回可展示的「字体缺失」错误，而不是产出豆腐块 PDF
- [ ] JSON 输入通道可用：题目数据能从外部注入模板并被读到
- [ ] 依赖可在 CI 与 Docker 镜像内安装就绪，无系统级原生库需求
- [ ] `ruff` 干净，后端现有测试全绿
