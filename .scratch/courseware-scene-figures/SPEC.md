# Spec：课件交互场景环节的多图演示（有序图形集）与只读画廊 play 进编辑

> 上游：ADR-0076。本 spec 是其可执行展开，决策以 ADR 为准，冲突时改 ADR 不改本文件。
> 拆分落地见本目录 `issues/01`–`04`。术语遵循 `CONTEXT.md`（课件 / 讲解环节 / 交互讲解场景 / 场景库 / 知识点）。

## Problem Statement

教师准备一节轴对称的课时，想在课件的一个**讲解环节**里先给学生摆出一组图形，让他们**对比着看、自己找规律**（哪些对折后重合、哪些不重合），而不是只演示一张图。

今天做不到：

- 课件环节里嵌的那份 SceneSpec 是**从知识点场景快照复制进来的一份默认讲解**，一个环节只对应**一张**图形。要展示第二张，教师只能退出去改关联或换环节，课堂上根本来不及。
- 讲课页那张图**一上来就在可操作状态**（或按 spec 配置的可交互态），教师没法先"只展示、不让学生乱动"，再在需要时放行某个图形让学生亲手折。
- 即使把若干张图摆出来，如果缩略图上直接标了"这个图形是轴对称"，学生扫一眼就拿到答案，"找规律"当场退化成"看答案"，动手验证这个动作也就死了。

结果就是：同屏对比这件最基础的教学动作，在当前课件里没有承载方式。

## Solution

让**课件环节自己携带一组有序图形**，讲课页按数据自动决定怎么摆：

1. **教师在本环节勾选要演示哪几个图形、按什么顺序。** 勾选结果写进本环节的 `section.scene`（环节级副本），不动知识点场景、不动后端 schema。
2. **讲课页按数据分派形态**：环节只有一张图 → 走今天的单场景渲染路径，是否可交互仍由 spec 自己配置；环节有一组图 → 渲染只读画廊网格，一屏并排摆开。
3. **画廊里的每张图是只读的**——只画轮廓和初始对称轴，不判、不标答案；右上角给一个 **play 角标**，点任意一处弹开对话框，进入可操作状态，能旋转 / 平移对称轴亲手验证。
4. **每张图弹开时的初始轴取该图形自带的默认轴**，不套用本环节配置的轴，避免横向图形一打开就停在竖轴上、看着像"题目错了"。

关键前提：这套能力的主体在仓库里**已经存在**（spec 带 `optionGroup` 时解释器就渲染只读画廊 + 点击弹可编辑演示）。本轮真正要新建的只有一件事——**课件语境下由谁来供给"哪几张图、什么顺序"**。

## User Stories

1. 作为教师，我想在课件的交互场景环节里勾选多个图形，以便一节课内同屏演示一组例子。
2. 作为教师，我想决定这组图形的**排列顺序**，以便按自己的教学逻辑组织（先对称、后不对称，或由易到难）。
3. 作为教师，我想只勾子集而不是被迫展示全部图形，以便围绕当堂目标裁剪，不让学生被无关图形干扰。
4. 作为教师，我想在勾选后立刻看到预览，以便确认顺序和图形对不对再保存。
5. 作为教师，我想随时改这组图形（加、删、换顺序），以便课后复盘时微调下一节课的演示。
6. 作为教师，我希望我的勾选**只影响本课件本环节**，以便调整演示不会污染知识点上的默认讲解和其他课件的环节。
7. 作为教师，我想在讲课（大屏演示）时看到这组图形并排摆开，以便让全班同时看到全部例子进行比较。
8. 作为教师，我想默认展示态是**只读**的，以便先讲解、不让学生一边听一边乱拖对称轴。
9. 作为教师，我想在需要时点某张图上的 play 把它打开，以便当场请一个学生上来亲手对折验证。
10. 作为教师，我希望点击区域是**整张卡**而不只是那个小图标，以便在大屏/触屏上稳定命中，也方便用手指和激光笔操作。
11. 作为教师，我想在弹窗里让学生旋转和平移对称轴，以便验证"这一条轴折过去能不能重合"。
12. 作为教师，我希望每张图打开时的初始轴是**该图形自带的对称轴方向**，以便画面一开始就是合理的，不用我先解释"为什么这条轴歪着"。
13. 作为学生，我想一眼看到好几个图形排在一起，以便自己比较、发现规律。
14. 作为学生，我想自己动手拖对称轴并立刻看到是否重合，以便通过操作建立直觉，而不是听结论。
15. 作为学生，我不希望在只看不动的状态下就被告知"这个是轴对称"，以便"找规律"是我想出来的而不是被告诉的。
16. 作为学生，我希望打开某张图时只影响这一张，以便我反复试不同的轴而不影响其他图形。
17. 作为教师（题库场景），我希望题库、错题、AI 讲解里的图形画廊**保持今天的行为**（整库铺开、带选项角标），以便探索类练习不受本轮改动影响。
18. 作为教师，我希望即使断网或后端不可用，已保存的这组图仍能渲染，以便课堂上不会因为依赖查询而出现"图形出不来"。
19. 作为教师（键盘/无障碍），我希望 play 入口可被聚焦并有语义标签，以便屏幕阅读器和键盘用户知道这张卡可以打开演示。
20. 作为开发者，我希望多图能力复用已有的 `optionGroup` 载体而不是新增一种场景类型，以便"同一模板派生多份实例"只有一份表达、不出现第二套平行语义。
21. 作为开发者，我希望"整库探索"与"教师编排"由**显式开关**区分，以便不会因为两者都带非空条目而被误判，造成题库路径的静默回归。
22. 作为开发者，我希望讲课页环节组件**不认识**任何 SceneSpec 字段，以便课件环节与场景规格的边界不被腐蚀。
23. 作为教师，我希望环节只有一张图时讲课页仍和今天一模一样，以便已有的课件（含已做好的演示课件）不受影响。
24. 作为教师，我希望在课件编辑器里看到清晰的空态与引导，以便知道这个环节"还没选图形"时该点哪里。
25. 作为教师，我希望勾选界面沿用全站一致的选中/焦点语言与图标，以便不出现另一套视觉方言。

## Implementation Decisions

### 数据载体：复用 `optionGroup`，不新增场景类型、不改后端

- 课件环节勾选的图形**就地写进本环节的 `section.scene`**，沿用 SceneSpec 里已有的 `optionGroup` 结构。新增一种 kind 或独立字段都会让"同一模板派生多份实例"出现第二份平行表达。
- **后端零改动**：课件环节的 `scene` 本身是裸 dict 透传、不校验、不剥字段，塞进 `optionGroup` 即可持久化；不需要新端点、不需要改 schema、不需要动题目侧的抽取逻辑。
- 条目的形状与题目侧抽取出来的**完全一致**（`label` / `caption` / `figureKey` / `points` / `defaultAxisAngle`），因此前端解析与前后端图形一致性门禁都不必改。课件语境没有 A/B/C 选项，`label` 留空串，`caption` 用图形中文名，**顺序即数组的顺序**（教学编排意图就落在顺序里）。
- 与"场景快照不可变"无冲突：环节里的 `scene` 是关联时快照复制进来的**环节级副本**，写入只看本课件的本环节，绝不回写知识点上的 `scenes`。

### `optionGroup` 增开 `curated` 显式开关

```jsonc
"optionGroup": {
  "curated": true,   // true = 只按 items 顺序渲染（课件编排）；缺省/false = 整库探索（题库现有行为）
  "items": [ { "label": "", "caption": "正方形", "figureKey": "square",
               "points": [[x,y]…], "defaultAxisAngle": 90 } ]
}
```

- **必须是显式开关，不能"有条目就裁剪"**：题库路径的条目恰好也非空（它们就是选项），两种语境无法靠有无区分；一旦裁剪，等于静默剥夺学生在题库里自由探索其余图形的能力——而那是刻意的产品决策。这是本轮最容易出静默回归的地方，必须有测试守。
- `curated: true` 时按条目的数组顺序解析出图形列表交给画廊，**不再走库序重排**。
- 解释器从 spec 里就地读取该开关后向下传参，**对外签名不变**，避免波及全部调用方。

### 讲课页按数据动态分派，不做"大画布 + 画廊"混合形态

- 环节**没有** `optionGroup` → 今天的单场景渲染路径；**是否可交互仍由 spec 自己的 `editable` 决定**，本轮不改这条口径。
- 环节**有** `optionGroup`（无论 `curated` 与否）→ 画廊网格。
- 明确**不引入**"上方一块大画布 + 下方画廊"的混合形态：竖直空间翻倍，且与"可交互由配置决定"的现状割裂。

### 只读卡加 play 角标：统一改共享画廊

- 卡片右上角加 play 角标（非 Material 图标体系）；左上角既有的"默认讲解"角标保持不动，两者不冲突。
- **保留整卡可点**：play 是可见性提示，不是唯一命中区——只留小图标做命中区会显著削弱触屏可用性。可点区仍走全站唯一的 `AppFocusableAction`，不另套手势识别器。
- 语义标签同步改写（如"播放某图形的对折演示"），保住键盘可达性。
- 统一改共享画廊，不另起一份课件专用组件：题库 / 错题 / AI 讲解 / 知识点场景编辑器 / 课件共用同一份，避免第二份实现日后漂移。

### 只读视图不标答案，守"只画不判"

- 只读卡上**不出现**任何"是否轴对称"的判定标记——打勾打叉、按是否对称分组、给教师一个"显示答案"开关，本轮全部不做。
- 一旦标了，学生扫一眼网格就拿到答案，"点开亲手折"这个动作当场死亡，与交互图形讲解的教学意图正面冲突。判断只能由学生在弹窗里亲手折出来。

### 弹窗的初始轴取"图形自带默认轴"

- `curated` 模式下每张图打开时的初始轴取**该图形自己的 `defaultAxisAngle`**，不套用本环节场景配置的轴；学生进弹窗后可再旋。
- 实证理由：若统一套用场景轴（如竖轴）打开唯一对称轴是横向的箭头，画面一开始就不重合，儿童会以为"题目错了"。这条同时也是画廊既有口径。

### 离线可用：保存时展开顶点

- 勾选保存时，条目的 `points` 由前端图形库**展开写入**，只存 key 让渲染层运行时回查。图形库是构建期从后端生成的常量产物，有前后端一致性测试钉住。
- 这样即使后端不可用，已保存的这组图仍能渲染——课堂演示不能因为一次查询失败就空白。

### 边界与红线

- **零回写**：只写本环节的 `scene`，绝不回写知识点的 `scenes`（场景快照不可变）。
- **文件规模棘轮**：共享画廊加角标与参数后逼近 400 行上限；超限按既有先例抽 part 文件，**不得上调基线绕过**。
- **导航回落**：新增的编辑器选择 UI 若在弹窗态，回落走单一出口，不用裸的返回调用。
- **全站禁 Material 控件**（根是 `ShadApp` + `CupertinoApp`），新增图标与可点区必须在不套 Material 的树里真构建验证。

## Testing Decisions

### 接缝（两条，一进一出）

1. **输出侧（主接缝，最高位）**：解释器的边界——**喂一份 `section.scene` 的 dict，断言渲染出来的东西**。三态分派（无组 / curated 组 / 非 curated 组）、卡片数量与顺序、play 角标存在、只读卡上无判定标记、点开后能旋转平移轴，全部在这条接缝上可见。这是"最高接缝"：所有下游渲染行为都能从这一份 dict 的输入观察，无需探进画廊内部。
2. **输入侧**：课件环节编辑器 + 假仓库——**断言教师勾选后保存出去的那份 dict**（条目顺序 = 勾选顺序、`points` 已展开、`curated` 已置上、`label` 为空、`caption` 为图形名）。编辑器产出的本质是数据，用假仓库接住保存调用即可，不必驱动真实持久化。

除此之外不新增接缝：画廊与解释器的内部结构不单测，编辑器内部状态不单测。

### 什么样的测试算好

- **只测外部行为**：断言渲染出来的可见结果（有几张卡、顺序、有无角标、有无判定标记、弹窗里轴能否动）和保存出去的数据内容。
- **不测实现细节**：不断言内部方法被调用、不测私有字段、不靠 widget key 去数内部结构、不给画廊的私有排序函数单独写用例。
- 每条用例必须能被一句产品语言描述（"教师勾了两张图，讲课页就摆两张、顺序一致"），凡是只能用实现语言描述的用例，说明接缝选低了。

### 覆盖的模块

- 场景解释器（三态分派 + 传参）。
- 图形画廊（play 角标、保序渲染、只读无判定、整卡可点仍成立）。
- 课件环节编辑器（勾选 → 写 `optionGroup`）。
- 讲课页环节组件：**本轮 diff 应为空**，用"零改造"本身当断言——若必须改它才能出多图，说明分劈错了，应回 ADR 重新决策。

### 既有先例（照抄其手法）

- 选项组渲染测试（守"带组就渲染画廊而非平铺 N 个场景"、"每个场景用图形自己的默认轴"）：它演示了**必须用 `setSurfaceSize` 设定表面尺寸**才能触发多列布局——默认测试表面太小，光在树上挂 `SizedBox` 改不了父约束，会误报溢出。
- 全仓禁 Material 祖先：新增控件必须在不套 Material 的树里真构建，否则构建期才抛错而静态检查照不出来。
- 文件规模守卫测试：本轮新增/改动的每个文件都要过行数基线，超限抽 part。
- 课件编辑器页 / 讲课页 / 场景库相关既有用例：作为"题库路径一字不变"的回归网。

### 回归要求

- 静态检查 0 issue；全仓测试无回归，重点覆盖上述既有先例。
- **题库 / 错题 / AI 讲解路径的现有观感必须一字不变**（整库探索 + 选项角标 + 整卡可点）。
- 后端本轮零改动，故后端测试无需重跑，但要在验收里明确写下"后端未改动"这一结论而非留空。
- 已有的内容型演示课件（单图、旧结构）在本轮后仍能渲染。

## Out of Scope

- ❌ **不支持教师上传任意图片当图形**：多图集合被锁在内置图形库里（十一个顶点预设）。自定义顶点是另一条独立议题。
- ❌ **不改后端**：不新增端点、不改课件环节 schema、不动题目侧的图形抽取逻辑（它仍只服务题目）。
- ❌ **不新增场景类型、不改解释器对外签名、不改造题库/错题路径的现有观感**。
- ❌ **不做"显示答案"开关、不做按是否对称分组**：那等于变相给答案。
- ❌ **不做"大画布 + 画廊"混合版面、不做单张翻页**：前者空间翻倍，后者丧失同屏对比。
- ❌ **不做图形集的复用/模板化**（如把一组勾选存成可复用预设）、不做跨环节复制。
- ❌ **不动知识点场景编辑器与场景库管理面**的既有能力（它们继续只管单份默认讲解）。
- ❌ **不做分组标题、讲解文案等教学内容编排**：本轮只解决"摆哪几张图、什么顺序、怎么打开"。

## Further Notes

- **工作量认知校正**：这不是从零实现。真正新建的只有"课件语境下谁来供给图形列表"这一件事；渲染、只读、弹窗交互、数据持久化四条链路都已存在。低估或高估都会导致分劈错误。
- **三个真实缺口**（对应 `issues/01`–`03`）：画廊缺显式 play 提示与保序渲染；解释器缺"教师编排子集"的通路；课件编辑器缺勾选多图的入口。`issues/04` 是三态验证与全量回归。
- **最容易踩的两颗雷**：① 把"有条目就裁剪"当成 curated 的判定条件 → 题库路径静默失去整库探索；② 弹窗套用场景配置的轴 → 横向图形一打开就不重合，观感像是题目出错。
- **为什么"只读"必须是默认**：展示态的职责是"摆出来让人看"，验证态的职责是"让人动手"。两者混在一起既削弱探究，也让大屏节奏失控。
- **与既有 epic 的归属**：本轮是**编辑器能力**，不并入纯内容填充的那条 epic，也不接上一轮已全部完成的课件编辑器轮次。
- **文档归属**：决策在 ADR-0076，本 spec 只做展开；两者冲突时改 ADR，不在本文件里偷偷改口径。
