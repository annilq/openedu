## 范围

底层组件层（四态统一 / `AppFocusableAction` 键盘可达 / 三档自适应 / 宽度令牌）**已经做对，本 epic 不动它**。
缺的是上面两层：

1. **路由层不存在**——全 App 只有一个 route，教师端 11 页靠 `setState` 平铺替换。
   由此派生出「Android 返回键直退应用 / 无深链 / 重启必回概览 / 壳内切页零转场」一串问题。
2. **菜单 IA**——11 项平铺无分组、两处命名撞车、课件的创建入口藏在另一个一级菜单里。

## 为什么按垂直切片（不是 wide refactor）

返回栈与路径序列化的爆炸半径都收在导航状态定义文件与组合根两个文件内；前端没有 JSON 列，
改形会编译报错而不是静默画空。所以每张票都能单独落地并保持 CI 绿，**不需要 expand–contract**。

唯一跨票的共同前置是 01（标题与图标单一映射表）——它是 prefactor，先抽出来让改名与顶栏标题两票变便宜，
也顺带满足「枚举 → 文案只在 `labels.dart` 写一次」的既有约定。

## 共同纪律

- **ADR-0059 不变式**：「当前页面」永远只有一个状态。返回栈只是它的历史，
  严禁退回「索引 + 覆盖层 + 布尔」并列——那正是历史上「点了我的但个人信息根本没进渲染树」那类 bug 的成因。
- **可用宽度是唯一断点依据**，禁止设备形态 / 屏幕朝向判定；尺寸一律走 `AppLayout` 令牌，不写裸数字。
- **可点区域一律走可聚焦动作组件**：手势（左滑关闭抽屉）只作补充，不得替换可点区域。
- 动画一律尊重 reduce-motion。
- 改名类改动同步页面内文案与空态引导——同一个概念不出现两套叫法。
- 每票落地后：`flutter analyze` 无告警 + `flutter test` 无回归（涉及导航状态的票必须补 widget 测试）。
