# 03: 教师端返回栈与系统返回键接管

**What to build:** 教师在壳内下钻（班级 → 班内学生 → 学生详情 → 编辑学生）时，页面自带的返回能**逐级**退回；Android 返回键、外接键盘 Esc、系统侧滑手势走同一条回退路径，只有在根页面（概览）才交给系统退出。**返回从「每个页面自己记得声明回落目标」变成结构默认。**

**Blocked by:** 无（可立即开工）

**Status:** ready-for-agent

## 验收

- [ ] 壳持有页面历史栈：下钻入栈、返回出栈
- [ ] 侧栏切换一级入口**清空**栈（切到「题库」后按返回不会先弹回上一次的班内学生页）
- [ ] 现有四个携带回落目标字段的下钻页，字段全部移除
- [ ] **新增下钻页零义务**：不需要记得声明回落目标，落栈由壳负责
- [ ] 系统返回键 / Esc 在非根页面触发**一次**回退，不退出应用
- [ ] 在根页面（概览）触发系统返回 → 不消费，交由系统处理
- [ ] 栈只记录历史，**不成为并列的第二个「当前页面」真源**（ADR-0059 不变式）
- [ ] 学生端同理：页签内的返回动作不退出应用
- [ ] widget 测试：四级下钻按返回键逐级回到概览；根页面按返回键不消费

## 纪律

- 保留 ADR-0059 的核心不变式：**仍然只有一个「当前页面」状态**，栈只是它的历史。
  严禁退回「索引 + 覆盖层 + 布尔」并列——那正是历史上「点了我的但个人信息根本没进渲染树」那类 bug 的成因。
- 出题生成这类**非常驻**流程不走栈（它有自己的收尾路径），本票不动。
- 本票只做机制，不改任何页面的内容或视觉。
