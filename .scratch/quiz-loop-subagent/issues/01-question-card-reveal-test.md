# Ticket 01 — 补判断题卡揭示行为的组件测试

- **What to build**: 学生在聊天里收到的判断题卡，未揭示时看不到答案、点「显示答案」后才揭示——这个契约目前没有任何测试守着，改题卡渲染的人可以无声破坏它。本票把揭示契约变成机器可验证的行为：喂一张 `judge: true` 的题卡，断言未揭示时答案 / 解析文本不在场、「显示答案」动作在场；点击后答案与解析渲染；再喂一张非 judge 题卡，断言答案默认在场（普通题卡不被阻碍）。
- **Blocked by**: —（无，可立即开始）
- **Status**: done
- **验收清单**:
  - [x] 在无 Material 祖先的树下真构建组件（项目纪律：根无 Material，套了 Material 的测试会掩盖构建期抛错）
  - [x] judge 题卡未揭示：答案 / 解析 / 出题思路文本均不在场；「请判断『对』或『错』」提示与「显示答案」动作在场
  - [x] 点击「显示答案」后：答案与解析渲染在场
  - [x] 非 judge 题卡：答案默认在场，无「显示答案」动作
  - [x] `flutter test` 该文件绿；不引入截图装置（禁 `RenderRepaintBoundary.toImage`，无真实合成器下永不完成）

## 决策锚点

- **断言文本 / 几何在场，不截图**：测试环境无真实合成器，`toImage` 永不完成——实测曾把整条 `flutter test` 从 ~46s 堵到 17min 不返回。要目检的结论一律改写成几何 / 文本断言（先例 `workbench_charts_layout_test.dart`）。
- **揭示态只存组件内存**：刷新即揭示。本票不测持久化——spec 已把「揭示态跨刷新持久化」列 Out of Scope。
- **先例**：`assistant_sources_bar_test.dart`（无 Material 祖先树下构建的既有写法）。
