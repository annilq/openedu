# 用户要求「架构视角 + 三段式」，并自带本仓 ADR 语境

用户（本仓主导开发者）要求分析 AI 助手 agent 的实现时，明确排除了技术实现细节，只要技术流程与架构；并要求**每个知识点都覆盖三件事**：架构优点、当时的设计决策、其他同类主流实现方式。同时一次挂了 show-me 与 teach 两个 skill。

**Implications（对未来课程的决定性影响）**
- 讲任何知识点都要配「同类主流实现」这一栏，且要给出**什么时候该选别家**（LangGraph / MCP / GenUI / LLM 路由 / 服务端线程），不能只讲本仓做法。
- 不贴大段源码；可以贴**文件树、常量表、事件/错误码表**这类「结构事实」。
- 图优先：用户同时挂了 show-me，说明希望结论可视化（时序图、状态图、分层图）。
- 不必解释 ADR 是什么、不用铺垫基础概念——用户熟悉本仓决策体系，直接引用 ADR 编号即可。

**Evidence**：请求原话「不需要具体的技术实现细节，重点在技术流程，架构」+「每个知识点都要说明架构优点、设计决策、目前其他同类主要的实现方式」。
