# ADR-0090 实施 Spec：判断题闭环子代理化（答案进历史）

> 本文件是 **ADR-0090** 的实施规格。仓库 `github.com/annilq/openedu`；标签 `ready-for-agent`。
> 实现已落地（提交 `2c37fa0` 后端 / `e035757` 测试 / `fce6b07` 前端 / `aeeaf51` ADR），
> 本 spec 为决策与测试契约的合成记录，供后续维护与回归对照。

## Problem Statement

出题与判定的旧形态是助手服务里一整块**服务端分支逻辑**：`_build_intent_signal` 把
action / 按钮负载 / 关键词归一化成 `IntentSignal`，紧跟 quiz 早返回与 `pending_quiz`
消费两组 if/elif。它带来三个后果：

- **冗余归一化**：判定侧的 `_judge_answer_bool` 只把模型返回的文本收口成布尔，真正的
  对错比对与讲解本就由 tutor LLM 完成——服务端这层分支不产生任何判断价值。
- **隐藏侧信道**：`Conversation.pending_quiz` 列把「待判定的题」钉在会话行上，题卡先被
  剥掉答案再落库、答案只活在 pending 列里；tutor 只能从这一列读，历史回放看不到完整题卡。
- **双轨契约**：`quiz_generate` / `quiz_judge` / `courseware_hint` 三个动作键横跨
  schemas、manifests、契约测试与前端请求，任一环节漏改即静默分叉。

学生侧的直接痛感：判断题卡一出现就带答案，「先判断再核对」的节奏被破坏；回答必须走
专门按钮，直接说「错」没有下文。

## Solution

删掉服务端 quiz 状态机（含 `pending_quiz` 列与信号归一化函数），出题与判定的决定权
**整体下沉到子代理**：

- **出题**：question 子代理自主判定 `judge`（文本含「判断题 / 判断对错 / 判断正误」），
  无 specs 时从会话上下文回填学科 / 年级 / 知识点；`judge` 标志经规格装配与序列化
  贯通进题卡 JSON。
- **落库**：题卡**连答案原样**进对话历史，服务端不再剥离任何字段。
- **判定**：tutor 从历史读题卡（题干 / 选项 / 正确答案 / 解析渲染进助手消息文本），
  判定口径写进 tutor SOP；学生直接回答对错即可触发判定。
- **前端**：`judge: true` 的题卡默认隐藏答案与解析，学生点「显示答案」后才揭示。
- **契约收敛**：question 子代理动作键收敛为仅 `task_generate`，tutor 动作键清空；
  请求与建议动作的 `quiz` 字段全删。

## User Stories

1. As a 学生, I want 说「出一道判断题」就拿到对 / 错二选一的题，so that 我快速自测概念掌握。
2. As a 学生, I want 题卡出现时先不显示答案，so that 我先自己判断再核对。
3. As a 学生, I want 判完点「显示答案」才看到答案与解析，so that 核对时机由我掌控。
4. As a 学生, I want 直接回答「错」就能得到判定，so that 不用先点专门按钮。
5. As a 学生, I want 答错时先给支架再讲，so that 我理解错因而不是只被告知错了。
6. As a 学生, I want 回答含糊（如「嗯」）时被请清是对还是错，so that 判定有明确依据。
7. As a 学生, I want 说「讲讲这题」时揭示答案并讲解，so that 我随时能求讲解。
8. As a 学生, I want 在课件语境里点「出一道判断题」，so that 就当前知识点出题。
9. As a 学生, I want 刷新页面后答案仍按揭示规则呈现，so that 回放与实时行为一致。
10. As a 教师, I want 历史回放里看到含答案的完整题卡，so that 复盘学生学过什么。
11. As a 教师, I want 对错由 LLM 判定并给出讲解，so that 服务端少一层易错的归一化分支。
12. As a 开发者, I want 助手服务里没有 `_build_intent_signal` 与 quiz 早返回，so that 意图归一化不再双轨。
13. As a 开发者, I want 出题与判定规则只存在于子代理 prompt 与 SOP，so that 领域知识有单一事实源。
14. As a 开发者, I want 会话表没有 `pending_quiz` 列，so that 会话状态没有隐藏侧信道。
15. As a 开发者, I want 老库启动期自动移除该列，so that 无需手工迁移脚本。
16. As a 开发者, I want `judge` 标志从出题结果贯通到题卡 JSON，so that 前端有稳定判据。
17. As a 开发者, I want question 子代理从上下文回填学科 / 年级 / 知识点，so that 按钮入口与文本入口行为一致。
18. As a 开发者, I want tutor 从历史题卡文本读答案判定，so that 答案不依赖服务端转存。
19. As a 开发者, I want 前后端请求都没有 `quiz` 旗标，so that 接口契约单一。
20. As a 开发者, I want 动作键收敛（question 仅 `task_generate`、tutor 清空），so that 路由表不留死键。
21. As a 前端, I want 题卡带 `judge: true` 即隐藏答案，so that 渲染层不需要额外信号。
22. As a 审计者, I want 运行轨迹里看到路由到 question / tutor，so that 排查判定问题有据。

## Implementation Decisions

- **删除服务端 quiz 状态机**：信号归一化函数（`_build_intent_signal` 及 `_ACTION_*`
  常量）、答案文本收口（`_judge_answer_bool` 及相关词表）、知识点上下文解析、出题文案、
  答案剥离与暂存记录、出题流式辅助、pending 消费与 SSE 辅助整体删除；聊天入口改为
  直接用消息文本与 action 构造意图信号。
- **会话表去列**：删除 `Conversation.pending_quiz`；启动期幂等迁移由「加列」改为
  **「删列」**——SQLite 先 `PRAGMA table_info` 探到列存在才 `ALTER TABLE … DROP COLUMN`；
  Postgres 走 `DROP COLUMN IF EXISTS`。老库遗留的未判定 pending 题随列消失，**不补偿**
  （视为会话已结束）。
- **judge 标志贯通**：出题结果模型、子代理输出结构、出题规格三者新增 `judge: bool = False`；
  经规格装配 → 出题流水线 → 序列化（`asdict`）进入题卡 JSON，成为前端揭示规则的唯一依据。
- **question 子代理自主判定**：规格解析阶段识别「判断题 / 判断对错 / 判断正误」并写入
  规格；子代理运行阶段在无显式规格且文本未带学科时，用会话上下文（学科 / 年级 /
  课件的知识点）回填，保证「出一道判断题」按钮在知识点语境下可用。
- **路由收敛**：question 子代理清单动作键收敛为 `["task_generate"]`，`triggers` / `hints`
  增加「判断题」（纯文本走文本路由而非动作键）；tutor 子代理动作键收敛为 `[]`。
- **历史读取补闭环**：历史读取函数原先只取 `{role, content}`、**丢弃消息负载里的题卡**，
  导致 tutor 从历史读不到答案（设计缺口，非缺陷）。新增题卡文本渲染：把题干、选项、
  **正确答案、解析**拼进助手消息 content。这是「答案进历史」方案的承重墙。
- **tutor SOP 增补判定口径**：判定依据是历史里题卡自带的 `answer`；说对 / 错先判再讲、
  答错先给支架、含糊请其对 / 错回答、求讲解揭示答案、不得编造题卡外结论。
- **前端题卡揭示**：题卡识别 `judge == true` 后下传标记；题卡体改为有状态组件，
  `showAnswer = 已揭示 || !isJudge`；未揭示时展示「请判断「对」或「错」后回答」提示与
  「显示答案」动作；答案 / 解析 / 出题思路仅在揭示后渲染。
- **请求契约去 quiz**：建议动作模型、聊天请求模型、notifier 的 `send` 同步删除 `quiz`
  字段 / 参数；建议动作回调签名收敛为只传 payload。
- **Supersede**：本设计取代 ADR-0072 的 `pending_quiz` 服务端待判定状态与
  ADR-0086 / ADR-0087 中的 `quiz_generate` / `quiz_judge` 动作键。

## Testing Decisions

- **只测外部行为，不测实现细节**：不断言内部函数调用顺序，只断言端点输出、落库形态、
  清单契约与组件渲染结果。
- **主接缝（唯一新接缝，最高点）= 助手聊天 SSE 端点**：一整轮对话驱动覆盖全部领域
  行为——用户发「出一道判断题」→ 出题子代理产出、题卡连答案落历史 → 用户答「错」→
  tutor 从历史读答案判定。出题规格判定、落库形态、判定口径、路由收敛都在此可观测，
  不开服务层 / 仓储层内部接缝。先例：`test_quiz_loop.py`、`test_assistant_quiz.py`。
- **既有接缝 1 = 子代理清单契约**：经清单发现入口断言动作键与触发词
  （question 仅 `task_generate`、tutor 空、triggers 含「判断题」）。先例：
  `test_intent_routing_contract.py`。
- **既有接缝 2 = 前端题卡组件（组件级 widget 测试）**：喂题卡 JSON（`judge: true`），
  断言未揭示时答案 / 解析不在场、有「显示答案」动作、点击后答案与解析渲染。
  **注意覆盖缺口**：该组件此前零测试（仅被裸 `Row(stretch)` 守卫点名），本 spec 将其
  记为必补。先例：assistant widget 测试族（无 Material 祖先树下真构建）。
- **判定路由的桩边界**：判定轮用可编排的路由 / 提供者桩断言「路由到 tutor」「未注入
  pending 态」「历史 content 含题干与正确答案」；纯文本与按钮两条入口都要覆盖。
- **归因纪律**：守卫类测试失败先在 HEAD 干净 worktree 上复跑，区分「本轮引入」与
  「既存红」，不把旧账算到本轮。
- **环境纪律**：测试内禁写截图装置（无真实合成器下永不完成，会堵死整条测试）；
  分层不变量（归属只走 guard）改动后端服务必跑对应 AST 守卫。

## Out of Scope

- 揭示态的跨刷新 / 跨端持久化（当前揭示态仅存活于组件内存）。
- 老库 `pending_quiz` 列存量未判定题的补偿迁移（随列消失，视为会话结束）。
- 新增题型或通用判题规则引擎（判定继续由 tutor LLM + SOP 承担）。
- 判定置信度、人工复核 UI、判题依据的可解释性面板。
- question 子代理之外的其他子代理（guide / query）的动作键整理。

## Further Notes

- **本设计的主收益是「删」**：助手服务少一整块 if/elif 与两个流式辅助函数，出题 /
  判定知识全部下沉子代理；题卡即答案载体，历史回放天然完整。
- **承重墙是历史读取补闭环**：若历史读取继续丢弃题卡，「答案进历史」整条链路断裂，
  tutor 将无答案可判——这是本方案唯一不能省的部分。
- **成本**：历史读取的助手 content 拼入题卡文本，token 变多；揭示态不持久，刷新即揭示。
- **测试基线**：后端全量 786 passed / 2 skipped；前端 assistant 相关 63 项全过；全量
  3 个失败在 HEAD 干净树上同样复现（feature_boundaries R2 / stretch_row_guard /
  students_notifier 空字段校验），属既存红，非本设计引入。
- **取号教训**：`docs/adr/` 内已有并发未提交的 0089 文件占号，本 ADR 顺延取 0090；
  取号前须 `ls docs/adr | sort | tail` + `git status docs/adr/`（未提交文件也占号）。
