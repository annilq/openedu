# ADR-0067 教师端课件：知识点驱动的课堂讲解环节

- 状态：提案（Proposed）· grill 已定 12 个分叉，待评审后进入实施排期
- 日期：2026-10-06
- 关联：ADR-0055（资料库 / 知识点）、ADR-0059（教师端单源导航）、ADR-0061（交互讲解 SceneSpec）、
  ADR-0064（知识点级联清理）、ADR-0066（知识点只来自教材）、ADR-0039（无模型不兜底）、
  ADR-0045（自适应布局）、ADR-0065（教师 / 学生定位）

## 1. 背景（Context）

产品定位转为教师 + 学生（ADR-0065）后，出现一个现有实体装不下的需求：**教师在教室里按知识点讲课**。
教师从资料库选一个知识点，页面切换出这个知识点的讲解安排（环节序列），逐环节点开全屏演示。
以「图形的运动（轴对称）」为例，教师期望的四个环节是：

1. 出示生活中的素材（蝴蝶、剪纸…），让学生观察共同点；
2. 判断平面图形是否轴对称、画对称轴，重点讲平行四边形不是轴对称图形；
3. 欣赏生活中的轴对称之美（建筑、艺术）；
4. 练习：AI 出题，学生回答，答错则 AI 引导。

读代码核到的四处理状，决定了这不是「加一个页面」：

1. **`KnowledgePoint.scenes` 装不下。** 它的语义是「一个知识点 → **一份**交互场景模板」
   （ADR-0061 §M 实测：205 个知识点里非空的只有 1 条且是脏数据）。需求要的是
   「一个知识点 → **一串有序、类型各异的环节**」——是上位容器，不是字段扩展。
2. **全工程零图片素材。** `frontend/assets/` 只有 fonts，pubspec 无 `assets` 段，无
   `cached_network_image`。环节 1 / 3 要的图没有来源。
3. **环节 2 基本现成。** 图库 `figures.dart` ↔ `scene_figures.py` 跨语言 parity 测试钉住，
   `ReflectionSceneWidget` 已支持拖轴 + 实时 ✓/✗ 判定；`para`（平行四边形）是刻意保留错切的
   手写顶点，ADR-0061 §O 有测试钉住「不许把它修正成矩形」——正好是环节 2 要讲的反例。
4. **环节 4 撞上派发制。** ADR-0065 §1：学生只答题 + 伴学，**任务全由教师派发**。

另有一条纪律约束贯穿全程：ADR-0066 刚删掉「预置知识点目录」，理由正是「把没有教材伪装成有目录」。
本 ADR 凡涉及「没有内容时显示什么」，一律沿用同一条：**如实告知，不伪造**。

## 3. 决策（Decision）

### 3.1 为什么必须独立建表，不能硬编码

三条理由，任何一条单独成立：

- 决策 2 是「AI 起草 + 教师调」——起草产物要有地方落，教师要能改。**硬编码等于把 AI 的产物扔掉**。
- ADR-0066 确立「知识点全部来自教师上传的教材」，**数量是动态的**（实测 205 条）。硬编码的课件
  追不上动态知识点集，等于每加一个知识点发一次版。
- 教师上传的素材引用必须落在数据里，写不进代码。

但「硬编码」有一半是对的：**环节类型（组件）** 确实是硬编码的有限集合——它是一个 **kind 注册表**
（§3.3），前后端双登记 + 契约测试钉住。硬编码的是「有哪几种环节」，不是「哪个知识点有哪些环节」。

### 3.2 数据模型

```
Courseware                            CoursewareAsset
  id                                    id
  teacher_id          ← core.guard       teacher_id       ← core.guard
  subject / grade / semester             storage_key      ← 复用 MATERIAL_UPLOAD_ROOT
  knowledge_point_id  (FK)               filename / mime / width / height
  kp_name             (冗余快照)          created_at
  title
  status: draft | ready
  sections: JSON [{id, kind, title, payload}]
  created_at / updated_at
```

四条取舍：

- **`sections` 用 JSON 列**，与 `KnowledgePoint.scenes` 同口径（ADR-0055 §10「快照不建外键」）。
  排序 / 增删改 = 整体覆盖写。**不建 `courseware_section` 表**——它只带来 JOIN 与孤儿行，
  换不来当前需要的能力。
- **`kp_id` + `kp_name` 双写**：外键保证「选得到」，快照保证展示不依赖 join，且知识点被清理后
  课件不会变成无名课件（连带处理见 §4.1）。
- **可空 JSON 列一律 `JSON(none_as_null=True)`**（ADR-0061 §N / §T）：否则 Python `None`
  被序列化成文本 `'null'`，`IS NOT NULL` 为真而内容为空，「这个课件有环节」类判断全部走偏。
- **迁移走启动期幂等 DDL**（ADR-0053 / ADR-0061 §D 纪律），SQLite `PRAGMA` + Postgres
  双分支，不引 alembic。

### 3.3 环节 kind 注册表（与 SceneSpec kind 分层，别混）

`CoursewareSection.kind` 是**环节类型**，与 ADR-0061 的 SceneSpec `kind`（渲染器类型）是
**两层**，初表：

| section kind | 用途 | payload | 来源 |
|---|---|---|---|
| `media_gallery` | 生活素材 / 欣赏（环节 1、3） | `{items:[{asset_id, caption}], prompt?}` | 新建 |
| `interactive_scene` | 交互判定（环节 2） | **直接嵌一份 SceneSpec** | **复用 ADR-0061** |
| `practice` | 课堂练习（环节 4） | `{qtype, count, hints?}` | 新建 |

⚠️ `interactive_scene` 这个字符串在两层各出现一次，语义不同：section 层是「这一环节是交互演示」，
SceneSpec 层是 `reflection` / `bar_chart` 这类渲染器名。**两套注册表各自登记、各自契约测试**，
不允许互相映射复用——混了以后改渲染器会连带改课件结构。

新 kind 入表走 ADR-0061 决策 9 的同一纪律：后端 `_KIND` + 前端枚举双登记，不接受自由字符串。

### 3.4 环节产出：AI 起草 + 教师调

对齐 ADR-0061 决策 3 阶段①：教师选知识点 → AI 按（名称 / 学科 / 年级 / 学期 + 该知识点下的
资料片段，走 `retrieval.py` 按 `knowledge_point` 过滤召回）产出环节草稿 → 教师在列表上
**增 / 删 / 改序 / 改标题 / 换素材**，场景参数走现有 `KnowledgePointSceneEditor` 弹窗调。

- **未配模型时不可起草**（ADR-0039：无离线 mock、无内置模型目录）。此时课件页只列已有课件，
  「新建课件」按钮给出「未配置模型」而非静默失败。
- **已落库的课件不依赖模型**：演示环节 1 / 2 / 3 全程离线可用。这是教室断网时的底线——
  只有环节 4 需要模型。

### 3.5 素材：教师上传为主，预置为辅，空态不降级

- **`CoursewareAsset` 独立建表**，不塞进 `Material`：资料（Material）是要切分、向量化的教材
  （`parser.py` 只吃 `.pdf/.docx/.txt/.md`），素材是要原样显示的图，**不进向量库、不切分**。
  物理存储复用现成的 `MATERIAL_UPLOAD_ROOT/{teacher_id}/{key}`（已有 per-teacher 目录与
  `storage_key` 机制），逻辑上是新实体。
- **平台预置包**：由维护者检索**明确 CC0 / 公有领域**的图，逐张记录来源与授权后随仓库分发。
  它只覆盖少数知识点，**这是已知的、可接受的覆盖缺口**。
- **无素材一律空态 + 上传引导**（ADR-0051 空态语言 + ADR-0066 不伪造纪律）。
  ⚠️ **明确不降级到顶点图库示意图形**：示意图在课件里效果不达预期，且学生分不清「示意」与「真实」，
  偷偷降级就是把「没有素材」伪装成「有内容」。顶点图库继续只服务于题目 / 练习场景
  （ADR-0061 §O / §U.3 的既有定位不变）。

### 3.6 练习：助手「课件练习」上下文，不建任务

复用唯一 AI 入口 `POST /assistant/chat`（ADR-0037）。`AssistantChatReq` 已有
`focus_interest` 这个「上下文透传给 SubAgent」的先例，课件上下文照同一条路子走：

```python
class CoursewareContext(SQLModel):
    courseware_id: UUID
    section_id: str
    knowledge_point: str
    subject: str
    grade: int
    semester: str = ""

class AssistantChatReq(SQLModel):
    ...
    courseware: CoursewareContext | None = None   # 新增
```

- **走 `guide` 路由但明确不建任务**（ADR-0054：写意图走 `guide`）。课件练习不是派发，
  不产生 `Task` / `TaskQuestion`。
- **答错引导复用 `tutor` 的分级提示能力**（只给提示、不直接给答案）。**触发者就是教师账户本身**——
  `tutor` manifest 的 `roles` 已含 `teacher`，无需扩权、无需伪造学生上下文。
  ⚠️ 身份与受众在这里是分离的：触发者是教师，提示内容的受众是大屏前的学生。
  这个分离是可接受的——课堂练习本就是「教师代录」，教师只是替学生按下那一次提问。
  若将来做强隔离，再考虑独立引导能力（不预建）。
- **不落作答记录**：ADR-0052 的取舍是「纸质作答不回流系统是设计不是缺陷」，大屏练习同理。
  口头答错不是可复核的作答记录，**不进错题本、不进掌握度**。

### 3.7 演示态与布局

- 逐环节**全屏展示**，走 `AppContentFrame`（ADR-0045：push 路由整页的唯一出口）。
- 设备形态未定，**先按平板 / 笔记本 + 投影做，布局只按可用宽度取档、不写死分辨率**。
  ⚠️ 现有布局只实测到横屏 1024×768，投影常见 1920×1080 **未实测**——首轮须补大尺寸验证，
  别让课件成为第一个在投影分辨率下溢出的页面。
- 全禁用 Material 控件（App 根是 `ShadApp` + `CupertinoApp`，无 Material 祖先）；
  可点区一律 `AppFocusableAction`；新文件 ≤400 行（ADR-0058，基线只许下调）。
- 导航：**不新增顶层菜单项**（§3.8）。课件是知识点行的下游动作，不是导航目的地，
  故 `TeacherPage` 与侧栏 `NavigationDestinations.teacher()` **均不改**。

### 3.8 入口与导航：挂在知识点行内，不加顶层菜单

**不新增顶层菜单项。** 课件从「资料库 → 知识点管理」每行的「课件」入口进入，与现有「讲解」入口
（打开交互场景编辑器）并排。两条理由：

1. 课件**依附知识点**，而知识点管理页**已经有完整的范围三选与知识点列表**（ADR-0066 `scopes`
   驱动的 `_ScopeBar`）。做一个顶层课件页等于把这套筛选原样重写一遍，还得再维护一份级联逻辑。
2. 侧栏已有 8 项，第 9 项带来的寻路成本高于收益。

⚠️ **代价（已接受，但必须有补偿）**：教室里的进入路径变成 **5 步**——资料库 → 知识点管理分段 →
三选范围 → 找到知识点 → 点课件。课前几分钟是最慌的时候，5 步会劝退人。
补偿手段是**「最近课件」回执**：知识点管理页顶部给一条「继续上次：图形的运动（轴对称）」，
一步直达演示态。**没有这条回执，本决策不成立**——它已进首轮切片（§6 切片 4c）。

备课与讲课依然是诉求相反的两个场景，只是共用同一个入口：

| | 备课 | 讲课 |
|---|---|---|
| 场景 | 办公室 / 课前，慢慢调 | 教室，投影前，要快 |
| 要什么 | 编辑、上传、AI 起草、改顺序 | 大字号、全屏、零编辑噪音 |
| 干扰容忍 | 高（可以有多级表单） | **零**（侧栏 / 底栏都是噪音） |

三条实现纪律：

1. **`TeacherPage` 与侧栏都不改。** 课件编辑页与演示页**都走 `Navigator.push` 出去的全屏页**
   （`AppContentFrame`，ADR-0045），演示态不带侧栏与底栏。
   这既满足「投影时零干扰」，又保住 ADR-0059 单源——课件不是导航目的地，是知识点行的下游动作。
   ⚠️ 两个都是 push 路由，**禁裸 `Navigator.pop`**（弹根栈最后一条 = 整个 App 白屏），
   返回走 `AppPushedPage` 的注入回调。
2. **知识点列表照旧列「有教材的知识点」，不是「有课件的知识点」。**
   范围三选复用 ADR-0066 的 `scopes` 接口与资料库页 `_ScopeBar` 的级联逻辑
   （切学科换年级、切年级退回整学年）。列表**每行标「已有课件 / 未建课件」**——
   只列已有课件的话，教师就再也找不到「可以建但还没建」的知识点，新建入口等于不存在。
3. **环节切换在页内完成，不逐级 push。** 教师点环节 2 是「切到这一环节」，不是「打开一个新页面」：
   push 会丢掉「现在讲到第几环节」的上下文，返回时还要重新找。用顶部步骤条 + 底部上一步 / 下一步，
   当前环节高亮、底部显示「2 / 4」。

演示页分区（自上而下）：

- **头部**：课件标题 + `学科 · 年级 · 学期` + 右侧「退出演示」。
- **步骤条**：四个环节横排，当前项实心高亮（`surfaceActive` 语言，ADR-0046），可点击直接跳。
- **主区**：环节标题 + **话术提问卡** + 环节内容（`media_gallery` 的图 / `interactive_scene` 的画布 /
  `practice` 的出题区）。画布是唯一的可变区域。
  ⚠️ **话术当提问卡直接投给学生**（决策 15）：投影时教师屏幕 = 学生所见，做「仅教师可见」在单屏下
  物理上不可能（除非双屏扩展模式）。而且课堂提问本来就该让学生看见——「这些图形有什么共同点？」
  抛出去才是引导学生观察，藏起来反而没了教学动作。不做折叠：多一次点击换来的是教师自己都记不住
  该问什么。
- **底部**：上一步 / `2 / 4` / 下一步。

⚠️ 布局只按**可用宽度**取档（ADR-0045），不写死分辨率；投影常见 1920×1080 / 1366×768 须实测（§6 切片 8）。

## 4. 连带与风险

### 4.1 知识点被清理后课件变孤儿（待定）

ADR-0064 的「删资料 → 清理孤儿知识点」会连带删掉知识点。**课件不级联删除**——它是教师花时间
调过的资产，跟着一次资料删除一起消失不可接受。方案：保留课件，列表行标注「所属知识点已移除」，
`kp_id` 置空、展示继续用 `kp_name` 快照。

### 4.2 素材被课件引用时的删除

**允许删除**（决策 10）。素材是教师的资产，不该被课件反向锁死——「删不掉」比「出现空洞」更让人恼火。
删除后引用它的环节显示**「素材已移除」占位**，文案与 §3.5 的空态同一语言（说清是什么没了、下一步做什么）。
不维护引用计数、不做级联——占位就是全部处理。

### 4.3 环节 2 的「画对称轴」

现有 `ReflectionSceneWidget` 是**拖三个滑块**（角度 / 横位 / 纵位），没有「画线」这回事。
**本轮沿用拖滑块**（决策 9）：零改动、立刻可用，且「拖到能重合即算找到对称轴」本身就是有效的探究动作。

⚠️ 已知代价：教室里拖三个滑块找一条线不够直观，与教师口头的「画出对称轴」不是一回事。
若上线后反馈强烈，下一步是**点击画布两点定轴**（两点 → 轴参数，复用现有重合判定，成本可控），
而不是一步跳到手指自由画线（需笔迹收集 + 拟合 + 擦除，且大屏触控精度未验）。该演进不进本轮。

## 5. 明确不做（Out of Scope）

- 顶层「课件」菜单项（决策 13：入口挂在知识点行内）
- 学生端查看课件（本轮只做教师端）
- 课件跨教师共享 / 课件市场
- 课堂练习的作答记录、错题回流、掌握度更新（§3.6，与 ADR-0052 同款取舍）

### 6.4 让并行成立的三条硬约定

1. **后端切片 2 与 3 不得共用 `router.py` / `schemas.py`。**
   各写 `asset_service.py` + `asset_router.py` + `asset_schemas.py` 与 `service.py` + `router.py` + `schemas.py`。
   `api/main.py` 的两行 `include_router` 在**批次 0 一次性写好**（含 import 占位），
   A / C 两条线都不再改这个文件——否则两个会话对同一行做 Edit 必然互相覆盖。
2. **前端三个环节组件各自独立文件**（`section_media_gallery.dart` /
   `section_interactive_scene.dart` / `section_practice.dart`），演示页只按 kind 分派
   （`SceneInterpreter` 同款模式）。天然不冲突，也顺带满足 ADR-0058 的 400 行约束。
3. **批次 0 必须先钉死四样契约**，钉完四条线才真的零耦合：
   - 表字段名与类型（`Courseware` / `CoursewareAsset`，§3.2）
   - REST 端点路径与 JSON 形状（`schemas.py` + `asset_schemas.py`）
   - Dart `Courseware` / `CoursewareSection`（`fromJson` / `toJson` 与后端逐字段对齐）
   - section kind 常量（后端 `_KIND` + 前端枚举双登记，§3.3）

   完成判据：四条线开工后**不再各自发明文件名与字段名**，只 import 这四份契约。

### 6.5 串行瓶颈与并行纪律

- **`material_knowledge_manage_view.dart` 实测 353 行**，切片 4（加「课件」入口）与 4c（最近课件回执）
  都改它，加完必然撞 ADR-0058 的 400 行棘轮（基线只许下调）。**批次 2 必须先拆文件再接线。**
  ⚠️ **搬代码块禁用正则删方法**：DOTALL 下 `.*?` 会跨进相邻方法把它的 body 吞掉（实测 58 个编译错）。
  正确做法是**逐行原样搬**，只对要改的行做 `line.strip() == '...'` 判定后单行 replace，helper 一律保留。
- **热点文件先查再改**：`core/db.py` 的 `run_migrations` 与 `api/main.py` 最近被多个会话改动。
  并行开工前先 `git status` + 看 mtime，定点 Edit，写完回读（本 ADR 之外的项目文件被并发整写覆盖过两次）。
- **多会话不要同时跑 `flutter test`**：它抢 `build/test_cache` 的锁（游离 `flutter_tester` 进程会占住），
  表现为莫名变慢或卡死。并行期间各跑各的测试文件，合并后再跑全量。
  `pytest` 同理须加 `--basetemp=/tmp/<新目录>`（沙盒下否则 `tmp_path` 用例集体 EEXIST）。
- **平台 CC0 素材包**（检索 + 逐张核授权 + 记录来源）不依赖任何代码，可随时插入任意批次并行。
