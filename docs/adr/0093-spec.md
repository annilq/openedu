# Spec：知识点审核视图增强（去近似重复 / 学期口径 / 覆盖度 / 溯源）

> 依赖顺序：本 spec 为单页增强，4 项任务相互独立，可并行评估；其中 #1 的 DB 约束为其余各项的前置不变量。
> **状态：已确认（2026-10-14）。** 用户采纳本计划并选择选项 A：保留工作树参考实现、按 ADR-0093 落地并补提交。四项决策已实施，详见 `0093-knowledge-audit-view.md`。

## Problem Statement

「知识点管理」页（`material_knowledge_manage_view`）当前是平面列表：教师能勾选待审/已转正、
按 (学科, 年级, 学期) 过滤，但**缺少审计信号**——看不出重复、看不出覆盖到哪、也查不到某个点
到底出自哪本教材哪一段。用户给出四点明确增强方向，要求先出计划确认再动手。

落地前必须正视两个**数据现实**（已实测，直接决定 #1 与 #4 的口径，非假设）：

- **真重复并不存在**。`app.db` 的 `knowledgepoint` 共 157 行，按唯一键
  `(teacher_id, subject, grade, name, semester)` 分组复核：`dup_violations = 0`。
  之前看到的「2 行同名」是同名跨学期，属设计内，不是突破唯一键的真重复。
- **`MaterialChunk.knowledge_point` 字段 1312 条全部为 NULL**。当初设想的「就近匹配」赋值逻辑
  实际从未跑过。因此知识点与资料之间唯一的真实链接是 `Material.knowledge_points`（名字串，无外键），
  溯源**只能**反查「哪些资料引用了这个名字」再展开该资料整篇切片，**不能**走 chunk↔KP 字段。

## Solution

四点增强，各自独立：

1. **不做近似重复**：不引入任何相似度/近似重复标记逻辑（无可靠判别标准，会误伤合法跨学期同名条目）。
   真重复交由物理唯一约束兜底——`app.db` 已建 `ix_knowledgepoint_unique`
   （`CREATE UNIQUE INDEX IF NOT EXISTS ... ON knowledgepoint(teacher_id, subject, grade, name, semester)`，
   实测 `removed dup rows = 0`、`index present = True`）。
2. **去「整年」只留学期**：模型层口径 `KnowledgePoint.semester` 必须具体（不再允许空）；「整学年」
   仅前端 UNION 聚合视图，不存空行。默认学期 `''` → `'上学期'`；`semestersOf` 只返回真实出现过的
   具体学期；视图切学科/年级级联到首个具体学期；学期下拉去掉空标签。
3. **显示覆盖度**：审核覆盖度 = `curated / total`（该范围内已转正 ÷ 总条数），前端计算，无后端改动。
   顶部加进度条。
4. **添加溯源**：行内加「溯源」入口，点击拉取并弹窗展示该名字命中的源资料 + 片段原文（走
   `Material.knowledge_points` 反查，非 chunk↔KP 字段）。新增一个只读 GET 端点。

## User Stories

1. As a 教师, I want 列表里不被「疑似重复」误标, so that 合法跨学期同名知识点不被当成脏数据。
2. As a 教师, I want 学期维度只有「上学期/下学期」没有「整年」空值, so that 过滤与确认不会落在语义模糊的空集上。
3. As a 教师, I want 一眼看到当前范围的审核进度（已审 / 总）, so that 我知道还差多少没转正。
4. As a 教师, I want 点一个知识点就能看到它出自哪本教材哪一段, so that 我能核对出处、判断涌现点是否靠谱。
5. As a 开发者, I want 真重复由 DB 唯一约束保证, so that 应用层不用维护一套易误判的近似逻辑。
6. As a 开发者, I want 溯源数据来自真实存在的链接（`Material.knowledge_points`）, so that 弹窗不会出现永远为空的字段。

## Implementation Decisions

### #1 不做近似重复，依赖 DB 唯一约束
- **不写**任何近似重复检测/标记代码。
- 唯一约束物化为 `ix_knowledgepoint_unique`。**待确认点**：当前是一次 DDL，未进迁移框架。
  选项 A 接受「部署脚本重跑同条 `CREATE UNIQUE INDEX IF NOT EXISTS`」；选项 B 补正式迁移（Alembic/等价）以便新环境自动获得。倾向 A（开发期库，索引幂等，低成本）。

### #2 学期口径收敛
- `knowledge_manage_provider.dart`：`semester` 默认 `'上学期'`(≈46)；`semestersOf`(≈111) 移除前置 `['']`，
  只返真实具体学期；失效回落取 `concrete.first` 或 `'上学期'`(≈193)；`setScope`(≈223) 不变。
- `material_knowledge_manage_view.dart`：`_ScopeBar` 切学科/年级级联 `firstSemester()`(≈263) 落到首个具体学期；
  学期下拉 `labels: km.semesters`(≈303) 不再含空标签。
- 测试 `knowledge_manage_scope_test.dart` 同步：入口期望 `'上学期'`、`semestersOf` 期望具体学期列表、
  「切学科」用例改名并断言级联到首个具体学期。
- **保留项（待确认）**：「整学年」作为 UNION 聚合视图仍可存在（跨学期并集展示），只是底层无 `semester=''` 行。

### #3 覆盖度（前端，无后端改动）
- 新增 `_CoverageMeter`（`material_knowledge_manage_view.dart` ≈103 调用 / ≈314 定义），在 pending 计数后
  展示「已审 X / 总 Y」进度条。
- **范围（待确认）**：本期只做**知识点级**审核覆盖度。教材**章节级**覆盖度需解析目录树，超出本期，不在本 spec。

### #4 溯源（新增只读端点 + 弹窗）
- 后端新增 `GET /materials/knowledge-points/sources`（`router.py` ≈225，参数 `subject/grade/name`）：
  - `repository.list_knowledge_point_sources`(≈339)：筛该教师同 (学科,年级) 资料，`name in material.knowledge_points`
    命中者取其全部 chunk（`seq` + `content`，按 `seq` 排序）。
  - `service.get_knowledge_point_sources`(≈723)：组装 `KnowledgePointSourcesResp`。
  - `schemas.py` 新增 `KnowledgePointSourceChunk`/`KnowledgePointSourceMaterial`/`KnowledgePointSourcesResp`(≈177/184/197)。
- 前端：
  - `material_repository`（shared）抽象 `getKnowledgePointSources`(≈293) + 模型类；`material_repository_impl`(≈67)
    经 `_network.get('/materials/knowledge-points/sources', query: ...)` 实现。
  - `knowledge_point_row.dart` 加 `onOpenSource`(≈24/32) + 行内「溯源」`AppTextAction`(≈91-94)。
  - `material_knowledge_manage_view.dart` 加 `_openSource`(≈215) 拉取并 `AppDialog.alert` 弹窗。
  - **新建** `knowledge_point_source_view.dart`：展示源资料列表 + 按 `seq+1` 展开的片段原文；空命中给出
    「该点由教材涌现、未绑定资料」说明。
- **精度说明（待确认）**：当前溯源是「资料级」——展示命中资料的整篇切片，不是「chunk 精准命中该知识点的那一段」
  （因 `chunk.knowledge_point` 缺数据）。若后续回填 chunk 级归属，可升级到片段级。
