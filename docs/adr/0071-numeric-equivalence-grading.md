# ADR-0071 数学客观题数值等价判分

- 状态：已采纳（第一轮实现）
- 日期：2026-10-07
- 关联：spec `docs/specs/numeric-equivalence-grading.md`；`Grader`（`app/domain/grader.py`）；`parse_numeric` / `numeric_equal`（`app/domain/numeric.py`）；出题管线（`app/ai/subagents/question/pipeline.py`）；ADR-0004 D5（题型模型）

## 1. 背景（Context）

当前 `Grader.grade` 对客观题（`choice` / `fill` / `calc`）采用「归一化字符串严格相等」判定：

```python
correct = re.sub(r"\s+", "", (text or "").strip().lower()) \
           == re.sub(r"\s+", "", (answer or "").strip().lower())
```

这把**数学填空题和计算题当成纯文本比对**，带来一类「会做却判错」的系统性误判，直接污染学习闭环（错题归集、掌握度统计、正确率失真）：

1. 带单位判错：标准答案 `12`、学生写 `12厘米` → 不等。
2. 分数与小数互转判错：`0.5` vs `1/2`、`2/4` → 不等。
3. 带过程 / 多余标点判错：`12。`、`（12）`、前缀空格 → 不等。
4. 量纲 / 写法差异无容错：`3又1/2` vs `3.5`、`1/3` vs `0.333`（有限小数近似）→ 不等。

根因不是「判分逻辑有 bug」，而是**缺一层数值语义解析**：数学客观题的答案应是「一个带量纲的数值」，而非「一段字符」。本 ADR 记录三项关键决策依据。

## 2. 决策（Decision）

### 2.1 新增数值解析层（`parse_numeric` / `numeric_equal`）作为判分纯函数前置积木

在 `Grader.grade` 的客观题分支内，对「**学科 = 数学** 且 **qtype ∈ {fill, calc}**」的题，先尝试把标准答案与学生作答双方解析成「数值 + 单位」，再做**数值等价 + 量纲兼容**比对；**任一端解析失败则回退当前严格相等判定**（安全兜底，绝不因解析器而误放或误杀）。

- `parse_numeric(text)`：正则抽取「数值 token + 可能单位」，支持整数、小数、真/假分数 `a/b`、带分数 `a又b/c`、负号；内置轻量单位表（长度→米、重量→千克、时间→秒、角度→度、货币→元，含常见拉丁别名 cm/m/kg/g/mm），转基准单位。含字母变量、等式、`π` / `√`、纯中文 → 返回 `None`（标记非数值）。
- `numeric_equal(ans, sub, eps, rel)`：双侧均解析成功且**量纲兼容**时按容差判等（默认绝对 `1e-9` + 相对 `1e-6` 双判，覆盖浮点舍入）；量纲不兼容 → `False`；任一侧无量纲（纯数字 / 含未登记量词如「个」）视为兼容、仅比系数——故 `12厘米` 与 `12`、`5个` 与 `5` 均可判等。

该层是**与现有 `_normalize` 并存的新纯函数**，不替换旧逻辑；自身可用单测独立验证（见 `tests/domain/test_numeric.py`）。

### 2.2 作用域仅限「数学 + fill/calc」

数值等价只对数学客观题有意义，故严格收窄：

- 应用题（`open`）→ 仍走 LLM 柔性判分（`grade_open`），需要过程 / 语义判断，数值比对会误伤。
- 多选题（`multi`，ADR-0004 D5）→ 仍走 `|` 连接选项文本的集合比对（顺序无关、去重）。
- 非数学学科 / 非 fill-calc（如语文 / 英语客观题，答案为词 / 短语）→ 仍走原严格相等，数值解析无意义。

前端**零改动**：只消费后端返回的 `correct` 布尔，判分逻辑全在后端。

### 2.3 仅用标准库，不引入 sympy / pint / numpy

- 保持隔离安装纪律与零重依赖（spec 用户故事 #12 的硬要求）。
- 本题只解决「单一数值答案」这一类的解析：标准库 `fractions.Fraction` 天然约分（`1/2 == 2/4`）、`decimal.Decimal` 控容差已足够。
- 符号 / 代数等价（`x=5`、`√2`、`π`、表达式化简）明确**不纳入**数值解析——这类本应归为 `open` 题由 LLM 判。若日后需更复杂数学习题判分，应作独立模块（如符号判分），而非在本数值层累加分支。

### 2.4 出题侧答案格式约束（与判分解耦，并入本批）

在数学出题 prompt 与 `QuestionSchema.answer` 加约束：**答案填纯数值或数值+标准单位，分数用 `a/b`**，降低标准答案歧义，让数值解析更稳定。不守约束时**不强制**——模型产出仍走原 `assemble_question` 安全闸门与落库流程，本约束只作提示，不影响现有出题链路。

## 3. 后果（Consequences）

**正**
- 修复学习闭环的数据正确性：正确作答不再被记成错题，错题归集与掌握度统计恢复可信。
- 回退纪律是「安全绳」：任何解析歧义都收敛到旧行为，保证「不会比现在更差」。
- 改动缝收敛在 `Grader` 一处（理想缝数量 = 1），易审计、前端无感。

**负**
- 仅覆盖数学 fill/calc，其余题型保持旧行为（这是有意收窄，非遗漏）。
- 容差默认偏严（1e-9 / 1e-6）；`1/3` vs `0.333` 这类粗近似需调用方放宽 `eps`，属预期。
- 多答案（`12或15`）拆候选集的逻辑属于第二轮，本批只落地解析原语与约束。

## 4. 验证（Verification）

- `cd backend && uv run ruff check . && uv run pytest -q --basetemp=/tmp/<新目录>`：数值解析单测（`tests/domain/test_numeric.py`）全绿；既有 `tests/domain/test_grader.py` 严格相等用例作回归不变。
- 出题侧：新增数学 prompt 约束后跑 `tests/ai/test_generate_question.py` 确认出题链路不破。
- 不变量断言：非数学学科题、`open` 题、`multi` 题的 `correct` 结果与改造前完全一致（后续 Grader 接入时显式断言）。

## 5. 明确不做（Out of Scope）

- 应用题（`open`）的 LLM 判分增强 —— 维持现状。
- 前端改动 —— 判分在后端完成，前端只收 `correct` 布尔。
- 符号 / 代数等价 —— 不纳入数值解析。
- 跨量纲智能换算（`厘米→千克` 等无意义换算、物理量纲自动识别）—— 仅做同量纲单位归一。
- 出题侧答案格式约束的强制校验 —— 仅提示，不阻断。
