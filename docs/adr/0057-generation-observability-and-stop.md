# 出题过程可观测与可停止：进度上移到壳、停止生成、题数不符分级提醒

出题是 SSE 直跑在请求协程内、过程中零持久化。前端两个 notifier 都非 autoDispose，**状态其实全程留存**，
但「看得见」断在三处。本 ADR 决定：把进度与成败的监听从生成页上移到壳、给家长一个「停止生成」动作
（断流但保留已出的题）、并把题数不符按成因分级提醒。全部落在 UI 层，**不动后端形态**。

## 背景：状态没丢，是「看得见」丢了

| 断裂 | 位置 | 后果 |
|---|---|---|
| ① 表单页重建 | 表单料（`_rows`/`_titleCtrl`/`_modelId`）是页内 state，`home_screen.dart:235` 只在该导航索引挂载 | 回来是新空表单，预览区却仍在渲染 → 表单内容与这批题对不上 |
| ② 监听随页注销 | 成功/失败只在生成页 `build` 内的 `ref.listen`（`parent_task_form_view.dart:197`）处理 | 人不在页上时：成功不提示、不 `reset()`、不跳转；失败更彻底——`build` 不渲染 `TaskGenError`，错误直接蒸发 |
| ③ 审核页无条件 reload | `parent_task_review_screen.dart:46` `initState → _loadDetail()`，`load()` 开头即 `state = ReviewLoading` | 在途的单题「换一题」进度被抹成转圈 |

另有一条**已经失效的承诺**：`home_notifier.dart:35` 的少题文案写「可在草稿页整卷重生成补齐」，
而 ADR-0056 已决定移除整卷重生成——文案指向一个不再存在的入口。

## 决策

- **进度与成败的监听上移到壳（`home_screen`），页面只渲染 state、不承担状态机的收尾动作。**
  理由不是"放哪里更整洁"，而是生命周期不对等：页面会被侧栏切换卸载，壳不会。凡是"任务结束了总得有人
  收尾"的逻辑（提示、`reset()`、跳不跳转）都必须挂在生命周期更长的那一层，否则页面一走就成了无人区。

- **停止生成 = 断流 + 保留已出的题；落库仍发生在「确认」时（沿用 ADR-0056）。**
  因为 0056 已把落库后移到确认，本 ADR 的「停止」不需要任何后端改动：停止只负责不再产出后续题目，
  已出的题本来就留在预览态内存里，家长确认时才写库。**停止 ≠ 放弃**，两者是两个独立动作。
  实现上要给 `streamPost` 补 `CancelToken`（当前全前端零取消入口）。
  ⚠️ **不承诺「立即停止消耗 token」**：服务端是否立刻掐断当前那次 LLM 调用取决于
  Starlette/uvicorn 的断连传播，需实测后再写文案（宁可说"后续题目不再生成"，不可说"已停止计费"）。

- **题数不符按成因分级，两种语气。** 三者混为一谈会把家长自己的操作渲染成系统故障：
  1. 单题失败（STEP error 帧，已有 `failures`）→ 故障语气，说明哪题、为什么；
  2. 静默少出（流正常结束但题数 < Σ specs.count，无 error 帧）→ 故障语气，只说少了几题，不编造原因；
  3. **家长主动停止** → 中性陈述「已停止 · 6/8 题」，不报警、不标红。

- **少题在草稿页长期可见：用 `Task.specs` 反推应出题数，不新增后端字段。**
  `Task.specs` 已持久化（`db/models/task.py:31`）、`TaskResp.specs` 已回传（`schemas.py:57`）、
  前端 `TaskModel.specs` 已接（`models.dart:325`）。落库之后 `expected` 原本只活在前端 state、
  一次提示即消失，而草稿页自己算得出「应出多少题」——这是纯前端能补的最大缺口。
  **列表卡片不显示**：`TaskSummaryResp`（ADR-0053 摘要化）不带 specs，为卡片加字段要动后端，本轮不做。

- **提醒的出口只有「回生成页重来一份」。** 草稿页不能加题（ADR-0056 硬约束：无添加题目入口），
  整卷重生成已移除，于是补题的唯一路径就是整份重来。文案必须指向真实存在的入口。

- **修订 ADR-0056「后果」段的一句。** 那里写「预览态期间切走或退出，题会丢，需要重跑一次 AI」；
  加了停止与常驻进度之后它不再无条件成立：**主动停止能保住已出的题**，只有"切走且不回来确认"才丢。

## Considered Options

- **服务端作业化（作业实体 + 进度落库 + 可远程取消）**——否（本轮）。它能真正实现「关 App 后继续生成」，
  但要新增实体与状态/进度持久化，与"本轮不动后端形态"的前提冲突。明确接受的代价：
  **关闭 App 即终止生成**，这与 ADR-0056 已接受的「预览态切走会丢」是同一种取舍，不是新引入的退步。

- **只做指示器、不做停止**——否。省 token 是最初诉求的一半，而 0056 落库后移之后，
  「停止」的实现成本已经降到"断流 + 不再喂事件"这么低。

- **让「取消」= 丢弃**——否。已出的题白白作废，且与上面选定的"保留"语义相反。

- **少题只在生成当次提示一次**——否。落库后信息即蒸发，家长隔天打开草稿页看不出这份少题，
  而少题的草稿派发出去就是一份少题的作业。

- **给列表卡片补 `expected_count` 字段**——否（本轮）。会让 ADR-0053 定下的摘要化回退，收益只是卡片上多一行字。

## 与既有 ADR 的关系

- **ADR-0056（审阅闸门）**：本 ADR 落在其之上并依赖它的三条结论——不自动跳转、落库后移到确认、
  草稿页移除整卷重生成。反向修订了它后果段中的一句（见上）。
- **ADR-0017 / ADR-0043（思路不落库、不进回灌历史）**：不变。本 ADR 只涉及进度与题数，不涉及 reasoning。
- **ADR-0053（列表摘要化）**：少题提示落在草稿详情页而非列表卡片，正是尊重这条边界的推论。

## 守卫

- 前端：`streamPost` 增加 `cancelToken` 入参并透传；停止后状态进入「已停止」，与「已完成」「失败」并列可渲染。
- 前端：草稿页 `load()` 在 `anyBusy` 时让位，不覆盖在途进度（守住上面断裂 ③）。
- 前端：`shortMessage` 系列文案不得出现「整卷重生成」——它已被 ADR-0056 移除；
  建议以断言或用例锁住，防止文案与能力再次脱节。
- 前端：由 `specs` 反推应出题数抽成纯函数并单测（缺 `count`、空 `specs` 等边界）。

## 后果

- 出题过程与结果在家长端的可见性不再依赖"人有没有停在这个页面"。
- 停止生成让"出到一半发现不对"有了中途退出的可能，不必等全部跑完再整份重来。
- 代价：仍不能跨会话（关 App 即终止）；服务端是否立刻停止消耗 token 未实测，文案必须保守。
- 文案与能力脱节（少题提示指向已移除的按钮）这类问题本轮暴露了一次，守卫项专门针对它加。
