# 助手写意图：不再落只读查询，给一个点得到的出口

2026-09-17 真机报障。家长对助手说：

> 帮我创建一个任务，包含四年级数学题

助手回：

> 我这边只能**查询**学习数据，不能生成或派发任务。创建任务（含选题、指定四年级数学题）
> 需要您到「任务/作业」相关页面操作，选好 2 道数学题后发布给娃娃即可。

这句回答**没有幻觉**，它如实描述了助手的能力——但用户下一步没有着落：他被引向
「任务/作业 相关页面」，却拿不到那个页面。这不是模型的毛病，是四处设计叠加的结果。

## 背景：四方叠加，只有第四层是缺的

实测路由（`agent_core.router.classify` 真跑，非推测；修复前只有 `query/question/tutor`）：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| 帮我创建一个任务，包含四年级数学题 | `query` | `guide` |
| 创建一个任务 | `query` | `guide` |
| 帮我建个作业，放2道四年级数学题 | `query` | `guide` |
| 帮我出2道四年级数学题 | `question` | `question` |
| 今天有什么作业 | `query` | `query` |

1. **路由层**：`query/manifest.py` 的 `triggers` 含泛词「任务 / 作业」，且 `priority=12`
   是当时最高（`question` 0 / `tutor` -10）→ 任何带「任务 / 作业」的**写意图**都被
   只读 agent 接走。`question` 的 triggers 刻意不含「任务」（ADR-0033 决策 6 有意为之，
   为了让「任务题目」归 query），所以那条路上没有第二个候选。
2. **能力层**：`QUERY_TOOLS` 八个工具全部只读；`question` 是单调用流式出题（产 `DATA` 题卡、
   **不落库**）；全仓没有任何 subagent 表达「创建 / 派发」意图。所以「我不能建」在能力上是真的。
3. **提示词层**：`query/agent.py#_SYSTEM` 与 `query/skills/query_sop.md` §边界 都写死
   「只读：不得暗示能修改任务、派发作业；需要写操作时引导用户到对应页面」。
   模型说这句是**照着规格答**。
4. **引导层（唯一真正断的环）**：ADR-0042 的卡片只下发结构化字段
   （`title / subject / items / stats / total / text`），**没有任何位置能放一个出口**；
   前端卡片渲染器也全是纯展示。用户被告知去别处，而别处没有门。

## 决策

- **写意图独立成 `guide` SubAgent，`priority=20` 压过 `query`(12)。**
  优先级是这条路由的**唯一**依据：只要不高于 query，「创建任务」就被只读查询接走。
  所以这不是调参，是功能本身，由守卫钉死。

- **`guide` 不持有工具、也不调用模型。**
  它没有任何信息要查，答案在代码里就是确定的。让模型自由生成这段文案只会带来
  「它又开始编页面名」的风险，而引导正确的唯一标准是**跳转目标正确**——那是编译期常量。
  无工具同时意味着 runtime 走一次性 `run`，省掉一轮模型往返。

- **词表只收「动作 + 对象」的完整短语，`hints` 留空。**
  路由是「词是否被包含」的匹配，泛词（`创建` / `建` / `任务`）会把
  「查一下我创建过的任务」也拽过来。写意图要的是**精度**，宁可漏给 `query`，
  也不误抢查询——`guide` 主动放弃了启发式兜底。

- **`roles` 仅家长。** 娃娃端没有布置任务入口，也不该被引导到一个它进不去的页面。
  娃娃端说「帮我创建任务」仍落 `query` 的只读答复（这是对的，不是遗漏）。

- **卡片加受控跳转动作：`actions: [{label, target}]`，`target` 是枚举不是 URL。**
  助手在服务端、导航在客户端，且同一个目标在家长端（push 的整页）与娃娃端（壳内页签）
  落点不同。下发 URL 等于让服务端描述客户端导航，也把 ADR-0042「不做服务端 UI schema」
  那条线一起越过。前端 `ShellDestination.fromTarget` 是唯一的解读者，
  **认不出的 target 什么也不做**——悄悄兜一个近似落点，会把「协议新增了值、前端没跟上」
  变成一个莫名其妙的跳转，而不是一个能被守卫测出来的失败。

- **跨页导航走声明式意图，不让卡片自己 push。**
  家长端助手是 `Navigator.push` 出来的整页（ADR-0047），壳在它下面。
  点出口 = 写一个 `shellNavigationProvider` 意图 + `maybePop` 退回壳；
  由 `HomeScreen` 消费意图切到目标页（走与点侧栏同一条 `_parentTap` 路径，含覆盖层清理）。
  `ShellDestination` 放在 `shared/presentation/`：壳的目的地属于壳，`assistant` 与 `home`
  都只依赖 `shared`，不制造 feature 之间的横向引用（ADR-0037）。

- **没有处理器的卡片不画出口按钮。** 只读回放里没人接这个动作，
  给一个点不动的按钮比不给更糟——会让人以为界面坏了。

- **空态文案不得承诺做不到的事。** 家长端空态原写「一句话就能布置任务」——
  它做不到，而这正是用户报障时的预期来源。改为「可以出题、查学情、看错题」+
  「布置与派发任务请到『布置任务』页」。

- **顺带修 `query` 的空口承诺**：提示词新增一条——用户想选题 / 找参考题时
  直接用 `list_bank_questions` 查出来，不要只反问「要不要我帮你查」。
  报障那条回答的能力清单几乎是 `QUERY_TOOLS` 的出场顺序复述（一轮工具都没调），
  反问只是把同一轮往返推回给用户。

## Considered Options

- **让模型生成引导文案（保留在 `query` 里改提示词）**——否。写意图仍会占据只读 agent
  的一轮模型往返，而文案里出现的页面名不受控（模型会编「任务管理」这类不存在的入口）。
  引导卡的价值全在「目标正确」，那是常量。
- **给助手真的写能力（AI 选题 → 落 draft 任务）**——本轮不做。写操作要处理权限、二次确认、
  幂等（重复调用不能建两次）、审计（哪条会话建了哪个任务），且它改变「家长必须亲自定题并确认发布」
  这条既有边界（ADR-0001 D7）。值得单独一个 ADR 认真做，不该顺手塞进这轮。
- **复用 `notice` 卡承载出口**——否。`notice` 的语义是「坏消息」（前端给它 `error` 前景色），
  引导卡是「这里有条路」，两者混用会让「出错了」和「去那边做」长得一样。
- **前端按 `kind` 特判、不加 `actions` 字段**——否。那会把「有哪些出口」这一协议事实
  硬编码进前端，后端加一个出口就得改前端渲染分支；而 `actions` 是纯数据，加值不改代码。

## 与既有 ADR 的关系

- **ADR-0042（卡片协议）的扩展，不推翻**：`kind` 仍是判别键、`result` 仍是结构化字段；
  只是多了一个可选的 `actions`。协议新增 `guide` 一种 kind，前端 `AssistantCardKind`
  同步登记一次（未登记的 kind 仍走降级卡，不丢内容）。
- **ADR-0037（前端分层）**：`ShellDestination` 落在 `shared/`，`home` 与 `assistant`
  各自依赖它，两者之间没有引用。
- **ADR-0047（助手整页）**：`showBack` 恰好区分「push 的整页」与「壳内页签」，
  出口动作据此决定要不要 `maybePop`——不需要猜宿主形态。
- **ADR-0026 / 0033（角色边界）**：`roles: [parent]` 沿用 `visible_businesses` 这条唯一真相源。

## 守卫

- 后端 `tests/ai/test_guide_subagent.py`：真机原句归 `guide`；**查询意图仍归 `query`**
  （词表放宽的第一批受害者）；`priority > query.priority` 的结构不变量；`guide.tools == []`；
  娃娃端不可见；卡片 `kind` 与 target 值域。
- 前端 `test/assistant_card_action_test.dart`：`actions` 解析与「半张动作卡整条丢弃」；
  `fromTarget` 覆盖后端全部 target 且未知返回 null；按钮点击把 target 交回宿主；
  无处理器时不渲染按钮；出口按钮键盘可达（ADR-0046）。

## 后果

- 「创建任务」类写意图不再消耗模型往返，回答确定性、无幻觉风险，且给出可点出口。
- **协议多了一处需要两端同步的常量**（target 值域）。跨语言无法直接断言一致，
  故两侧各自守卫自己的那一半：后端断言 target ∈ 常量集，前端断言常量集都有映射。
  新增 target 时**必须**同时改 `guide/agent.py` 与 `ShellDestination.fromTarget`，
  否则按钮会静默变成「点了没反应」。
- 娃娃端说「帮我创建任务」仍是只读答复（无出口）——这是有意的：娃娃端没有那个页面。
