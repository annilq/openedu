# 出题预览的审阅闸门：思路不落库，生成完停在原页等确认

2026-09-20 报障。家长在「布置任务」页用 AI 出题，生成过程中能看见「出题思路」；
生成一结束界面切到「任务草稿」页，思路不见了。

> 请分析出题思路是否持久化到数据库中，如果没有持久化的话，那在页面跳转后就看不到了。

报障人的推断是对的。但查完之后结论要往前走一步：**这不是数据丢失，是两件事叠在一起**——
思路本就不落库（ADR-0017 明文决策），而"生成完自动跳走"让这个正确决策看起来像个 bug。
本 ADR 保留"不落库"的结论，把被推翻的那半（自动跳转 + 流结束即落库）改掉。

## 背景：闭合的证据链

思路（reasoning）在整条链路上**三重不存在**——不是"写了没返回"，不是"字段漏赋值"：

| 环节 | 位置 | 事实 |
|---|---|---|
| 产出 | `app/ai/subagents/question/parsers.py:45-57` | `QuestionOut.reasoning`，docstring 明写「仅用于流式预览态展示，不落库」 |
| 落库 | `app/features/tasks/service.py:486-496` | `_question_fields()` 白名单**硬排除** reasoning，注释「那是给人看的推理文本，不进题目表」 |
| 表结构 | `app/db/models/question.py:20-43`、`task.py:35-58` | `Question` / `TaskQuestion` 均无 reasoning 列（只有 `explanation`） |
| 读回 | `app/features/tasks/schemas.py:65-77` | `QuestionResp` 无该字段 → `GET /tasks/{id}` 结构上不可能返回 |
| 前端模型 | `shared/domain/models/models.dart:127-217` | `QuestionModel` 无 reasoning；只有预览态的 `QuestionPreview` 有（`:234`） |
| 迁移 | `app/core/db.py` `run_migrations` | 无任何 reasoning 相关 DDL |

前端其实**把 reasoning POST 给了** `/tasks/from-generated`（`models.dart:273`），是后端白名单主动丢弃的。

### 让"正确的决策"看起来像 bug 的两处设计

1. **生成完自动跳走，且落库发生在跳转之前。**
   `home_notifier.dart:124` 的 `_persist()` 在 SSE 流一结束就 `POST /tasks/from-generated`（任务已是 `draft`）；
   随后 `parent_task_form_view.dart:197-221` 在 `ref.listen` 的 post-frame 回调里无条件下发跳转。
   家长没有任何"停下来看一眼"的机会，思路的消失被体验成"刚才那段东西丢了"。

2. **草稿页自己又在重生成时显示思路。**
   `parent_task_review_screen.dart:264-269` 在单题重生成 / 整卷重生成时用 `liveText` 渲染
   `StreamReasoningPanel`。也就是说同一张题卡，"正在重生成"时思路可见、"生成完刷新"就没了——
   同一个页面给了两种答案，这才是真正的不一致。

### 一条硬约束：草稿页是全局唯一能改题目的地方

- `service.py:1145` 的 `edit_question` 有 `_require_draft` 守卫；`questions/router.py`
  只有 GET / DELETE / 归档，**没有任何 PUT / PATCH**。
- 草稿页**没有「添加题目」入口**（整份文件无添加按钮）→ 「删除」是单向的，删掉就少一道题。
- 因此单题「换一题」（`parent_question_card.dart:443-473`）不只是重生成，它是草稿页
  **唯一能维持题数不变地改掉一道题**的手段。

## 决策

- **思路仍然不落库（ADR-0017 的结论不变）。**
  它是模型**这一次**生成的中间产物，不是题目的属性。语义上它归属 `TaskQuestion`（任务↔题关联行）
  而非 `Question`（题库实体）——题库是跨任务复用的共享实体（ADR-0004），把一次生成的独白写进
  共享题库，正是当年拒绝落库的理由。**但既然不落库，这个归属只是语义澄清，不产生任何列。**

- **思路 = 生成过程的附属品，草稿页彻底不提它。**
  两处规则统一为「哪里正在生成，哪里就有思路；生成结束，思路即随过程结束」。
  不做"带进草稿页、刷新即消失"的折中——那会造出一个新的、更糟的不一致（刚进来有、刷新就没）。

- **生成结束不再跳转，停在生成页等家长确认。**
  思路消失的时刻从"系统自动"变成"用户按下确认"，这是本轮最核心的体验修复。
  预览态与草稿态的边界也因此变得可见：**未确认 = 预览（可整份重来），已确认 = 草稿（可精修）。**

- **落库时机后移到「确认」时——预览态纯内存，不碰数据库。**
  这一条同时解决两个问题：
  1. 「重新生成」不再产生第二份 draft。若沿用"流结束即落库"，预览页点重来会落第二张表行，
     而"生成完家长不满意直接走"也已经会留下孤儿 draft。
  2. **后端少一次必然发生的聚合写入**——被放弃的生成在数据库里不留任何痕迹，
     「放弃」甚至不需要调 `DELETE /tasks/{id}`（本来就没写过）。

- **草稿页去掉「整卷重生成」，保留单题「换一题」。**
  整卷重生成等价于"这份推翻重来"，与"回生成页重来一份"功能重复，且是全量重跑；
  在"生成页停住、可整份重来"的新流程下它是冗余的。
  单题换一题**必须保留**：删掉它是真正的削足适履——草稿页不能加题，删了就少一道，
  剩下的唯一路径是回题库页重选再组卷（见上面的硬约束）。

- **生成页明写边界文案：思路仅在生成过程中展示，不会随任务保存。**
  行为（思路不进草稿）与文案（明说它不保存）互相印证。只改行为不改文案，
  下一次仍会被当成 bug 报上来。

## Considered Options

- **把思路落库（加列 + 迁移 + 模型 + 赋值 + schema + 前端模型 + 渲染）**——否。
  本轮确认了它的用途是"当场判断这题出得对不对"，不是留档回溯。
  为一次性的审阅动作永久存储模型中间产物，还要付迁移与两端同步的成本，不划算。
  且它会与 ADR-0043「REASONING 不进回灌历史」的边界纠缠：落了库，
  后续任何"把题目上下文喂回模型"的改动都要额外判断要不要带上思路。

- **思路跟着进草稿页（内存传参，刷新即消失）**——否。
  它把"消失"从一个可解释的时刻（按下确认）挪到了一个随机的时刻（刷新），
  用户会当成新的 bug。

- **保留"流结束即落库"，只加确认闸门**——否。
  「确认」会变成一道假闸门：它拦不住任何写，家长不确认直接切走照样留下孤儿 draft；
  而生成页一旦要提供"重新生成"，就会批量产出第二份、第三份 draft。
  要给错误的落库时机打补丁，就得让前端记住 `lastTaskId` 并在重来前补一次删除——丑且易漏。

- **草稿页的重生成全砍（连单题换一题也砍）**——否。
  见硬约束：草稿页不能加题，砍掉之后"9 道题里第 3 道不好"只能删掉它（题数 -1）
  或整份重来（9 道全废），两条路都很难受。

## 与既有 ADR 的关系

- **ADR-0017（出题推理打字机）结论不变，本 ADR 不修订它。**
  「仅预览态、不落库」仍然成立并被重申；被推翻的是 0017 **没有写**的那半——
  "生成结束后自动跳转、且跳转前已落库"。ADR 不原地改写，故新增本条。
- **ADR-0043（推理/正文分流）**：思路走 `TextKind.REASONING` 通道、不进回灌历史。
  本轮不落库的决定与之一致——落了库反而会让"要不要把思路喂回模型"变成新的判断题。
- **ADR-0004（Question 表即题库）**：不把一次生成的独白写进跨任务复用的共享实体，是这条的直接推论。
- **ADR-0053（长列表 / 归档）**：孤儿 draft 的减少同时降低了任务列表的噪声，与"归档三套语义"不冲突。

## 守卫

### 已实现（2026-09-20，前端）

- `home_notifier.dart`：新增 `TaskGenReady` 态（生成结束、未落库）+ `_Pending`（内存中的题卡与请求体）。
  流结束**不再**调 `_persist()`；落库收口到新的 `confirm()`，`discard()` 只清内存。
- `parent_task_form_view.dart`：`_buildActionArea` 在 `TaskGenReady` 时渲染审阅闸门
  （确认并进入草稿 / 重新生成 / 放弃，`Wrap` 排布）；`_buildPreview` 兼容 `TaskGenPreview`
  与 `TaskGenReady` 两态，并在存在思路时显示边界文案。跳转只在 `TaskGenSuccess`
  （即确认并落库成功）之后发生。
- `parent_task_review_screen.dart`：`_buildActionBar` 移除「整卷重生成」；`_EmptyHint`
  去掉 `onRegen`（删空之后页内无法补齐，给按钮是误导），只留指路文案；
  随之失效的 `_onRegenerateAll` 一并删除。单题「换一题」保留。
- `flutter analyze` No issues found! · `flutter test` 245 passed。

### 尚未实现

- **后端白名单守卫**：`tests/api/routes/` 补一条断言——`/tasks/from-generated` 的入参
  **含** `reasoning` 时被 `_question_fields` 丢弃（锁住"不落库"，防止有人顺手把它存进去）。
  这是本 ADR 最关键的不变量，目前只有代码注释与 docstring 在守。
- **行为级守卫**：确认前不存在任何 draft 行（可用"生成后不确认 → 任务列表为空"的用例守住）。
- 前端闸门本身无单测（`TaskGenReady` → `confirm()` → `TaskGenSuccess` 的状态机）。

### 已知遗留

- `parentTaskReviewNotifier.regenerateAll` 及其下的 repository / api client / 后端端点
  `POST /tasks/{id}/regenerate-all` **仍保留但已无调用方**（草稿页入口是本仓唯一使用者）。
  同理 `ReviewLoaded.progress` 现在恒为 null，草稿页顶部进度区成为死分支。
  未一并删除的原因：跨 4 层的删除面较大且可能波及既有测试，留待单独一轮清理——
  **别把它当成"还有别的入口在用"**。

## 后果

- 思路的消失变成用户主动行为的结果，不再是"东西丢了"。
- 预览态纯内存 → 被放弃的生成不产生任何数据库写入，任务列表不再堆积孤儿 draft；
  「放弃」不需要删除调用。
- **代价：预览态期间切走或退出，题会丢，需要重跑一次 AI。** 已评估：现状同样会丢弃产物，
  只是丢下的是**数据库里的一行垃圾**；新方案丢下的是**什么都没有**，严格更干净。
  且生成页已停在那里等确认，手滑概率低。
- 草稿页少了整卷重生成，但保留了精准的单题换一题——后者是刚需，前者与新流程重复。
