# ADR-0050 · query 题库工具支持自然语言时间过滤与路由加固

- 状态：Accepted（2026-09-16）
-  supersedes：—（承接 ADR-0049 的 `list_bank_questions`）
-  相关：ADR-0042（卡片协议）、ADR-0040（strict 模式缺席编码）、ADR-0033（查询 SubAgent 分层）

## 背景 / 问题

ADR-0049 落地了「查询题库题目」工具，参数提取走 LLM 函数调用（genkit 适配器
`return_tool_requests=True`，模型读工具 schema 抽参）。复盘两个真实诉求发现三处缺口：

1. **时间维度缺失**：用户说「查近三天的题」时，工具 / 服务 / 仓库三层都**没有日期过滤参数**，
   仓库只 `order_by(created_at.desc())` 排序。模型没有任何槽位可放「近三天」——只能忽略约束或
   靠 `limit` 取最近 N 条后在脑子里后过滤（不可靠，且撞 SOP「查不到就说查不到，不许估算」）。
   注：`created_at` 已随题目返回，模型「看得到时间」却「无法变成 SQL 过滤条件」。
2. **字符串维度是严格等值匹配**：`subject` / `knowledge_point` / `qtype` 都用 `==`。模型若吐
   「数学题」「二次方程」「选择题」这类近义 / 中文标签就匹配不到 → 空结果。grade 因是整数躲过此劫。
3. **路由不敏感**：`query` 的 triggers 是「题库 / 查题库…」关键词，manifest 描述甚至没列「题库」。
   一句没有「题库」二字的「查 4 年级的题」可能不被识别成题库查询、路由不到本工具。

## 决策

### 1. 加相对天数参数 `since_days`
仓库层 `list_bank_questions` 新增 `since_days: int | None`，过滤
`Question.created_at >= now_utc - timedelta(days=since_days)`（闭区间，含当天）。
服务层与工具层透传；工具 schema 暴露 `since_days: integer`，描述「只返回最近 N 天内创建的题目；
0 或空＝不限时间」。模型输出自然数 N 即可，「近三天」→ `since_days=3`，与「按创建时间推算」一致。

**不选**绝对日期 `created_after`：自然语言里家长几乎不会说具体日期，相对天数覆盖近三天 / 上周 /
本月且模型最易输出；两者都加会多一个参数、加大模型选型负担（ADR-0040 的 strict 必填陷阱）。

### 2. 字符串维度保持精确匹配，靠 schema 描述引导模型抽对（不引入模糊匹配）
参数提取本就由 LLM 读 schema 完成。故只在三个字符串参数的 `description` 里写清**规范取值**，
让模型吐出服务端能精确匹配的值，而非加 ilike / 归一逻辑（避免扩大误命中、保持语义确定）：
- `subject`：取值须与题库存储一致（数学 / 语文 / 英语…），不要加「题」等后缀；
- `knowledge_point`：必须与题库中该知识点**原文**完全一致（如「一元二次方程」），不要改写 / 缩写；
- `qtype`：题库里的 `qtype` 原值（如 `calc` / `choice`），不要翻译为中文。

### 3. 路由加「查」触发词（非「年级 / 题目」）
`query` manifest 的 `triggers` / `hints` 增加「查」（单字动词）。使无「题库」二字的
「查 4 年级的题」也能命中本 SubAgent（子串匹配 + priority=12 压住 `question`）。

**踩坑修正**：初版曾加「年级」「题目」作触发词，但路由是子串匹配、`query` 优先级最高，
导致「帮我出 3 道三年级分数选择题」因含「年级」「题目」被误抢到 `query`（出题意图丢失，
`test_question_intent_still_goes_to_question` 红）。「查」字精准区分两类意图——查询类必有
「查 / 查看 / 查询」，出题类说「出 / 生成 / 写」，**不含「查」**，故加「查」不会误抢出题；
真正裸的「4 年级的题」（无动词）仍属歧义句，可接受落到 `question`（出题），不在本题范围。

## 后果

- 正向：「近三天 / 上周 / 本月」「4 年级」「三年级语文」等自然语言现在都能落到可执行过滤；
  路由对裸问句更鲁棒。
- 负向 / 风险：
  - `since_days` 基于 `created_at`（创建时间），非「最近复习 / 最近答错」时间——语义是「最近添加的题」。
    若日后要「最近做错的题」需另开参数（那是错题本维度，不在本题库工具）。
  - 字符串维度仍非模糊：若模型坚持吐近义词（如「二次方程」vs 存储「一元二次方程」）仍会空结果；
    靠 `ToolArgumentError` 回灌自愈，不保证 100% 命中。
  - `since_days` 与 `limit` 叠加：`limit` 在 `since_days` 过滤后的结果上截断（取最新 N 条）。
- 契约测试：工具集仍为 8 个（`list_bank_questions` 仅新增可选参数，不影响 `PARENT_ONLY_TOOLS`
  豁免）；新增仓库层 `since_days` 过滤的单测。

## 备选

- 绝对日期 `created_after`：弃，理由见决策 1。
- 字符串维度改 ilike 模糊：弃，近义会扩大误命中、且「一元二次方程」vs「一元二次方程组」本就不同，
  模糊反而危险；保持精确 + 写好 schema 风险更可控。
- 路由不改、要求用户必带「题库」：弃，与「AI 按输入抽参」目标相悖。
