# ADR-0099 已确认规格的跨轮回灌（续话不丢上下文）

- 状态：提案（待评审）
- 日期：2026-10-19
- 关联：ADR-0095（slot filling 与 `Conversation.slots`）、ADR-0034（结构化规格接缝）、ADR-0097（question 改 tool loop）、ADR-0038/0033（引擎失败归因）

## 1. 背景（Context）

`Conversation.slots` 自 ADR-0095 起就按 business 分组持久化已确认槽位，写入点在
`service.chat` 的预检块，每轮 `commit()`。读码核实（非凭记忆）：

- 槽位**只有一处写入**（`service.py` 的 `{**_store, business: merged}`），全仓无置空 / pop /
  clear，槽位记忆**永不失效**；
- 注入生成器的条件是 `business == "question" and (extracted or _was_incomplete)`——
  即「本轮抽到槽」或「本轮刚补齐」。

于是出现一个用户可见的断层：

1. 用户说「出2道三年级数学选择题」→ 槽位齐备、规格注入、正常出题；
2. 用户说「再出几道」→ 消息不含槽关键词 → `extracted` 为空，且 `_was_incomplete` 已为
   `False` → **不注入** `ctx.extra["specs"]`；
3. 出题子代理（ADR-0097 的 tool loop）拿不到结构化规格，只能从
   `ctx.history` 里由模型自行重建科目 / 年级 / 题型。而历史经
   `load_chat_history_with_summary` 的 compaction（`limit=20` 条 / `4000` tokens）后，
   最旧轮次被丢弃或压成一句 ≤80 字摘要。

表现在用户侧就是「上一轮刚说过三年级数学，这一轮它又问一遍 / 出的题跑偏」。

**关键点：丢的不是记忆，是回灌。** 规格一直躺在 `slots` 里，只是没被交给生成器。

## 2. 决策（Decision）

### 2.1 注入与汇总帧解耦，注入改由「本轮是否在作出题请求」判定

`service.py` 预检块拆成两条独立判定：

- **注入**（`ctx.extra["specs"]`）：本业务为本轮意图时注入已确认规格；
- **汇总帧**（「已确认规格」ASSISTANT_MESSAGE）：仍只在本轮带来新 / 变更规格时下发，
  否则每轮都弹一遍确认卡是噪声。

「本轮是否为本业务意图」由三道**确定性**证据判定（任一生效，无模型参与）：

1. 消息含 manifest 的 `triggers` / `hints` 词（如「再出几道」）；
2. 本轮抽到了槽（如「换成一年级语文」——无出题意图词，但明确在改规格）；
3. 本轮刚好补齐槽位（刚回答完澄清，仍在同一流程内）。

三者皆无 → 「谢谢」这类无关话不注入，避免拿旧规格再出一轮题。
词表复用 manifest（`_business_triggered`），不在 service 另写一份意图词。

### 2.2 规格按「基底 + 覆盖」合并，不再拼接后各自展开

`generate_questions` 原先把 `ctx.extra["specs"]` 与模型 `from_args` **append 成列表**再各自
展开。注入持久规格后，模型若仍按历史填 args，count 会相加（「再出 2 道」变 4 道）。

改为 `specs.merge_spec_layers(base, overrides)`：基底的持久规格为准，`overrides` 只覆盖
自身**有值**的字段（absent 编码 `""` / `0` / `False` 视为未提供）。这既保住 ADR-0095
「结构化规格优先、不让模型改写」，又让模型表达的新意图（换难度 / 换题型）生效。

### 2.3 规格的生命周期边界 = 会话，不引入「意图会话」

本 ADR **不**新增意图开始 / 结束状态机。分析过的退出条件（闲置超时、路由切换、
生成成功、用户显式结束）没有一个站得住：

| 候选退出条件 | 后果 |
|---|---|
| 闲置超时 | 需定时器 + 时间戳字段，且 5 分钟与 5 小时在产品上无差别 |
| 路由到别的业务即结束 | 问一句别的再回来说「再出几道」就丢规格，正是要修的病 |
| 生成成功即结束 | 「再出几道」必成新意图，规格重新收集，回到原点 |
| 用户显式结束 | 产品无此动作 |

真正的模型是**一份会话内规格文档，最新消息可修订它**。换科目 / 年级由
`fill_slots` 已有的 extracted 覆盖 merged 语义完成，用户无需「退出」再「进入」。
清空只需新建会话：`slots` 随新 `Conversation` 自然为空，无需新代码。

多规格（同会话保留多套并在其间切换）**不做**：家长出题场景没有编排多套规格的需求，
重述一次科目年级的成本远低于一套多规格 UI 的理解成本。若日后成为真需求，改为
`slots[business]` 存列表 + 活跃指针，成本明确可估。

## 3. 后果（Consequences）

**变好**

- 续话（「再出几道」「降低难度」）稳定复用已确认规格，不再依赖模型从会被压缩的历史重建；
- compaction 挤出首轮后规格仍从 `slots` 回灌，长会话不再失忆；
- 消除了 count 双计这一既有潜在缺陷。

**代价 / 已知边界**

- 「换成一年级语文」这类**无出题意图词但改规格**的句子，依赖第 2 道证据（抽到槽）才注入；
  若模型改写措辞到既无意图词也抽不到槽，仍会回落历史通道。这是确定性抽取的固有边界，
  不打算用 LLM 兜底（儿童产品要求路由与预检确定性）。
- 同一会话内旧规格被新规格覆盖后不可回退到旧规格（单规格文档模型）。

## 4. 守卫

`backend/tests/features/assistant/test_slot_context_carryover.py`：

- 续话轮必须重新注入已确认规格（在旧实现上**红**）；
- 续话轮不重发汇总帧；
- 改规格轮覆盖槽位并照常下发汇总帧；
- 长会话 compaction 后规格仍回灌（在旧实现上**红**）；
- 「谢谢」等无关消息不注入（锁定服务端闸门不依赖路由兜底）；
- 新会话不继承旧会话语义；
- `merge_spec_layers` 的覆盖 / 缺席编码 / 不双计。

既有回归 `test_slot_filling_integration.py::test_unrelated_followup_does_not_regenerate`
继续为绿——本 ADR 的注入闸门正是为守住它而设计。
