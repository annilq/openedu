# Spec：SceneSpec 与 Figure 统一（几何只留一份表达）

> 仓库 `github.com/annilq/openedu` · 标签 `ready-for-agent` · 对应决策 **ADR-0091**
> 依赖顺序：**本 issue 先做**；「场景感知的出题与答疑」issue 依赖它（后者落库时盖的章就是本 issue 定下的形状）。

## Problem Statement

同一个「几何」现在有三种写法，而它们本该是同一个东西：场景规格把顶点摊平在自己顶层；
场景规格里那组选项条目又用另一套字段名带一份顶点；通用图形类型带了身份键却是第三套名字。
结果读写两侧对同一份几何各有各的认识——生成侧按「顶层字段覆盖」合并，渲染侧按「条目解析」读取。

身份缺失已经造成了一个真实缺陷：选项条目不带图库身份键，图形画廊只能拿**展示名**当身份用。
教师在画板里改一次图形的名字，卡片角标与高亮的映射就断了；同名图形还会被静默合并成一个。

之所以现在才动，是因为统一的代价是**改写存量快照**。项目未上线，这个窗口还开着。

## Solution

让「图形」成为几何的**唯一载体**，场景规格从「把顶点摊平在自己身上」改为**持有一个图形**：
一次演示 = `kind` + 一个主图形 +（可选）一组选项图形。前端的图形模型补齐连接关系字段，
与后端同构；场景规格在前端第一次拥有类型（此前它只是一张裸字典，解析散落在两处）。

随之删掉：选项条目的旧投影类型、选项组那层嵌套、旧形状的兼容适配层、来源标记字段、
以及「顶层字段覆盖」这套合并语义（改为「替换主图形」）。

顺带修掉身份缺陷：画廊改用真正的图库身份键，展示名回归它本来的用途——显示。

## User Stories

1. As a 开发者, I want 几何只有一种写法，so that 生成侧与渲染侧不再各自解析一遍同一份数据。
2. As a 教师, I want 改图形名之后课件与题目里的卡片角标不错位，so that 身份由身份键承担而非展示名。
3. As a 开发者, I want 场景规格在前后端都是类型而不是裸字典，so that 形状变更能被静态发现而不是线上崩。
4. As a 开发者, I want 删掉旧形状兼容层与重复投影类型，so that 上线后不用长期维护两套形状。
5. As a 学生, I want 图形画廊的行为不变（点卡片仍弹出可拖轴的对折演示），so that 形状归一不带来观感回归。
6. As a 教师, I want 我在画板里自绘的图形在场景里也有稳定身份，so that 它与内置图形享有同等地位。
7. As a 开发者, I want 一次演示的交互参数仍然不进规格，so that 几何与交互不会因为改外壳而互相污染。
8. As a 开发者, I want 存量快照一次性改写而不是两套形状长期共存，so that 双读分支不会把旧形状永久化。
9. As a 学生, I want 场景里没有几何时看到讲清原因的空态而不是空白画布，so that 我知道为什么没有演示。
10. As a 开发者, I want 迁移脚本可重复执行且能先干跑，so that 我敢在开发库上跑它。
11. As a 教师, I want 课件环节里编排的图形顺序被严格保留，so that 我排的顺序就是学生看到的顺序。
12. As a 开发者, I want 图形身份键只用于身份与溯源、渲染始终用内联顶点，so that 运行时依旧零图库依赖。

## Implementation Decisions

- **统一后的形状**（schema 片段取自 ADR-0091 草案，比散文更精确）：

```json
{
  "kind": "reflection",
  "figure":  { "key": "para", "label": "平行四边形", "points": [[0.30,0.40],[0.70,0.40],[0.82,0.70],[0.42,0.70]], "edges": [[0,1],[1,2],[2,3],[3,0]] },
  "options": [ { "key": "square", "label": "正方形", "points": [[...]], "edges": [[...]] } ],
  "curated": false
}
```

  `options` 非空 → 渲染图形画廊（既有行为）；否则渲染 `figure` 单场景；
  两者皆空 → 空态（回答「为什么空 + 下一步」）。

- **图形类型定义不变**：`{key, label, points, edges}`，渲染只吃 `points` / `edges`。
  本 issue 只负责**落地**这个类型（它的决策记录在 ADR-0089）；若「AI 链路」issue 先开工，
  类型会先在那里落地，则本 issue 只改场景规格的形状。
- **反转 ADR-0083 决策 6**：由「规格不含身份键」收窄为「**渲染不消费身份键**」。
  带键只为身份 / 溯源 / 校验；「运行时零图库依赖」（决策 7）**不变**。
- **前端图形模型补 `edges`**：与后端同构（此前前端只有顶点、按序闭合）。
- **删除**：选项条目的旧投影类型、选项组嵌套层、旧形状兼容适配层、来源标记字段、
  以及顶层几何覆盖语义（改为「替换主图形」）。
- **交互参数的归属不变**：`kind` 仍是稳定契约，轴初值 / 控件 / 引导语继续由**交互外壳**提供，不进规格。
- **存量快照一次性幂等改写**，范围：题目与任务题的场景规格列、知识点场景配置、课件环节内嵌场景。
- **身份键缺失的处理**：旧快照本来没有身份键 → 按顶点反查图形几何库取键；查不到 → 生成自绘前缀键。
  渲染期的最后兜底图形**不参与落库**。
- **不做双读**：代码只认新形。双读分支正是「两套形状」的持久化，留着就白统一了。
- **模块改动范围**：场景域的融合模块（三个生产函数改产新形）、资料域服务（知识点场景读写）、
  题库 / 复习 / 任务的响应侧（形状变了，端点与契约名不变）、前端图形模型与场景解释器、
  课件环节的画板写规格处、新增一次性迁移脚本。
- **实施顺序**：类型与校验入口 → 生产端改形 → 消费端改形 → 迁移脚本 → 前端类型 → 前端消费端 → 测试。

## Testing Decisions

好测试的标准：**只测外部行为**——断言端点下发的形状与学生 / 教师看到的结果，
不断言内部函数怎么被调用；形状类断言走**端点级**而不是服务级
（历史教训：只测服务会漏掉某个端点整段忘了下发）。

- **接缝一（出题链路）**：题目详情 / 任务详情 / 错题本三个 REST 端点，按端点断言下发的场景规格
  是新形（顶点在 `figure` 里、选项组是图形数组），并断言快照不可变
  （改图形几何库的顶点后，已落库的顶点不变）。既有先例：题库场景的接口级测试。
- **身份缺陷回归**：改图形的展示名后，画廊角标映射不变（真身份键生效）——本次修复的缺陷，必须有断言。
- **校验入口**：新形直读；**旧形被拒绝**（断言它返回空 / 拒绝，而不是静默适配成旧形）。
- **迁移脚本**：幂等（跑两次结果相同）+ 干跑开关 + 旧形样本 → 新形且顶点反查拿到身份键。
- **前端**：几何断言而非截图（本仓库禁止在测试里做截图装置：无真实合成器会挂死，
  实测把前端测试从约 46 秒拖到 17 分钟）。全量前端测试与静态检查不回归；
  静态检查以输出里的「No issues found!」为准（该命令退出码常非 0）。
- **后端**：改 `features/*/service.py` 必跑分层不变量测试（归属判定只许走 `core.guard`）。

## Out of Scope

- 新增可渲染的 `kind`（需开发者工作流 + 前端渲染器发版）。
- 图形类型本身的定义变更（ADR-0089 已定）。
- 「AI 链路」（删除文本抽取、选项内嵌图形、目录投影 / 校验 / 盖章、答疑三层识别、前端选项渲染）
  ——独立 issue，依赖本 issue 定下的形状。
- 允许的一个降级：若消费端改形时序列化调用点过多，可退为「后端保持字典形状 + 统一校验入口」，
  但**形状必须一致**（顶点在 `figure` 里），只是省掉类型化。

## Further Notes

- **本 issue 唯一的成立条件是「未上线」**：它唯一不可逆的代价是一次性改写存量快照。上线后不得再做。
- **它不是纯整理**：顺带修掉「画廊拿展示名当身份键」这个已存在的缺陷。
- **与 ADR-0083 的关系**：决策 5（规格瘦成几何 + 交互归外壳）**不动**；
  决策 6（不含身份键）**收窄**为「渲染不消费身份键」；决策 7（零图库依赖）**不动**。
- **与 ADR-0089 的关系**：本 issue 落它定义的图形类型，并让场景规格持有它；
  后者再用这个形状做「AI 出题与答疑」的闭环。
