# Spec：场景感知的 AI 出题与答疑（删除文本抽取，图形内嵌选项）

> 依赖顺序：**被「SceneSpec 与 Figure 统一」issue 阻塞**——本 issue 落库时盖的章就是那边定下的形状。
> v1（复用旧选项组）与 v2（`OptionFigure` + 关键词门控）均已被 v3 取代，本文件为当前唯一有效版本。
> **状态：已落地**（2026-10-13 全部 4 票 done；对应 ADR-0089 v3.1 已标「已实现」）。

## Problem Statement

「下列图形哪些是轴对称图形」这类选择题，每个选项本身就是一个平面图形——学生要**逐个亲手试**，
而不是读一段文字描述。今天这条链路能跑，但方向错了：送进渲染的顶点靠正则扫文字反猜
（扫选项文字、扫题干与提问）。代价是三个：

1. 命中取决于模型恰好写出标准中文图形词——换个说法（「这个图形有几条对称轴」）就静默失效；
2. **任一选项猜不出就整题无图**（全-or-无）；
3. 教师在画板里自绘的图形因为词表里没有它，永远进不来。

答疑侧同病：伴学子代理用正则从学生提问里猜图形名来决定是否弹交互场景卡——
「平行四边形是轴对称图形吗？」今天能出图，靠的就是命中「平行四边形」四个字。

项目仍在开发期，宁可现在删干净，不留上线后的维护债。

## Solution

删掉整族文本抽取（整个抽取模块及其测试），几何改由 **AI 显式引用身份键 + 后端盖章**产生；
图形**内嵌进选项本身**（选项 = 文字 + 可选图形）；答疑侧改为**三层识别**：
确定性门控 → 模型结构化微调用 → 后端校验盖章。

目录投影 / 校验 / 盖章这套逻辑出题与答疑共用，独立成一个模块；
它不新增任何关联表或列——知识点场景本来就是知识点与场景的关联，场景库只是它的派生视图。

## User Stories

1. As a 教师, I want AI 出的图形选择题每个选项都渲染成平面图形，so that 学生看图而不是读描述。
2. As a 教师, I want 我在画板里自绘的图形也能被出题引用，so that 图形不再局限于内置的那几个。
3. As a 学生, I want 点选项上的图形就能拖对称轴做对折演示，so that 我亲手验证而不是看答案。
4. As a 开发者, I want 后端不再有任何「从自然语言猜图形」的代码，so that 命中不依赖模型措辞。
5. As a 开发者, I want 模型只引用身份键、绝不输出顶点，so that 几何始终来自图形几何库这一处权威。
6. As a 学生, I want 问「平行四边形是轴对称图形吗」时答疑直接给出可交互图形，so that 讲解直观。
7. As a 学生, when 我的提问与图形无关（问作业 / 问定义 / 纯计算）, I want 不弹任何场景卡，
   so that 不会凭空冒出一个不相干的图形。
8. As a 教师, when 模型只给部分选项配了图形, I want 整题退化为纯文字，
   so that 学生不把「没图」误当成「这个选项不是图形」。
9. As a 开发者, I want 「图形」这个概念前后端只有一个名字，so that 选项、答疑场景卡、课件画廊复用同一形状。
10. As a 教师, I want 出题时系统只把可用的图形清单给模型、不把顶点给模型，so that 模型没有坐标可以编。
11. As a 学生, I want 场景卡先于讲解正文出现，so that 我先看到图形再读文字。
12. As a 学生, I want 同一张图不会在连续追问里反复弹出，so that 它不干扰我阅读。
13. As a 开发者, when 意图判定调用出错, I want 讲解正文照常完整输出，so that 增强功能绝不吞掉主功能。
14. As a 教师, I want 我为学生自编的知识点也能参与出图，so that 图形能力不被内置目录限制。
15. As a 开发者, I want 门控不靠关键词，so that 「要不要出图」不依赖学生的措辞。

## Implementation Decisions

- **删除整族文本抽取**：扫选项文字的函数、扫题干与提问的函数、整个抽取模块、以及它们的测试。
  留任何一个都等于留一半猜测逻辑。
- **保留并改名盖章原语**：「按身份键取权威顶点 → 产出纯几何场景」这一步正是新链路要用的，
  但它的名字里有「兜底 / 默认」语义，会误导后人以为那是降级路径——改名（4 处调用 + 测试一并改）。
- **选项数据结构**（schema 片段取自 ADR-0089 草案）：

```json
"options": [
  { "text": "A. 正方形",     "figure": { "key": "square", "label": "正方形",   "points": [[...]], "edges": [[...]] } },
  { "text": "B. 平行四边形", "figure": { "key": "para",   "label": "平行四边形", "points": [[...]], "edges": [[...]] } }
]
```

  - `text` 恒存在：它是作答与评分的唯一依据，选项前缀保留（去掉前缀会破坏判题比对）；
  - 几何**内联**在选项里（渲染只吃顶点与连接关系、零图库依赖、离线课堂可用）；
  - **不带 `kind`**：演示类型取题目级场景规格的 `kind`，避免每个选项各说一份；
  - **全-or-无挪到校验层**：数据形状允许逐项可空，但落库前校验——部分选项有图 → 整题全部丢弃。
- **用容错读取过渡**：选项列的兼容读取支持「字符串 → 包成对象」，判题改走「取选项文字」；
  同一列，**无 DDL 迁移**。
- **目录投影 / 校验 / 盖章独立成模块**：只装三件事。输入是知识点场景（优先教师已配置的图形）
  回落图形几何库全量；**不新增任何关联表或列**。场景库是派生视图，生成不读它。
  **若只有一个消费方本可省掉这个模块**——正因出题与答疑两个消费方需要完全相同的这套逻辑才独立。
- **目录条目用「身份键 + 中文名」的轻量类型，而不是图形本身**：类型层面就保证顶点进不了提示词
  （图形类型带着几何，直接序列化进提示词就会漏）。
- **出题侧**：题卡的结构化输出增加每项的图形身份键（**只给键，不给顶点**）；出题提示词注入
  「可用图形清单」；落库前校验 + 盖章。模型的判断通过「填不填」表达，不需要额外一次调用。
- **答疑侧三层识别**（schema 片段取自 ADR-0089 草案）：

```json
{ "should_show": true, "figure_key": "para", "rationale": "提问在问该图形的对称轴数量" }
```

  - **L0 确定性门控（不调模型）**：能解析出知识点（课件 / 题目 / 学生当前知识点；
    都没有则走资料片段检索命中知识点）**且**能投影出非空图形目录 → 才发起调用。
    ⚠️ **不用意图关键词**——那仍是猜，且知识点场景是教师显式配置的、更强且零成本的信号。
  - **L1 模型判定**：一次结构化微调用，输入只有四样——知识点名、图形目录（只给键与中文名）、
    学生原话、（有则）上下文。提示词**必给反例**（问作业 / 问读音 / 纯计算 → 不出）。
  - **L2 后端校验盖章**：`should_show` 与 `figure_key` 必须自洽（冲突取保守）、键必须在目录内、
    图形几何库必须有这一行——任一不过就不发射。
  - **模型有建议权，没有决定权**：决定权在后端校验层，这与「防臆造」是同一条纪律。
  - **去重**：同一会话内与上一条已发射的键相同 → 不重复发射。
  - **`kind` 不由模型输出**：它是稳定契约；首版恒为轴对称，多类型后由目录投影带上知识点的类型。
- **粒度分工**：知识点级（这一类配不配演示）由**数据**答；提问级（这一问要不要）由**模型**答。
- **成本**：答疑有知识点上下文时多一次结构化微调用，且因为它要先于正文，首个 token 多一个 RTT
  （首版串行；并行化列为优化项）。
- **前端**：选项模型持图形（**复用前端已有的通用图形模型，零新增类型**），选项行内渲染平面图形，
  点击弹对折演示对话框；前端卡槽已就绪，答疑侧**零前端改动**。

## Testing Decisions

好测试的标准：**只测外部行为**——断言端点下发了什么、学生看到了什么，
不断言内部函数怎么被调用；形状类断言走**端点级**而不是服务级
（历史教训：只测服务会漏掉某个端点整段忘了下发）。

- **接缝一（出题链路）**：题目与任务详情端点按端点断言下发 `options[].figure`，
  并断言快照不可变（改图形几何库的顶点后，已落库的顶点不变）。既有先例：题库场景的接口级测试。
- **接缝二（答疑链路）**：聊天 SSE 一整轮——提问走完路由拿到场景卡 DATA 帧，
  断言卡里的几何来自图形库且**先于正文**到达；未命中 → 无卡且正文完整。
  既有先例：一整轮的答疑循环测试。
- **盖章三态**：合法键 → 顶点内联且顺序等于选项顺序；**部分有图 → 整题丢弃**；
  未知键 / 库里没有这一行 → 丢弃。
- **门控**：无知识点或目录为空 → **微调用 0 次**（断言调用次数，不是断言结果）。
- **L2 四态**：`should_show` 为假 → 不发射；键为空 → 不发射；两者冲突 → 不发射；
  键不在目录或库里没有 → 不发射。
- **异常态**：微调用抛错 → 不发射**且讲解正文完整照常**（绝不吞主功能）。
- **容错读取**：字符串选项 → 包成带空图形的对象；判题用「取选项文字」不变。
- **前端**：几何断言而非截图（本仓库禁止在测试里做截图装置：无真实合成器会挂死，
  实测把前端测试从约 46 秒拖到 17 分钟）。静态检查以输出里的「No issues found!」为准
  （该命令退出码常非 0）。
- **后端**：改 `features/*/service.py` 必跑分层不变量测试（归属判定只许走 `core.guard`）。

## Out of Scope

- 新增可渲染的 `kind`（需开发者工作流 + 前端渲染器发版）。
- 注册表运行时编辑 / 实时绑定（已否决）。
- 课件环节选项组统一到同一形状（独立 issue 已覆盖场景规格侧；课件侧的编排不动）。
- 答疑微调用与讲解流并行化（首版串行）。
- 场景规格自身的形状归一（独立 issue，阻塞本 issue）。

## Further Notes

- **本 issue 的主收益是「删」**：后端从此不再猜任何东西。新增代码只有一个纯数据类型 + 一个模块。
- **能力不回退**：旧路径里「没配模板但题面点名了图形也会出图」这个能力，在新设计里由
  「AI 发射身份键 → 盖章」承接，而且自绘图形**第一次**可用。
- **一处事实更正**：早前判断「答疑侧零命中交互场景卡」是错的——实证是它**已经在发射**，
  只是靠正则驱动。本 issue 是把驱动方换成模型，不是从零补能力。
- **本版相对上一版的两处反转**：图形类型从「选项图形」改为「图形」（它不只属于选项，
  只与渲染有关；前端早有通用图形模型，后端造窄名会造成概念错位），字段名统一为 `label`；
  答疑门控的**意图关键词被删掉**。
- **发布受阻**：当前 `gh` 未登录（`You are not logged into any GitHub hosts`），本文件先落盘；
  `gh auth login` 后按仓库惯例 `gh issue create --body-file ...` 并打 `ready-for-agent` 即可发布。
