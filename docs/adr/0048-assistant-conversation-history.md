# 助手会话历史：页内切模式 + 孩子的会话只读回放

库里一直有 `Conversation` / `Message`（ADR-0022），`POST /assistant/chat` 每轮都在写，但**没有
用户面的读路径**：只有 `/ai/debug/conversations` 一个调试端点（返回全部 step 与原始 payload，
前端零客户端）。于是「上周问过的那道题」在 App 里无法找回——关掉页面就没了，`AssistantNotifier`
的 `_currentSessionId` 是纯内存的，重启即丢。

本 ADR 决定**把这个读路径做出来**，并顺手钉死三件此前模糊的事：会话的术语粒度、家长与娃娃的
入口不对称、以及回放凭什么可信。

## 背景：同一批行有三种读法

`Conversation` / `Message` 能被读成三种东西，此前没有一处文字把它们分开：

1. **一次 AI 运行**（表的原义）：`kind` 是首条消息的路由结果，`status` 是运行状态；
2. **一段可续接的多轮对话**（前端 `session_id` 的语义）：用户心里的「那次对话」；
3. **一次运行轨迹**：路由步、工具调用与结果、被拦步骤——只有排障 / 审计才需要。

三个术语就此定死在 `CONTEXT.md`：**会话**（2）、**交换**（会话内的一问一答）、**运行轨迹**（3）。
本 ADR 做的读路径返回的是 1 与 2 的交集——**会话**；3 仍归 `/ai/debug/conversations`。

## 决策

### 1. 一个入口，页内三种模式

家长端助手页（ADR-0047 已收敛为 push 整页）在**页内**切换 `chat` / `history` / `reading`
三态，不新增路由：

- `chat`：顶栏 trailing = 历史图标 → 进列表；
- `history`：顶栏为「返回 + 新对话」。**顶栏就是模式切换器**——去翻历史的人，下一步常常是
  想开一段新的，两个动作因此各占一个 40 宽槽位，不挤第二个图标；
- `reading`：孩子的会话，气泡区与对话态共用 `AssistantMessageList`，输入栏换成一句说明。

栈深恒为 1。再 push「列表页 → 回放页」会变成三层栈（本页已经是 push 出来的整页），而且
输入栏逻辑会分到两处。

### 2. 端点新开，不与 debug 复用

新增 `GET /api/v1/assistant/conversations`（列表）与 `GET /api/v1/assistant/conversations/{id}`
（概要 + 气泡），均为**家长专属**（`CurrentParent`）。

`/ai/debug/conversations` **原样保留**：两者是**两个消费者**，不是两条实现。用户面要的是气泡
（可渲染的对话），审计面要的是保真度（全部 step、原始 payload、安全标记）。复用会同时伤害两边。
**折叠放服务端**（哪些行算气泡是领域判定，与「喂给模型的上下文」同一个口径），但**卡片怎么画
仍归前端**——这不违反 ADR-0042：那边禁止的是服务端拼接**展示串**。

### 3. 列表分两段，孩子的只能只读

列表返回**家长自己的 + 名下娃娃的**（归属口径就是 `Conversation.parent_id`），前端分两段：

- **我的对话**（`child_id IS NULL`）：点开 = **恢复续接**；
- **孩子的对话**（按娃分段）：点开 = **只读回放**，行上带「只读」徽标，回放态底栏说明原因。

这条分叉不是 UX 取舍，是**后端语义**：家长发请求时 `child_id` 恒为 `None`，拿孩子的
`session_id` 去续接必然过不了归属校验（`service.chat` 的 `existing.child_id == child_id`），
后端会**另建一段会话**并把新 id 回写——屏幕上却像续上了。更糟的是第二层：校验失败会启用
`history = req.history` 兜底，前端消息列表里**孩子的消息会被当成家长的 prompt 历史**灌进那个
新建会话。所以「孩子的条目允许输入」不只是 UX 不一致，是语义污染。

### 4. 会话命名：首条用户消息截断

建会话时写 `title = 首条用户消息折叠空白后截断 20 字`（写入点唯一，值天然稳定）。不调模型生成
标题：那要在首轮多挂一次调用并处理失败回退，而标题并非必需项（对比 compaction 摘要——那是
上下文连续性的必需项）。

读出侧必须**回落**：`title` 自 ADR-0022 起就是死字段，此前建立的会话全为 NULL，没有回落它们
在列表里会全部显示成空行。

### 5. 回放的可信度依赖 turn，而 turn 此前是坏的

**先修缺陷，再做功能**（独立 commit `fix(assistant): 多轮续接的 turn 撞号导致历史错序`）：

`event_stream()` 每轮都从 `turn = 1` 重新起算，而续接轮的 user 消息用的是 `next_turn()`
（= 该会话消息总数）——两个计数器不同源，第二轮起 routing / tool / 输出会与第一轮撞号。
`_read_history` 按 `turn` 升序读出可见轮次拼进下一轮 prompt，撞号之后的顺序就成了
「…第一轮回答、**第二轮回答**、第二轮提问」：模型拿到的上下文里回答跑在提问前面。

它是本特性的**前置**（回放与 prompt 历史共用同一个排序键，不修就会把同样的错序渲染给用户），
但它同时是既有的现网缺陷、观测口径也不一样（`_read_history` 是 prompt 侧，回放是展示侧），
所以拆成独立 commit——将来 bisect「某段历史顺序乱了」时能判断是哪一半。

守卫：`tests/api/routes/test_assistant.py::test_multi_turn_history_keeps_causal_order`
（同一 session 连发两轮，断言 turn 无重复且可见轮次读出为「提问→回答」重复）。
单轮时 turn 恰好是 0/1/2 不撞号，既有单轮用例照不出来；repository 单测用 fake session 直接喂
排好序的行，也绕开了排序——两处都漏，所以这条守卫必须是端到端的。

**已写入的历史数据不回填**（撞号已发生，排序无唯一解），修复只对之后写入的会话生效。

### 6. 三条「不做」，都是有意的不做

- **列表不返回 `preview`**，只回 `title` + `bubble_count` + 时间。预览对单轮会话（大多数）与
  标题重复，还会把行撑成三行。字段取到了却不画，比不取更糟。
- **回放里没有 `blocked`**。`Message` 上那组安全标记列（`input_safe` / `output_safe` /
  `blocked` / `block_reason` / `latency_ms` / `usage` / `model`）**从未被写入**，真正的被拦记录
  只在 `TutorLog`——那正是「AI 答疑记录」（F-305）的「已拦截」徽标所读的东西。所以两个页面
  **并存且各司其职**：F-305 的粒度是**交换**（一问一答 + 学科标签 + 已拦截徽标），会话列表的
  粒度是**会话**（一段多轮对话）。不要用「顺带补一个字段」把它掩盖成看起来能用的空值。
- **入口只给家长**。娃娃端没有 child-scoped 列表路由，也不该有：孩子看到自己「被拦过」的记录
  是负面强化，而「找回我问过的那道题」对孩子是次要需求。这是**有意的不对称**，不是漏做。

### 7. `updated_at` 开始写入

`Conversation.updated_at` 此前与 `created_at` 一样是死的（`default_factory` 只在构造时求值，
不会随写入刷新）。列表排序键取它：一个刚被续接过的旧会话应该浮到最上面。在 `service.chat` 的
收尾处显式赋值。

### 8. 已知缺口（本次不处理，记档）

- **无删除、无保留策略、无 FK 级联**（全仓 `ondelete` 零命中）。列表一露出来，「永远只增、
  不能删」就变成用户可见的事实。删除要连带处理 `Message` 且没有级联，不该顺手做。
- **无分页**：只做 `limit`（默认 50，上限 200）+ `updated_at` 倒序。
- 孩子的会话组排序取「该组第一段在整体倒序中的位置」（零额外查询、确定性），不是按娃娃的
  固有顺序。

## Considered Options

1. **复用 / 改名 `/ai/debug/conversations`**：用户面会白白拖走工具原始 payload，审计侧则要丢掉
   保真度去迁就用户面；且前端今天对 debug 端点零客户端，改名等于把调试能力绑上产品需求。拒绝。
2. **icon push 独立的列表页**：三层栈 + 输入栏逻辑分两处。拒绝。
3. **列表只列家长自己的**（不做孩子的）：能保住「一个列表一类条目」的单一性，但家长确实关心
   孩子问了什么——那就该扩充 F-305，而不是另造入口。用户选择了包含，于是必须付出「两类条目
   点击行为分叉」的代价，这个代价由「只读徽标 + 回放态说明」承担。
4. **只读回放的折叠放前端**：要按 `MessageResp` 自己过滤 `system/routing`、`tool/*`——
   等于把服务端已经在跑的判定写第二遍。拒绝。
5. **模型生成会话标题**：更好看，但要在首轮多挂一次调用 + 处理失败回退。拒绝。

## 后果

- 家长能翻回任何一段会话：自己的继续聊，孩子的只读看。
- 「AI 答疑记录」（F-305，侧栏页签）与会话列表**并存**，粒度不同（交换 vs 会话）。两者的
  区别写进了 `CONTEXT.md`，否则半年后一定有人问「这俩页面有啥区别」。
- `AssistantNotifier.reset()` 从死代码变成有调用方（历史的「新对话」）；同时新增 `resume()`
  ——恢复续接只是换掉 `_currentSessionId` 与气泡，后端零改动。
