```
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │ 特性层        │  │ 领域层        │  │ AI 编排层         │  │
│  │ app/features │→ │ app/domain    │→ │ app/ai           │  │

│  └──────┬───────┘  └──────┬───────┘  └────────┬─────────┘  │
│         │                │                   │            │
│  ┌──────▼────────────────▼───────────────────▼──────────┐ │
│  │ app/db/models/（SQLModel 表）+ app/core/db.py(engine) │ │
│  └──────────────────────────────┬───────────────────────┘ │
└─────────────────────────────────┼──────────────────────────┘
                                   ▼
                  ┌──────────────────────────┐
                  │ PostgreSQL（家庭/生产）    │
                  │ 本地开发可回退 SQLite      │
                  └──────────────────────────┘

        ★ 关键隔离：业务（app/features/app/domain）从不直接绑定具体 LLM 框架；
          厂商适配只在 app/ai（engine.resolve_engine + Genkit 引擎）内；
          换模型 = 改配置（BUILTIN_MODELS / ModelConfig / LLM_PROVIDER），业务零改动。
```

请求流（AI 出题/伴学为例）：
1. 前端 → `POST /api/v1/assistant/chat`（自由文本 + 角色）
2. `app/features/assistant/router.py` 解析 `CallerDep` 角色，建 `Conversation/Message`，交由 `app.ai.runtime.AgentRuntime`
3. `AgentRuntime` 按 manifest 规则 + 启发式路由到对应 SubAgent（question / tutor / tasks）
4. SubAgent 经 `app/domain`（Grader / QuestionGenerator / TutorService）与 `app.ai`（generate_question 共享核心 / engine）产出结果，以 SSE 流式推送 AG-UI 事件帧
5. 业务落库（出题卡片经 `POST /tasks/from-generated` 落库；伴学日志落 `TutorLog`）由对应 feature 仓储完成

## 3. 技术栈选型与理由

| 关注点 | 选型 | 理由 |
|---|---|---|
| Web 框架 | **FastAPI** | 异步原生、类型提示驱动、自动 OpenAPI、生态成熟 |
| 工程基线 | **fastapi/full-stack-fastapi-template** | 官方模板；裁剪 React 前端/邮件/Traefik，保留后端骨架（ADR-013） |
| 架构风格 | **Feature-First**（ADR-0027） | 每能力一个 `app/features/<name>/`（router+repo+schemas+service），ORM 表集中 `app/db/models/`，共享内核 `app/domain/`+`app/core/`，AI 编排 `app/ai/` |
| ORM | **SQLModel** | SQLAlchemy + Pydantic 合一，模型即 schema |
| 运行模式 | **同步**（`create_engine` + `Session`） | 跟随模板；家庭规模并发极低，同步够用且调试简单 |
| 本地回退 DB | **SQLite** | 无 Docker 也能跑通验证 |
| 生产 DB | **PostgreSQL**（`psycopg[binary]`） | 关系清晰、JSON 字段可用、未来 RAG 向量（pgvector）可同库 |
| 鉴权 | **pyjwt (JWT) + pwdlib（Argon2+bcrypt）** | 模板原生方案；pwdlib 替代 passlib，规避 passlib/新 bcrypt 冲突 |
| 主键 | **UUID**（`uuid.uuid4`） | 模板约定；无自增泄漏、分布式友好 |
| AI 编排 | **app/ai runtime + SubAgent**（ADR-0021/0024/0027） | 意图路由 = manifest `triggers` 优先 + 启发式兜底；所有 AI 入口统一收敛到 `/assistant/chat`（AG-UI SSE 事件信封） |
| LLM 引擎 | **Genkit（Python）仅作底层引擎** | 经 `engine.genkit` 被 `app/domain` 调用，不经 `genkit_fastapi` 暴露原生 action；厂商抽象由 Genkit 插件（genkit-openai / genkit-ollama）提供 |
| 配置 | **pydantic-settings** | 环境变量 + `.env` 统一，敏感信息不入代码 |
| 容器化 | **Docker + docker-compose** | 本地一键起 PG + backend |
| 运行 | **uvicorn (ASGI)** | 异步性能足够家庭/小规模使用 |
| Python | **>=3.14** | 跟随模板 |
| 测试 | **pytest**（模板 conftest 模式） | 自带 `TestClient` + 临时 DB 覆盖约定 |

> 需真实 LLM 引擎才能跑通 AI 生成闭环（出题→答疑→批改）。`LLM_PROVIDER=mock`（默认）表示无可用引擎，出题/伴学将返回 `LLM_UNAVAILABLE`，**不再有确定性 mock 兜底**（ADR 迁移 08b 纯单栈）。注册→加娃→作答→打卡→进度不依赖 LLM，仍免 key。

## 5. 领域层与 AI 编排（核心架构决策落地）

### 5.1 LLMProvider 抽象（`domain/provider.py`）

```python
@dataclass
class GeneratedQuestion:
    subject, grade, knowledge_point, qtype   # choice|fill|calc|open
    stem, options, answer, explanation, difficulty

class LLMProvider(ABC):
    async def generate_question(self, *, subject, grade, knowledge_point, qtype, difficulty) -> GeneratedQuestion
    async def grade_open(self, *, question, student_answer) -> dict
    async def tutor(self, *, ...) -> str
```

- 业务只依赖这个抽象，**不感知** 真实模型还是无引擎；无引擎时 `generate_question`/`tutor` 返回 `None`、批改抛错，由上层以 `LLM_UNAVAILABLE` 报错（不再静默回退假数据）。
- `qtype` 约定：客观题 `choice|fill|calc` 规则判分；`open` 开放题交给 provider。
- provider 方法均为 **async**；web 层是同步路由，业务层用 `asyncio.run()` 在独立线程调用 provider，避免事件循环冲突；**数据库会话（Session）仍是同步的**。

### 5.2 Provider 工厂与可插拔（`domain/__init__.py`）

```python
def build_provider() -> LLMProvider:
    from app.domain.genkit_provider import GenkitProvider
    return GenkitProvider()   # 统一单栈；Genkit 仅作底层 LLM 引擎
```

- 真实模型解析在 `app/ai/engine.resolve_engine`（优先级：家长 `ModelConfig` 表 → `BUILTIN_MODELS`(env) → 全局 `LLM_PROVIDER` → None）。
- 换厂商 = 改配置，业务零改动。

### 5.3 AI 助手统一入口（ADR-0024/0025/0026）

所有 AI 功能（出题 / 伴学答疑 / 查任务 / 治理观测除外）统一走 `POST /api/v1/assistant/chat`（SSE，AG-UI 事件信封：`USER_MESSAGE / THINKING / TOOL_CALL / TOOL_RESULT / DATA / ASSISTANT_MESSAGE / DONE`）。

- 双端通用：`CallerDep` 解析角色；娃娃端带输入安全 + 使用配额（ADR-008/T10），家长端可出题/查任务/伴学。
- 意图路由 = `app/ai/runtime/manifest.py` 的 `triggers` 规则优先 + 启发式兜底，分发到 `subagents/`（question / tasks / tutor）。
- 会话持久化复用 `Conversation` / `Message` 表（边流边记）。
- **废弃旧端点**（已收敛）：`/ai/tutor/ask`、`/ai/tasks/generate`、`/tutor/ask`。家长侧「管控 + 可观测」端点（`/tutor/logs`、`/tutor/quota`、`/tutor/usage`）非 AI 生成，保留在 `features/tutor`。

### 5.4 出题 / 批改流程

- `QuestionGenerator` + `app.ai.generation.generate_question`（共享核心，SSE 出题复用同一算法，消除双实现漂移）。
- `Grader`：客观题（choice/fill/calc）归一化字符串比对 `correct`+`score`；开放题（open）委托 `provider.grade_open()`。

## 6. 数据模型与 ER

```
User ──<parent_id>── User              (家长 1—* 娃娃，自关联 UUID)
User(parent) 1 ──< parent_id >── * Task
User(child)   1 ──< child_id  >── * Task
Task          1 ──< task_id   >── * TaskQuestion   (派发快照，冻结不随题库改)
TaskQuestion   *──< question_id >── 1 Question     (题库层，可跨 Task 复用；草稿期 question_id 可空)
Question      1 ──< question_id>─ * AnswerRecord
User(child)   1 ──< child_id  >── * AnswerRecord
User(child)   1 ──< child_id  >── * Checkin
Task          1 ──< task_id   >── * Checkin
User(child)   1 ──< child_id  >── * WrongQuestion
Question      1 ──< question_id>─ * WrongQuestion
User(child)   1 ──< child_id  >── 1 TutorQuota      (每娃一条)
User(child)   1 ──< child_id  >── * TutorUsage      (按日一条：当日累计秒数)
User(child)   1 ──< child_id  >── * TutorLog
Conversation  1 ──< conversation_id >── * Message    (助手会话持久化)
```

| 表 | 主键 | 关键字段 | 说明 |
|---|---|---|---|
| user | UUID | username(唯一), hashed_password, role(parent\|child), display_name, grade, parent_id, interests | 家长与娃娃同表，role 区分；娃娃 parent_id 指向家长 |
| task | UUID | parent_id, child_id, title, status(draft→ready→assigned→done), specs(JSON), focus_interest | 一次布置=一个任务；`status` 四态（ADR-0004） |
| task_question | UUID | task_id, question_id(可空), subject, grade, knowledge_point, qtype, stem, options(JSON), answer, explanation, difficulty | 派发快照层（冻结），家长改题库不污染已派发任务 |
| question | UUID | subject, grade, knowledge_point, qtype, stem, options(JSON), answer, explanation, difficulty | 题库层，可跨 Task 复用 |
| answer_record | UUID | question_id, child_id, student_answer, correct, score, source(practice\|review), created_at | 每次作答一条 |
| checkin | UUID | child_id, task_id, checkin_date | 打卡，连续天数 streak |
| wrong_question | UUID | child_id+question_id 唯一, first_wrong_at, wrong_count, review_stage, last_wrong_at, due_at | 错题集；遗忘曲线调度 |
| tutor_log | UUID | child_id, grade, subject, knowledge_point, question, answer, input_safe, output_safe, blocked, created_at | AI 答疑日志（F-305） |
| tutor_quota | UUID | child_id(唯一), daily_ask_limit, daily_minutes_limit, allowed_subjects(JSON) | AI 使用管控配置（T10） |
| tutor_usage | UUID | child_id+usage_date 唯一, used_seconds | 当日 AI 使用累计 |
| model_config | UUID | owner_id, label, provider, model_name, base_url, api_key(加密), is_default | 家长自定义模型（ADR-0015） |
| conversation / message | UUID | parent_id, child_id, kind, status, turn, role, step, content, payload | 助手会话与步骤持久化 |

**SQLModel 约定**：模型即 schema——`UserBase` 派生 `UserCreate`/`User`/`UserPublic`，不另建 schemas 文件（`models.py` 仅作 re-export shim）。
**答案安全**：`answer` 仅家长端接口返回，娃娃端 `Question.answer` 恒为 `None`，防作弊。

### 6.1 掌握度口径（T06，F-204）

- **基础分（0~100）**：历史作答正确率 40% + 最近 10 次 60% 加权（练习/复习统一计入）。
- **活跃错题封顶**：存在未毕业错题时分数封顶 `min(85, 60 + max_review_stage×6)`，毕业解除可达「已掌握（≥85 且无活跃错题）」。
- **等级**：未开始 / 待加强(<50) / 薄弱(50~69) / 巩固中(≥70 有活跃错题) / 较扎实(70~84 无活跃错题) / 已掌握(≥85 无活跃错题)。

### 6.2 内容安全设计（T08，F-304 / AC-302）

三层防护（确定性、可单测）：① `tutor_system_prompt(grade, subject)` 年龄锁系统 prompt（每次模型调用前注入）；② `check_input()` 扫描越狱/指令注入/非学习类主题（命中不调模型，直接 `SAFE_REFUSAL` 并 `blocked=True`）；③ `check_output()` 敏感词扫描。日志 `tutor_log` 记录 `input_safe/output_safe/blocked`，家长可在 `/tutor/logs` 监督，**不向娃娃暴露拒绝原因**。

### 6.3 AI 使用管控设计（T10，故事 23/26）

家长按娃配置（`tutor_quota` + `PUT /tutor/quota`），`/assistant/chat`（娃娃端）前置强制 `domain/quota.check_quota`，顺序：学科范围 → 次数上限 → 时长上限。越界（内容范围）→ **403**；超额（次数/时长）→ **429**；非法配置 → **422**。

### 6.4 教材知识库检索设计（T11，故事 24/25 / AC-305）

`TutorService.explain` 在输入安全校验后、调用模型前执行检索（`domain/retriever.py`）：`KnowledgeRetriever.retrieve(subject, grade, knowledge_point, query) -> list[KnowledgeChunk]`。当前 `MockKnowledgeRetriever` 检索内置**自编**知识点库（无版权风险）；`build_retriever()` 工厂按 `RETRIEVER_PROVIDER`（mock/builtin/vector 预留）切换。🔴 **教材版权（ADR-012）为对外分发硬门槛**，本层仅实现检索能力，不解决授权。

## 7. API 契约总表

基址：`/api/v1`（本地默认 `http://127.0.0.1:8000/api/v1`）。鉴权：`Authorization: Bearer <JWT>`。（✅=已落地，SSE=流式）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/auth/register` | 公开 | 家长注册（role=parent），返回 token+user |
| POST | `/auth/login` | 公开 | 登录，返回 token+user |
| GET | `/auth/me` | 任意 | 当前用户 |
| POST | `/children` | 家长 | 新增娃娃账号（绑 parent_id） |
| GET | `/children` | 家长 | 列出当前家长的娃娃 |

### 8.2 部署形态

- **本地开发**：`cd backend && uv run python -m app.main`，SQLite，默认 mock（无引擎）；接真实模型配 `BUILTIN_MODELS` 或 `LLM_PROVIDER`。
- **家庭/生产**：`docker-compose up` 起 `postgres` + `backend`；前端 Flutter 改 `kApiBase` 为局域网/公网地址。
- **可上云**：backend 无状态、DB 外置，CORS/密钥走环境变量。

## 9. 安全设计（非功能约束，对应 ADR-008/009）

1. **密码**：pwdlib 哈希（Argon2 优先 + bcrypt 兼容），不用明文。
2. **鉴权**：pyjwt（HS256），`deps.get_current_user` 解析；`require_parent`/`require_child`/`CallerDep` 角色守卫。
3. **授权**：任务/进度操作校验 `parent_id`/`child_id` 归属，越权返回 403/400。
4. **答案隔离**：娃娃端永远拿不到标准答案（见 §6）。
5. **内容安全**：系统层 prompt 锁死「只输出适合 X 岁、纯学习相关内容」；输出后 `safety.check_output` 校验；家长可查所有 AI 交互日志与配额。

## 12. 关键设计决策与质量亮点

1. **LLM 可插拔**：业务只依赖 `LLMProvider` 抽象；换模型=改配置，不碰业务代码（ADR-003）。
2. **AI 统一入口**：所有 AI 能力经 `/assistant/chat` + AgentRuntime 路由，意图路由可插拔（ADR-0024/0027）。
3. **内容安全（儿童硬约束）**：双层确定性校验 + 年龄锁 + 全程日志，前端无需重复校验。
4. **答案隔离**：娃娃端永远拿不到标准答案，从源头防作弊。
5. **掌握度算法**：基础分 + 活跃错题封顶 + 等级映射，复习答对自然抬升分数，口径清晰可单测。
6. **快照隔离**：`TaskQuestion` 派发冻结，家长编辑草稿/题库不污染在做的任务。
7. **架构纪律**：ADR + Feature-First + ruff/pytest 门禁，文档与代码同步演进。

## 13. 已知技术债 / 待办

- [ ] **缺 Alembic 迁移**：当前 `init_db()` 直接 `create_all`；`TaskQuestion`/`Question` 模型演进需数据迁移，生产前需补回。
- [ ] 🔴 **教材版权（ADR-012）**：知识库为自编内容；凡对外分发/上线前必须取得教材授权或换公版/自编。硬门槛。
- [ ] **缺后台任务框架**：二期复习调度真正「到点 push」需 APScheduler/Celery（当前为娃娃端拉 `/review/due`）。
- [ ] **作答写多表非单事务**：练习/复习分两次 `commit`，极端并发下掌握度看板可能读中间态；生产前可合并事务。
- [ ] **缺限流/监控**：对外服务前需加 rate limit 与基础观测。
- [ ] **模型输出校验重试**：需用 `output_schema` 约束结构化输出，并补失败重试与降级。
- [ ] **Genkit 引擎兼容性**：接真实模型时验证 `genkit-openai`/`genkit-ollama` 在 Python 3.14 的行为。
