# Spec：教师端导航重构与学情统计

> 决策依据：[ADR-0070 教师端导航重构与学情统计](../adr/0070-teacher-nav-restructure-and-analytics.md)。
> 依赖：[ADR-0068 班级实体](../adr/0068-class-entity-and-student-management.md)（统计的分组来源）。
> 术语以 `CONTEXT.md` 为准（教师 / 学生账户 / 班级 / 错题 / 错题本 / 掌握度 / 学情统计）。
> 本文件是 GitHub issue 的正文源；落库后以 issue 为准。
> 范围：ADR-0070 全文。**依赖 ADR-0068 先落地**——统计的「按班级」作用域需要班级实体。

## Problem Statement

教师端的导航是围绕「当前选中的那一个学生」建起来的，规模上来后这套模型失效：

1. **侧栏有两项是单学生维度，却挂在全局菜单里。** 错题本和 AI 答疑记录点进去，如果没在侧栏顶部选学生，就直接显示「请先选择学生」的空态。它们是学生的数据，却是全局的入口。
2. **顶部那个学生选择器没有搜索也没有分页。** 40 个学生全量渲染在一个浮层里往下滚，找人要滚半天。
3. **「切换上下文」和「维护花名册」挤在同一个浮层里。** 高频的切人和低频的加人混在一起，谁都做不好。
4. **教师看不到全班。** 系统里所有聚合都是单学生视角——单个学生的进度、单个学生的掌握度。教师想知道「这个班哪个知识点错得最多」「这次作业整体正确率多少」，当前**没有任何接口能回答**。
5. **学生维度的数据被全局状态污染。** 「当前学生」是一个全局状态，一旦学生详情页和它并列，就会出现「详情页显示 A 学生、出题却按 B 学生出题」这种漏清 bug，而且静态检查查不出来。

## Solution

**导航侧**：移除侧栏顶部学生选择器与它背后的全局学生上下文，学生维度的数据下沉到**学生详情页**（错题本、AI 答疑记录成为详情页内的页签）。侧栏改为八项：概览 / 任务 / 布置任务 / **学生** / 题库 / 资料库 / 模型管理 / **统计**。

**统计侧**：新增统计页，按**学科 / 年级 / 学期 / 知识点**对**错题数、正确率、掌握度**做聚合，作用域可在**单个学生 / 单个班级 / 全体学生**之间切换。

**代价补偿**：学生管理列表的每一行直接显示该学生的错题数，并提供行内入口直达其详情页的错题页签——弥补「切学生即看错题」这条高频路径被拉长的问题。

## User Stories

**导航重构**

1. 作为教师，我想从侧栏直接进入学生管理，以便维护花名册而不必打开顶部浮层。
2. 作为教师，我想在学生列表每一行直接看到这个人的错题数，以便不点进去就知道谁问题最多。
3. 作为教师，我想从列表行一键跳到某个学生的错题本，以便少点几层。
4. 作为教师，我想点开一个学生看到他的完整档案页（概览 / 错题本 / AI 答疑记录），以便在一个地方看完全部信息。
5. 作为教师，我想在学生详情页用页签切换概览、错题本、AI 答疑记录，以便不用反复进出页面。
6. 作为教师，我希望学生详情页的页签切换不会改变其他页面的上下文，以免出现「看着 A 却按 B 出题」。
7. 作为教师，布置任务时我想在表单里直接选择派发给哪些班级或哪些学生，以便不依赖「当前选中的是谁」这种隐式状态。
8. 作为教师，我希望出题的年级从我选的派发对象自动推导，以便少填一个字段。
9. 作为教师，当我选的派发对象跨年级时，我希望系统明确指出冲突让我手选，而不是悄悄替我猜一个。
10. 作为教师，我想知道为什么「按兴趣出题」这次不可用（派发对象的兴趣没有交集），而不是开关灰掉却没解释。
11. 作为教师，我希望概览页告诉我待派发、待审核、谁没交这些**待办**，而不是某个学生的数据。
12. 作为教师，我希望题库页的年级由我显式选择，以便不再依赖某个学生的年级兜底。

**学情统计**

13. 作为教师，我想看全班（或某个学生、某个班）的错题分布，以便知道该重点讲什么。
14. 作为教师，我想按**学科**看错题数和正确率，以便判断哪科最薄弱。
15. 作为教师，我想按**年级**看错题数和正确率，以便横向比较。
16. 作为教师，我想按**学期**看，以便区分上学期和下学期的掌握情况。
17. 作为教师，我想按**知识点**看错题数、正确率与掌握度，以便精确定位到「分数加减」这一层。
18. 作为教师，我想把作用域从「全班」切到「某个学生」，以便先看大盘再下钻到个人。
19. 作为教师，我想把作用域切到「某个班级」，以便比较我带的几个班。
20. 作为教师，我想区分「练习正确率」和「复习正确率」，以便知道学生是第一次就不会，还是复习时又忘了。
21. 作为教师，我想知道有多少错题**因为原题已被删除而无从归类**，以便判断统计数字的可信度。
22. 作为教师，我希望空学期（整学年）的题被归到「整学年」而不是单独冒出一个空白分组，以免列表里出现看不懂的一项。
23. 作为教师，我希望打开统计页时它是快的，即使我带了 60 个学生。
24. 作为教师，我希望统计里的「年级」指的是**题目的年级**，并且界面上明确标注，以免我误以为是学生的年级。

## Implementation Decisions

**移除全局学生上下文（本 spec 风险最高的一项）**

- 侧栏顶部选择器**整体移除**，不做降级保留。「切换 / 添加 / 编辑」三件事一起走。
- 全局学生状态一并移除。保留一个「当前学生」会让学生详情页和全局上下文成为两个事实源，一旦并列必然出现漏清 bug，且静态检查查不出来（ADR-0059 的核心教训）。
- 各消费方的替代来源：

| 原消费方 | 替代方案 |
|---|---|
| 概览 | 改为**教师工作台**：待派发 / 待审核 / 谁没交 + 全班速览；学生维度数据下沉到详情页与统计页 |
| 布置任务 | 表单内**显式派发对象选择器**（班级多选 / 学生多选） |
| 错题本 | 学生详情页页签 |
| AI 答疑记录 | 学生详情页页签 |
| 题库 | 教师**手选年级**，取消学生兜底 |
| 任务 | 按作业聚合，可按班级过滤 |

- 出题年级从派发对象推导：单选班级取该班年级；多选或跨年级取**众数**，平票则由教师手选。
- 兴趣主题：多选派发对象时取兴趣**交集**，交集为空则自动关闭兴趣模式并**在界面上说明原因**。
- 布置任务表单里的派发对象选择器复用 ADR-0069 的派发关系语义。

**导航状态**

- 教师端导航仍是**唯一的 sealed 状态**，新增「学生管理」与「学生详情（带学生 ID）」两个页面状态。
- 学生详情页内的页签是**局部状态**（页内切模式），**禁止**提升为全局状态。

**统计**

- 作用域三态：单个学生 / 单个班级 / 全体学生。
- 维度：学科 / 年级 / 学期 / 知识点。指标：错题数（活跃 + 已毕业）、正确率、掌握度。
- 三个聚合端点，共享作用域与维度过滤参数。
- 数据无需新表：作答记录与错题 JOIN 题目即可拿到四个维度。

**四项必须钉死的口径**（本 spec 最易翻车处）

1. **年级取「题目的年级」，不取学生的年级。** 统计的是错题分布，维度来自题；学生年级另有用途（筛选学生）。二者是不同东西，界面上必须分别标注，禁止共用一个下拉。
2. **学期口径**：学期当前没有字典表，是散落在多张表里的裸字符串（空 / 上学期 / 下学期，知识点默认上学期）。统计把空值**归入「整学年」，不单列空值组**；同时把取值收敛为常量，禁止各处再写新字面量。
3. **孤儿错题**：题库支持硬删，题删了错题行仍在，而学科 / 知识点 / 学期全挂在题目上。统计把这些错题归入「未知」分组并在界面上**显式标注数量**。本轮**不修改硬删行为**。
4. **掌握度跨学生必须走批量聚合**：掌握度目前是内存分组而非 SQL 聚合，逐学生调用等于 N 次全量扫作答记录。统计页必须新写批量聚合端点，**严禁**循环调用单学生掌握度接口。本轮**不引入掌握度快照表**。

**正确率定义**：正确条数 / 总条数于作答记录；按来源（练习 / 复习）可分看，界面提供切换。

## Testing Decisions

**主测试缝：REST 端点（统计部分）。** 沿用仓库既有的端点测试缝——FastAPI TestClient 打真实临时 SQLite 库（夹具 `tests/conftest.py` 的 `client`，身份助手 `tests/utils/user.py`），先例 `tests/api/routes/test_mastery.py` 与 `test_wrong_questions.py`。

**次测试缝：扩展既有导航守卫测试。** 教师端单源导航已有一条守卫测试（`teacher_nav_single_source_test.dart`），本 spec **扩展它**覆盖新增的两个页面状态，不新建测试缝。

好的测试只断言**外部行为**：统计数字通过打端点验证，不看内部函数；导航通过真实构建 widget 验证，不 mock 状态。

必测场景（统计）：

- 三态作用域都返回正确分组（学生 / 班级 / 全体）
- 四个维度各自的分组求和等于总数（防止 JOIN 丢行或重复计数）
- 边界：**孤儿错题**（原题已删）落入「未知」且数量被标注
- 边界：**空学期**归入「整学年」，不产生空白分组
- 边界：**跨年级班级**（班级自带年级但学生可跨年级）时题目年级与学生年级不混淆
- 活跃错题与已毕业错题分开计数
- 练习 / 复习两种来源的正确率分看
- 大班（≥60 学生）下统计接口响应时间可接受——这是批量聚合是否被正确实现的唯一判据
- 越权：别的教师的学生不得出现在我的统计里

必测场景（导航）：

- 移除全局学生状态后 `flutter analyze` 应为零错误（有残留引用即说明漏改）
- 学生详情页页签切换不影响其他页面
- 布置任务在跨年级派发对象下要求教师手选年级
- 派发对象兴趣无交集时兴趣模式自动关闭并给出说明

运行纪律：`pytest` 沙盒须 `--basetemp`；`flutter test` **先关代理**；新增 Flutter 组件须在**不套 Material** 的树里真构建（App 根无 Material 祖先，`flutter analyze` 查不出）；新文件受 400 行规模棘轮约束并登记基线。

## Out of Scope

- 时间趋势（按周 / 月）——数据已具备，留作下一轮
- 学生横向对比排行榜——中小学场景涉及学生排名，需产品与合规确认
- 统计结果导出（PDF / Excel）
- 掌握度历史快照表
- 修复题库硬删导致孤儿错题（独立议题，本轮只在展示侧兜底）
- 概览页「教师工作台」的具体视觉设计（需先出原型再实施）

## Further Notes

- **这是破坏性 UX 变更。** 「切学生即看错题」从一步变成「学生 → 点人 → 点页签」三步。行内错题徽标与直达入口是补偿，但退化客观存在，需要在验收时实际走一遍再确认可接受。
- **概览页改造成「教师工作台」是全新设计**，不在既有代码里，建议先出原型再排期，不要与统计混在同一个批次里实施。
- 移除全局学生状态牵动六处消费方与四个加载触发，是本 spec 回归面最大的一项，建议单独成一个提交批次。
- 仓库当前存在若干既有的失败测试（场景 / 反射相关），与本 spec 无关，提交前须确认不混入本批改动。
