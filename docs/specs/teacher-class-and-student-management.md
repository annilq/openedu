# Spec：班级实体与学生管理（含 Excel 批量导入）

> 决策依据：[ADR-0068 班级实体与学生管理](../adr/0068-class-entity-and-student-management.md)。
> 术语以 `CONTEXT.md` 为准（教师 / 学生账户 / 班级 / 任务 / 错题 / 错题本）。
> 本文件是 GitHub issue 的正文源；落库后以 issue 为准。
> 范围：ADR-0068 全文。依赖方：ADR-0069（批量派发）、ADR-0070（统计按班级分组）。
> ⚠️ 本 spec **正式重开 ADR-0065 §7 已关闭的「不做班级 / 学生组」分叉**；ADR-0065 §7 其余三条维持关闭。

## Problem Statement

教师带的是**一个班几十个学生**，但系统里维护学生的方式还停留在「一个人带一两个孩子」的规模：

1. **加学生只能一个个敲。** 唯一的入口是侧栏顶部那个浮层里的「添加学生」，每次填昵称、账号、密码、年级，加 40 个人要重复 40 遍。
2. **学生多了根本找不到人。** `GET /students` 一次返回全部学生，浮层全量渲染，没有搜索、没有排序、没有分页。40 个人全挤在一个下拉里往下滚。
3. **没有批量导入。** 教师手上本来就有花名册（Excel），但系统完全没有导入能力，`openpyxl` / `csv` 在前后端依赖里都是零。
4. **加错了不能删。** `/students` 只有创建、编辑、列表三个接口，**没有删除**。一个建错的学生账号会永远留在列表里。
5. **学生之间没有分组。** 教师没法说「这是三班的」「这是四班的」，派作业和看学情都只能按「我名下所有人」这个粒度。

同一件事在数据层还有一层：学生是 `user` 表里的**真实账号**（`username` 全局唯一 + 密码登录）。所以「导入学生」从来不只是插入几行记录，它必须同时把登录账号造出来，否则学生登不进来。

## Solution

引入**班级**作为学生账户的分组单元，一个学生至多属一个班，班级自带年级。新增独立的**学生管理**页面，把花名册维护从侧栏浮层里搬出来：按班级分组展示、支持搜索、可批量分班、可删除、可 **Excel 批量导入**，导入后导出一份账号表给教师分发给学生。

侧栏顶部浮层里「添加学生 / 编辑学生」两项随之移除（浮层本身的整体去留由 ADR-0070 处理）。

## User Stories

1. 作为教师，我想新建一个班级（名称 + 年级），以便把我名下的学生分成可管理的组。
2. 作为教师，我想给班级改名或改年级，以便在学期初调整分班。
3. 作为教师，我想删除一个班级，以便清理已毕业或建错的班。
4. 作为教师，我删班时希望班里的学生**不被一起删掉**，只是变成未分班，以免误删学生账号和他们的错题数据。
5. 作为教师，我想按班级筛选学生列表，以便只看某个班的人。
6. 作为教师，我想按姓名或学号搜索学生，以便在几十人里快速定位某一个人。
7. 作为教师，我想把一批学生一次性移入某个班级，以便不用逐个人点编辑。
8. 作为教师，我想把一批学生移出班级（变成未分班），以便学期末清空分班。
9. 作为教师，我想看到「未分班」这个分组，以便知道还有哪些学生没整理进班级。
10. 作为教师，我想上传一份 Excel 花名册批量创建学生，以便不用手工敲几十遍。
11. 作为教师，我希望 Excel 只需要「姓名」和「学号」两列，以便我直接用学校现成的花名册，不用先改造表格。
12. 作为教师，导入后我想看到成功多少、跳过多少、以及每一行失败的原因，以便我修正表格重新导入。
13. 作为教师，我希望同一份文件重复导入时不会创建出重复账号，以便我不必担心误操作。
14. 作为教师，我想导出一份账号表（班级 / 姓名 / 学号 / 初始密码），以便打印或发给学生和家长。
15. 作为教师，我想删除一个建错的学生账号，以便列表里不留下垃圾数据。
16. 作为教师，删学生时我希望系统明确告诉我连带清掉了多少条错题 / 作答 / 打卡记录，以便我确认没有误删。
17. 作为教师，我希望别人无法查看、修改或删除我的班级和学生，以便数据隔离。
18. 作为学生，我希望用学号和初始密码就能登录，以便教师不用单独教我怎么注册。
19. 作为教师，我希望导入时学号重复的行被跳过而不是覆盖已有账号，以免把同名学生的历史数据冲掉。
20. 作为教师，我想在班级列表上直接看到每个班有多少人，以便快速核对分班结果。

## Implementation Decisions

**班级实体**

- 新增 `Class` 表，归属教师，字段为名称与年级（1–9），`CREATE TABLE` 内声明 `(teacher_id, name)` 唯一。
- 由于 SQLite 的 `ALTER TABLE ADD COLUMN` 会**静默忽略** `UNIQUE` 子句（ADR-0061 §R），老库补不上这个约束。因此服务端建班时必须**显式查重**，不得依赖数据库约束兜底。
- 学生侧新增可空的班级外键，仅对 `role=student` 有意义。
- 迁移**不回填**既有学生，他们的班级外键保持为空。

**未分班**

- 班级外键为空的学生在学生管理页归入「未分班」分组，可批量移入班级。
- **不自动创建「默认班级」**——自动建班会掩盖「教师还没整理花名册」这一事实。

**Excel 导入与账号策略**（本 spec 最核心的一组决定）

- Excel 最小列为 `姓名` + `学号`；任一缺失即**整行拒绝**并回传行号，不做猜测、不做半成功。
- `username` **直接取学号原样**，不做拼音转换、不加前缀、不自动去重。
- 初始密码为统一常量，走后端配置项 `STUDENT_DEFAULT_PASSWORD`。
- 学号已存在 → 该行落入 `skipped`，**绝不覆盖**既有账号。
- 导入结果返回 `{created, skipped, errors: [{row, reason}]}`。
- **幂等**：同一份文件重复导入应全部落到 `skipped`。
- 提供账号表导出（班级 / 姓名 / 学号 / 初始密码）供教师分发。

**端点**

- 班级 CRUD 四个端点，列表带 `student_count`。
- 学生列表增加班级过滤与姓名 / 学号搜索。
- 新增学生删除端点、Excel 导入端点（multipart 上传）、批量移动端点。

**归属校验**

- 班级与学生的归属判定**只经 `core.guard`**（分层不变量 9）：复用 `require_owned_student`，班级新增一个对应的守卫。**禁止**内联比较 `teacher_id`。

**删除学生的级联**

- 定为**硬删 + 级联清理**，在**一个事务**内完成，响应回传各表清理行数。
- 备选的 `is_active` 软删不采用：那样登录、派发、统计、列表全部要加过滤条件，污染面更大且极易漏。

**依赖与前端**

- 新增后端 `openpyxl`（解析 xlsx + 导出账号表）与前端 `file_picker`（选文件）两个外部依赖。
- 新页面受文件规模棘轮约束（单文件 ≤400 行、一个文件只暴露一个公开物），列表 / 导入结果 / 批量操作条拆为独立组件并登记基线。
- 新页面须在**不套 Material** 的树里真构建一次——App 根没有 Material 祖先，`flutter analyze` 查不出这类崩溃。

## Testing Decisions

**主测试缝：REST 端点。** 用仓库既有的端点测试缝——FastAPI TestClient 打真实临时 SQLite 库（夹具见 `tests/conftest.py` 的 `client`，身份助手见 `tests/utils/user.py` 的 `register_teacher` / `login` / `auth_headers`），先例为 `tests/api/routes/test_wrong_questions.py` 与 `test_mastery.py`。

好的测试只断言**外部行为**：发一个请求，看响应状态和随后的 `GET` 结果。不直接调用内部函数、不断言私有实现细节。

必测场景：

- 建班成功 / 重名被拒（显式查重，不靠 DB 约束）
- 删班后班内学生班级外键置空，且学生账号与其错题仍在
- `GET /classes` 的 `student_count` 与实际一致
- 导入：正常导入、学号冲突落 `skipped`、缺列整行拒绝并带行号、重复导入幂等、大班（≥60 行）
- 导入后 `GET /students?class_id=` 能查到，且该 `username` + 初始密码**能真正登录**
- 未分班分组、按班级过滤、按姓名 / 学号搜索
- 批量移入 / 移出班级
- 删学生的级联清理行数正确
- 越权：别的教师对我的班级 / 学生做增删改应 403
- 老库形状回归：手工造一个**缺班级表、学生表缺班级外键列**的库，确认迁移幂等且服务端降级正常

运行纪律：`pytest` 在沙盒里必须带 `--basetemp` 指向新目录，否则 `tmp_path` 用例会集体 EEXIST 被误判为回归；真库在 `backend/app.db`，迁移脚本必须 `cd backend` 跑。

## Out of Scope

- 多班归属（学生可属多个班，如行政班 + 教学班）
- 班级间共享题库 / 资料（ADR-0065 §7 维持关闭）
- 学生自助注册、班级码加入
- 首次登录强制改密
- 学生头像、家长联系方式等扩展档案字段
- 顶部浮层的去留（ADR-0070）

## Further Notes

- **`username` 是全局唯一，不是按教师隔离。** 同校两位教师导入相同学号会撞车。本 spec 的行为是报「该学号已存在」由教师自行加前缀；**不做自动加后缀**，因为那会生成教师无法预期的账号。这一点在导入结果里要说清楚，不能只回一句「失败」。
- **导入是新增攻击面**：`openpyxl` 解析外部上传文件。需要对文件大小与行数设上限，避免超大文件拖垮服务。
- 账号表导出与花名册导入共用同一个 xlsx 库，不需要第二套依赖。
- 本 spec 落地后，ADR-0065 §7 的「不做班级 / 学生组」不再成立，后续任何引用 ADR-0065 §7 的地方都必须先读 ADR-0068。
