# Spec：课件模块一等化（courseware-first-class-module）

> 决策依据：[ADR-0078 课件模块一等化](../adr/0078-courseware-first-class-module.md)。
> 来源：grill-with-docs 流程先盘代码、再对齐 4 个岔路 + 2 个核实结论（见 ADR-0078 §背景）。
> 术语以 `CONTEXT.md` 为准（课件 / 知识点 / 环节 / 素材 / 场景 / 课堂练习 / 教学目标）。
> 本文件是 issue 的正文源；落库后以 issue 为准。本地发布（未建 GitHub issue；`gh` 未登录）。
> **Triage：ready-for-agent**

## Problem Statement

课件目前不是一等模块，而是「从知识点行进入 → AI 代写」的副作用产物。教师实际会遇到四件具体的事：

1. **课件模块没有自己的新增入口。** 左侧「课件」菜单只跳进一个列表页，列表里只有已存在课件的卡片；真正的创建被藏在「知识点管理」里每一行知识点的「课件」按钮后面。一个以「课件」命名的模块，自己却无法创建课件——教师必须从另一个模块绕进去才能建。
2. **课件信息不能编辑。** 编辑器页标题直接拿知识点名当课件名，课件级的标题、学科/年级/学期、状态（草稿 / 可上讲台）都没有编辑入口。中心页卡片上的「编辑」实际是进入编辑**环节**，不是编辑课件信息。后端 `PATCH /{id}` 早已支持改 title/status，但前端从没接上。
3. **讲解环节只能删、不能加。** 环节列表头部只有一个「选择」（批量删）入口，没有任何「添加环节」。环节只能来自 AI 起草或重起草——教师想补一段自己的讲解也做不到。而且环节类型（kind）只有「素材展示 / 交互讲解 / 课堂练习」三种，没有「纯讲解话术」这一最基础的形态。
4. **AI 是唯一的作者，不是辅助。** 后端 `create_courseware` 强制按知识点 AI 全量起草（标题 + 所有环节），前端点「新增课件信息」即一次出整份。教师无法「先选知识点、填一部分课件信息，再让 AI 基于这些补充」，也看不到 AI 到底写了什么、能不能逐段保留自己手写的。

同一件事还有两个被忽略的隐患：(a) `课堂练习` 环节虽然在模型里存在，但演示页 `PresentStage` 根本没渲染它——练了等于没练；(b) 所谓「AI 起草」目前只召回教材文本片段当上下文，素材和场景是留空的，AI 并没有从服务端拿到真实的提问/素材/场景三类数据来回填，所以「AI 补充」出来的课件和知识点已有的资源库是脱节的。

## Solution

把课件扶正为一等模块，手段是四个互相咬合的改动：

- **独立新增入口：** 「课件」中心页加一个「新增课件」主按钮，打开新建表单（选知识点 + 填标题 + 可选教学目标），提交即建一个**空壳课件**（`draft=True`，不触发 AI）。知识点行里的「课件」按钮保留为次级快捷入口，两处都通向同一新建流程。
- **课件信息可编辑：** 编辑器顶部加一张「课件信息」卡片（标题 / 学科·年级·学期 / 状态），配「编辑」按钮，调已有的 `PATCH /{id}`。纯前端接端点，无新后端。
- **去 kind 化 + 手动添加环节：** 环节不再按 `kind` 类型化分类，统一成「内容块」——一个环节里可以有哪些内容就渲染哪些（有素材→图廊、有场景→交互演示、有练习→练习块、有话术→讲解）。列表头部加「添加环节」→ 打开空白编辑弹窗 → 保存即追加并 `PUT /sections` 整体落库。
- **AI 降为显式触发的辅助：** 新建建空壳（不调 AI）；编辑器/中心加「AI 补充讲解」按钮，复用 `redraft_diff` 让 AI 出整稿、教师逐段决定保留旧版还是用新版（可保住手动环节）。后端起草前先查该知识点的**素材库 + 场景库**候选，让 LLM 引用真实 asset id / scene 模板回填，使课件与知识点资源库接通。

## User Stories

**新增入口（独立一等模块）**

1. 作为教师，我在「课件」模块点「新增课件」就能开始建课件，这样我不必先跑去「知识点管理」里找某一行。
2. 作为教师，我在新增表单里能看到并可选择一个知识点，这样新建的课件自动归属到正确的知识点上下文。
3. 作为教师，我在新增表单里能填标题（和可选的教学目标），这样课件一建出来就有我自己的命名，而不是被知识点名顶替。
4. 作为教师，我提交新增表单后得到一个空壳课件并直接进编辑器，这样我可以先看到结构、再决定要不要让 AI 补充。
5. 作为教师，我新建空壳课件后状态是「草稿」且不含任何 AI 环节，这样我清楚知道此刻内容是我自己掌控的。
6. 作为教师，我在「知识点管理」里点某行知识点的「课件」按钮仍能进编辑器，这样老入口不丢、和新的中心入口并存。
7. 作为教师，我从知识点行进和从中心进建出的课件形态一致（都是先建壳、再可选 AI），这样两条路径不会行为分裂。
8. 作为教师，我在新增表单里没选知识点就提交会被拦截并提示，这样不会建出无归属的孤儿课件。

**课件信息编辑**

9. 作为教师，我在编辑器顶部能看到课件信息卡片（标题 / 学科·年级·学期 / 状态），这样我一眼知道正在编的是哪份课件。
10. 作为教师，我点课件信息卡片的「编辑」能改标题，这样课件名不必永远等于知识点名。
11. 作为教师，我能在课件信息里把状态从「草稿」切到「可上讲台」（反之亦可），这样我能标记一份课件是否准备好进课堂。
12. 作为教师，我改完课件信息保存后看到卡片即时更新、且下次打开仍在，这样编辑是真实落库的而非仅界面闪烁。
13. 作为教师，我在中心页卡片上也能看到课件当前状态，这样我不用进编辑器就能区分草稿和可上讲台的课件。

**环节去 kind 化 + 手动添加**

14. 作为教师，我在环节列表头部点「添加环节」就能新建一段，这样我不必等 AI 给。
15. 作为教师，我添加环节时弹出的编辑框是空白的，这样我是从零写、不是被迫接受某种 AI 模板。
16. 作为教师，我在新环节里只写一段话术、不挂任何素材/场景/练习，保存后它作为「纯讲解」出现在列表和演示里，这样最朴素的讲解也能成立。
17. 作为教师，我在新环节里贴了素材就看到图廊、填了场景就看到交互演示、勾了练习就看到练习块，这样「环节有什么内容」由我填的定、不由一个类型标签定。
18. 作为教师，我在编辑器里给环节拖拽重排后顺序被记住，这样我能按讲课节奏组织环节。
19. 作为教师，我勾选多个环节批量删除，这样我能清理不要的段。
20. 作为教师，我打开一份旧的、带 `kind` 标签的课件仍能正常演示，这样去 kind 化不破坏历史数据。
21. 作为教师，我给环节改完内容保存后，下次打开仍是改后的，这样手动添加/编辑是稳定的。

**AI 作辅助（补充而非代写）**

22. 作为教师，我建好空壳课件后点「AI 补充讲解」才触发 AI，这样 AI 不是默认作者、我保有控制权。
23. 作为教师，我点「AI 补充讲解」后看到 AI 出的整稿与我已有的环节并排成 diff，这样我能逐段决定留旧还是用新。
24. 作为教师，我保留自己手写的环节、只采纳 AI 新增的几段，这样补充是增量、不覆盖我的原稿。
25. 作为教师，我采纳的 AI 环节里引用了知识点真实的素材和场景（而非空占位），这样补充出来的课件和知识点资源库接通。
26. 作为教师，我选了知识点并填了教学目标后，AI 补充出的环节贴合这个目标和这个知识点，这样「辅助」是真的基于我的输入而非凭空。
27. 作为教师，我在空壳课件上点「AI 补充讲解」时，diff 全部是新增段（因为没有旧稿可比），这样首次补充也走同一套交互。
28. 作为教师，我中断或放弃一次 AI 补充后，课件回到补充前的状态、没有半截脏数据，这样试错无成本。

**课堂练习可见（kind-free 下的练习块）**

29. 作为教师，我在环节里配置了课堂练习，进演示页时学生真能看到题目并能作答，这样练习不再隐形。
30. 作为教师，我在演示页的练习块里能看到题量/题型，这样练习的配置是可见可核对的是。
31. 作为学生，我在演示页做到练习环节能提交并看到对错反馈，这样课堂练习闭环成立。

**跨切面**

32. 作为教师，我整轮操作（新增→编辑信息→加环节→AI 补充→上讲台）都不出现任何 Material 风格的报错或异常控件，这样 neo-brutalist 设计语言保持一致。
33. 作为教师，我在桌面宽窗和移动窄屏都能用新建表单、信息卡片、环节编辑，这样自适应布局覆盖课件模块。
34. 作为维护者，单文件不超过 400 行、改动落在既有分层（presentation 不 import data），这样棘轮约束不被打破。

## Implementation Decisions

- **模块边界**：改动集中在 `features/courseware`，沿用既有分层（presentation 不 import `*/data/`，环节读写走 repository）。新建/编辑/补充三件事各自成文件，不把逻辑塞进现有页。
- **新增入口（T01）**：中心页 `CoursewareCenterScreen` 加主按钮 → 新建表单（选知识点 + 标题 + 可选教学目标）。后端 `create_courseware` 增加「不自动 AI」开关（`draft=True` 时跳过 `draft_sections`，产出空壳）。知识点行的「课件」入口保留，两处都先建壳再进编辑器。
- **课件信息编辑（T02）**：编辑器顶部「课件信息」卡片 + 编辑弹窗，调已有 `PATCH /{id}`（支持 title/status）。**不新增端点**，纯前端接上；空态卡片显示学科·年级·学期·状态。
- **去 kind 化（T03，改动面最大）**：后端 `kind` 字段改可选并放宽校验，diff 匹配键去掉 kind 依赖；前端 `PresentStage`/`editor_section_list`/`CoursewareSectionEditDialog` 改为「按填了什么渲染/编辑」，不依赖 `kind` 枚举；枚举标记为 deprecated 而非立即删除（保护旧数据）。渲染层已有「按填了什么」的雏形（`PresentStage` 有素材→图廊、有场景→交互演示），本次把它做全。
- **手动添加环节（T04）**：`editor_section_list` 头部加「添加环节」→ 开空白 `CoursewareSectionEditDialog`（传空 section）→ 保存 append 到 `sections` 并 `PUT /sections` 整体落库。Blocked by T03。
- **AI 作辅助（T05）**：新建走空壳（不调 AI）；编辑器/中心「AI 补充讲解」按钮复用 `redraft_diff`——AI 出整稿，前端逐段 diff，教师保留旧/用新（可保住手动环节）。后端起草前查该知识点的素材库 + 场景库候选，让 LLM 引用真实 asset id / scene 模板回填（补齐当前「materials/scene 留空」的缺口）。Blocked by T01 + T03。
- **课堂练习内容块（T06）**：决定练习是第四内容块还是暂不支持。若做内容块，则 `PresentStage` 显式渲染 `SectionPractice`（qtype/count），使 `courseware_practice_test` 的练习能力在演示页真正可见；已有带练习的课件不静默丢弃。Blocked by T03。
- **状态模型**：课件状态沿用 `draft` / `ready`（可上讲台），不引入新枚举；空壳课件初始 `draft=True`。
- **AI 补充语义**：采用「整稿重起草 + 逐段保留」而非「仅追加」或「整稿替换」——改动最小（复用 `redraft_diff`），且能保住教师手动环节，最贴合「补充」本意。
- **不引入 Material 控件**：所有新弹窗/卡片走既有 neo-brutalist 控件（`AppFocusableAction`/`ShadCard` 等），测试树挂 `CupertinoApp`（同 `courseware_editor_page_test` 写法）。

## Testing Decisions

- **好测试的标准**：只测外部行为（点按钮看到什么、保存后落库什么、去 kind 后旧课件能否演示），不测实现细节（不改私有方法、不依赖具体 widget 树路径）。
- **测试 seam（优先复用既有，不新开）**：沿用 `courseware_editor_page_test` 那套——内存假仓库 `_FakeRepo`（只实现用到的 repository 方法并记 `lastUpdated`/`lastReplaced` 便于断言）、不读 SharedPreferences 的 `_FakeStorage`、`CupertinoApp` 根（无 Material）、`flutter_test`。新增用例直接挂在这三个既有 seam 上，不新建测试基建。
- **要测的模块**：
  - 新建表单（T01）：选知识点 + 填标题提交 → 断言 `create_courseware` 收到 `draft=True`、返回空壳、且知识点行为空；知识点未选被拦截。
  - 课件信息编辑（T02）：改标题/状态 → 断言 `PATCH /{id}` 被调用且卡片更新；旧知识点名不被强制覆盖。
  - 去 kind + 手动添加（T03/T04）：带 kind 旧课件可演示（回归）；无 kind 新课件可添加纯讲解环节并演示；批量删、拖拽重排顺序持久。
  - AI 补充（T05）：空壳点补充 → diff 全新增；有手动环节时补充 → 可保留手动段、采纳新增段；中断后回到补充前状态。
  - 练习内容块（T06）：环节配练习 → 演示页 `PresentStage` 渲染 `SectionPractice` 且可读题作答（接 `courseware_practice_test` 既有能力）。
- **Prior art**：`courseware_editor_page_test`（拖拽重排 + 多选批量删）、`courseware_present_page_test`（演示渲染）、`courseware_practice_test`（练习部件）已是同模块范例，新测试照搬其假仓库与构建写法，保证风格一致、零新基建。

## Out of Scope

- 课件的多端同步/协同编辑、版本历史。
- 知识点管理模块本身的重构（行内「课件」入口仅保留，不迁移）。
- 素材库 / 场景库的创建与治理（本 spec 只消费它们，让 AI 引用；治理归 ADR-0077 资产库线）。
- 课件导出为 Typst/试卷（归打印导出线，不在此轮）。
- 练习块的出题质量与自动评分策略（仅保证「在演示页可见且可作答」，评分逻辑沿用既有）。
- GitHub issue 的远程创建（`gh` 未登录；本 spec 与 round-3 票均先落本地，登录后可一键转 issue 并保持 `ready-for-agent`）。

## Further Notes

- 本 spec 是 umbrella，落到 6 张垂直切片票（`.scratch/courseware-round-3/`），建议实现顺序：**T01（中心新增入口+空壳）→ T02（信息编辑）→ T05（AI 补充三项回填，依赖 T01）** 先打通「新增→空壳→AI 补充」主干；**T03（去 kind，改动面最大，单独一轮）→ T04（添加环节，依赖 T03）→ T06（练习块，依赖 T03）** 后做。
- T03 是唯一会触碰历史数据与渲染层分支的票，务必带「旧带 kind 课件仍能演示 + 新无 kind 课件能与 AI 补充互写」的回归，避免静默破坏已有课件。
- 合并纪律：按 subsystem 拆 commit、排除并行 session 文件、记忆类更新用 `chore(memory):` 独立 commit；提交后跑 `flutter analyze lib/features/courseware` + 定向测试再汇报。
