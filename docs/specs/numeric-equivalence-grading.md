# Spec：数学客观题数值等价判分

> 决策依据：[ADR-0071 数值等价判分](../adr/0071-numeric-equivalence-grading.md)（已落地）。
> 术语以 `CONTEXT.md` 为准（题型 / 学科 / 任务 / 任务题 / 作答记录 / 错题 / 掌握度）。
> 本文件是 GitHub issue 的正文源；落库后以 issue 为准。
> 范围：仅覆盖「数学 + 填空题 / 计算题」的客观题判分；应用题（open）、多选项（choice/multi）、非数学学科均不在本 Spec 内。

## Problem Statement

当前学生端提交答案后，后端 `Grader` 对客观题（choice / fill / calc）采用「归一化字符串严格相等」判定：

```
correct = re.sub(r"\s+", "", (text or "").strip().lower())
           == re.sub(r"\s+", "", (answer or "").strip().lower())
```

这把**数学填空题和计算题当成纯文本比对**，带来一类「会做却判错」的系统性误判，直接污染学习闭环（错题归集、掌握度统计失真、家长/教师看到的正确率偏低）：

1. **带单位判错**：标准答案是 `12`、学生写 `12厘米`，字符串不等 → 错。
2. **分数与小数互转判错**：`0.5` vs `1/2`、`2/4` 均不等 → 错。
3. **带过程或多余标点判错**：`12。`、`（12）`、前缀空格 → 错。
4. **量纲/写法差异无容错**：`3又1/2` vs `3.5`、`1/3` vs `0.333`（有限小数近似）→ 错。

其根因不是「判分逻辑有 bug」，而是**缺一层数值语义解析**：数学客观题的答案应是「一个带量纲的数值」，而非「一段字符」。

## Solution

在 `Grader.grade` 的**客观题分支**（非 open、非 multi）内，对「**学科 = 数学** 且 **qtype ∈ {fill, calc}**」的题，先尝试把标准答案与学生作答双方解析成「数值 + 单位」，再做**数值等价 + 量纲兼容**比对；**任一端解析失败则回退当前严格相等判定**（安全兜底，绝不因解析器而误放或误杀）。

其余路径完全不动：

- 应用题（`open`）→ 仍走 LLM 批改（`grade_open`）。
- 多选题（`multi`）→ 仍走 `|` 连接选项文本的集合比对。
- 非数学学科 / 非 fill-calc → 仍走原严格相等。
- **前端零改动**：只消费后端返回的 `correct` 布尔，判分逻辑全在后端。

## User Stories

1. As a 数学学生, I want 我写的 `12厘米` 被判定为与标准答案 `12` 相同, so that 带单位的正确答案不再被误判为错。
2. As a 数学学生, I want 我写的 `1/2` 或 `2/4` 被判定为与 `0.5` 相同, so that 分数与小数的等价写法都能得分。
3. As a 数学学生, I want 我写的 `3又1/2` 被判定为与 `3.5` 相同, so that 带分数写法不被误杀。
4. As a 数学学生, I want 我写的 `0.333` 被判定为与 `1/3` 相同（在容差内）, so that 有限小数近似写法不被误判。
5. As a 数学学生, I want 标准答案 `5` 与我写的 `5个` 被判定相同, so that 无单位的纯数值不被「多余量词」干扰。
6. As a 数学学生, I want `5cm` 与 `5kg` 判为不同, so that 量纲不同的答案仍被正确判错。
7. As a 数学学生, I want 当答案含字母或等式（如 `x=5`、`π`）时系统回退到原严格比对, so that 这类本该归为 open 的题不会因解析器而错误地放过。
8. As a 数学学生, I want 标准答案给出多解（如 `12或15`）时我写任一解就算对, so that 多答案题不被误判。
9. As a 教师, I want 我手录的、格式不规范的填空题答案不会因新逻辑而行为突变, so that 存量题目的判分保持可预期（解析失败即回退旧逻辑）。
10. As a 教师, I want 数学以外的其他学科（语文/英语）判分行为完全不变, so that 改数学判分不会引入跨学科回归。
11. As a 教师, I want 应用题仍由 LLM 柔性判分而非数值比对, so that 需要过程/语义判断的题不被数值逻辑误伤。
12. As a 平台, I want 判分改造不引入新的第三方重依赖（如 sympy / pint）, so that 部署与隔离安装纪律不被破坏。
13. As a 测试, I want 新增数值等价用例的同时保留原严格相等用例作为回归, so that 改造不悄悄改变旧行为。
14. As a 维护者, I want 改造点收敛在 Grader 一处且前端无改动, so that 判分链路保持单一职责、易审计。

## Implementation Decisions

- **唯一改动缝（Seam）**：`Grader.grade` 的客观题判定分支。不新增 endpoint、不改动 `answer()` 流程、不改动前端。理想缝数量为 1。
- **新增纯函数（与现有 `_normalize` 并存，不替换）**：
  - `parse_numeric(text) -> (value: Fraction|Decimal|float, unit: str|None) | None`
    - 用正则抽取「数值 token + 可能单位」；支持整数、小数、真/假分数 `a/b`、带分数 `a又b/c`、负号。
    - 用标准库 `fractions.Fraction` 承载分数（天然约分，`1/2 == 2/4`），`decimal.Decimal` 承载小数与近似相等判定。
    - 单位归一：内置轻量单位表，覆盖长度（米/分米/厘米/毫米）、重量（千克/克）、时间（时/分/秒）、角度（度）、货币（元/角/分）等常见量纲，转基准单位。
    - **无法解析**（含字母变量、等式、纯中文、π/√ 等符号）→ 返回 `None`（标记非数值）。
  - `numeric_equal(ans: parsed, sub: parsed, eps) -> bool`：双侧都解析成功且**量纲兼容**时，按容差判等；量纲不兼容 → `False`。
- **容差策略**：相对误差 `1e-6` 与绝对误差 `1e-9` 双判（覆盖 `1/3` vs `0.333` 这类有限小数近似）。
- **多答案**：标准答案含 `|` 或「或」分隔时，拆为候选集，学生作答与任一候选数值等价即判对。
- **回退纪律**：`parse_numeric` 任一侧返回 `None` → 整题走原 `_normalize` 严格相等。这是零回归的硬保证。
- **作用域收窄**：仅 `subject == "数学"` 且 `qtype in {"fill", "calc"}` 进入新路径；`open` / `multi` / 非数学一律不进入。
- **依赖**：仅用 Python 标准库 `re` / `fractions` / `decimal`。**不引入 sympy / pint / numpy**（保持隔离安装纪律，避免重依赖）。
- **（可选增量，不与判分耦合）**：出题侧在数学 prompt / `QuestionSchema` 加约束「答案填纯数值或数值+标准单位，分数用 `a/b`」，降低歧义。属独立改动，可单独成批。
- **不动的契约**：`AnswerResult`（correct/score/explanation）、前端 `PracticeRepositoryImpl.submitAnswer`、错题归集 `upsert_wrong_question` 全部不受影响——只改变 `correct` 这个布尔的算出方式。

## Testing Decisions

- **测试缝（优先既有）**：扩展 `backend/tests/domain/test_grader.py`（已存在，覆盖 `Grader.grade`）。新增数值等价用例，**保留**原严格相等用例作回归。不新建测试文件、不新增端点缝。
- **好的测试只看外部行为，不测实现细节**：断言 `grade()` 返回 `correct` 布尔，不测 `parse_numeric` 内部正则。
- **必测矩阵**（行为级）：
  - 等价命中：`12`≈`12厘米`、`0.5`≈`1/2`≈`2/4`、`3又1/2`≈`3.5`、`1/3`≈`0.333`（容差内）、`5`≈`5个`、多答案 `12或15` 命中其一。
  - 明确判错：`5cm` vs `5kg`（量纲不兼容）、`12` vs `13`。
  - **回退断言**：`x=5` vs `5`（含字母→解析失败→回退严格相等→判错，与现状一致）；教师手录格式乱答案→回退，行为不变。
  - **不变量断言（零回归硬指标）**：非数学学科题、`open` 题、`multi` 题的 `correct` 结果与改造前**完全一致**（新增用例显式断言，防止新逻辑误入这些分支）。
- **先验参考**：`tests/domain/test_grader.py` 现有用例结构；`tests/features/export/test_document.py` 对 `qtype` 含义的既有约定（`_q("应用题", qtype="open")`）作为题型语义锚点。
- **运行验证**：改造后跑 `pytest` 全量（沙盒须 `--basetemp=/tmp/<新目录>`）确认全绿，再汇报。

## Out of Scope

- **应用题（`open`）的 LLM 判分**：维持现状，不在本 Spec 内做符号/语义增强。
- **前端改动**：判分在后端完成，前端只收 `correct` 布尔，本 Spec 不 touch 任何 Dart 文件。
- **符号 / 代数等价**：`x=5`、`√2`、`π`、表达式化简等不纳入数值解析（这类本应归为 `open` 题，由 LLM 判）。
- **跨量纲智能换算**：仅做同量纲单位归一（长度/重量/时间/角度/货币），不做「厘米→千克」这类无意义换算，也不做物理量纲自动识别。
- **出题侧答案格式约束**：列为可选增量，不在本 Spec 强制。
- **英语/语文客观题**：维持严格相等（其答案多为单词/短语，数值解析无意义）。

## Further Notes

- 该特性的价值不在「多判对几题」，而在**修复学习闭环的数据正确性**：错题归集与掌握度统计依赖 `correct` 布尔，当前误判会让正确作答被记成错题，长期污染复习调度。
- 回退纪律是本改造的「安全绳」：任何解析歧义都收敛到旧行为，保证「不会比现在更差」。
- 建议与 ADR-0071 同批落地；ADR 正文记录「为何新增数值层、为何仅限数学 fill/calc、为何不引 sympy」三项决策依据。
- 若日后要扩展到更复杂的数学习题（含变量、方程、几何），应作为独立模块（如符号判分），而非在本数值层累加分支——本层只解决「单一数值答案」这一类。
