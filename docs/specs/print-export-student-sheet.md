# Spec：打印导出（学生卷）

> 决策依据：[ADR-0052 打印导出：服务端排版学生卷](../../adr/0052-print-export-student-sheet.md)。
> 术语以 `CONTEXT.md` §打印导出 为准（打印导出 / 导出文档 / 打印分节 / 学生卷 / 作答留白）。
> 本文件是 GitHub issue 的正文源；落库后以 issue 为准。

## Problem Statement

家长已经在平板上用题库和任务攒了一批题，但**这些题只能停在屏幕里**。真实的使用场景是：家长想把题变成一张纸，打印出来给娃娃用笔写——屏幕做题费眼、费电，而且家长希望控制做题节奏。

目前仓库在这条链路上是**零**：后端没有 PDF 依赖、没有静态文件挂载、没有导出端点先例；前端依赖里没有 `pdf` / `printing` / `pdfx`。四个已经有题目的页面（题库、任务、错题本、复习）都没有把题变纸的出口。

更麻烦的是，纸和屏是两种媒介：屏幕上题是可交互的（点选项、看解析），纸上必须**留出写字的地方**、且**不能带答案**——家长用外部批改 App 扫码批改，纸上一旦印了答案就废了。这不是「把屏幕截图打印」能解决的事。

## Solution

家长在四个页面里勾选题目或任务 → 点导出 → App 弹出**预览页**看到即将打印的那份 PDF → 确认后调系统打印或分享面板出纸。

PDF 由**服务端用 Typst 排版**生成并下发，客户端只负责预览与投递。因为预览组件渲染的就是那份将要投递的字节，**「预览和导出不一致」在构造上不可能发生**。

纸上只有题干、选项和作答留白，**绝不出现答案与解析**。批改靠家长用外部批改 App 扫码完成。

## User Stories

**导出入口与选择**

1. 作为家长，我能在题库页勾选若干题目后点「导出打印」，这样我能把已经挑好的题直接变成纸。
2. 作为家长，我在题库页勾选后能复用现有的多选底栏，这样我不用学一套新的选择交互。
3. 作为家长，我能在任务页勾选若干任务后导出，这样我能把一次布置的任务整份印出来。
4. 作为家长，我能在任务页看到每行的勾选框，这样我知道哪些任务会被印出来。
5. 作为家长，我能在错题本页导出娃娃**全部未毕业错题**，这样我能印一份阶段性错题汇总卷。
6. 作为家长，我在错题本页能勾「只看今天到期」，这样我可以用同一份入口印出今天的复习卷。
7. 作为家长，我能在复习页一键导出**当前到期的复习项**，这样纸上的题和屏幕上该复习的题完全一致。
8. 作为家长，我在没有勾选任何题目时看到导出按钮为禁用态并说明原因，这样我不会点了个没反应的按钮。
9. 作为家长，我在一次导出里不能混选题库和任务，这样分节标题不会变成一堆来源混在一起的怪东西。

**预览与投递**

10. 作为家长，导出后我先看到一份**预览页**，这样我确认没问题再打印，不会白费纸。
11. 作为家长，我能在预览页逐页翻看整份卷子，这样我能确认排版没把題目切断。
12. 作为家长，我能在预览页点打印直接进系统打印对话框，这样我选打印机就能出纸。
13. 作为家长，我能在预览页点分享走系统分享面板，这样我能把 PDF 发给家人或存进「文件」App。
14. 作为家长，我在预览页能看到「N 道题含公式或图片，已按纯文本打印」的提示，这样我不会以为打印机坏了。
15. 作为家长，我在预览页点返回能回到原来的列表且勾选状态不丢，这样我能回去改选项再导一次。

**纸面内容**

16. 作为家长，我拿到的纸上**只有题干和选项**，这样娃娃看不到答案，卷子可以用。
17. 作为家长，我拿到的纸上**没有解析**，这样卷子不会被讲题内容占满。
18. 作为家长，我看到选择题后面留了一点空白，这样娃娃能在选项旁打勾。
19. 作为家长，我看到填空题题干里有一条横线，这样娃娃知道往哪填。
20. 作为家长，我看到计算题和应用题后面有一块空白答题区，这样娃娃有地方写过程。
21. 作为家长，我看到纸上题号是**连续**的（跨分节不重置），这样我用批改 App 扫码时题号不会出现两个「第 1 题」。
22. 作为家长，我看到页眉左边是卷子标题、右边是「姓名 ____ 日期 ____」，这样多个娃娃能用同一份卷子，且我能知道是谁什么时候做的。
23. 作为家长，我看到页眉的姓名和日期是**空着的**，这样同一份卷子能复用于多个娃娃。
24. 作为家长，我看到任务名作为分节标题，这样我知道哪几题属于哪个任务。
25. 作为家长，我看到题库导出的题按学科分节并带几何标记（■ ● ▲），这样黑白打印也能一眼分清学科。
26. 作为家长，我只勾了单一学科时**看不到多余的分节标题**，这样卷子不会为了分节而分节。
27. 作为家长，我看到纸上不印任务状态（draft/assigned 之类），这样纸面干净、娃娃也看不懂那些词。
28. 作为家长，我印出来的卷子即使**用黑白打印机**也清晰可读，这样我不必为了印卷子专门开彩色打印。

**顺序与规模**

29. 作为家长，我看到纸上的题目顺序和我勾选时列表里的顺序一致，这样我不会被导出器偷偷重排。
30. 作为家长，我一次勾选超过 60 题时收到「建议分批」的提示，这样我知道继续下去预览会变慢。
31. 作为家长，我在后端不可达（离线）时看到导出入口禁用并说明原因，这样我不会以为 App 坏了。

**跨角色与守卫**

32. 作为家长，我只能导出**自己账号下**的题目和任务，这样别的家庭的题不会出现在我的卷子上。
33. 作为家长，我只能导出**自己娃娃**的错题，这样归属边界和 App 内其他页面一致。
34. 作为家长，我在中文字体没配好时看到明确的错误提示，而不是拿到一份全是豆腐块的 PDF，这样我不会白打印一次。

## Implementation Decisions

- **生成端在服务端，客户端只预览与投递。** 后端新增 `export` feature（schemas / repository / service / router 四件套，沿用 `questions` 的骨架约定：repository 与 service 都是**模块级函数、显式传 `session=`**，router 用 `APIRouter(prefix="/export", tags=["export"])` 并在 API 主路由里注册，schemas 用 SQLModel）。排版用 **Typst**（`typst-py`，Apache-2.0，Rust 编译的 wheel，无系统库）跑 `.typ` 模板，题目数据经 `sys_inputs` 以 JSON 传入。

- **API 契约：`POST /api/v1/export/sheet`（家长 JWT）。**

  ```jsonc
  // 请求
  { "source": "bank" | "task" | "wrong_book",
    "ids": ["<uuid>"],          // bank=题目 id；task=任务 id；wrong_book 可为空（取该娃娃全部）
    "title": "可选，缺省由服务端推导",
    "child_id": "wrong_book 必填",
    "due_only": false }         // wrong_book 专用：只看今天到期
  ```
  响应 `200 application/pdf`，`Content-Disposition: inline`；错误 `400`（来源混选 / 超硬上限）、`403`（越权）、`503`（字体缺失，明确告知，不静默产出豆腐块）。

- **三个来源，不是四个。** 复习页的「当前到期复习项」与错题本页勾了「只看今天到期」是**同一份查询**（同一张错题表 + `due_at` 过滤），所以复用 `wrong_book` + `due_only: true`。若实现时发现两页取数语义确有差异，再拆独立 source——不在本轮预设。

- **一次导出只允许单一来源**，请求层校验，混选直接 `400`。

- **无数据库迁移。** 这是一条纯读路径：读 `Question` / `Task` + `TaskQuestion` / 错题表，不新增字段、不新增表。任务来源印的是 `TaskQuestion` 的**深拷贝快照**，与源题日后被编辑无关。

- **归属校验一律走 `core.guard`，不允许手写 `parent_id ==` 比较。** 题库来源对每个题目 `require_owned(model=Question, ...)`；任务来源对每个任务 `require_owned(model=Task, ...)`；错题来源先 `require_owned_child` 再按娃娃过滤。分层不变量测试会静态扫描内联归属判定，手写比较会直接红。

- **`export` service 不得 import `fastapi` 或任何 `router`**——分层不变量会自动扫描新 feature 的 `service.py`，这条是硬约束。

- **文档模型是唯一的内容边界，题号在模型里就算好。** 模板只负责渲染，不做判断：

  ```python
  @dataclass(frozen=True)
  class ExportQuestion:
      no: int              # 跨节连续题号，由文档装配阶段计算
      qtype: str           # choice | fill | calc | open
      stem: str            # 已降级为纯文本
      options: list[str]   # 已去除 "A. " 之类重复前缀
      answer_space: str    # none | blank_line | writing_area

  @dataclass(frozen=True)
  class ExportSection:
      heading: str | None        # None = 不分节（题库仅单学科）
      subject_mark: str | None   # ■ ● ▲
      questions: list[ExportQuestion]

  @dataclass(frozen=True)
  class ExportDocument:
      title: str
      sections: list[ExportSection]
      downgraded: int            # 含公式/图片、已按纯文本打印的题数
  ```

  **模型里没有 `answer` 和 `explanation` 字段——答案不是「过滤掉」，而是「从来没有」。** 这比在渲染层过滤更强：类型系统就拒绝了它们。模板拿不到就不可能印出来。

- **选项前缀去重。** 库里有的题自带 `A. ` 前缀，屏幕上的字母是 UI 层生成的；纸面排版必须去重，否则会出现 `A. A. 第一个选项`。

- **作答留白按题型推导，不按 qtype 名字硬猜**：沿用既有判据「`options` 非空即走选项，否则走留白」。`choice` 6mm；`fill` 题干内一条 40mm 横线；`calc` 35mm；`open` 50mm。

- **纸面规格固定一套**：A4 纵向；左右 20mm、上 18mm、下 16mm；题干 12pt / 选项 11pt / 页眉 9pt、行高 1.5；页眉左标题右「姓名 ____ 日期 ____」（**不预填娃娃名**）。

- **纸面视觉「轻装饰」**：保留墨黑描边与学科几何标记，**不铺任何彩色填充**——家长很可能用黑白激光打印机，色块会印成一团脏灰；而几何标记本就是三重编码里为色觉障碍准备的第二层，在黑白纸上天然成立。

- **题干按富文本（标准 Markdown）承载，本轮纸面降级为纯文本。** 剥离 `$...$` 定界符保留内部文本（`1/2`、`x^2`），剥离图片语法。**降级题数由客户端自己算**（它本来就有题目数据）——不新增响应头，协议保持一个二进制。

- **中文字体由配置指定，启动冒烟校验。** 新增配置 `EXPORT_FONT_DIR`（pydantic-settings，无 env 前缀，与既有字段一致），**不在代码里硬编码路径**。在 `lifespan` 里沿用 ADR-0041 的模式加一条校验（生产抛错、开发告警）；端点侧缺失时返回 `503`。中文由 Typst 自动子集化输出，不需要手工处理 `NotoSansSC.ttf` 的 17.7 MB。

- **编译是 CPU 密集，走线程池**（`anyio.to_thread.run_sync` 一类），不占事件循环。60 题量级同步返回即可。

- **上限：软 60 / 硬 200**（对 ADR-0052 的一处澄清）。客户端在超过 60 题时提示「建议分批」但**允许继续**——家长要印 100 题的复习卷是合理需求；服务端设 `EXPORT_MAX_QUESTIONS = 200` 作为防超时/防内存的硬边界，超过返回 `400` 并带可展示的中文消息。ADR-0052 守卫里「超过 60 题时返回明确提示」应据此修正为「服务端硬上限 200 / 客户端软提示 60」。

- **前端新增 `features/export/`，但只放契约、取字节与预览页。** 按 ADR-0037（feature 之间不得横向互引，唯一豁免是 `home` 的展示层），导出器**不能**去读题库/任务/错题的 provider。四个入口各自把已选数据转成 `ExportDocument`，装配点在 `home/presentation`。这样导出器不反向依赖任何 feature，边界守卫的棘轮不会响。

- **四个入口的改造量不同**：题库页复用现有多选底栏加一个按钮（选择态已有）；任务页需**新做选择态**（目前只有 Tab）；错题本页与复习页各加一个导出入口。新增的可点区域一律用 `AppFocusableAction`（ADR-0046），裸 `GestureDetector` 不进焦点树。

- **网络层需要补一个「取二进制」的方法。** 现有网络抽象只有 get/post/put/delete/streamPost，需加一个下载字节的方法（Dio 侧 `responseType: ResponseType.bytes`）。注意现有错误处理会吞掉非 2xx 的响应体，而这里必须区分 `403`（越权）与 `503`（字体缺失），实现时要保留错误响应内容。

- **预览页是 `Navigator.push` 的整页**，按 ADR-0045 **不在壳的宽度兜底范围内**，页面自己套宽度约束（`contentWide`），否则内容会浮在屏幕中间。

- **预览用 `pdfx` 渲染字节，打印/分享用 `printing`。** 新增依赖只有 `printing` + `pdfx`（`printing` 自带分享能力，不引 `share_plus`）。iOS 的打印对话框自带「存储为 PDF / 分享」，App 内**不落盘、不做导出历史**，没有文件清理负担。

- **离线时导出入口禁用并说明原因**——这是选择服务端生成换来的明确退让，要如实告知而不是点了没反应。

## Testing Decisions

**什么算好测试**：只测外部行为，不测实现细节——不断言 Typst 模板字符串的内容，不断言编译器被调用时的参数，不断言内部中间结构（除非它就是契约本身）。

**接缝一（主，最高层）：`POST /api/v1/export/sheet` HTTP 端点。** 走现有 `TestClient` fixture 与家长注册/登录 helper，用 `tests/conftest.py` 的 `db` fixture 造数据。断言：

- 正常导出返回 `200` + `application/pdf` + `%PDF-` 魔数；
- 用**另一个家长**的题目/任务 id 请求 → `403`，且响应里不含该题内容；
- 混选题库与任务 → `400`；
- 字体目录缺失 → `503` 且消息可读（**不**静默产出豆腐块 PDF）；
- 超过硬上限 → `400` 且消息可读。

先验：`tests/api/routes/` 下的问题库 HTTP 测试。

**接缝二（次，纯函数）：`build_export_document()`。** 之所以需要它：PDF 是二进制且 Typst 会子集化字体，文本层 grep 不到内容，所以内容规则在**文档模型层**断言更强也更便宜。直接调函数，无需 DB / HTTP，断言：

- 任务来源按任务分节、题库来源按学科分节、单学科时不产生分节标题；
- 题号跨节连续，不按节重置；
- Markdown 与 `$...$` 被剥离，降级计数正确；
- 选项的重复字母前缀被去掉；
- **文档模型里不存在 `answer` / `explanation` 键**（整棵树递归断言）；
- qtype → 作答留白的映射正确。

先验：`tests/features/review/test_service.py`（service 层直接调函数 + `monkeypatch` + 自造数据）。

**前端（`flutter test`）**：

- 契约转换：四个入口各自能把已选数据转成 `ExportDocument`，且不含答案字段；
- 预览页几何：`setSurfaceSize` 后整页自带宽度约束，内容不浮在屏幕中间（ADR-0045）；
- 边界守卫：既有棘轮测试自动覆盖新目录，`features/export/` 不得新增 R4/R5 违规，不得横向 import 其他 feature。

**不测**：PDF 的像素级外观（仓库没有 golden 设施）；Typst 模板的排版细节靠**一次人工目视**——第一份卷子真的打印出来看一遍。

## Out of Scope

- **答案卷与解析导出。** 学生卷是当前唯一形态，批改靠外部 App 扫码。
- **公式渲染（`$...$` → 版式）与配图。** 本轮纸面降级为纯文本；屏幕侧富文本渲染与图片管道（上传 / 存储 / 鉴权）是**独立后续 ADR**，不在本 spec 内。
- **ASCII 字符画题干。** 已明确取消，题干后续按标准 Markdown 承载。
- **一次导出多份 PDF / 批量下载。** 永远产出一份，按来源分节。
- **App 内导出历史、文件落盘与清理。** 打印对话框与分享面板已经承担这件事。
- **页眉预填娃娃姓名。** 同一份卷子可能给多个娃娃用，必须手填。
- **导出器内的排序与筛选。** 节内顺序 = 列表当前展示顺序；筛选是各列表页自己的事。
- **客户端离线生成 PDF。** 已明确选择服务端生成。
- **导出内容的分页控制（家长指定每页几题）。** 由模板决定。

## Further Notes

- **与 ADR-0042 的张力已登记**：ADR-0042 立过「服务端不拼展示串、排版归前端」。服务端排版 PDF 表面冲突，ADR-0052 论证为正当例外——它禁的是助手卡片通道下发 UI schema 做通用 GenUI，而 PDF 是**最终产物**，`.typ` 模板不下发、客户端也不解释它。本 spec 沿用该结论，不扩大适用范围。
- **部署体积**：新增 Typst wheel（Linux ~33 MB）+ 一份中文字体，无系统库依赖。
- **已知代价**：屏幕题干（Flutter 富文本）与纸面（Typst）是两套排版系统。这不是一致性缺陷——二者职责本就不同（一个可交互、一个要留白）。
