# Spec：列表规模（取数与密度）

> 决策依据：[ADR-0053 列表规模：分页 / 密度 / 归档](../adr/0053-list-scale-pagination-density-archive.md)。
> 术语以 `CONTEXT.md` 为准（题目 / 题库 / 任务 / 任务题 / 错题 / 错题本 / 复习项）。
> 本文件是 GitHub issue 的正文源；落库后以 issue 为准。
> 范围：ADR-0053 的 **P0（取数）+ P1（密度）**。归档（P2）单独成 spec，不在本文件内。

## Problem Statement

家长用得越久，题库、任务、错题本三块内容就越长，但三个页面**一屏能放的东西是固定的**。家长实际会遇到四件具体的事：

1. **题库里第 21 条之后的题目，家长在 App 里根本看不到。** 后端 `GET /questions` 早就返回了 `page` / `page_size` / `total`，但前端每次都只取第 1 页 20 条，界面上也没有任何翻页或「加载更多」的控件——分页能力建好了，一直没接上。家长攒了 80 道题，看到的还是最新那 20 道，于是反复重新生成已经出过的题。
2. **任务页越用越慢，最后会卡住。** `GET /tasks` 不分页，而且每个任务都把全部任务题（含题干、选项、答案、解析）内嵌进响应，只为在卡片上显示一句「10 题」。100 个任务 × 10 题 ≈ 1000 条带答案的题目，全量拉到客户端再在前端分成三个 Tab。数据量上来后先卡网络、再卡内存。
3. **家长错题本一屏只有三张半卡片。** 每张卡把完整题干、标准答案、整段解析一次全展开，而且题干没有行数上限——一道长题干能撑掉半个屏幕。更糟的是这个页面不是懒加载，500 条错题会一次性把 500 张卡全部构建出来。
4. **长列表没有终点感。** 家长滑到下面不知道还有多少条、是不是已经到底了，只能一直滑。

同一件事在桌面端还有一层：窗口可以拉得很宽，但列表还是单列一条条排下去，横向空间白白浪费。

## Solution

三个列表统一改成**「游标分页 + 追加式加载」**：首屏取 20 条，滑到底部自动追加下一批，底部常驻一个「加载更多」按钮（键盘和读屏也能用），到底后给出明确终止提示。任务列表不再内嵌题目，改成只带题目数的摘要。家长错题本改懒加载，并把题干截到 2 行、解析默认折叠。

密度不靠压缩留白：卡片内边距维持 12 不动，靠的是**内容截断、解析折叠，以及宽度够时自动变两列**。

## User Stories

**题库：翻页与加载**

1. 作为家长，我在题库页滑到底部时能自动加载下一批题目，这样我不用去找翻页按钮。
2. 作为家长，我在题库页底部能看到一个「加载更多」按钮，这样我用键盘或读屏也能继续加载。
3. 作为家长，我在题库页能看到「还有 N 条」的提示，这样我知道还剩多少、值不值得继续滑。
4. 作为家长，我滑到题库最底部时能看到「已全部加载」，这样我知道到底了，不会再无意义地滑。
5. 作为家长，我在题库页切换学科 / 年级 / 题型或输入关键词后，列表从第 1 页重新开始，这样我不会看到上一批筛选的残留。
6. 作为家长，我改筛选条件时已加载的题目会被清空，这样新结果不会和旧结果混在一起。
7. 作为家长，我在加载下一批时看到底部有加载指示，这样我知道 App 没卡死。
8. 作为家长，我在加载失败时能在底部看到「加载失败，重试」，点一下就能续上，这样我不用回到顶部重刷整页。
9. 作为家长，我翻到第 3 批时发现最初那批题目的顺序没有因为期间新生成了题而错位，这样我不会看到重复的题或漏掉题。
10. 作为家长，我在题库页勾选题目后翻页再翻回来，勾选状态不丢，这样我能跨页挑题组卷。
11. 作为家长，我在题库页能一次看到第 21 条及以后的题，这样我攒的题不会白攒。

**任务：列表与状态 Tab**

12. 作为家长，我在任务页滑到底部时能加载更多任务，这样我能翻到很早以前布置的任务。
13. 作为家长，我在任务页三个 Tab（草稿 / 进行中 / 已完成）切换时，各自独立分页，这样切到「已完成」不会从第一页开始就只有 20 条。
14. 作为家长，我在任务页三个 Tab 上看到的数量徽标仍然准确，这样即使任务总数超过一页，我也知道每个状态有多少个。
15. 作为家长，我在任务卡片上仍然看到「N 题」和派给哪个娃娃，这样分页没有砍掉我认任务需要的信息。
16. 作为家长，我打开任务页时首屏出现得更快，这样列表不再为显示「10 题」而下载 10 道题的全文。
17. 作为家长，我点某个任务进复核页时能看到完整题目，这样摘要只影响列表、不影响审核与派发。
18. 作为家长，我在任务页滑到底时看到「已全部加载」，这样我知道没有更多任务了。

**错题本：家长端**

19. 作为家长，我在错题本页滑到底部时能加载更多错题，这样娃娃攒了几百条错题我也能翻到底。
20. 作为家长，我在错题本页一屏能看到更多错题，这样我能快速扫一遍娃娃最近错在哪。
21. 作为家长，我看到每张错题卡的题干最多两行、超出的用省略号，这样一张长题干不会占掉半屏。
22. 作为家长，我能点开某张错题卡看完整解析，这样需要细看时仍然看得到全文。
23. 作为家长，我默认不看到完整解析，这样列表不会被大段文字占满。
24. 作为家长，我仍然能在卡片上直接看到标准答案，这样我扫一眼就能判断娃娃错在哪。
25. 作为家长，我在错题本页看到「还有 N 条」与「已全部加载」，这样长列表有终点。
26. 作为家长，我在打开错题本时首屏出现得更快，这样几百条错题不会一次性全部构建。

**错题本：娃娃端**

27. 作为娃娃，我在错题本页滑到底部时能加载更多错题，这样我能翻到更早的错题。
28. 作为娃娃，我滑到底时看到「已全部加载」，这样我知道看完了。
29. 作为娃娃，我在卡片上仍然看不到答案，这样分页改造不会把答案泄露到我的列表里。

**密度：列数与留白**

30. 作为家长，我在宽窗口 / 大屏上看题库时列表自动变成两列，这样一屏能看到差不多两倍的题。
31. 作为家长，我在窄窗口或分屏下看题库时列表是一列，这样题目不会被挤得看不清。
32. 作为家长，我在两列布局下两列之间有清晰间隔，这样我能分清哪张卡属于哪一列。
33. 作为家长，我在三个页面里看到的行间距、页面留白是一致的，这样切换页面时不会有「这个页面更挤」的突兀感。
34. 作为家长，我看到的卡片内边距没有变得局促，这样题目文字仍然好读、卡片仍然好点。
35. 作为家长，我在大屏上点某条错题或某道题时详情在右侧栏展开，这样左边列表的滚动位置不丢，我不用反复进出。

**可达性与失败**

36. 作为用键盘操作的家长，我能用 Tab 键走到「加载更多」按钮并按 Enter 加载，这样我不必依赖鼠标滚动。
37. 作为用键盘操作的家长，我在「加载更多」按钮上看到焦点环，这样我知道焦点在哪。
38. 作为家长，我在网络断开时看到加载失败并可重试，这样我不会面对一个空白页不知道发生了什么。
39. 作为家长，我在加载过程中反复滑到底部不会触发重复请求，这样不会加载出重复的题目。
40. 作为家长，我在打开系统「减少动态效果」后，追加加载的入场动画被关掉，这样列表不会闪烁。

## Implementation Decisions

**取数：统一信封 + 游标分页**

- **三个列表端点统一返回 `PageResp<T>`：`items` / `total` / `next_cursor`。** `next_cursor` 为 `null` 表示已到底。现有的 `BankListResp`（题库）已带 `total` / `page` / `page_size`，扩展而非替换：`page` / `page_size` 字段保留，新增 `next_cursor`，避免一次改坏 AI 助手的题库查询链路。
- **排序键固定为 `(created_at DESC, id DESC)`，游标取 keyset 条件，不用 offset。** 三个列表都是「新数据从顶部插入」，offset 分页在两次请求之间插入一行就会重复或漏掉一条（用户故事 9 就是为这条写的）。游标编码的是上一批最后一条的排序键值：

  ```python
  # 游标 = 上一批最后一条的 (created_at, id)，base64 编码后作为不透明字符串下发
  # 下一页条件：(created_at, id) < (cursor_created_at, cursor_id)
  # 边界：created_at 可能为 NULL（旧数据）→ 排序时 NULLS LAST 由 DEFAULT 兜底，
  #       游标比较对 NULL 走 id 兜底，不能让 NULL 行在页界处反复出现
  ```

- **`page_size` 默认 20、上限 100**，沿用题库现有取值。`page` 参数保留但标记 deprecated，前端不再使用。
- **任务列表不再内嵌任务题。** 新增 `TaskSummaryResp`：只带 `id` / `title` / `status` / `child_id` / `created_at` / `question_count` / `subjects`（本卷涉及的学科摘要）。完整任务题只在单个任务详情端点返回——复核页、派发、练习走的都是详情端点，不受影响。
- **任务列表响应额外带 `counts: {draft, ready, assigned, done}`。** 三个 Tab 徽标目前靠全量数据客户端统计，不补这个字段的话分页省下的流量又会被徽标吃回去。
- **家长端与娃娃端两个错题端点共用同一条 service 分页分支**，新增 `only_active` 参数（默认 `true`），为 P2 的毕业归档预留，本轮传与不传行为一致。
- **`total` 改用 `SELECT COUNT(*)`。** 现在题库的 `total` 是把全部行读进内存再 `len()`——分页省下的 IO 又赔在计数上。
- **补复合索引**：`Question(parent_id, created_at DESC)`、`Task(parent_id, created_at DESC)`、`WrongQuestion(child_id, first_wrong_at DESC)`。现有 `WrongQuestion.child_id` 是单列索引，覆盖不了排序。
- **归属校验仍一律走 `core.guard`**，不允许因为「分页只要加个 where」就手写 `parent_id ==` 比较——分层不变量测试会静态扫描内联归属判定。
- **AI 助手的查询工具不受影响**：它们走 `limit` 一次性取数（上限 200），本轮不动。

**交互：追加式加载，不做页码器**

- 三个页面统一：首屏 20 条 → 触底自动追加 → 底部常驻「加载更多」按钮。按钮不是装饰：触底自动加载对键盘 / 读屏用户不可达，且是触底判定失败时的兜底。
- **不做页码器。** 三个页面的定位职能由已有筛选器（学科 / 年级 / 状态 / 关键词）承担，「跳到第 7 页」与这个心智重复；页码按钮在触屏上还踩 44 触控目标的下沿。
- **追加必须给终点感**：底部显示「还有 N 条」（`total - loaded`），到底后换成发丝线 + 「已全部加载」。
- **触底回调必须防抖**，一次触底只触发一个请求；前一个请求未返回时不发下一个。
- **筛选条件变化时重置到第 1 页**，并清空已加载项。
- **跨页勾选状态保留**（题库的组卷选择），因为家长是「翻一遍挑题」，不是「一页内挑题」。
- **桌面（可用宽 ≥ `AppLayout.largeMin`）靠 detail 栏提效，不靠更密的列表**：点击行在右栏展开详情，列表滚动位置不丢。
- **追加的行走 `PopIn` 入场动画，但 `duration` 必须尊重 `reducedMotionOf(context)`**——隐式动画不会自动跟随系统设置。
- **新增的「加载更多」按钮必须走 `AppFocusableAction`**，裸 `GestureDetector` 不进焦点树，是 bug。

**密度：先加列、再截断内容，间距最后动**

- **卡片内边距保持 `AppSpacing.md` 12 不动。** 题库行 95px、任务卡 70px 都在 `AppLayout.tapTarget` 44 之上，把 `md` 降到 `sm` 只省 8px（不到 10%），却会打破「卡片内边距 = md」这条全站约定。
- **行间距统一到 `AppSpacing.sm` 8。** 现在三个页面三种值：题库 8、任务 12、错题本 16。行卡自带发丝描边，8 足够分隔。
- **页面外边距统一**：左右 `AppLayout` 的 `AppSpacing.lg` 16、顶部 16、底部 `AppSpacing.xl2` 28。现在顶部有 12 / 16 / 12 三种值。
- **列表正文一律 `maxLines: 2`。** 家长错题卡的题干目前没有任何行数上限，这是单卡高度不可控的直接原因。
- **家长错题卡：答案保留一行，解析折叠。** 展开控件走 `AppIconAction`（禁止 `CupertinoButton(padding: zero)`——它默认 44×44 会撑高同行，还会强制系统字体覆盖内嵌的 Inter + Noto Sans SC）。单卡高度 ≈250 → ≈150。
- **内容宽 ≥ 1048 时列表走 2 列网格。** 列宽锚 `AppLayout.contentCard` 520，用 `maxCrossAxisExtent` 由 `LayoutBuilder` 的 `maxWidth` 推导实际列数（1080 → 2 列；中屏 700 → 1 列；大屏 detail 打开时主栏约 446 → 1 列）。**上限 2 列**：3 列会把列宽压到 352，低于 `contentNarrow` 480 的可读下限。列间距 `AppSpacing.md` 12——比行间距大一档，因为列与列之间没有描边分隔。
- **列数判定只看 `LayoutBuilder.constraints.maxWidth`**，禁止 `MediaQuery.size` / `orientationOf` / 平台判断（ADR-0045 的硬约束）。
- **家长错题本从 `SingleChildScrollView` + `for` 改成 `ListView.builder`**（娃娃端已经是 builder，照抄它的 `IntrinsicHeight` 包法——左侧学科色条用 `Row(stretch)`，在无界高的 `ListView` 里必须给有界高度）。
- **不新增任何裸数字**：上面每一档都能落到 `AppLayout` / `AppSpacing` 现有令牌上；需要新档位时加到令牌里，不要在页面里写常量。

**分层约束**

- 后端新 / 改的 `service.py` 不得 import `fastapi` 或 `router`（分层不变量测试会扫）。
- 前端改动不得让 `shared/` 反向 import `features/`；新组件若订阅了某个 feature 的 provider，就落回该 feature。

## Testing Decisions

**什么样的测试算好测试**：只测外部可观察行为——「给定这批数据，用户看到了什么、点下去发生什么」，不测内部实现（不断言 SQL 语句长什么样、不断言内部字段名叫什么）。分页这类功能最容易写歪成「断言调用了某个私有方法」，一律拒绝。

**接缝：两侧各一条，都是仓库里已有的，不新增。**

- **前端：`FakeNetwork implements NetworkService`**（`review_notifier_test` / `assistant_notifier_test` 已在用）。在 HTTP 客户端层打桩、按 path 返回预置 JSON，repository 实现是真的——连解析一起测到，比在 repository 接口打桩高一层。
- **后端：service 层函数 + `tests/conftest.py` 的临时 SQLite session**（`tests/features/tasks/test_service.py` / `tests/features/review/test_service.py` 已在用）。不走 HTTP。

**具体用例**

- 前端（FakeNetwork 驱动 notifier + 少量 widget 断言）：
  - 追加后 `items` 长度正确累加、`hasMore` 随 `next_cursor` 翻转；`next_cursor == null` 后不再发请求。
  - 触底回调防抖：连续触发只产生一个请求；前一个请求未返回时不发下一个。
  - 筛选条件变化后重置到第 1 页，已加载项清空。
  - 题库跨页勾选：翻页再翻回，勾选 id 集合不变。
  - 加载失败时状态落到可重试态，重试后接着上一次的游标续上（不重新从首页开始）。
- 前端（widget，几何与可达性）：
  - 可用宽 1080 → 2 列；700 与 446 → 1 列；列间距 = `AppSpacing.md`。
  - 家长错题卡题干最多 2 行；解析默认不渲染，点展开后出现。
  - 「加载更多」按钮可被键盘聚焦（在焦点树里）并响应 Enter。
- 后端（service 层）：
  - **游标翻页在「两次请求之间插入一条新数据」时不重不漏**——这是选游标而不要 offset 的唯一理由，必须有一条测试盯着它。
  - `total` 与过滤条件一致（学科 / 年级 / 关键词过滤后总数跟着变）。
  - `page_size` 越界钳到 [1, 100]。
  - 任务列表项不含 `questions` 且 `question_count` 与详情端点一致；`counts` 四项之和等于该家长全部任务数。
  - 娃娃端错题列表不含答案。
  - owner 隔离：换一个家长取不到别人的数据（`core.guard` 生效）。
- **既有守卫不得回归**：`adaptive_shell_layout_test`、`app_focusable_keyboard_test`、`stretch_row_guard_test`、`feature_boundaries_test`、`task_empty_state_test`（空态改造后仍然要分 Tab 指路）。

## Out of Scope

- **归档（ADR-0053 的 P2）**：题库 `archived_at`、任务按月分段折叠、错题毕业写时间戳——单独一份 spec。
- **错题毕业机制的语义变更**：本轮只加 `only_active` 参数占位，不改「末位阶段答对即删除」的现有行为。
- **页码器 / 跳页**：明确不做，理由见 Implementation Decisions。
- **虚拟滚动与第三方分页库**：`ListView.builder` 已够用。
- **待复习队列的到达率**：错题本真正会长的是「从不复习」的错题（`review_stage` 恒为 0），那是复习调度的问题，不是列表分页能解决的。
- **AI 助手查询工具的分页**：仍走 `limit` 一次性取数。
- **打印导出的分页**：走 ADR-0052 自己的链路。

## Further Notes

- **迁移注意**：`BankListResp` 新增 `next_cursor` 字段，前端 `models.dart` 的 `BankListResp` 需同步加字段并给 `null` 兜底——旧版本 App 打新后端时不应崩。
- **游标的已知代价**：游标分页不能跳页，「直接翻到很靠后的位置」只能靠筛选器缩小范围。这是刻意换来的：宁可不跳页，也不要在顶部插入新数据时出现重复行。
- **2 列网格与大屏 detail 的相互作用**：大屏 detail 打开时主栏约 446px，会掉回 1 列——这是符合预期的，不是 bug；两列只在内容宽度的确够时才出现。
- **顺序建议**：先做 P0 取数（数据可见性 + 载荷），再做 P1 密度。P0 里「任务列表拆摘要」会动到 `TaskResp` 的形状，复核页 / 派发 / 练习都依赖它，先跑通 `flutter analyze` 与后端 `pytest` 再动 P1。
- **本 spec 落地后**，ADR-0053 的 P2（归档）应另开一份 spec，其中错题那一项（毕业改为打时间戳）会与 `mastery` 的 `active_wrong` / `max_review_stage` 统计口径耦合，需要在那份 spec 里单独处理。
