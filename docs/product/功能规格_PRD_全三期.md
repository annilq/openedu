# 功能规格文档（PRD）— 全三期

> 项目：娃娃学习 App（小学二年级 / 四年级起步，规划至初中）
> 形态：平板原生 App（Flutter）+ Python/LangChain 后端 + PostgreSQL
> 配套：`技术架构_后端.md`、`技术架构_Flutter.md`、`娃娃学习App_ADR.md`、`娃娃学习App_术语表.md`
> 需求描写遵循 **EARS 原则**（Ubiquitous / Event-driven / Unwanted / State-driven / Optional）。

---

## 1. 背景与问题陈述

家长希望为两个娃娃（二年级、四年级）提供日常学习工具，覆盖数学、语文、英语等学科。痛点是：市面产品要么太游戏化、要么不贴合自家教材进度、要么家长缺乏可见管控。本 App 定位为「家庭私用、家长当班主任、AI 辅助出题与讲解」的学习闭环工具。

---

## 2. 目标

- **产品目标**：让家长可布置任务、娃娃可完成练习与打卡、双方能看到进度与薄弱点；AI 负责出题与（三期）答疑。
- **成功指标（北极星）**：两个娃娃**每周有效练习天数 ≥ 5 天**；家长**每周查看进度 ≥ 1 次**。
- **范围边界**：一期仅客观题为主、AI 即时批改；主观题与自由答疑放三期；教材版权上线前必须解决（ADR-012，🔴硬门槛）。

---

## 3. 用户角色与画像

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 家长（parent） | 应用创建者/管理员 | 布置每日任务、查看两娃进度与薄弱点、设使用时长/内容范围 |
| 娃娃-二年级 | 7~8 岁，低龄 | 点选作答、即时反馈、打卡拿徽章、被家长表扬 |
| 娃娃-四年级 | 9~10 岁 | 同上，题目难度更高、可承载更多题型 |

> 设备假设：共用一台平板、娃娃切换账号（架构可按各一台扩展）。

---

## 4. 用户故事（节选）

- 作为家长，我想按「学科+知识点+题型+难度+题量」给某个娃娃生成一套练习，以便针对性巩固。
- 作为家长，我想查看每个娃娃的正确率、连续打卡天数，以便知道谁需要关注。
- 作为二年级娃娃，我想在平板上点选答题、立刻看到对错和解析，以便即时纠错。
- 作为娃娃，我想每天打卡积累连续天数和徽章，以便获得成就感。
- （二期）作为娃娃，我想看到自己答错的题在几天后被提醒复习，以便对抗遗忘。
- （三期）作为娃娃，遇到不懂的题能问 AI 并获得适合我年龄的讲解，且家长能看聊天记录。

---

## 5. 总体功能地图

| 期 | 主题 | 核心功能 |
|---|---|---|
| **一期 MVP** | AI 出题刷题 + 家长打卡 | 注册/登录、娃娃账号、AI 出题、作答批改、打卡、进度 |

# 一期 MVP 详细规格

## 6. 一期功能清单

| 编号 | 功能 | 角色 | 说明 |
|---|---|---|---|
| F-101 | 家长注册/登录 | parent | JWT 鉴权 |
| F-102 | 娃娃账号管理 | parent | 增/列娃娃，绑 parent_id，设年级 |
| F-103 | AI 出题并建任务 | parent | 选 child/subject/grade/kp/qtype/difficulty/count |
| F-104 | 娃娃查看今日任务 | child | 拉取分配给自己的任务与题目（无答案） |
| F-105 | 作答与即时批改 | child | 提交单题，返回 对错/分数/解析 |
| F-106 | 任务打卡 | parent/child | 完成后打卡，标记 done |
| F-107 | 娃娃进度看板 | parent | 正确率、连续打卡天数、累计打卡天数 |

## 7. 一期 EARS 需求

- **Ubiquitous**：系统应始终对家长专属接口校验调用者角色为 parent，对非归属数据返回 403/400。
- **Ubiquitous**：系统应始终对 `/tasks/today` 与娃娃端作答接口隐藏标准答案字段。
- **Event-driven**：当家长调用出题接口时，系统应根据所选知识点与题型，调用 LLMProvider 生成指定数量题目并写入题库，返回含答案的任务。
- **Event-driven**：当娃娃提交某题作答时，系统应即时批改（客观题规则判分，开放题交 provider）并返回对错、分数与解析。
- **Event-driven**：当任务所有题目作答完成且请求打卡时，系统应将该任务状态置为 done 并写入一条打卡记录。
- **Unwanted**：若 LLM 返回无法解析的内容（出题/批改），则系统应记录兜底题或返回明确错误，而不是崩溃或返回脏数据。
- **State-driven**：当娃娃处于「未登录/非 child 角色」状态时，系统应拒绝其访问 `/tasks/today` 与作答接口（403）。
- **Optional**：若配置了 `LLM_PROVIDER=langchain` 且 base_url/model 有效，则系统应使用真实大模型出题；否则使用 MockProvider 兜底。

## 8. 一期流程说明

**(1) 出题闭环**
家长登录 → F-103 选参 → 后端 `QuestionGenerator` 调 provider 出 N 题 → 写 Task+Question → 返回含答案任务（家长可见）。

**(2) 做题批改**
娃娃登录（role=child）→ F-104 拉 today → 逐题 F-105 提交 → `Grader` 即时判 → 显示对错+解析。

**(3) 打卡**
任务完成 → F-106 打卡 → Task.status=done + Checkin 记录。

**(4) 进度**
家长 F-107 → 聚合 answer_records（正确率）+ checkins（streak）→ 看板。

## 9. 一期交互说明

- **登录页**：用户名/密码；成功后按 role 跳 home。
- **家长首页**：娃娃列表 + 各娃今日任务入口 + 「生成任务」表单（学科/年级/知识点/题型/难度/题量）。
- **娃娃首页**：今日任务卡片列表，点进进入做题；底部「我的进度」「打卡」。
- **做题页**：题干 +（选择题选项 / 填空输入 / 计算输入）；提交后弹「✓正确 / ✗错误 + 解析」；可下一题。
- **打卡**：任务全部作答后可点打卡，显示连续天数 +1 动画。
- **进度看板（家长）**：每娃 正确率百分比、连续打卡天数、累计天数、最近薄弱知识点。

## 10. 一期边界与异常场景

| 场景 | 期望 |
|---|---|
| 同一用户名重复注册 | 400「用户名已存在」 |
| 娃娃访问 `/tasks/today` | 仅返回自己任务；无任务返回空列表 |
| 娃娃拿到题目后直接调答案接口 | 娃娃端永远不含 answer 字段 |
| LLM 出题返回非 JSON | 兜底题 + 记录日志，不阻断流程 |
| 网络中断提交作答 | 本地暂存，恢复后重试；或提示稍后 |
| 家长查看非自己娃娃进度 | 400 无权限 |

## 11. 一期权限规则

- 家长接口（`/children`, `/tasks/generate`, `/tasks/children/{id}/progress`）需 `require_parent`。
- 娃娃接口（`/tasks/today`, `/tasks/{id}/answer`）需 `role=child` 且数据归属本人。
- 打卡两角色均可，但均校验任务归属。

## 12. 一期数据口径

- 正确率 = 正确作答数 / 总作答数（按 child 聚合）。
- 连续打卡天数 = 从今天向前连续有 checkin 的天数。
- 知识点（knowledge_point）由家长出题时指定，作为后续薄弱点分析维度。

## 13. 一期埋点（数据指标）

| 事件 | 字段 |
|---|---|
| 生成任务 | parent_id, child_id, subject, kp, qtype, count, ts |
| 提交作答 | child_id, question_id, correct, score, ts |
| 打卡 | child_id, task_id, ts |
| 登录 | user_id, role, ts |

## 14. 一期验收标准（AC）

- [ ] AC-101：家长可注册并登录，获得有效 JWT。
- [x] AC-102：家长可创建两个娃娃账号（二年级/四年级），列表可见。（T13：家长首页「添加娃娃」入口 → AddChildScreen，POST /children；前端校验 + 创建后自动刷新并选中）
- [ ] AC-103：家长按参数出题，返回题量正确、字段完整、含答案（家长端）。
- [ ] AC-104：娃娃 today 接口仅见自己任务，且题目无 answer。
- [ ] AC-105：客观题提交后即时返回正确/错误+解析；连续答对/答错计入正确率。
- [ ] AC-106：完成任务可打卡，进度看板正确率/连续天数更新正确。
- [ ] AC-107：MockProvider 模式下整套闭环零报错（已本地验证通过）。
- [ ] AC-108：`LLM_PROVIDER=langchain` 配置真实模型后，出题无需改业务代码即生效。

# 二期 详细规格（错题本 + 遗忘曲线复习）

## 15. 二期功能清单

| 编号 | 功能 | 角色 |
|---|---|---|
| F-201 | 错题自动归集 | system/child |
| F-202 | 遗忘曲线复习排程 | system |
| F-203 | 复习任务推送与作答 | child |
| F-204 | 错题/掌握度看板 | parent |

## 16. 二期 EARS

- **Event-driven**：当娃娃作答错误时，系统应将该题记入该娃娃的错题集（child_id + question 快照 + 错误答案）。
- **State-driven**：当到达某错题的复习时间点（按遗忘曲线，如 1/2/4/7/15 天）时，系统应将其纳入该娃娃的「待复习」队列。
- **Event-driven**：当娃娃完成一次复习作答且正确时，系统应降低该错题的紧急度或标记掌握。
- **Unwanted**：若复习作答再次错误，则系统应重置其遗忘曲线计时。

## 17. 二期流程与交互

- 错题随 F-105 自动产生，无需额外操作。
- 娃娃首页新增「复习」入口，显示今日待复习题数。
- 复习作答复用 F-105 批改逻辑。
- 家长看板新增「各知识点掌握度」热力/进度条。

## 18. 二期验收标准

- [x] AC-201：答错的题自动进入错题集，家长/娃娃可在错题本查看。
- [x] AC-202：系统在约定间隔推送复习，且再次错误会重置计时。
- [x] AC-203：复习正确后该知识点掌握度提升并反映在看板。

# 三期 详细规格（AI 伴学答疑 + 知识库 RAG）

## 19. 三期功能清单

| 编号 | 功能 | 角色 |
|---|---|---|
| F-301 | 教材知识库管理（前期检索/后期 RAG） | parent/system |
| F-302 | AI 自由答疑（适龄讲解） | child |
| F-303 | 意图路由（出题/讲解/答疑分流） | system |
| F-304 | 内容安全层（双层防护 + 日志） | system/parent |
| F-305 | AI 交互日志可查 | parent |
| F-306 | AI 使用管控（每日次数/时长上限 + 内容范围） | parent/system |

## 20. 三期 EARS

- **Event-driven**：当娃娃提交一个自然语言提问时，系统应先经意图路由，再调用 Tutor 生成适龄讲解。
- **Ubiquitous**：系统应始终在 AI 输出前套用内容安全层，确保仅返回适合该娃娃年龄、纯学习相关的内容。
- **Unwanted**：若安全层检测到越狱/敏感内容，则系统应拦截该回复、不显示给娃娃，并生成一条待家长查看的提示。
- **State-driven**：当家长设置了「每日 AI 使用时长上限」且已达上限时，系统应拒绝新的 AI 答疑请求。
- **Optional**：若已建教材知识库，则系统应优先基于知识库检索结果作答（RAG），否则基于联网检索/模型内知识。

## 21. 三期流程与内容安全设计

```
娃娃提问 → IntentRouter → Tutor.ask()
                             │
                  ┌──────────┴──────────┐
            知识库检索(RAG)           模型直答（兜底）
                             │
                        SafetyGuard.check()
                          ├─ ok  → 返回娃娃
                          └─ 异常 → 拦截 + 转家长提示 + 记日志
```

- **系统层约束**：prompt 锁死「只输出适合 X 岁、纯学习相关内容」（后端 `langchain_provider._SYSTEM` 已就位）。
- **输出后校验**：`domain/safety.py` 敏感词/越狱检测。
- **家长可见**：所有 AI 交互存 `tutor_logs`，家长可查。

## 22. 三期验收标准

- [x] AC-301：娃娃可就一道题/知识点自由提问，获得适龄讲解（T08：/tutor/ask + TutorService）。
- [x] AC-302：越狱/敏感提问被拦截并转安全兜底，娃娃看不到违规内容（T08：domain/safety 输入/输出双层校验）。
- [x] AC-303：家长可查阅全部 AI 交互日志（T08：TutorLog + GET /tutor/logs）。
- [x] AC-304：达每日上限后 AI 答疑被拒（T08：TUTOR_DAILY_LIMIT + count_tutor_today，429）。注：MVP 以「每日消息条数」计上限，时长上限为后续增强。
- [x] AC-305：知识库就绪后，答疑优先基于知识库检索结果。（T11：`KnowledgeRetriever` 检索层已落地——`/tutor/ask` 命中内置自编知识点库时把内容注入讲解上下文；🔴 **教材授权仍未解决**（ADR-012），当前为自编内容源，对外分发前须换用已授权/公版内容。）
- [x] AC-306：家长可按娃配置每日 AI 使用上限与内容范围，超额/越界请求被拒并提示（T10：tutor_quota 配置 + check_quota 前置强制——学科越界 403、次数/时长达限 429；时长按服务端累计答疑耗时计；PUT/GET /tutor/quota、GET /tutor/usage）。
- [x] AC-307：Flutter AI 伴学模块完整落地（T12：娃娃提问/适龄讲解、拦截内容转安全提示、受时长与内容范围管控、家长可查日志、notifier 状态机 Idle/Loading/Success 有 mocktail 单测；故事 18/20/21/22/23/26）。

# 跨期非功能需求

- **性能**：出题 P95 < 5s/题；批改 < 1s。
- **安全**：密码 bcrypt、JWT 无状态、答案隔离、三层内容安全（三期）。
- **合规 🔴**：教材（人教版等）有版权；自用无碍，**凡对外分发/上线前必须取得授权或改用公版/自编内容**（ADR-012）。
- **护眼/可访问性**：低龄字号、暖色护眼、大点击区（见 Flutter 架构 §10）。
- **可演进**：Provider 可插拔、框架可换、可上云（见后端架构 §5.4）。
