# Impeccable Design Guidelines — 娃娃学习 (kids_learn)

本项目为「娃娃日常学习 App」，Flutter + Riverpod，**平板优先**。

> **ADR-0014 确认（修订 ADR-0003）**：采用**双模式**——家长工作台（Parent Mode，密排专业）与娃娃学习台（Child Mode，更大字号+学科色+适度趣味）。两者共用 surface/spacing/radius 令牌，仅在字号阶梯、语气与学科色权重上分化。暖绿主题已删除，保留中性+靛蓝基底 + 受控学科色。

## Design Context

### Users
- **家长（Parent Mode，工作台）**：创建/管理娃娃账号、生成任务、查看进度（正确率、连续打卡）、管控 AI 额度。需要 Linear/Notion 级的专业工作台观感——密排信息、精确排版、键盘快捷、微交互反馈。沿用 15sp 密排基线。
- **孩子（Child Mode，学习台）**：小学低年级（1-3 年级）儿童，回家后完成家长布置的每日任务。低龄、需动力——独立字号阶梯（~17sp 基线）、更圆角、学科色凸显、暖容器、打卡/徽章有轻动效。与 Parent Mode 共享令牌，仅密度与语气不同。

### Brand Personality
- **关键词：精致、专业、克制**（refined / professional / restrained）。
- 情感目标：家长感到「这是一个认真的工具」而非「玩具」；界面靠工艺精度而非花哨色彩建立信任。

### Aesthetic Direction
- **Linear/Notion 风格中性主题**：微暖白 surface（`#FBFAFA` 亮 / `#0F0F0E` 暗）+ 纯白卡片（`#FFFFFF`）+ 1px 极细描边分层（`#DEDDD8`），**无阴影**。单一靛蓝强调色（`#5E6AD2` 亮 / `#7B82EA` 暗）用于 selection/focus/progress/link。CTA 按钮近黑底白字。
- **亮暗双主题**：暗色暖中性深炭（非纯黑），保留靛蓝强调色提亮。
- **密排统一字号**：正文 15sp 基线，双端共用。Inter（西文/数字，变量字体打包于 `assets/fonts/Inter.ttf`）+ HarmonyOS Sans SC（CJK 回退）。每个字号有对应 tracking，行高按用途区分。
- **表面五级层次**：surface（内容区）/ surfaceRaised（卡片）/ surfaceHover（hover 态）/ surfaceSunken（侧栏/凹槽）/ surfaceActive（选中药丸）。禁止手动 withValues(alpha:) 透明度变体。
- **语义色降饱和**：positive（极淡绿 `#EFF5EC`）/ warning（极淡琥珀 `#FAF3E8`）/ error（极淡红 `#FCE8E6`）/ info（极淡靛蓝 `#EEF0FC`）。用于 badge/chip/icon 容器底色，不用于大面积背景。
- **学科色（Subject Accents，ADR-0014 新增）**：在中性+靛蓝基底上叠加受控多色——数学=蓝 `#4C7DE0`、语文=玫瑰 `#D85A6E`、英语=翠绿 `#3FA67E`（均中饱和，预留扩展槽）。每个学科配 `container`+`fg` 降饱和对，仅用于学科标识/进度条/图标容器，不用于大面积背景；Parent Mode 数据可视化中低调使用，Child Mode 凸显。
- **交互 Tier 1+2**：全局 hover 态、press 反馈、转场分级（120ms 交互 / 200ms 状态 / 300ms 页面）、loading→loaded crossfade、tooltip（延迟 500ms）、Cmd+K 命令面板、侧栏首字母快捷键。**无半透明 focus ring**——focus 用 bg 变化表达。
- **反参考（anti-reference）**：
  - 不用暖绿主题（已删除）
  - 不用大字护眼基调（≥20sp 已废弃）
  - 不用重阴影分层（Linear 用描边不用阴影）
  - 不用高饱和荧光色
  - 不用半透明 focus ring
  - 不用俗套 AI 紫蓝渐变

### Design Principles
1. **双模式、共享令牌**：Parent Mode 密排专业、Child Mode 大字趣味，靠令牌分化而非两套独立体系；一致性仍来自令牌。
2. **精致但克制**：靠 tracking/字重/描边/hover 的精确校准建立品质感，而非色彩堆砌。一色（靛蓝）+ 四档降饱和语义色，到此为止。
3. **描边分层，无阴影**：所有层次靠 1px 极细描边 + surface 色阶表达，不用 BoxShadow。
4. **亮暗双主题，中性一致**：亮色微暖白、暗色暖中性深炭，均走令牌，避免纯黑。
5. **一致性来自令牌而非临时值**：所有间距/圆角/字号走 `AppSpacing / AppRadius / AppText`，禁止 `Colors.*` 硬编码。
6. **转场分级**：120ms 交互态 / 200ms 状态切换 / 300ms 页面进入。loading→loaded 用 crossfade。不用统一 200ms 一刀切。
7. **反馈即信任**：hover（surface 变色）、press（bg 深一档）、tooltip（500ms 延迟）、骨架屏加载、空态引导、温柔错误+重试——每个状态都有完整的、符合专业语气的反馈。

### 描边只有一个令牌：outline（硬约束）

曾经存在 `outline` / `outlineVariant` / `surfaceContainerHigh` 三档"三灰分工"，
分隔线另用更淡的一档——结果是同一页面出现两种深浅的线，层次反而糊。
**现已收敛为一条线：`outline`**。

| 令牌 | 职责 | 取值（亮 / 暗） | 误用示例 |
|---|---|---|---|
| `outline` | **唯一的线**：卡片 / 输入 / 按钮 / 徽章的 1px 描边，**分隔线也用它** | `#DEDDD8` / `#2F2F2C` | 不得用于 surface 填充 |
| `outlineHover` | **hover 描边**：仅用于可点击 `AppCard` hover 时边框微深 | `#D1D1CE` / `#3D3D3A` | 不做静态分隔 |
| `surfaceSunken`（= `surfaceContainerHigh`） | **面**：凹槽 / 侧栏 / 弱化底色 | `#F4F4F2` / `#1A1A19` | 禁止当线用（它是面不是线） |

- 线与面二分：**线只有 `outline` 一档**，面走 `surface*` 家族；禁止再造"更淡的线"。
- `outlineHover` 仅用于**可点击 `AppCard` 的 hover 边框**（shadcn 原生 button/input 无 hover-border API，故在 `AppCard` 内以 `ValueListenableBuilder` 接）。
- 改前：原 `outline #ECECEA`（~1.18:1）在白卡上近乎不可见，导致"描边分层"失效；现已提到可见但仍克制的发丝值。

## 控件高度（统一，硬约束）

输入框、按钮、下拉选择器同为「交互控件」，必须共用同一高度，禁止各自写死不同像素值（否则会出现同行控件高低不齐，如布置任务表单中 36px 按钮与 ~40px 输入框并排错落）。

- **令牌配置形式（避免硬编码）**：控件高度**不写死**，由 `AppControl` 这一单一事实源按「用户模式 × 密度」推导，**全部取自间距令牌 `AppSpacing`，无魔法数字**。
  - `AppControl.height(AppUserMode, AppDensity)` / `AppControl.heightSm(...)`：纯函数，返回间距令牌。
  - `AppControl.heightOf(BuildContext)` / `heightSmOf(BuildContext)`：从上下文解析（需 `UserModeScope` / `DensityScope` 挂载，未挂载回退 parent/normal）。
  - 密度维度 `AppDensity { normal, compact }` 与亮暗、用户模式正交；`DensityScope` 为 InheritedWidget，包裹子树即可局部切紧凑（未接入时默认 normal）。
- **推荐高度矩阵（依据间距 4 基准模数 + 触控目标）**：
  | 用户模式＼密度 | normal | compact |
  |---|---|---|
  | parent（密排专业） | **xl4 = 40** | xl3 = 32 |
  | child（大字趣味）  | **xl5 = 48** | xl4 = 40 |
  - parent/normal=40：贴近 Apple HIG 44 下限、落在 Material 48 内，兼顾专业密排；child 字号放大一档故控件放大到 48 匹配更大点击区；compact 各降一档用于密集列表 / 表格。
- **输入框**：`AppTextField` 的 `ShadInput` 用 `BoxConstraints(minHeight: AppControl.heightOf(context))` 钉死下限，垂直内边距收到 7，确保渲染高度恒等于当前模式/密度下的按钮高度；`AppPickerField` 选择器内容驱动，保持与输入同行齐平。
- **按钮**：`AppPrimaryButton` 默认 `height` 为 null，build 内回退 `AppControl.heightOf(context)`；所有行内 `ShadButton.outline` 一律 `height: AppControl.heightOf(context)`，不得再写 `36` / `44` 等魔法值。
- **圆角**：控件圆角统一 `AppRadius.input` / `AppRadius.button` = 6（见圆角令牌节）。
- 新增任何交互控件，高度必须引用 `AppControl.heightOf(context)`（或 `height(mode, density)`），不允许裸写数字。

## Motion · Celebrate（适度趣味动效，ADR-0014）

保留 interaction 120 / state 200 / page 300。新增：

- `celebrate` **450ms easeOutBack**：徽章解锁、连击 +1、打卡成功反馈。**仅 Child Mode 启用**；Parent Mode 不触发。

## Shadcn 映射契约（AppColors → ShadThemeData）

App 主题由 `app_theme.dart` 的 `AppTheme.shadThemeData()` 一次性生成 shadcn `ShadThemeData`。
**设计系统令牌是唯一事实源，shadcn 只是消费方**——映射写死在这一处，页面不得再自行覆盖配色。

### 1. 色值映射（ShadColorScheme）

| shadcn 字段 | 取值 | 说明 |
|---|---|---|
| background / foreground | `surface` / `onSurface` | 内容区 |
| card / popover | `surfaceRaised` | 卡片与浮层同面（纯白 / 深炭） |
| primary / primaryForeground | `cta` / `onCta` | 实心 CTA（近黑底白字，暗色反色） |
| secondary / secondaryForeground | `surfaceSunken` / `onSurface` | 中性灰次按钮（**去琥珀**，见 ADR-0003 收敛 B） |
| muted / mutedForeground | `surfaceContainer` / `onSurfaceVariant` | 弱化块与次文字 |
| **accent / accentForeground** | `surfaceSunken` / `onSurface` | ⚠️ **陷阱**：shadcn 的 `accent` 是「hover 高亮」语义，**不是设计系统的靛蓝 accent** |
| destructive / destructiveForeground | `error` / `onError` | 危险操作 |
| border / input | `outline` | 1px 描边统一 |
| ring / selection | `accent`（靛蓝） | focus / 文本选择 / 进度 |
| `custom[...]` | 见下 | 设计系统扩展令牌 |

### 2. `custom` 扩展键命名

新代码**只用语义名**，旧角色名仅作兼容保留（CONTEXT.md 已把
`primaryContainer` / `secondaryContainer` / `tertiaryContainer` 列为 Avoid 词）：

- 语义色（四档，**AI 归 info**）：`semanticPositive(Fg)` / `semanticWarning(Fg)` / `semanticError(Fg)` / `semanticInfo(Fg)`
- 强调与 CTA：`accent` / `onAccent` / `cta` / `onCta` / `ctaHover`
- Surface：`surfaceRaised` / `surfaceSunken` / `surfaceActive` / `surfaceHover` / `outlineHover`
- 浮层：`toast` / `onToast` / `scrim`
- 学科色：`subjectMath(Container|Fg)` / `subjectChinese…` / `subjectEnglish…` / `subjectReserved…`

读取方式：`ShadTheme.of(context).colorScheme.custom['semanticWarning']`；
业务代码更推荐直接用 `AppTheme.colorsOf(context).semanticWarning`（类型安全，不拼字符串）。

### 3. 组件主题覆盖清单

不接管这些主题时，shadcn 会退回内置 slate 配色 + 阴影，同一页面出现两套管语言。
`shadThemeData()` 已统一接管，**新增 shadcn 组件前先看这里**：

| 主题 | 处理 |
|---|---|
| card / popover / dialog / alert | `surfaceRaised` + 1px `outline` + `AppRadius.card` + **无阴影** |
| input / textarea / select | `surfaceRaised` 底 + `outline` 边框，focus 换 1px `accent`（`disableSecondaryBorder: true`，无半透明 ring）；高度钉死 `AppControl.height`，与按钮同高 |
| option（下拉项） | hover `surfaceHover` / selected `surfaceActive` / 勾色 `accent` |
| toast | `toast` / `onToast`，圆角 `AppRadius.bubble`，无阴影 |
| badge | 语义容器底 + 语义前景（primary=info、secondary=中性、destructive=error） |
| switch / checkbox / radio | 选中态统一靛蓝 `accent`（近黑 primary 只留给 CTA） |
| progress | 轨道 `surfaceActive` + 填充 `accent` |
| separator | `outline`（与卡片边框同档；不再有更淡的一档） |
| tooltip | 延迟 **500ms**，反色底无阴影 |
| button hover / press | hover `surfaceHover`（CTA 走 `ctaHover`）→ press `surfaceActive`，**hover 不得等于常态** |
| button / input / select 高度 | 统一 `AppControl.height(mode, density)`（`buttonSizesTheme` + `inputTheme.constraints`），禁止各写各的 36/40/44 |

### 4. 令牌落地四件套（硬约束）

新增 / 改令牌必须同步四处，缺一即视为违规：

1. `AppColors`（字段 + 语义别名 getter）
2. `_customColors()`（shadcn `custom` 映射）
3. 本文档的令牌表（若属公开令牌）
4. `lib/dev/theme_preview.dart` 预览样例

## 规范一致性（落地前必须）

- 禁止 `withValues(alpha:)` 透明度变体（改用令牌的 `container`/`surfaceSunken` 等实体色）。
- 所有卡片走 `AppCard`（含 1px 描边）；散落 `Container` 直接着色视为违反。
- 出现硬编码 `Colors.*` / 魔法十六进制（如 `Color(0xFF2F2A24)`）即视为违反；一律走令牌（`scrim` / `toast` 等已补齐，不要再写死）。
- 动效时长与曲线走 `AppMotion` / `AppCurves`；禁止裸写 `Duration(milliseconds: …)` 与 `Curves.*`。
- 语义色一律用 `semanticPositive/Warning/Error/Info(+Fg)`（**AI 标记归 info**，不再新增与 warning 重复的琥珀档）；禁止用 `primaryContainer`/`secondaryContainer`/`tertiaryContainer` 表达语义（角色名会错读，历史上 warning 曾误用 error 容器）。
- **排版单事实源（设计系统约束 D）**：字号阶梯只有一份——`app_theme.dart` 的 `AppText._typeScale`（同时驱动 `AppText` 与 shadcn `ShadTextTheme`）。新增/调整字号必须改这一处，禁止在 `_shadTextTheme` 或页面里另写尺寸表，避免双排版漂移。
- **禁止裸 `Text()`（设计系统约束 D）**：所有文案必须走 `AppTheme.textOf(context)`（基于 `AppText` 令牌）或 shadcn 文本主题；裸 `Text(..., style: TextStyle(fontSize: ...))` 直接写字号视为违反——会破坏双模式缩放与字号一致性。确需裸写时须显式引用令牌并加 `// ignore`。analyzer 级强制需 `custom_lint`（一条 LintRule），目前为文档硬约束。

## 令牌预览入口（Design Token Preview）

改动主题层（颜色 / 排版 / 交互态 / hover）后，用独立预览入口做运行时自检，不要靠翻业务页面：

```sh
flutter run -d macos  -t lib/dev/theme_preview.dart   # 桌面，有真实鼠标 hover（推荐）
flutter run -d chrome -t lib/dev/theme_preview.dart   # web
```

`lib/dev/theme_preview.dart` 是 **dev-only** 入口（不被 `main.dart` 引用，不进生产包），
以「改前 vs 改后」并列呈现四项收敛：

| 区 | 验证内容 | 怎么看 |
|---|---|---|
| A | 品牌主色统一为靛蓝 accent（primary = accent，CTA / 状态色 / 图标 / 选中态全站同色） | 左列显式传旧近黑 #1D1B17 模拟改前，右列走主题 |
| B | `secondary` 去琥珀 → 中性灰 + 1px 描边 + hover | 两个 secondary 按钮并排，hover 对比 |
| C | 标签 hover 克制版（同色微深，前景不变） | 上排 `_LegacyPill` 复刻改前填实饱和色，下排 `AppTags`/`AppBadge` |
| D | 排版单一事实源 | 逐行对照 `ShadTextTheme` 与 `AppText` 的 size/weight/height，一致打 ✓ |

顶部两个按钮可切 **亮/暗** 与 **Parent/Child**，用于验证双模式与亮暗 parity。
新增令牌或组件时，应同步在该预览页补一组样例。
