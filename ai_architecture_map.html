① 一句话结论 已收敛处

「对话式 AI」已经收敛到唯一一处：所有聊天形态的 AI（问答/答疑/出题对话/课堂提示/判断题闭环/讲课现场）都走同一个 POST /api/v1/assistant/chat 端点、同一个 AssistantChatPage 页面、同一个 AssistantNotifier + AiTextFold、同一套 DATA 卡片渲染协议。

你感知到的「不统一」，根因不在对话通道，而在两点：(a) 多套「结构化 AI 端点」在做同一件事（出题有 4 条传输通道、课件起草有 2 条）；(b) 师生入口形态与可见能力的不对称（这是刻意的安全/产品决策，不是缺陷）。真正该收口的，是「出题引擎」「卡片渲染」「助手打开入口」三处实现，而非再叠一层统一层。

③ 你提到的三个「不统一」根因拆解

感知的不统一代码真相是否缺陷
学生 vs 教师交互方式不同 已统一：双端都是右下角浮球 FAB（FloatingAssistant，ADR-0036/0047），仅标题与空态口径不同（教师「AI 学习助手」/ 学生「问 AI 老师」），都 push 进同一个 AssistantChatPage。角色在后端 JWT 解析（visible_businesses(role)）——ADR-0097 后五个 business 全部双端可见，答案隔离下沉到工具层（题库查询 / create_draft 对学生恒拒绝）。 已统一
AI 问答 走 /assistant/chat 的五个 subagent：tutor(答疑) + tasks(学情/任务) + students(名单) + capability(能力自述) + question(题库/出题)。ADR-0097 起 query/guide 已删，学情查询与写意图（只起草）都迁入 tasks。 已统一
AI 出题 现存 3 条传输通道：① /assistant/chat 的 question subagent（对话出题，经 generate_questions 流式 tool，STEP/DATA 帧逐帧外发）② req.quiz 判断题闭环 ③ POST /tasks/generate（教师任务表单，显式路由 business="question"）。共用同一 generate_question 管线；原 /tasks/…/regenerate（换一题）通道已不在。 传输分散
「讲课」 讲课现场没有独立 LLM 调用：课件演示页 FAB 把 coursewareContext 注入 → 仍走 /assistant/chat 的 tutor subagent。课件本身的 AI 起草/重起草端点已删（ADR-0087 收尾），/courseware 现为纯 CRUD（7 条 REST，无 provider 依赖）。 讲解统一

关键事实（刻意设计，非遗漏）：tutor 功能另有 GET /tutor/logs 日志查看器，不调 LLM；师生都能续接自己的历史会话（ADR-0096：归属=本人可见，教师看不到学生的）；写操作（发布任务）必须经人确认——AI 只起草（票 07 的确认卡 REST 端点待建）。

④ 已经收敛到一处 ✓

  • 对话通道唯一：所有聊天形态 AI 都过 /assistant/chat。
  • 前端单页面 + 单入口：一个 AssistantChatPage + assistantNotifierProvider + AiTextFold 折叠器；师生双端共用同一个 FloatingAssistant 浮球（ADR-0036/0047），讲课现场是页内 FAB 变体。
  • 卡片协议统一：所有 AI 产物都是 DATA{type} 帧，由 assistant_cards.dart 单分派器渲染（未知 kind 走降级卡不丢内容）。
  • 引擎统一：出题都调 generate_question 管线（对话内经流式 tool 封装，帧不丢）；答疑都调 TutorService。
  • 能力自述单一事实源：capability 清单从 runtime.manifests 现生成，增删 agent 零维护（ADR-0097）。

⑤ 待收口 / 已知缺口 →

  • 出题三通道仍分散：对话出题 / quiz 闭环 / tasks/generate 共用 generate_question 管线但触发面三处——保留独立传输、共享引擎即可，不强行合一。
  • 草稿确认卡（票 07）：task_draft_card 前端渲染 + POST /tasks/{id}/confirm + /assign 两个 REST 端点尚未实现——当前 AI 能起草但发布链路断，属 epic 剩余项。
  • 前端 guide 卡死代码：后端已无 type:"guide" 发射点，但 AssistantCardKind.guide / AssistantGuideCard / ShellDestination 映射仍在，随票 07 一并清理。
  • 不必强行合一：结构化出题（任务表单）是批量产出，与流式对话语义不同；师生角色差异是产品决策。

⑥ 收敛后的理想心智模型

把 AI 看成 「一个对话入口 + 一个共享引擎 + N 个产品触发面」：

对话入口：/assistant/chat 页面：AssistantChatPage（双端同一浮球进入） 折叠：AssistantNotifier + AiTextFold 路由：rt.decide 规则→兜底（5 个 business） 引擎：generate_question / TutorService / rag 卡片：DATA{type} → AssistantCards

触发面（学生浮球 / 教师浮球 / 讲课 FAB / 空态推荐 / 判断题闭环 / 任务表单出题）都只是「往上述单核里喂不同的 context 与意图」，不应各自再带一套 AI 逻辑。写操作是唯一例外：AI 只起草，发布必经人确认（票 07 补确认卡与 REST 端点）。
