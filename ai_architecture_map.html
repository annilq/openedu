① 一句话结论 已收敛处

「对话式 AI」已经收敛到唯一一处：所有聊天形态的 AI（问答/答疑/出题对话/课堂提示/判断题闭环/讲课现场）都走同一个 POST /api/v1/assistant/chat 端点、同一个 AssistantChatPage 页面、同一个 AssistantNotifier + AiTextFold、同一套 DATA 卡片渲染协议。

你感知到的「不统一」，根因不在对话通道，而在两点：(a) 多套「结构化 AI 端点」在做同一件事（出题有 4 条传输通道、课件起草有 2 条）；(b) 师生入口形态与可见能力的不对称（这是刻意的安全/产品决策，不是缺陷）。真正该收口的，是「出题引擎」「卡片渲染」「助手打开入口」三处实现，而非再叠一层统一层。

③ 你提到的三个「不统一」根因拆解

感知的不统一代码真相是否缺陷
学生 vs 教师交互方式不同 入口形态不同：学生=首页 tab3「问AI老师」；教师=可拖动 FAB；讲课现场=页内 FAB。但三者都打开同一个 AssistantChatPage，底层端点、Notifier、渲染完全一致。角色在后端 JWT 解析（visible_businesses(role)）。 不是
AI 问答 走 /assistant/chat 的 tutor(答疑) + query(学情) 两个 subagent。学生只能命中 tutor/query；教师还能命中 guide/question。 已统一
AI 出题 实际有 4 条传输通道做同一件事：① /assistant/chat 的 question subagent（对话出题）② req.quiz 判断题闭环 ③ POST /tasks/generate（教师任务表单）④ /tasks/…/regenerate-stream（换一题）。它们都调用同一个 generate_question 管线，但触发面分散。 传输分散
「讲课」 讲课现场没有独立 LLM 调用：课件演示页 FAB 把 coursewareContext 注入 → 仍走 /assistant/chat 的 tutor subagent。课件话术本身的生成另走 POST /courseware(draft) + /redraft 两条独立端点（内容创作，非对话）。 讲解统一/起草独立

关键不对称（刻意）：学生端无「历史会话」入口；tutor 功能只是 GET /tutor/logs 日志查看器，不调 LLM。这些是按 ADR-0048 / ADR-008 的有意设计，不是遗漏。

④ 已经收敛到一处 ✓

  • 对话通道唯一：所有聊天形态 AI 都过 /assistant/chat。
  • 前端单页面：一个 AssistantChatPage + assistantNotifierProvider + AiTextFold 折叠器，师生/讲课/练习共用。
  • 卡片协议统一：所有 AI 产物都是 DATA{type} 帧，由 assistant_cards.dart 单分派器渲染（未知 kind 走降级卡不丢内容）。
  • 引擎统一：出题都调 generate_question 管线；答疑都调 TutorService。

⑤ 建议收口到一处 →

  • 出题引擎单实现：把 ①对话出题 ②quiz闭环 ③tasks/generate ④regenerate 明确收敛为「generate_question 管线的 4 个触发面」，router 层只做装配，逻辑不重复。
  • 打开助手单入口：在壳层定义唯一 openAssistant(context)，消除学生 tab / 教师 FAB / 讲课 FAB 三处重复拼装 AssistantChatPage + coursewareContext。
  • 课件起草归属清晰：/courseware draft/redraft 属「内容创作」而非「助手对话」，保留独立但应在文档/类型上明确标注，避免被误认为是第 5 个对话通道。
  • 不必强行合一：师生入口形态差异是产品决策；结构化出题（任务表单/换题）是批量产出，与流式对话语义不同——保留独立传输但共享引擎即可。

⑥ 收敛后的理想心智模型

把 AI 看成 「一个对话入口 + 一个共享引擎 + N 个产品触发面」：

对话入口：/assistant/chat 页面：AssistantChatPage 折叠：AssistantNotifier + AiTextFold 引擎：generate_question / TutorService / rag 卡片：DATA{type} → AssistantCards

触发面（学生 tab / 教师 FAB / 讲课 FAB / 课堂练习 / 推荐操作 / 判断题闭环 / 任务表单出题 / 换一题 / 课件起草）都只是「往上述单核里喂不同的 context 与意图」，不应各自再带一套 AI 逻辑。
