# WF-2 · 数据建模与无 Alembic 迁移方案

> 类型：research（AFK）｜状态：✅ 已收口（见底部 Resolution）｜阻塞：无

## Question

在 `User` 表新增 `interests` 字段（JSON，存受控分类 id 列表 + 自由文本），需要改哪些 schema（`UserBase` / `UserCreate` / `UserPublic` / `User`）？当前 `init_db` 用 `create_all` 在**缺 Alembic** 下如何安全加列并回填旧 child 数据（默认 `[]`）？给出精确 SQLModel 改动 + 加列/回填伪代码，并说明对 `parent_id` 自关联与其他表的影响。

## Resolution（/research 子代理收口，2026-08-28）

见下方「实施规格」。

### 1. Schema 改动（`app/models.py`）

`interests` 作为可选 JSON 列加到 `UserBase`（使 `UserCreate`/`UserPublic`/`User` 自然继承，符合「模型即 schema」约定）：

```python
class UserBase(SQLModel):
    username: str = Field(unique=True, index=True, max_length=64)
    display_name: str = Field(max_length=64)
    role: str = Field(max_length=16, default="child")
    grade: int | None = Field(default=None)
    is_active: bool = True
    # 兴趣画像：受控分类（叶子 key 列表）+ 自由文本，存为 JSON 对象
    # 形状：{"categories": ["动物","恐龙"], "free_text": "养蚕" | None}
    # （2026-08-28 经 WF-1/WF-5 修正：原草案 list[str] 改为 dict，以区分受控项与自由项）
    interests: dict | None = Field(default=None, sa_type=JSON)
```

- `UserCreate` / `UserPublic` / `User` 自动继承，**无需各自再写**。
- 取值约定：`{"categories": ["动物", "恐龙"], "free_text": "养蚕"}`。
  - `categories`：受控词表**叶子 key**列表（选了二级就存二级如"恐龙"，只选一级就存一级如"动物"）；空列表或全空=`[]`。
  - `free_text`：「其他爱好」自由文本（≤50 字）或 `None`。
  - 整段未设 = `None`（见回填）。

### 2. 缺 Alembic 的加列与回填（`app/core/db.py`）

现状：`init_db()` 调 `SQLModel.metadata.create_all(engine)`，只建表、不加列、不迁移旧数据。两条路：

- **路线 A（推荐，零风险）**：首次部署用全新库 → `create_all` 直接带新列，无旧数据，无需回填。
- **路线 B（已有库需保留）**：`create_all` 不会给旧表加列。需手动执行一次 DDL + 回填：

```sql
-- 加列（PostgreSQL）
ALTER TABLE "user" ADD COLUMN IF NOT EXISTS interests JSON;
-- 回填旧 child：NULL → '[]'
UPDATE "user" SET interests = '[]'::json WHERE interests IS NULL;
```

> 本地回退 SQLite 同样适用 `ALTER TABLE user ADD COLUMN interests TEXT;`（存 JSON 字符串）。

实现建议：在 `init_db()` 末尾加一段**幂等**补齐（检测列不存在则 ALTER + UPDATE），或在 `db.py` 暴露 `ensure_interests_column()` 由启动脚本调用，避免依赖 Alembic。`app/crud.py` 的 `create_user` 无需改（SQLModel 自动处理可选字段）。

### 3. 影响面

- `parent_id` 自关联、其他表（`Task`/`Question`/`AnswerRecord`/`WrongQuestion`/`Tutor*`）**完全不受影响**。
- `UserPublic` 现在会返回 `interests`——家长端可见自己娃娃的兴趣（符合预期）；娃娃端不返回 `UserPublic`，无泄露。
- 前端 `UserCreate` → `POST /children` 需新增 `interests` 字段透传（见 WF-5）；取值为 `{"categories": [...], "free_text": "..."|null}`。
- **编辑娃娃资料**需要后端新增 `PUT /children/{id}`（当前仅 POST/GET，无更新端点）——属 WF-5 落地依赖，见 WF-5 票。
