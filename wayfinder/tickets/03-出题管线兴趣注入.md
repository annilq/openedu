## Question

`LLMProvider.generate_question` 与 `QuestionGenerator.generate` 增加 `interests` 形参后，需同步改哪些调用点（`tasks.py` batch-generate、`mock_provider.py`、`langchain_provider.py` prompt 模板）？给出每个文件的精确改动点 + 「轻融入」与「兴趣题模式」两种 prompt 措辞草案（须紧扣 `knowledge_point`、不偏离教材、不绕过安全）。

## Resolution（2026-08-28）

### 1. 抽象层：`app/domain/provider.py`

`LLMProvider.generate_question` 抽象方法加两个带默认值的形参（保证老调用方/测试不破）：

```python
async def generate_question(
    self, *, subject, grade, knowledge_point, qtype, difficulty,
    interests: list[str] | None = None,      # 轻融入：娃娃兴趣池
    focus_interest: str | None = None,        # 兴趣题模式：指定聚焦的兴趣主题
) -> GeneratedQuestion: ...
```

`GeneratedQuestion` 数据类**无需改动**（兴趣只影响生成过程，不进题库字段）。

### 2. 薄封装：`app/domain/question_generator.py`

`QuestionGenerator.generate` 透传：

```python
def generate(self, *, subject, grade, knowledge_point, qtype, difficulty,
             interests=None, focus_interest=None) -> GeneratedQuestion:
    return asyncio.run(self.provider.generate_question(
        subject=subject, grade=grade, knowledge_point=knowledge_point,
        qtype=qtype, difficulty=difficulty,
        interests=interests, focus_interest=focus_interest,
    ))
```

### 3. 实现层 A：`app/domain/langchain_provider.py`

`generate_question` 接收新形参，按模式拼 prompt（** `_SYSTEM` 年龄锁保持不变**）：

- **轻融入（focus_interest 为 None 且 interests 非空）**：
  ```
  请为{grade}年级《{subject}》的“{knowledge_point}”出一道{qtype}题，难度{difficulty}。
  可结合该娃娃的兴趣（如：{兴趣列表}）作为题目情境包装，但内容必须紧扣“{knowledge_point}”，
  不得偏离教材知识点，不得引入与学习无关或不当内容。
  返回 JSON：{"stem": str, "options": list[str]|null, "answer": str, "explanation": str}
  ```
- **兴趣题模式（focus_interest 指定）**：
  ```
  请围绕该娃娃感兴趣的主题“{focus_interest}”，为{grade}年级《{subject}》的“{knowledge_point}”
  出一道{qtype}题，难度{difficulty}。题目情境应以“{focus_interest}”为载体讲清“{knowledge_point}”，
  必须紧扣知识点，不偏离教材，不引入不当内容。
  返回 JSON：{...同上...}
  ```

### 4. 实现层 B：`app/domain/mock_provider.py`

`generate_question` 接收新形参并在 stem 中可见地体现（保证零 key 闭环测试能观察到兴趣生效）：

```python
async def generate_question(self, *, subject, grade, knowledge_point, qtype, difficulty,
                            interests=None, focus_interest=None) -> GeneratedQuestion:
    # 现有 seed 逻辑不变；在构造 stem 时追加兴趣标记：
    flavor = f"（兴趣：{focus_interest}）" if focus_interest else (
        f"（兴趣池：{','.join(interests)}）" if interests else "")
    stem = f"【{subject}】{knowledge_point} 的正确答案是什么？(难度 {difficulty}){flavor}"
    # ... 其余 choice/calc/fill/open 分支同原逻辑，仅 stem 追加 flavor
```

### 5. 调用方：`app/api/routes/tasks.py`（关键改动点）

兴趣是**按娃娃（child）**的，不是按 spec 的。因此从 `child_id` 取 `User.interests` 后，在生成循环统一下传：

- **`_generate_task_questions_for_specs`**（line 124）：加形参 `interests: list[str] | None = None`，循环内 `gen.generate(..., interests=interests)`（line 149）。
- **`batch_generate`**（line 177）：拿到 `child_id` 后查 `child = session.get(User, child_id)`，`interests = child.interests if child else None`，传给 `_generate_task_questions_for_specs(payload.specs, interests=interests)`。
  - 注意：`child_id` 可能为 `None`（先成卷晚点派）→ 此时 `interests=None`，不融入（符合预期，因无目标娃娃）。
- **`regenerate_all`**（line 428）：从 `task.child_id` 取兴趣，传 `_generate_task_questions_for_specs(specs, interests=...)`.
- **`regenerate_one`**（line 397）：需先 `task.child_id → child.interests`，传给 `gen.generate(..., interests=child.interests)`.
- **`create_single_subject_task`**（line 212，兼容端点）：内部转调 batch，自动继承。

> 双模式开关（轻融入 vs 兴趣题模式）由**请求体**决定：`TaskSpec` 或 `TaskBatchCreate` 增加可选 `focus_interest: str | None`（兴趣题模式时由前端传具体主题；留空=轻融入）。`focus_interest` 透传到 `_generate_task_questions_for_specs` → `gen.generate(..., focus_interest=...)`.

### 6. 影响面与边界

- 老端点/测试（不带兴趣）因默认值 `None` **零改动可用**，闭环不破。
- `from-bank`（题库复用闭环，line 229）**不注入**兴趣——题库题是预生成内容，属本票范围外（见地图 Not yet specified）。
- 兴趣绝不进入 `knowledge_point` / 答案 / 解析的正确性：mock 仅改 stem 文案，langchain 约束"必须紧扣知识点"。
- 实施前用 `grep` 确认 `crud.py`、测试文件中无其它 `gen.generate(` / `generate_question(` 直接调用遗漏。
