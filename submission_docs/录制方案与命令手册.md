# 演示视频录制方案与命令手册

> 配套文档：
> - `录制进度说明.md` —— **14 段分镜**（目标时长 / 逐段操作 / 红线 / 坑），录制时对着它点。
> - `narration.md` —— 14 段旁白文案（字幕与配音的单一事实源）。
> - `安装手册.docx` —— 后端 + 前端 + 模型配置步骤。
> - `视频脚本.docx` —— **提交用分镜表**（14 段：时段 / 端 / 画面 / 旁白 / 红线），由 `gen.py` 从 `narration.md` 生成，改文案后重跑即刷新。
> - 本文件只补「怎么录、怎么出字幕 / 配音、怎么合成」的工程细节，并给出 AI 控屏备选方案。

## 0. 方案决策（结论先行）

| 项 | 决定 |
|---|---|
| 主体素材 | **真实 App 录屏**（macOS 桌面端运行 openedu） |
| 字幕 | **程序硬烧入字幕** —— 录完一键出 SRT 并烧入，改稿零成本、自包含、任意播放器可见 |
| 配音 | **已采用**：AI TTS 中文语音（`voice/seg01..14.mp3`，`gen_voice.py` 生成），与字幕同源同轴 |
| 自动化 | **手动录屏为主**；AI computer-use 控屏录屏作为**技术验证备选**，失败即回退 |
| 不采用 | 纯人工配音（易返工）、把 AI 全自动作为交付主路径（风险高） |

> **交付口径**：任务只要求「演示视频 ≤8 分钟」，本片自我加严到 **≤6 分钟**；当前成片 **4:21**（音轨 + 硬烧字幕都有）。配音与字幕同取 `narration.md` 一处文案，时间轴取**实测**时长（配音 mp3、录屏 mov 各量一次），音画逐段等长。

核心思路：**录制时只采视频、不录声音**，字幕后期由 `gen_subs.py` 自动按片段时长切片烧入。单段可独立重录、改稿零成本。

## 2. 视频采集（三种任选其一）

> 建议**按 14 段分段录制**，文件名 `demo_01.mov` … `demo_14.mov`，放入 `submission_docs/raw/`，便于单段重录与剪接。每段的目标时长见 `录制进度说明.md` §1 速查表。

### 2.1 系统自带区域录屏（零安装，最快）
```bash
screencapture -v -R 100,100,1280,800 submission_docs/raw/demo_01.mov
# Ctrl-C 或菜单停止录制
```
> 前提是把窗口摆到固定位置、坐标自己量准；想「自动定位 openedu 窗口」直接用 §2.4 的脚本。
> ⚠️ 不要写成 `-v -i`：视频模式不接受 `-i`，会报 `video not valid with -i`。

### 2.2 ffmpeg 全屏采集（需先装 ffmpeg：`brew install ffmpeg`）
```bash
ffmpeg -f avfoundation -list_devices true -i ""   # 确认屏幕索引（如 "1"）
ffmpeg -f avfoundation -i "1" -r 30 -pix_fmt yuv420p -capture_cursor 1 submission_docs/raw/demo_01.mp4
# 若报错要求显式音频索引，改为 -i "1:none"
```

### 2.3 OBS Studio（推荐：质量最高、可「窗口捕获」只录 App）
- 来源 → 窗口捕获 → 选 openedu；设置 1920×1080、30fps → 开始录制。
- 优点：直接框定 App 窗口，避免录到桌面杂乱；后期也能加麦克风旁白轨。

### 2.4 用 `screencapture` 精确锁定 openedu 窗口（零安装、系统自带）

> ⚠️ **两个已实测踩到的坑**（macOS 26 / 2026-10）：
> 1. `screencapture -v -i` 直接报 `video not valid with -i` —— 视频模式不再接受 `-i`，交互框选改用 `-J video`。
> 2. `lsappinfo … -only WindowBounds` 恒返回 `[ NULL ]` —— 该键已废弃，取窗口坐标这条路走不通。
>
> 现方案：用 CoreGraphics 窗口列表拿到 `windowid`，再 `-v -l <id>` **按窗口录**（窗口被遮挡/移动都跟随，且不录桌面与阴影）。

**① 交互式框选（最快，无需脚本）**
```bash
screencapture -v -J video submission_docs/raw/demo_01.mov
# 拖拽框选 openedu 窗口区域；Ctrl-C 停止
```

**② 按窗口精确录制（脚本，适合 14 段分镜重复录）** —— `submission_docs/record_app.sh`：
```bash
chmod +x submission_docs/record_app.sh
./submission_docs/record_app.sh 1                  # 录第 1 段 → submission_docs/raw/demo_01.mov（Ctrl-C 停止）
DURATION=90 ./submission_docs/record_app.sh 2      # 录 90 秒后自动停（每段按分镜时长设）
REGION=100,200,1280,800 ./submission_docs/record_app.sh 3   # 手动指定区域，跳过探测
APPNAME=kids_learn ./submission_docs/record_app.sh 4        # 显式指定进程名
```
脚本做的事：自动识别「bundle 落在本仓库内」的 App 进程名 → `swift` 调 CoreGraphics 取窗口 `windowid` → `screencapture -v -l <id> -o -x -k -C` 按窗口录。

降级顺序：`REGION` 手动区域 → `windowid` 按窗口录 → System Events 取坐标 + `-R` 区域录 → 交互框选。

- ⚠️ **进程名不是 `Runner`**（旧文档写错了）：`flutter run -d macos` 的产物名随项目而变，当前工程是 **`kids_learn`**。脚本自动探测，无需手填；要覆盖再传 `APPNAME=`。
- ⚠️ **输出路径固定** `submission_docs/raw/demo_0N.mov`（补零两位，与 `gen_subs.py` 的 `demo_01.mov` 查找对齐；与运行目录无关）。
- ⚠️ **首次授权**：系统设置 → 隐私与安全性 → 屏幕录制，勾选你跑脚本的终端；否则录出黑屏。
- 默认显示鼠标点击（`-k`）+ 录光标（`-C`）；`CLICK=0` / `CURSOR=0` 可关掉。
- 输出是 `.mov`，后续由 `gen_subs.py --all` 用 ffmpeg 变速贴合、转 `.mp4`、烧字幕并合入配音。

## 3. 字幕 + 配音 + 成片（一条命令）

`gen_subs.py` 是「分段成片」脚本：读 `narration.md` 的 14 段旁白，量每段**实际**录屏与配音时长，
把三者对齐后烧字幕、铺配音、拼接。旁白/配音/字幕三者同源，不会漂移。

```bash
cd submission_docs

# 3.1 全流程：出字幕 + 变速贴合 + 烧入 + 合并 → final_demo.mp4
python gen_subs.py --all

# 3.2 只出字幕（预览用，不渲染视频，秒出）
python gen_subs.py

# 3.3 先渲一段试看，满意再全量
python gen_subs.py --burn --only 1
```

> ⚠️ 试看只用 `--burn --only N`，**不要**配 `--all`：`--all` 会连带合并，而合并只认本次渲染过的段，会把 `final_demo.mp4` 覆盖成单段。全量出片一律用 `--all`（不叠加 `--only`）。

### 3.1 为什么需要「贴合」

录制时手速与 AI 等待时长每次都不一样，实测 14 段录屏合计 **7:56**，而旁白只有 **4:16** ——
差距最大的第 6 段（课件与 AI 备课）录了 **134 秒**，旁白仅 28 秒，需 **4.76 倍**才贴得上。
所以时间轴一律取**实测值**，不再用标题里的估算时间：

| 情况 | 处理 |
|---|---|
| 视频比配音长 | **加速画面**去追配音，上限 `--max-speed`（默认 5.0 倍） |
| 视频比配音短 | **减速画面**，下限 `--min-speed`（默认 0.85 倍）；仍不够则**定格最后一帧**补足，保证旁白不被截断 |
| 夹完仍追不上 | 尾部留静音（画面继续，配音已结束）——默认 5.0 倍下本片已无静音段（14/14 段贴合） |

**配音本身从不变速**，全片语速一致；字幕时间轴 = 配音实际时长，按句字数占比切片。
所以「配音比目标时长短」这个问题从此不存在：目标就是配音本身。

**本片实际处理**（成片 4:21，零静音）：

| 处理 | 段 |
|---|---|
| 加速 >3 倍 | 6（4.76x）、1（3.96x） |
| 加速 1.1～2.6 倍 | 12（2.58x）、10（2.13x）、8（1.76x）、3（1.43x）、2（1.16x）、14（1.11x） |
| 原速（±1%） | 7、9 |
| 减速 + 定格补足 | 4（0.91x）、5/11/13（0.85x，定格 4.4/0.6/5.3s） |

```bash
python gen_subs.py --all --max-speed 6.0      # 允许更激进的加速
python gen_subs.py --all --min-speed 1.0      # 只加速、不减速
python gen_subs.py --all --no-fit             # 画面完全不动（原速 + 尾部静音）
```

### 3.2 字幕样式与产物

- 样式：白字 + 黑描边 + 苹方（PingFang SC，macOS 自带中文 CJK 字体，避免豆腐块），底部居中。
- ⚠️ 描边而非色块：画面是浅色纸底，白字必须靠黑描边才立得住；色块会挡住 UI。
- ⚠️ 字号不是像素：libass 对无 PlayRes 的 SRT 按 288 高度基准缩放（本片 1006 高 → 约 3.49 倍），
  故 `FontSize=13` 实际约合 45px。改字号要按这个比例换算，别直接当像素填。
- 烧入为 **hard-burn**（字幕像素化进视频），交付文件自包含，评卷方用任何播放器都能看到。
- 产物：`subs/segNN.srt`（分段，输出时间轴）、`subs/all.srt`（整片，累计偏移）、`out/out_NN.mp4`、`final_demo.mp4`。

> 想微调某句出现时间：改 `subs/seg0X.srt` 的时间码后单独重渲该段 —
> `python gen_subs.py --burn --only X`（脚本会重算时间轴，手工改动会被覆盖，适合临时试看）。

## 6. 备选：AI 自动控屏录屏（技术验证，非交付主路径）

- **思路**：computer-use 类 agent（截图 → 视觉决策 → 模拟点击/键盘）按 `录制进度说明.md` 的 14 段步骤驱动 openedu macOS App；同时 OBS 录屏。
- **工具候选**：Anthropic Computer Use / 本地 vision+action 循环（需自备视觉模型与 API Key）。
- **风险**：原生 Flutter UI 对坐标与文字识别敏感，易在中途失败；每段必须可独立重跑。
- **回退触发**：任一段连续失败 2 次，即放弃该段自动方案，改用 §2 手动录。
- **结论**：仅作「技术亮点」验证；正式提交仍以手动录屏 + 字幕为准。
