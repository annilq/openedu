# 演示视频录制方案与命令手册

> 配套文档：
> - `视频脚本.docx` —— 7 段分镜（时长 / 画面 / 旁白），本方案直接采用，不再另起。
> - `安装手册.docx` —— 后端 + 前端 + 模型配置步骤。
> - 本文件只补「怎么录、怎么出字幕 / 配音、怎么合成」的工程细节，并给出 AI 控屏备选方案。

---

## 0. 方案决策（结论先行）

| 项 | 决定 |
|---|---|
| 主体素材 | **真实 App 录屏**（macOS 桌面端运行 openedu） |
| 字幕 | **程序硬烧入字幕（推荐，无语音）** —— 录完一键出 SRT 并烧入，改稿零成本、自包含、任意播放器可见 |
| 配音 | **可选**：AI TTS 中文语音（`voice/seg01..07.mp3` 已生成，随时可合入）；不需要语音也能交 |
| 自动化 | **手动录屏为主**；AI computer-use 控屏录屏作为**技术验证备选**，失败即回退 |
| 不采用 | 纯人工配音（易返工）、把 AI 全自动作为交付主路径（风险高） |

> **为何默认走字幕而非语音**：任务只要求「演示视频 ≤8 分钟」，未强制语音；烧入字幕的静音演示对评分更清晰（关键点直接可见），且省掉 TTS 生成、音画对齐、混音三步。已生成的 7 个 mp3 留作备选，哪天想加语音随时合入。

核心思路：**录制时只采视频、不录声音**，字幕后期由 `gen_subs.py` 自动按片段时长切片烧入。单段可独立重录、改稿零成本。

## 2. 视频采集（三种任选其一）

> 建议**按 7 段分段录制**，文件名 `demo_01.mov` … `demo_07.mov`，放入 `submission_docs/raw/`，便于单段重录与剪接。

### 2.1 系统自带区域录屏（零安装，最快）
```bash
screencapture -v -R 100,100,1280,800 submission_docs/raw/demo_01.mov
# Ctrl-C 或菜单停止录制
```
> 前提是把窗口摆到固定位置、坐标自己量准；想「自动定位 openedu 窗口」直接用 §2.4 的脚本。
> ⚠️ 不要写成 `-v -i`：视频模式不接受 `-i`，会报 `video not valid with -i`。

### 2.2 ffmpeg 全屏采集（需先装 ffmpeg：`brew install ffmpeg`）
```bash
ffmpeg -f avfoundation -list_devices true -i ""   # 确认屏幕索引（如 "1"）
ffmpeg -f avfoundation -i "1" -r 30 -pix_fmt yuv420p -capture_cursor 1 submission_docs/raw/demo_01.mp4
# 若报错要求显式音频索引，改为 -i "1:none"
```

### 2.3 OBS Studio（推荐：质量最高、可「窗口捕获」只录 App）
- 来源 → 窗口捕获 → 选 openedu；设置 1920×1080、30fps → 开始录制。
- 优点：直接框定 App 窗口，避免录到桌面杂乱；后期也能加麦克风旁白轨。

### 2.4 用 `screencapture` 精确锁定 openedu 窗口（零安装、系统自带）

> ⚠️ **两个已实测踩到的坑**（macOS 26 / 2026-10）：
> 1. `screencapture -v -i` 直接报 `video not valid with -i` —— 视频模式不再接受 `-i`，交互框选改用 `-J video`。
> 2. `lsappinfo … -only WindowBounds` 恒返回 `[ NULL ]` —— 该键已废弃，取窗口坐标这条路走不通。
>
> 现方案：用 CoreGraphics 窗口列表拿到 `windowid`，再 `-v -l <id>` **按窗口录**（窗口被遮挡/移动都跟随，且不录桌面与阴影）。

**① 交互式框选（最快，无需脚本）**
```bash
screencapture -v -J video submission_docs/raw/demo_01.mov
# 拖拽框选 openedu 窗口区域；Ctrl-C 停止
```

**② 按窗口精确录制（脚本，适合 7 段分镜重复录）** —— `submission_docs/record_app.sh`：
```bash
chmod +x submission_docs/record_app.sh
./submission_docs/record_app.sh 1                  # 录第 1 段 → submission_docs/raw/demo_01.mov（Ctrl-C 停止）
DURATION=90 ./submission_docs/record_app.sh 2      # 录 90 秒后自动停（每段按分镜时长设）
REGION=100,200,1280,800 ./submission_docs/record_app.sh 3   # 手动指定区域，跳过探测
APPNAME=kids_learn ./submission_docs/record_app.sh 4        # 显式指定进程名
```
脚本做的事：自动识别「bundle 落在本仓库内」的 App 进程名 → `swift` 调 CoreGraphics 取窗口 `windowid` → `screencapture -v -l <id> -o -x -k -C` 按窗口录。

降级顺序：`REGION` 手动区域 → `windowid` 按窗口录 → System Events 取坐标 + `-R` 区域录 → 交互框选。

- ⚠️ **进程名不是 `Runner`**（旧文档写错了）：`flutter run -d macos` 的产物名随项目而变，当前工程是 **`kids_learn`**。脚本自动探测，无需手填；要覆盖再传 `APPNAME=`。
- ⚠️ **输出路径固定** `submission_docs/raw/demo_0N.mov`（补零两位，与 `gen_subs.py` 的 `demo_01.mov` 查找对齐；与运行目录无关）。
- ⚠️ **首次授权**：系统设置 → 隐私与安全性 → 屏幕录制，勾选你跑脚本的终端；否则录出黑屏。
- 默认显示鼠标点击（`-k`）+ 录光标（`-C`）；`CLICK=0` / `CURSOR=0` 可关掉。
- 输出是 `.mov`，后续由 `gen_subs.py --burn` 用 ffmpeg 转 `.mp4` 并烧字幕。

## 3. 字幕生成与烧入（推荐主路径，无需语音）

脚本 `gen_subs.py` 复用 `gen_voice.py` 的同一份 7 段旁白，自动按每段录片时长切片生成 SRT 并硬烧入。

```bash
cd submission_docs

# 3.1 仅生成 SRT（录制后即可；缺片时用占位时长预览）
python gen_subs.py

# 3.2 生成 SRT 并硬烧入每段 -> out/out_01.mp4 ... out_07.mp4
python gen_subs.py --burn

# 3.3 烧入后合并为 final_demo.mp4（≤8 分钟由分段时长控制）
python gen_subs.py --burn --concat
```

- 字幕样式：白字 + 半透明黑底 + 苹方（PingFang SC，macOS 自带中文 CJK 字体，避免豆腐块），底部居中。
- 切片逻辑：每段旁白按句末标点切句，均分到该片时长，段间留 0.2s 间隙；重录某段后重跑即可。
- 烧入为 **hard-burn**（字幕像素化进视频），交付文件自包含，评卷方用任何播放器都能看到。

> 若想微调某句出现时间：直接改 `subs/seg0X.srt` 的时间码，再单独 `python gen_subs.py --burn`（仅重烧已改段）。

## 6. 备选：AI 自动控屏录屏（技术验证，非交付主路径）

- **思路**：computer-use 类 agent（截图 → 视觉决策 → 模拟点击/键盘）按 `视频脚本.docx` 的 7 段步骤驱动 openedu macOS App；同时 OBS 录屏。
- **工具候选**：Anthropic Computer Use / 本地 vision+action 循环（需自备视觉模型与 API Key）。
- **风险**：原生 Flutter UI 对坐标与文字识别敏感，易在中途失败；每段必须可独立重跑。
- **回退触发**：任一段连续失败 2 次，即放弃该段自动方案，改用 §2 手动录。
- **结论**：仅作「技术亮点」验证；正式提交仍以手动录屏 + 字幕为准。
