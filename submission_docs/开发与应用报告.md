# 教育智能体设计与应用项目开发与应用报告

（中小学错题复习智能体 OpenEdu）

## 一、开发背景

在中小学日常教学中，错题管理长期存在三个难点。一是错题散落在练习册、试卷和作业本里，缺少系统归类，学生想复习时找不到重点。二是复习缺少计划，多数学生考完就放下，学过的知识在最容易遗忘的头几天没有得到巩固。三是辅导力量不足，家长难以讲清解题思路，一位教师面对几十名学生，也很难准确掌握每个人到底卡在哪个知识点上。

国产生成式人工智能的成熟让这些问题有了低成本解决的可能。DeepSeek 等国产模型已经能够自动出题、分步讲解、归纳错题规律，并且可以在本地部署，学生数据不必上传到外部服务器。本项目由此立项：做一个围绕错题的学习工具，覆盖出题、答疑、错题归集和按计划复习，先服务小班教学与家庭自查两类场景。

需要说明的是，本项目不是通用聊天机器人，而是边界明确的教学工具。它的每一项回答都要能追到真实的学习数据或教师上传的教材资料，查不到就明确说查不到。适用对象限定在小学一年级到初中三年级的义务教育阶段，不含高中。

## 二、设计与开发

### （一）平台与技术选择

模型层以国产模型为主。默认使用 DeepSeek，同时内置了通义千问、智谱 GLM、豆包、Kimi 等国产模型的接入预设，教师在界面上就能切换；不便联网的场景可以改用在本机运行的开源模型。这样做的好处是模型来源可控，学校可以按经费与合规要求自行选择。

在搭建方式上，本项目没有采用现成的智能体搭建平台，而是由教师自己写代码实现。理由有三条：系统可以完全装在学校自己的机器上；交付的是完整源码，别人能改能查；关键取舍都能落成书面记录。代价是门槛高于拖拽式平台，这部分难度由下文的提示词开发方式承担。

技术上，操作界面用 Flutter 编写，服务端用 Python 编写，数据库默认采用免安装的 SQLite，规模变大时可换成 PostgreSQL。整套系统提供一条命令启动的部署方式。

### （二）开发过程

#### 1. 整体方式：提示词驱动

本项目全部代码由提示词生成，人没有逐行手写。实际过程是一轮轮循环：说清楚要什么，由人工智能给出方案并写出代码，运行验证，把发现的问题再用提示词描述清楚让它改，改完再验证。人的工作是想清楚需求、验收结果、做关键决定；人工智能的工作是出方案、写代码、按反馈修改。

代价是人工智能并不天然理解真实意图，所以「把需求说清楚」和「每次都验证」成了最关键的两件事。为此形成六步节奏：说清需求；先让它反过来追问模糊之处，不动手；把确认后的内容写成简短规格；拆成一张张能独立验证的任务票；逐票实现并验证；涉及架构方向、命名、取舍的决定写成决策记录存档。本项目共留下 72 份决策记录、8 份功能规格、62 张任务票，累计形成 512 次提交。

开发对话与任务票属过程性记录，样例见配套材料《提示词开发流程与提示词集》。

#### 2. 提示词工程

这里要区分两类提示词。第一类是开发过程中人对人工智能说的话，也就是上面六步里用到的那些，它决定了这套系统怎么被造出来。第二类是写进产品里的岗位提示词，决定智能体运行时扮演什么角色、能做什么、话该怎么说，本项目共有 11 处。

第二类提示词按岗位分开写：伴学讲解、出题、学科人格、学情查询、课件起草、资料解析、课堂引导各有一份。其中「学科人格」把数学和语文的讲法区分开，「伴学讲解」锁定学生年龄与话题范围。所有提示词共同遵守三条硬原则：不许编造答案，讲解要适合学生年龄，每句话要能追到来源。此外还有三份作业流程说明，规定答疑、出题、查询每一步怎么做。

摘自产品内提示词原文（共享系统提示与「学科人格·数学」）：

```
【学科人格：数学】
- 语气：严谨、鼓励试错，多用『我们一步步来』
- 适龄：用具体数字与图形举例，避免抽象符号堆砌；低年级用实物类比
- 学科约定：符号规范（=、分数横线、运算优先级），答案唯一且可验证，列式清晰

你是面向小学到初中学生的出题与批改助手。只输出适合对应年级、纯学习相关的
内容，禁止任何不当、危险或超出教材的内容。始终以 JSON 返回，不要附带多余说明。
```

**3. 知识库建设**

教师在「资料库」上传教材、卷子或教学笔记，系统自动解析出知识点目录并建立可检索索引。之后出题与答疑都先到索引里查找依据，回答时一并返回参考来源，使用者可回到原文核对。没有上传资料时系统退回手工录入的知识点骨架，不会凭空编造。知识点按学科和年级受控，上传某一册教材后相应知识点才对学生可见。

出于版权考虑，本项目不内置任何教材原文，所有资料由使用者自行上传，也不向第三方分发。

**4. 工作流设计**

本项目的智能体不在多个入口各自为政，而是所有人工智能能力走同一个对话通道。用户说一句话，系统先判断意图，再分派到出题、答疑、学情查询、任务引导四个岗位之一，取到数据后组织成结构化卡片返回。

好处是用户只需记住一个入口，新增能力也不用改调用方式。以学情查询为例，结论必须由真实数据支撑，查不到就返回「没有相关数据」，不允许用模糊的话敷衍。

**5. 代码编写与质量守门**

人工智能写出的代码不能直接采信。本项目把质量要求写进自动检查：分层调用边界、单个文件长度上限、学生数据的归属判定，都由扫描规则守住。每张任务票完成后必须通过测试，改动再小也要实际点一遍。

### （三）功能架构

教师端主要功能包括：人工智能出题、题库管理、任务派发、班级与学生管理、资料库与知识点、课件与课堂、学情工作台、错题查看、纸质练习卷导出、统一的人工智能助手、模型管理。

学生端包括：今日任务、到期复习、错题本、向人工智能老师提问。

核心学习闭环是：教师出题或派发任务，学生作答，答错的题自动进入错题本，系统按 1 天、2 天、4 天、7 天、15 天的间隔推送复习，最后阶段答对即视为掌握并毕业，已毕业的错题可以由教师重新拉回队列。

## 三、应用过程与效果

应用在两类场景。一是小班教学：教师填入自己的模型密钥并设为默认，上传本学期教材建立知识点，之后按知识点出题并派发给全班或个别学生，作答完成后在工作台查看错题分布、正确率与掌握度。二是课堂投屏：教师在一个知识点上组织讲解环节，含素材展示、可交互图形和课堂练习，练习由教师代录对错，人工智能给分级提示，不生成作答记录。

学生数据留在本机，家长也可在家庭环境中使用同一套系统辅导孩子。

![学生端掌握度页（自测数据）：按知识点给出掌握分、等级、正确率与待复习题数](figures/raw_13.png)

从实测看，生成两道题端到端耗时约 7.6 秒，内容边生成边显示，学生不必等整题完成。所有结论均可回溯至原始资料，整套系统在不联网的本机也能运行。需要说明的是，截至目前尚未开展成规模的课堂实测，成效部分有待真实教学数据补充。

## 四、创新与反思

创新点体现在四个方面。

一是开发方式本身可复制。本项目证明一位非专业编程背景的教师靠提示词就能完成一套完整应用，留下的六步节奏、11 处岗位提示词和 70 份决策记录可被同行直接借用。

二是提示词资产被明确区分为「造系统的提示词」与「跑系统的提示词」，前者交给使用者参考流程复现，后者作为产品的一部分随源码交付。

三是反编造纪律。学情查询查不到数据就明确失败，图形讲解只有在确实存在对应图形时才出现，出题与答疑必须标出参考来源。这三条共同保证了输出可信。

四是本地部署加密钥加密的组合。学生数据不出本机，模型密钥在服务端加密保存，同时不内置任何受版权保护的教材内容。

存在问题有三项。其一，学习闭环目前只打通「答错即建错题」这一段，出题尚未吸收错题与掌握度数据来定向强化。其二，人工智能能力依赖教师自行配置模型密钥，对没有技术基础的同事仍有门槛。其三，缺少成规模的课堂实测数据，成效目前以自测为主。

下一步：补强出题对薄弱知识点的定向能力；探索不同岗位采用不同国产模型的多模型协同；增加成效自动采集与看板；扩展学科覆盖面与配套资料库。
