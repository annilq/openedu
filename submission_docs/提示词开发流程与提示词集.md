# 提示词开发流程与提示词集

> 配套资源说明。本项目从 2026 年 8 月 20 日到 10 月 9 日共 502 次提交，全程以对话方式驱动 AI 完成，代码中未手写业务逻辑的部分由提示词产出。
> 本文档回答两件事：配套资源要不要交源代码，以及这个项目实际经历了哪些阶段、每个阶段用了什么样的提示词。

---

## 一、关于"配套资源"要不要交源代码

### 结论：要交。提示词是主角，代码是证据，两者缺一不可。

任务原文是"提供完整的开发流程、截图、提示词等资源，参考流程则可做到复现。文档则包含使用手册、安装手册、开发记录等有助于他人顺利使用的文档"。

这句话容易读成"只交提示词和流程就行"，但有三处不支持这个读法。

**第一，"等"字出现两次。** "提示词等资源"和"开发记录等"都是非穷举列举，说明这是配套资源的**最低内容要求**，不是全部清单。原文没有写"仅限以下"。

**第二，复现这个词有两种含义，两种都要满足。** 如果复现指"别人照着流程也能做一个类似的智能体"，那流程和提示词是核心；如果指"别人能把你这个智能体真的跑起来"，那代码和安装手册是核心。评审看到"复现"二字时取的往往是后一种。只交提示词，评审无法验证，因为同一段提示词换个模型、换个时间，产出的代码不一样。

**第三，去掉代码换不来任何好处。** 打包一个压缩包成本极低，而少交代码的后果是被判"无法验证"。

### 建议的交法

主次要分清：**提示词和流程放在最显眼的位置**，代码作为验证材料附在后面。原因很实际，本项目 502 次提交、70 份决策记录，如果直接把整个仓库丢进去，评审翻不到提示词，等于没交。

建议压缩包根目录这样组织：

```
openedu-教育智能体/
├── 00-先看这里.md              目录导航，三句话说清每份文件是干什么的
├── 01-开发流程.md              七个阶段，含每阶段截图位
├── 02-提示词集.md              开发用提示词 + 智能体内置提示词
├── 03-使用手册.docx
├── 04-安装手册.docx
├── 05-开发记录.docx
├── 06-演示视频.mp4
├── screenshots/               各阶段界面截图
└── source/                    完整源代码
```

## 二、本项目实际经历的七个阶段

下表每一行的"痕迹"都是仓库里现在还查得到的真实产物，不是事后补写的。

| 阶段 | 本项目的真实痕迹 | 产出物 |
|---|---|---|
| 1. 有个想法 | 首次提交 `2e7f687`（2026-08-20）"初始化娃娃学习App项目" | 一句话定位 |
| 2. 探可行性 | 早期决策 ADR-0001 题库模型；9 月反复排查"配了模型却出不了题"，真因是运行环境缺一个开关 | 能跑通的最小验证 |
| 3. 探边界 | `CONTEXT.md` 术语表；ADR-0002 家长儿童双模式；后来 ADR-0065 整体改判为教师学生 | 术语表 + 范围界定 |
| 4. 析功能 | 产品说明 14 个功能模块；`frontend/lib/features/` 逐个落地 | 功能清单 |
| 5. 定架构 | ADR-0027 按功能分包、ADR-0003 子智能体契约、ADR-0024 统一对话入口、ADR-0025 流式事件契约 | 70 份决策记录 |
| 6. 切票据 | `docs/specs/` 9 份规格说明；`.scratch/` 8 轮共 62 张票 | 规格 + 票 |
| 7. 实施 | 502 次提交，票号对得上（T01 到 T09） | 可运行的产品 |

第 5 到第 7 步是循环往复的，不是走一遍就完。每落地一轮，会冒出新的边界问题，再回到第 3 步重新界定。比如教师端规模化那一轮，就是先把班级和学生两个概念定义清楚（ADR-0068），再拆成 20 张票去做。

## 三、每个阶段的提示词

**这些提示词是根据仓库里的真实产物复盘还原的模板，不是当时的逐字原文。** 逐字原文没有保存下来。它们的作用是可复用，你拿去改改就能用在别的题目上。

### 阶段一：想法

这一步的目标不是让 AI 写代码，是让它帮你把模糊的想法讲清楚。

```
我想做一个帮小学生复习错题的应用。孩子做完题会错题，
但错题散在各处，复习也没计划，家长自己也不会讲。

请先不要写代码，帮我回答三个问题：
1. 这个想法里，最关键的是哪一个动作？
2. 如果只能做一个功能，做哪个？
3. 有哪些看起来该做、但其实可以先不做的？
```

**要点**：明确说"先不要写代码"。不写这句话，AI 会立刻开始生成代码，而这一步你需要的是判断。

### 阶段二：探可行性

这一步要的是"能不能成"的证据，不是方案。

```
我要验证一件事：能不能让 AI 自动生成小学数学题，
并且题目能自动存进数据库。

请给我一个最小验证方案，要求：
- 只做一条通路，不做界面
- 能跑通就算成功，跑不通就明确告诉我卡在哪
- 列出这条通路需要的前置条件

另外，我打算用国产模型，请告诉我需要准备什么。
```

**要点**："跑不通就明确告诉我卡在哪"这句很关键。没有它，AI 倾向于报喜不报忧。本项目在这个阶段踩的坑就是环境开关没开，但表面症状看起来像代码写错了。

### 阶段三：探边界

这一步最容易被跳过，也最容易在后期返工。

```
我们现在要用到的词有点乱，一会儿说"学生"一会儿说"儿童"，
一会儿说"题目"一会儿说"试题"。

请帮我做一份术语表：
- 列出这个项目里的核心概念
- 每个概念给一个唯一的说法
- 标出哪些说法是禁止混用的

另外请告诉我：这个产品给谁用？明确列出不属于它的场景。
```

**要点**：本项目的真实产物是 `CONTEXT.md`，里面明确写了"题目"不等于"试题"、"儿童账户"不等于"学生"。这份术语表在后来的每一轮里都被反复引用，是避免需求漂移的锚点。

### 阶段四：析功能

```
基于产品定位（教师和学生两个角色），请列出完整功能清单。

要求：
- 按角色分组
- 每个功能写一句话说明，说明用户拿它干什么
- 标出哪些功能依赖 AI，哪些不依赖
- 标出哪些功能必须先有，否则后面的做不了
```

**要点**：让 AI 标出依赖关系。本项目的学习闭环里，"答错就自动建错题"是最早打通的一段，而"出题时参考错题"一直到最后仍在打磨，就是因为依赖没理顺。

### 阶段五：定架构

这一步 AI 容易过度设计，要主动约束。

```
请给一个技术架构方案，约束如下：
- 后端用 Python，前端用 Flutter
- 数据库先用最简单的，能零依赖跑起来
- AI 相关的代码要单独放，不要和业务代码混在一起，
  因为以后可能换模型
- 所有 AI 对话只走一个入口，不要每个功能各开一个

请先给方案，等我确认再动手。
另外，每个重要决策请单独写一份决策记录，
写清楚为什么这么选、放弃了什么。
```

**要点**：本项目留下了 70 份决策记录，每一份都写"决策 + 放弃的方案 + 后果"。这是最有价值的资产之一，评审看到这个就知道不是随手搭的。

### 阶段六：切票据

这一步决定了后面能不能稳。切不好的标志是：一张票做三天还没完。

```
请把这份规格说明拆成可独立交付的票。

每张票必须包含：
- 要做什么（一句话说清）
- 被谁挡着（没有就写"无"）
- 完成标准（可勾选的清单）

约束：
- 单张票不要超过一天
- 每张票做完必须能单独验证
- 标出哪几张可以并行，哪几张必须排队
```

**要点**：本项目 62 张票，每张都带"完成标准"勾选清单。做之前先看有没有被挡住，被挡住就先做挡路的那张。`.scratch/teacher-scale-up/INDEX.md` 里画了依赖链，一眼能看出该先做哪张。

### 阶段七：实施与守门

这一步的提示词要带上项目自己的规矩，否则 AI 会写出不符合既有约定的代码。

```
请实现 05 号票。

动手前先读这几份文件，里面的硬约束必须遵守：
- AGENTS.md（入口索引）
- docs/agents/development.md（命令与规范）
- CONTEXT.md（术语，用词不许漂移）

完成后必须自查：
- 静态检查零问题
- 相关测试全通过
- 单个文件不超过 400 行
- 没有引入项目禁用写法

先说你打算怎么改，我确认再动手。
```

**要点**：本项目把这些硬约束写进了代码检查里，不是靠人记。比如"文件不超过 400 行""分层不许跨层调用"都有自动检查守着。这样 AI 写完自己就能发现问题。

## 四、智能体自己的提示词

上面七类是**开发时用的提示词**，是你对 AI 说的话。还有另一类完全不同：**写进产品里的提示词**，是智能体运行时对用户说的话。两类都要交，别混在一起。

本项目产品里的提示词共 11 处，分三个用途。

**岗位提示词**（决定智能体扮演什么角色）

| 位置 | 作用 |
|---|---|
| `app/domain/safety.py` | 伴学答疑，锁定年龄与话题范围 |
| `app/domain/prompts.py` | 出题与批改，要求按固定格式返回 |
| `app/ai/subagents/subject_personas.py` | 学科人格，数学和语文的讲法不同 |
| `app/ai/subagents/query/agent.py` | 只读查询，查学习情况 |
| `app/ai/subagents/guide/agent.py` | 课堂大屏出题 |
| `app/features/courseware/service.py` | 课件起草 |
| `app/features/materials/service.py` | 从教材资料里提取知识点 |
| `app/features/assistant/service.py` | 对话摘要 |

**作业流程提示词**（三份独立文件，规定每一步怎么做）

`query_sop.md`、`question_sop.md`、`tutor_sop.md`，分别在 `app/ai/subagents/` 下的三个目录里。

**兜底提示词**（不出意外时不出现，出了意外才生效）

模型没配时说什么、问题超出范围时怎么回应、卡片上的引导按钮写什么。这部分是确定性的，不走模型。

### 三条硬原则

本项目所有智能体提示词都遵守这三条，写新的提示词时也建议保留。

**不许编造。** 查不到就直说查不到，不许编一个看起来像真的答案。所有结论必须能追到真实数据。

**适合年龄。** 对象是中小学生，讲解用词和深度都要按年级调整。

**可以溯源。** 回答里要标注依据来自哪份教材的哪个知识点，让用户能回去翻。

## 五、两点提醒

**关于截图。** 开发流程这部分必须配截图，否则评审看不到"过程"。建议每个阶段留一到两张，重点是能看出"这是 AI 参与的"：比如提示词输入框、AI 生成的方案、按票提交的记录。空着的地方先用占位标注，不要临时编。

**关于原文缺失。** 第三节的提示词是复盘还原的模板，不是逐字原文。如果评审细问"这是当时的原话吗"，如实说明即可。真正有说服力的不是某句话怎么说的，而是这套流程确实产出了 502 次提交、70 份决策、62 张票和一个能跑起来的产品。
